## 复算与证据

从 #813 归档或对应 Actions artifact 复制到新目录后，在仓库根目录运行（`<F1场景目录>` 为 F1 的 `measure-*/scenarios`；规模目录多一层 `scale-1x/` 或 `scale-10x/`）：

```powershell
python scripts/measure/summarize.py <F1场景目录> --output <新F1汇总.json>
python scripts/measure/summarize.py <F2的scale-1x场景目录> --output <新规模1汇总.json>
python scripts/measure/summarize.py <F2的scale-10x场景目录> --output <新规模10汇总.json>
```

结果取 `scenarios.*.openings.A.by_operation`。三张典型负载表分别读 `click_to_operable_seconds`、`operable_to_ready_seconds`、`load_button_to_operable_seconds`，规模表读前两项。范围下限从同批 `scene-operations.jsonl` 中 `kind=open`、`sample_valid=true` 的这些字段取最小值；上限为汇总的 `maximum`。归档派生文件为 `issue-813-f1-openings.json`、`issue-813-f2-openings-{1,10}x.json`。不纳入无效 P1、P2、F7，也不纳入预演 P1-R、P2-R。原始数据与逐轮明细留在 [#813 报告](https://github.com/odradekk/train/issues/813#issuecomment-6477047742)。
