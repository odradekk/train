## 节点稳态增量

典型 standard-world 取 F4；重负载规模 1× 的节点取 F2b、地图取 F2c，各 3 轮。节点 Ready 后及地图末段均保持 60 秒，末 10 秒私有字节 `(max−min)/min ≤1%` 才记 stable。每轮取末 10 秒 nearest-rank P50，然后按轮序号作**跨独立进程配对**：节点减地图；不是同进程进入前后的差。F2b／F2c 的产品及节点路径相同，版本差异只影响地图保持和离线统计，按 #813 已批准的方式复用。

每格为三轮中位数（最小–最大）：

## 复算与证据

从 #813 归档复制到新目录后，在仓库根目录运行；每个 `<场景目录>` 为对应 `measure-*/scenarios`（规模多一层 `scale-1x/` 或 `scale-10x/`）。汇总器读取同目录的 `summary.json`、各轮 `report.json`、`process.json`、`scene-operations.jsonl`；节点／地图稳定性另需 `scene-frames.jsonl`，F3 分析另需 `scene-collections.jsonl`：

```powershell
python scripts/measure/summarize.py <F4场景目录> --output <新F4汇总.json>
python scripts/measure/summarize.py <F2b某规模场景目录> --output <新节点汇总.json>
python scripts/measure/summarize.py <F2c同规模场景目录> --output <新地图汇总.json>
python scripts/measure/summarize.py <某轮长测场景目录> --output <新长测汇总.json>
python <归档脚本目录>/issue-813-analyze-f3-memory.py <F3场景目录> --output <新F3分析.json>
```

节点／地图读 `scenarios.*.memory_stability.A[]`，按 run 配对相减；长测读 `scenarios.scene-soak.hourly_memory.A.runs[].hours[]`，同一小时跨三轮取中位数和范围；绝对值读各原报告 `assessment.items` 的 game_private／game_working_set／game_render；存活堆读 F3 分析的 `forced_gc`。

归档派生文件为 `issue-813-f4-paired-memory.json`、`issue-813-f2c-paired-memory.json`、`issue-813-f3-memory-analysis.json`、`issue-813-soak-combined.json`；采样峰值比为 `issue-813-final-extra-evidence.json`，计数和公式见上文，逐轮来源见 [#813 报告](https://github.com/odradekk/train/issues/813#issuecomment-6477047742)。原始字节和记录文件保留在归档。排除无效 P1、P2、F7 和预演；使用 F7-R（40712398120，目录仍名 f7）。`a54efab3` 前仅保持 5 秒的 scene-map 数字不与新基线混算。
