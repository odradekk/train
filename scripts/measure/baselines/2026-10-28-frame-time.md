## 典型负载：完整路线（F4）

standard-world 的 1×／8× 各 3 轮，均完整走完路线、无预演截断或暂停。以下每格为跨轮中位数（最小–最大），不拼接不同进程的帧。帧分位数使用 nearest-rank。

帧统计只取 `timing.frames.elapsed_seconds > startup.first_operable_at`，排除打开段，保留可操作后的补齐、切换及报告末尾轨迹帧。单位 ms：

## 复算与证据

复制 #813 归档后，在仓库根目录运行。`<F4场景目录>` 为其 `measure-*/scenarios`；归档分析脚本连同原始记录复制：路线需要同目录的 `report.json` 和 `route-frames.jsonl`；长测需要 `report.json`、`scene-frames.jsonl`、`scene-operations.jsonl`、`scene-collections.jsonl`。输出使用新文件：

```powershell
python scripts/measure/summarize.py <F4场景目录> --output <新F4汇总.json>
python <归档脚本目录>/issue-813-analyze-f4-route.py <F4场景目录> --output <新路线分析.json>
python <归档脚本目录>/issue-813-analyze-soak.py <某轮长测场景目录> --output <新长测分析.json>
```

路线取 `runs[].post_operable_frames`、`actual_speed_reported` 和 `gc_windows`。归档另存的 `post_operable_actual_speed` 按原报告 `timing.frames` 中首次可操作帧（elapsed_seconds 等于 first_operable_at）到末帧的 completed_steps 差／60／elapsed_seconds 差复算。长测取 `runs[].frame_groups[]` 同视图／倍速／负载类别，每轮分布分别取值后计算三轮中位数、最小和最大；GC 取 `natural_gc`。

基线复用了归档 `issue-813-f4-route-analysis.json`、`issue-813-{f5,f6,f7}-soak-analysis.json` 和 `issue-813-soak-combined.json`，未重新采样游戏。完整窗口、帧数、分类和逐轮值见 [#813 报告](https://github.com/odradekk/train/issues/813#issuecomment-6477047742)。原 F7（40704847748）、P1、P2 无效，预演也不入统计；F7-R 的归档目录仍名为 `issue-813-f7`，有效 run 是 40712398120。
