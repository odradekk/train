# 临时数组报告

`gc-heap.json.Arrays` 只分析真实对象中的 `System.Byte[]` 和 `System.Char[]`，统计采用原始图大小；图采样时这些仍是原始采样统计，完整性限制与主报告相同。数组大小包含对象头，不推断元素个数。报告不保存图、节点索引或地址，第一份图返回匿名汇总后再读取第二份。

- `Histogram`：按对象字节分为 `[2^k, 2^(k+1))`，零大小单列 `[0,1)`。每档列类型、边界、数量与字节。
- `LargestByteArrays`／`LargestCharArrays`：各取最大 50／20 个。每项有大小、第一根类别和最多 128 步的第一路径；`DirectReferrers` 列出图中全部直接引用者的类型及数量。同一父对象的重复边去重，同类型的不同父对象计数累加。合成根明确标成 `synthetic_root`；固定静态字段标签可附声明类型和字段名。
- `BeforeSameSizeCount`：第一图里同类型、同对象大小的数组数；`SameSizeCount` 为本图数量。这只是大小粗配。单图分析没有第一图，前者为 null；配对报告的第一图与自身配对。
- `ParentTypes`：每个数组对每种直接父类型只计一次。跨父类型共享的数组分别计入各组，所以组间会重复，不能把各组求和当作总量或独占保留量。合成父节点统一归为 `synthetic_root`，其字段细节保存在最大数组条目。
- `PoolTypes`：按真实类型名包含 `ArrayPool` 的规则统计对象数，并列出这些类型直接引用的两类数组数量和字节。数组仍按父类型去重。类型名匹配只提供证据分类，不证明运行库池行为。
- `StackPaths`：分别从工具记录的 `[local vars]` 和 `[thread static vars]` 出发，统计可达数组以及其中存在经过池类型路径的数组。即使同一数组也有更短的直接 stack 路径，较长池路径仍计入。每类根内每个数组只计一次，两类根之间可能重叠。stack 标签不能直接证明某个线程或栈帧，也不把实际 TLS 一律推断为 stack。

`gc-difference.json.arrays` 按相同键对齐四类汇总：Histogram、ParentTypes、PoolTypes、StackPaths；不存在的组按零计算，再给 before、after 和增量。最大数组条目只在各快照中列出，第三次快照带首次同大小数量。

静态字段只解析固定的 `[static var <type>.<field>]` 格式。声明类型允许命名空间、嵌套类型、常见泛型和数组语法，字段必须是标识符；路径、地址、控制字符、未知标签均省略。普通实例字段仍不可得。路径上的静态字段标为 `gcdump_static_field_label`，宿主 `_content` 的源码推断保留原标记。

分析先找目标数组，再扫描全部节点的边，仅为目标数组保留反向父集合。每类根采用“尚未经过池／已经过池”两个访问状态，每条边每类最多处理两次，允许循环和多根。入边汇总与可达性是 `O(V+E)`；代表数组排序是 `O(A log A)`。额外内存为 `O(V+A+E_target)`，不建立全图反向索引。只为最多 70 个代表数组构造路径。

`check-gc-arrays` 用真实序列化图验证首个小数组与另一个持有者的大数组、多父去重、较长池路径、TLS、大小边界、粗配、50／20 上限、无根和截断。`check-gc-array-scale` 用已知结构检查百万级节点统计和耗时；`work-object-count` 是数组与普通工作节点数，另有固定池对象及合成根。原始图始终放工作树外，并在结束时删除。
