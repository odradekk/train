# 体素引擎公开契约

本页落实[体素引擎层公开契约：场景、拾取与编辑会话](https://github.com/odradekk/train/issues/289)的决定。业务与表现规则仍见[场景](../design/01-voxel-engine-and-scenes.md)、[渲染](../design/07-rendering.md)、[编辑器](../design/15-design-editor-and-tools.md)；公共语义、身份与提交沿用[公共约定](conventions.md)、[跨层协议](transactions.md)和[编辑协议](editing.md)。

当前生产实现提供世界会话生命周期、不可变帧和增量、32³ 区块占格、立方体网格与拾取、贴图方向与跨格平铺、只读设计预览，以及 #315 的线路场景数据生成。线路生成使用固定 Core／Content 读视图，独立行为入口为 `scripts/test.ps1 -Project scenes -Layer fast`；受控后台测试与实际线路生成测试分别验证会话时序和几何行为，不证明真实四模块联调或 Godot 画面。节点及跟随穿越节点、下一场景预建待 #316；战斗、生物、损伤与 TerrainCollision 待 #353；会话中铁轨数／断点增量更新、断点缺口和工地待 #345；标准形状与模型几何待 #388；编辑待 #333；模板预览待 #389。Scenes 已接入 C# 检查工具的隔离矩阵，单次隔离结果以运行证据为准；真实 Godot 接入和阶段联调归 #298，仍需各自证据。

按 [#248 批准方案](https://github.com/odradekk/train/issues/248#issuecomment-6135067760)，Cube 表现且 Shape 为 null 或 `"cube"` 时生成立方体几何并参与遮面；其他形状及模型保留占格和拾取，不遮挡邻面，几何待 #388。节点、战斗生成以及跟随列车进入节点仍抛带对应 Issue 编号的 NotImplementedException，经后台故障路径报告 Faulted／scene_internal_fault；OpenEditor、PreviewTemplate 分别注明 #333、#389。

线路按 64 米分段后台构建，输出地形柱、地貌过渡、削坡填方、水面、带键随机装饰、按轨数选择的桥梁与洞口、钢轨和轨枕。河流与湖泊识别 Demo 清单的 `river`／`lake` 特征 id。道床暂用线路地貌的 RockVoxel（上层 19 格、下层 21 格），顶面位于轨面下 1 格以支撑轨枕，不增加内容字段；装饰平整地形时保留铁路净空和水域。中心线依固定输入和铁轨上限预留走廊，当前轨数只决定以 34 格中心距对称放置的铁轨；长度由圆弧与直线构造，短节点间距或坡度使地图直距不可用时采用 [#315 批准规则](https://github.com/odradekk/train/issues/315#issuecomment-6135918111) 的场景弦长。节点基准高程统一为 0，地图 X／Y 映射到场景 X／Z；端点地形转换到节点局部坐标后使用共享采样，调整弦长不会改变节点的采样空间。越过端点的车辆沿切线直线延长摆放。

线路显示各铁轨上的全部列车；仅相邻完成步之间插值，运动和浮动原点平移复用网格，FindPose 与拾取共用显示姿态。车长取设计 VehicleLengthCells；编组存在未知车长时，各成员用 Missing 标记置于权威编组中心并报告 vehicle_length_unknown，不猜测长度。轮对按根网格 Z 行生成，档位轨距为 3／7／15 格，半径为 0.5／1／2 格、轮宽为 0.25／0.5／1 格，均为集中定义的暂定数值；转角由显示弧长直接计算。Locate 和 TerrainHeight 仅在已接入分段提供映射；相机采样转换到稳定线路空间。后台任务和工厂共享几何表有界，内容重绑定按实际读取的值依赖复用未变化分段。灯光、特效集合仍为空，NodePanBounds 为 null，DebugLayers 不产生 DebugLines。这些是阶段实现状态，下面的完整目标契约保持不变。

## 公开面与责任

声明项目为 [Train.Scenes.Contracts](../../Contracts/Scenes/Train.Scenes.Contracts.csproj)，只引用核心和内容契约。

| 声明 | 调用方使用的内容 |
| --- | --- |
| [Values.cs](../../Contracts/Scenes/Values.cs) | 运行身份、坐标、结果、诊断与命中 |
| [World.cs](../../Contracts/Scenes/World.cs) | 工厂、世界快照、观察目标与场景会话 |
| [Rendering.cs](../../Contracts/Scenes/Rendering.cs) | 不可变显示帧、增量、网格、实例和特效 |
| [Editing.cs](../../Contracts/Scenes/Editing.cs) | 编辑修订、操作、预览、选取、撤销与固定快照 |
| [Authoring.cs](../../Contracts/Scenes/Authoring.cs) | 只读设计预览、固定聚居地模板的空间预览与地块拾取 |

实现程序集只公开 `Train.Scenes.ScenesFactory.Create()`，返回 `IScenesFactory`；其余实现类型为 internal。Godot 的 `App/Composition/` 调用真实工厂，其他代码只接收契约。体素实现负责地形与铁路生成、网格与遮面、对象姿态、逐格拾取、编辑动作及内部任务；不把区块、中心线算法、重建队列、线程池或缓存策略交给宿主配置。

核心负责世界规则，内容负责设计计算、外观定义与资产原始字节。Godot 负责输入、相机控制、界面覆盖层、文件、日志和真实渲染资源；它不遍历设计布局生成场景，也不计算设计哈希、部件编号或路线。宏观地图与管理面板可直接读取核心，场景接口不是这些查询的中转层。

## 坐标与身份

- 场景以格为单位，一格 0.5 米、一个 Godot 单位；`+X` 右、`+Y` 上、`+Z` 前。核心长度仍是米，换算只发生在表现边界。格 `(x,y,z)` 占据 `[x,x+1] × [y,y+1] × [z,z+1]`；正交朝向绕格中心旋转。
- `ScenePoint` 为当前节点或线路空间中尚未减浮动原点的双精度坐标，不是宏观地图坐标。`ISceneFrame.Origin` 与单精度显示坐标相加才得到该空间内的位置。不同 `Space` 不能直接相减。
- `ScenePose` 为单位四元数及平移，无缩放或剪切；根相对该帧浮动原点，子对象相对父对象。所有向量和标量有限；射线方向归一化，长度为正；集合不可为 default。
- `SceneBinding` 由宿主在运行会话或有效内容更换时重新分配，不是存档 UUID。`SceneSessionId` 由体素创建；同一绑定可以关闭后重开场景，产生新的会话身份，二者不是一一对应。`SceneRequestId` 区分显式观察请求，`SceneSpaceId` 区分节点、线路及编辑空间；这些都是运行身份，不入权威存档。
- 帧修订在会话内单调增加；对象、效果身份在会话内不复用。稳定对象更新继续使用原 ID，不以重建批次冒充业务身份。`WorldObjectId`、设计、部件及内容身份沿用各自契约。

宿主传入的 `SceneWorldSnapshot` 来自同一完整边界，核心 `InputIdentity` 与内容 `Core.Identity` 相同。同一有效世代中，本局已保存草稿或新聚居地模板副本可以增加 `PersistentRevision`；只要业务输入及世代仍匹配，就能交入新的固定视图。体素不得把不同边界查询拼成一次快照。OpenWorld 在创建前检查初始核心视图与内容业务输入身份，不匹配时抛 ArgumentException，不创建会话。

生物按核心查询或本次事件的 `Definition`，从配对固定内容视图的 `FindCreature` 取得当前种类外观；核心不提供生物设计哈希。生物死亡后的瞬时表现也按事件保留的种类解释，不要求死亡个体仍在查询结果中。车辆和建筑仍按实例或事件中的设计身份取得对应布局。

## 世界场景会话

一次调用顺序如下：

1. `OpenWorld(binding, snapshot)` 轻量创建，不等待场景生成。随后 `RequestView` 选择地点、指定列车中的车辆或战斗。地点可含线路弧长，用作初始观察中心；不是要求生成一个单独世界位置。跟随车辆必须属于指定列车。
2. 宿主在命令或模拟完成后串行 `Observe(snapshot, newEvents)`，交入本次新事件。它不触发同步大场景构建，也不接受倒退的模拟位置。事件必须有序、不重复，且不晚于输入边界。绑定、内容世代或业务输入身份不匹配、模拟位置倒退以及事件乱序、重复或超出边界均违反接口前提，必须在接入前检查并抛出 ArgumentException，保留原输入，不返回业务失败码。
3. 体素自行安排首次构建、线路分段与至多一个下一场景预建。宿主逐显示帧调用 `Present`，取得当前可显示部分、加载状态与诊断；核心继续推进，不等待构建。
4. Godot 准备本帧需要的资产与资源，在帧之间完整应用 `Update`，成功后才把它记为实际显示帧。相机、拾取和下一次 `Present` 都使用这份帧。
5. 观察目标切换调用 `RequestView`。新目标无效时返回 Failure，旧请求保持；成功产生新身份，即便目标值相同也使旧请求失去接入资格。跟随中的边、节点切换由体素处理，不要求宿主发区块命令。
6. 不再显示或活动绑定更换时关闭会话。`DisposeAsync` 调用即撤销输入与交互资格，然后等待内部任务退出；可先打开新会话，不能为了旧任务退出暂停新核心。

会话变更操作在宿主同一协调线程串行调用，禁止并发和重入；`DisposeAsync` 的等待不占用该线程执行构建。体素工作线程只读已固定输入，完成后由 `Present` 接入。普通模拟推进不废弃所有在建工作：体素核对依赖，补齐当前损伤、对象存在性、设计及铁路变化，必要时只重建受影响部分。取消、关闭或跨绑定的迟到结果只能丢弃，不能复活已删除对象或旧拾取。

`Loading` 表示目标尚无可显示内容，`Partial` 表示部分空间未就绪，`Ready` 表示当前需要范围完整，`Failed` 表示目标构建失败。未就绪区域显式列在 `FoggedRegions`，不能伪装成空地。一次 Present 返回 Faulted 时宿主报告表现故障并停止该会话的交互，不回滚或冻结核心；可重开场景。正常目标消失通过 `target_missing` 报告，宿主按相机规则选择下一目标。

跟随切换遵守[场景切换](../design/01-voxel-engine-and-scenes.md#跟随列车时的场景切换)：依次经过线路、节点、线路，不跳过节点；不知道下一线路就不猜，预建来不及用雾收住。核心公开世界种子、所选铁路规则、节点进入/下一线路与编组正反，详见[核心查询](core.md#读视图查询与事件)。更换有效内容时重开场景会话；实现可共享未变化的不可变几何，仍须只重建受影响对象和区块，不能把重开理解为一律重算整个场景。

## 显示更新与资源

`ISceneFrame` 是可保留的不可变显示边界，包含同一时刻的姿态、拾取、空间映射和显示更新。帧身份统一使用 `Update.Frame`。`Present` 的 `displayedFrame` 必须是已经完整接入 Godot 的最后一帧；不能传仅计算或准备过的帧。`Update.Base=null` 唯一表示完整替换：首次、传 null 或空间变更时返回该帧的全部对象。增量更新的 Base 必须等于实际显示帧的 `Update.Frame`。

Godot 按以下顺序准备并一次接入：完整替换时移除旧场景；增量时先给所有现存根加 `ShiftExistingRoots`，再删除 Removed、加入或替换 Upserts，最后替换 Environment。Upserts、Environment、效果和调试线已经使用新原点；父子关系无环，每个存活对象的父对象必须存在。移除包含不再存在的子对象，Godot 不猜测级联业务语义。同一更新内 ID 不重复且不同时出现在删除与更新中。

浮动原点平移不重建网格；运动只更新姿态并复用原不可变几何。`FindPose` 返回合成到当前根空间的显示姿态，相机与渲染共用它。`SceneCameraSample` 携带实际显示帧及焦点，体素负责转到稳定空间并沿线路定位。`Locate` 给出业务地点，`TerrainHeight` 返回相对本帧原点的格高度，尚无几何映射时为 Missing。

`NodePanBounds` 由体素给出节点场景完整的水平相机范围，分量为本帧根空间的 X、Z 格坐标，随浮动原点一起换算；不是当前已生成网格的包围盒。节点的 Partial／Ready 帧必须提供，Loading 尚未确定时可为 null；非节点帧为 null。Godot 只限制节点自由环绕的焦点，范围缺失时保留焦点，不猜边界；跟随相机继续使用显示对象姿态。此字段由[Godot 宿主契约](https://github.com/odradekk/train/issues/290)补齐已有的相机规则，不冻结具体场景尺寸。

Base 不匹配、资源尚未准备好或适配失败时，不部分应用更新，也不把新帧设为 displayedFrame。下一次仍以最后成功的帧请求；必要时传 null 获取完整替换。绑定切换后旧画面失去交互资格，即使为过渡暂时保留，也不能继续拾取。GPU 资源的创建、原子接入和退役由 Godot 契约落实。

显示值及其全部集合元素不可变，调用方可以跨更新或关闭保留，不需要归还缓冲；不再使用时释放引用，由 GC 回收。关闭会话不会释放 Godot 的纹理、网格或材质。双方可共享不可变值，不要求每帧深拷贝全部世界；不公开租借期限、引用计数或区块释放协议。

### 网格、模型与效果数据

| 数据 | 格式与责任 |
| --- | --- |
| `SceneMesh` | 对象局部格坐标，顶点法线归一化，三角形索引合法且个数为三的倍数，从外侧看逆时针；Godot 转换引擎绕序 |
| `SceneVertex` | TextureUv 为已计算的贴图坐标；FaceUv、外露边标志、相对高度、损伤供着色器使用；比例在 `[0,1]` |
| `SceneMaterial` | 面贴图只含资产修订、材质类别及可选涂装；钢轨、轨枕、水面和施工表现使用项目自带材质 |
| `SceneVisual.Model` | 一格一个原始模型引用，材质次序沿用内容元数据；对象 Pose 已包含格放置和绕格中心的朝向。Godot 只将模型米坐标换为格，不额外适配尺寸。相对高度平面把模型局部格坐标换成所属对象高度比例，用于积灰 |
| `Wheelset` | 体素给出位置、轴向、尺寸和转角，Godot 提供轮对模型；轴为对象局部 X，转角为弧度，尺寸为正数格 |
| `SceneLight` | 位于所属对象的局部原点，额外灯位使用子对象；范围为正数格，损伤比例 `[0,1]`；颜色与随机键交给 Godot |
| `PersistentSceneEffect` | 当前状态派生的烟、火等，位置相对对象，强度 `[0,1]`；对象移除同时结束其持续效果 |
| `SceneEffectCue` | 实际新事件产生的一次性效果，位置相对帧原点，稳定 ID 防重复；可带来自内容的碎片碰撞类别，不含 GPU 粒子资源 |
| `TerrainCollisionPatch` | 近似地形高度场，X 最快的行优先数组，长度 Width×Depth；高程相对 Patch.Origin，间距正数格。只供相机之外的碎片等表现碰撞，不做逐体素刚体 |

立方体贴图按体素的 24 种局部朝向选面：局部 +Y、-Y 分别用 Top、Bottom；局部 +Z 在 Front 与 Side 的 `AssetRevision` 不同时用 Front，其余面用 Side。侧面和 Front 的图像上方朝局部 +Y，顶面、底面朝局部 +Z。`TextureUv` 的 `(0,0)` 是图像左上角，U 沿「图像上方 × 外法线」增大，V 沿图像上方的反方向增大，从面外看图像不镜像。

Top、Bottom、Side 沿贴图轴以对象网格的整数坐标作向下取整的取模，按跨度 1／2／4／8 选取图中的子块，每格 `TextureUv` 均在 `[0,1]` 内。同一周期中相邻格的共边坐标相等，周期边界从 1 回到 0，由宿主重复采样衔接；负坐标沿用同一规则。Front 与 Side 的资产修订不同时，Front 使用单格 `[0,1]` 且不平铺；相同时视为没有 Front，局部 +Z 使用 Side 并参与平铺。内容侧在缺省 Front 时须保持 Front = Side。平铺只影响 `TextureUv`，`FaceUv` 和外露边标志仍使用相互一致的单面坐标。真实 Godot 纹理采样由 #298 联调验证。

体素只生成标准形状、铁路等自己的几何，不接收像素或导入模型几何。模型纹理、材质、磨损图案、粒子实现和缺失标记外观归 Godot，见[资产交接](README.md#表现资产的交接)。

体素保存最近两个相邻已完成模拟步的输入；同一步的命令更新当前边界，跨步缺失时只用当前值，不伪造中间运动。`Interpolation` 为 `[0,1]`，只在相邻边界插值，不外推未来；`SimulationSeconds` 是本帧对应的模拟表现时间。节点等离散转换不能把不同空间的坐标直接插值。

车辆、炮塔、生物、烟火和碎片均跟随这个时间，暂停时固定；相机和 UI 不受影响。Godot 将该时间用于自身粒子/碎片，不借真实帧增量继续播放世界效果；倍速下仍遵守[真实时间闪烁上限](../art/06-wear-damage-and-motion.md#特效的强度上限)。瞬时效果只来自收到且处于已观察场景中的事件，资源准备重试使用相同 ID；错过的旧事件、场景关闭期间的事件或已经结束的效果不补演。持续状态可从当前查询重建。效果按所属会话和 Space 清理，不跨场景残留。

## 拾取与命中有效性

`ISceneFrame.Pick` 使用该帧的网格与对象姿态，射线、命中点、法线和距离都在该帧根空间。Cell、Face 则属于命中对象自身格网，NestedObjectPath 指向嵌套对象；DDA 始终按完整格，与楔形、空心模型或视觉凹槽无关。距离最近的可拾取格优先；先进入未构建区域时返回 NotReady，不把它当透明空白。

钢轨、轨枕、水面及粒子不是可拾取体素，不阻挡射线；铁路施工仍从地图或面板指定线路与断点。缺失单格保留原格占位；缺失功能复合体占格未知，只在放置点显示标记，通过诊断定位，标记不拦截 DDA。

世界命中携带核心对象、设计及部件身份；地形命中携带业务地点。编辑命中携带编辑会话、修订及内部元素身份，不把编辑位置当成核心 PartId。`Resolve` 在当前世界输入下核对请求、空间、对象存在性与设计/部件是否仍适用；普通模拟推进本身不让所有命中失效，已毁部件、旧设计或旧观察请求则明确拒绝。它不执行任何核心命令，也不是之后命令的业务许可；宿主仍走正式命令入口。

旧帧在会话关闭后仍可用于历史显示或只读拾取，不能重新取得当前交互资格。编辑选择前，宿主核对命中的 EditSessionId 和 EditRevision 与 Read 相同；Apply 还会核对预览基准，不能只靠 UI 按钮拦截。

## 设计编辑会话

`OpenEditor` 接收固定有效内容与 Complete 或 Partial 评估；宿主保证初始评估由这份内容产生。无需合法设计，Partial 始终具有承载已知布局、元素和锁的 Scene，但 Scene.Design 可以没有规范哈希。Failed 没有可解释草稿则拒绝。打开时建立自己的工作副本，初始无未保存修改；新建草稿是否需要先提示命名由宿主决定。一个会话始终使用该份有效内容，[结束编辑后再发布](editing.md#编辑会话与保存边界)，不提供会话内内容重绑定。

`Read` 返回不可变 EditState，`Capture` 返回整份固定草稿与 EditStamp；后续修改不影响它们。Elements 是当前固定修订的可定位元素清单，内部 ID 跨不改身份的操作保持，删除后不复用；诊断路径和数组下标只对应本修订。体素实现按原缺失引用维护锁，不等待迟到的完整内容评估才执行锁定。

`Select` 替换选区；`Enter` 只能进入可编辑的组装体/场景模型副本，null 回根。封闭功能复合体不能进入。切换层级清空选区及未应用预览；选取、相机、平面、剖切均不修改草稿修订、脏状态或撤销栈。框选遇到封闭复合体按整件处理。

所有操作坐标属于当前进入对象。Properties 改该对象文字与同类别参数，不偷偷转换设计类别。PlaceNested 使用内容公开的副本或封闭引用；体素解析自己的工作布局进行编辑，但不重做内容哈希、BOM 或完整合法性。CaptureObject 导出可编辑嵌套副本在自身坐标中的独立草稿；它不改变宿主设计，不给封闭引用解封，也不能绕过缺失项的复制锁。另存蓝图仍须完整校验，并在结束编辑后由内容发布。

格范围包含两端；Move/Copy 的 Offset 是整数格偏移。RotateSelection 绕正轴按右手规则旋转指定的 90° 次数，Pivot 指定格的中心。Stroke.Samples 是每次立方笔刷的最小角格，覆盖各点起始的 BrushWidth³ 格后合并去重；宿主连续采样，不把离散采样间未覆盖的格隐式连线。笔刷预览与实际提交共用这些定义。

### 预览、提交与撤销

`Preview` 固定操作、选区、当前进入对象和 EditStamp，不修改草稿。区域覆盖去重、上限、确认门槛沿用[编辑规则](../design/15-design-editor-and-tools.md#编辑)。CoveredCells 是覆盖格数，AffectedCells 是实际将改变的格数，SkippedCells 是空格或无变化等不适用格数，不能把冲突计为跳过后部分提交。未知占格时 OccupancyComplete=false，不能声称已完成完整冲突检查。

Conflicts 提供具体格或元素及原因。HighlightCells 在当前进入对象坐标中表示 RotateSelection 离散 90° 编辑动作的扫过范围、放置/替换/移动/复制的目标覆盖，其余为操作范围；Godot 画覆盖层，不自行算扫掠。工作平面与包络分别来自 EditViewOptions 和内容评估，Godot 可按这些公开几何值画线框。体素只做动作约束，内容诊断负责完整设计合法性；草稿暂时不连通或不合法仍可保存。

设备 rotation 行为的全角度范围与冲突格读取当前评估的 Scene.RotationSweeps，不能用 HighlightCells 代替。按 NestedItemIndices 匹配选中对象（空路径为根），体素用已有层级放置与本帧原点变换生成覆盖线框，经 Present 返回帧的 DebugLines 交出；这些编辑线框不要求开启开发调试图层。Godot 直接绘制帧中线框，不转换嵌套设计坐标或重算内容合法性几何。SweptCells 与 ConflictCells 的 Known/Unknown 分别显示，未知提示读取 CurrentEvaluation，不能将未知冲突显示为完整无冲突。AcceptEvaluation 拒绝的迟到结果不能更新这些覆盖层；草稿改变后随 CurrentEvaluation 清空，不能保留旧范围冒充当前结果。

`Apply` 只接受本会话产生的当前预览。新预览、切换进入对象、草稿改变或关闭后旧预览失效；选择改变不重定向已固定的预览。RequiresConfirmation=true 时必须显式 confirmed=true；否则返回 confirmation_required。已知冲突导致整笔拒绝，草稿、修订与撤销不变。未知引用保留并锁定，父级、选区、移动、旋转、复制、替换等均不能间接改变它；允许编辑其他已知部分不意味着未知处被推定为空。

一次成功修改整笔入栈，草稿修订增加；无变化操作不制造修订或历史。Undo/Redo 同样产生新的编辑修订，恢复对应工作值，不能使旧异步结果重新有效；新编辑清空重做。撤销不限步数但只活在本会话中，不进存档。体素内部用不可变共享或其他实现控制成本，不把存储结构列入契约。

### 校验与保存完成

宿主 Capture 后把 Draft 交给固定内容的 EvaluateDesign，可在后台运行；回到协调线程调用 AcceptEvaluation。宿主负责把原请求标识与结果成对保留，并保证计算使用的内容世代等于 EditStamp.Content；DesignEvaluation 本身不携带来源证明，不能把另一份内容的结果重新贴上当前标识。会话核对请求中的会话、修订、内容世代及结果草稿与当前值相符才接入，返回 true。草稿匹配必须递归比较全部字段及集合中的内容，不能用默认 record 的 == 或 Equals 代替深层内容比较；迟到或关闭返回 false，不覆盖当前诊断、缺失锁或按钮状态。每次草稿变化后 CurrentEvaluation=null，原结果不能冒充当前结果；旧内容评估故障按原请求报告，不污染新请求。

MarkSaved 只在对应保存目标成功后调用：本局草稿内容记录已提交就成功，用户/包草稿须写盘成功。它确认捕获版本，而不是宣布游戏已经存盘；期间新增修改仍脏，旧会话通知返回 false。撤销恢复到已确认保存的同一工作值时可以清除编辑脏标记，不依赖业务设计哈希。保存失败不调用它，保留活动草稿和旧记录。

设计保存、蓝图发布及核心提交由内容/Godot 负责，体素没有文件写入或核心提交方法。关闭前的保存/放弃/取消由宿主执行；Dispose 不自动保存，立即使预览、校验接入及修改入口失效，重复 Dispose 无副作用，保留的快照和帧仍不可变。

## 只读设计预览

图标与设计缩略图使用 `PreviewDesign(content, initial)`，无需打开编辑会话。宿主保证评估来自这份固定内容；与 OpenEditor 一样，Complete 或 Partial 可以预览，Failed 没有可解释草稿则拒绝。返回 `IDesignPreview`，只提供内容世代、`Present` 和 `Dispose`，不建立撤销、编辑修订、选区或脏状态。

`Present` 使用与世界、编辑及模板预览相同的体素网格生成规则，返回时间为零的完整替换帧。缺失引用保留已知部分和明确诊断，不把预览成功当成设计合法。这个入口只承诺固定设计显示，不新增通用预览框架；网格、材质引用、坐标和不可变值责任沿用本页的显示契约。调用同步完成，不启动需要宿主轮询的后台任务。Dispose 结束预览资格，重复关闭无副作用，关闭后的 Present 抛 ObjectDisposedException；已返回帧仍可保留，Godot 自行持有和释放渲染资源。

货物图标按 `FindGood(good)` 的 `DisplayDesign` 调用 `FindDesign`，再创建只读预览并 `Present`。宿主无需读取布局或重新选择同构成的设计；无显示设计的货物走其已有图标入口。可编译调用见消费样例的 `DesignIconConsumer`。

## 开发模板预览

聚居地模板由 Godot 持有 `SettlementTemplateDraft` 表单；PreviewTemplate 接收固定草稿、修订及内容，生成场景模型、已知预建建筑与地块显示资料。它不需要创建虚假核心世界，不修改表单，不拥有第二套撤销或发布流程。可在后台调用，仅结果仍匹配该表单修订和内容时接入。

ITemplatePreview.Frame 是完整替换帧；Plots 提供地块局部范围及在预览空间中的姿态。DraftIndex 使用固定数组下标，草稿里重复的地块编号不会错误定位另一个条目。PickPlot 单独拾取地块占地，最近者优先、等距离按下标；普通体素拾取仍用 Frame.Pick。Godot 根据拾取结果修改公开表单字段，再请求预览，不自行遍历场景模型布局或摆放建筑几何。

缺失模型或建筑时返回已知部分与明确诊断，不虚构引用的内容；无法解释的输入返回 Failure。预览成功不代表模板合法，完整规则及发布校验仍归内容。结果为不可变值，无需 Dispose；旧结果只可保留展示，不能覆盖更新的表单。

## 失败、线程与验证

SceneResult.Success 表示本次操作正常完成，包括仍在加载的帧和含无效设计的编辑状态。Failure 表示预期拒绝，至少一条 SceneProblem；Faulted 表示体素内部故障，宿主报告并停止故障会话的可变调用，不影响核心。缺失内容本身是诊断和占位，不强制变成整个场景故障。正常输入的生成算法失败必须报告，不能偷偷换种子或篡改核心长度。

稳定错误码至少覆盖 `target_missing`、`stale_request`、`stale_hit`、`content_missing`、`build_failed`、`edit_locked`、`invalid_operation`、`region_limit`、`occupancy_conflict`、`stale_preview`、`confirmation_required`、`scene_internal_fault`。Godot 不解析 Detail 分支；SceneProblem.Content 和 Package 保留引用及已知来源包，内容提供了来源时不得丢弃，确实未知时 Package 为空。宿主据此同时在界面与控制台显示缺失资料，不按设计哈希猜包名。绑定、内容世代或业务输入身份不匹配、Observe 位置倒退及事件顺序或重复错误属于接口前提违反，抛 ArgumentException，接入前仍须检查；真实交互过期继续返回 stale_hit、stale_request 或 stale_preview。default 集合/非有限数/无效枚举等编程前提错误抛 ArgumentException；关闭后的修改调用抛 ObjectDisposedException，AcceptEvaluation/MarkSaved 则按约定返回 false。

工厂无可变调用会话状态，可独立创建多个候选；世界和编辑会话的变更只在各自协调线程串行执行。只读设计预览的 Present 和 Dispose 在调用方协调线程串行调用。固定帧、输入快照与模板预览可并发只读。体素背景线程不调用 Godot 或内容加载器，不读文件、不回调宿主；内部任务完成状态只经 Present 暴露。

[消费样例](../../prototypes/scenes-contract/README.md)证明公开面可调用，不提供生产算法或复制业务规则的替身。后续共享契约用例须对真实实现及有限情景替身分别执行：

| 输入场景 | 输出断言 |
| --- | --- |
| 固定核心/内容与相邻步 | 同帧姿态和拾取一致；不外推，暂停、倒车、编组中心和读档重建一致 |
| 分段未完成、跟随切换、旧任务晚到 | 进度与雾明确，旧请求不能接入，删除对象不复活，不等待核心 |
| Base 不符、准备重试、浮动原点平移 | 不部分应用；完整替换可恢复，同帧相机及拾取不漂移；效果不重复 |
| 保留旧网格/帧后更新或关闭 | 旧值不变，无显式归还义务；新交互拒绝旧绑定 |
| 缺失单格/未知范围复合体 | 前者原格占位，后者放置点标记且不拦截 DDA；诊断可定位 |
| 编辑区域、嵌套副本与封闭引用 | 原子提交、门槛确认、拒绝无写入、锁不能绕过、导出副本可交给内容 |
| 新编辑后校验/保存迟到、撤销、关闭 | 不启用旧结果，不清除新修改；显式保存版本与整局落盘分离 |
| 模板缺失或重复地块编号 | 已知部分可预览，按数组下标定位，预览不承担发布校验 |

实际隔离仅提供目标契约/样例和允许的 Core、Content 契约，不提供产品实现源码或程序集。真正模块独立测试按[验证规范](testing.md)另行实现；真实 Godot 的资源、绕序、Custom Mesh 轴向、相机、闪烁与碎片时间，以及视觉观感均须在那里验证，不能用纯数据测试替代。

区块边长、分段长度、预取距离、单帧重建预算、内存峰值和 GC 成本不在此冻结。实施时测量首次进入、长编组跨分段/原点、局部破坏和大尺寸编辑；按已有 Demo 负载验证后决定预算。若普通不可变数据不能满足实测要求，再按受控变更流程修订，不预建缓冲池公共协议。
