# 体素引擎公开契约

本页落实[体素引擎层公开契约：场景、拾取与编辑会话](https://github.com/odradekk/train/issues/289)的决定。业务与表现规则仍见[场景](../design/01-voxel-engine-and-scenes.md)、[渲染](../design/07-rendering.md)、[编辑器](../design/15-design-editor-and-tools.md)；公共语义、身份与提交沿用[公共约定](conventions.md)、[跨层协议](transactions.md)和[编辑协议](editing.md)。

## 当前实现状态

当前生产实现提供世界会话生命周期、不可变帧和增量、32³ 区块占格、立方体网格与拾取、贴图方向与跨格平铺、只读设计预览，以及 #315 的线路、#316 的节点、#326 的聚居地模板与实例表现、跟随切换和单候选预建。#496 阶段目标为节点场景按焦点流式构建：全局布局、道床、高度和边界件常驻，入口、站线、旁路线、回转线和停车轨道网格按线路相同的 64 米弧长分段，与地形共用近处优先的有界并行构建、预取、保留和卸载；焦点范围按水平圆形与区块相交筛选。建筑及停放车辆按完整旋转包围盒整件参与预取、保留和卸载，停车先完成全局排位；资源装饰不筛选。普通打开不显示阻挡操作的全屏遮罩；首个可操作状态须有焦点目标和近处操作区显示、可业务拾取且输入实际响应。显示范围 Ready 要求范围内地形、轨道段、建筑和车辆就绪；远处在首个可操作状态后 5 秒内补齐，未加载或已卸载区域显示雾。32／64／80／96 米范围和每帧 4 毫秒软预算均为暂定，实测后由用户确认。此处记录阶段实现方向，不改变下文契约语义。独立行为入口为 `scripts/test.ps1 -Project scenes -Layer fast`，使用固定 Core／Content 读视图；生产几何和受控后台用例覆盖摆放与会话时序，不证明真实四模块联调或 Godot 画面。战斗、生物、损伤与 TerrainCollision 待 #353；线路与节点入口铁轨数、线路断点的会话内增量更新、断点缺口和工地待 #345；标准形状与模型几何待 #388；编辑待 #333；模板预览待 #389。Scenes 已接入 C# 检查工具的隔离矩阵，单次隔离结果以运行证据为准；真实 Godot 接入、画面与性能仍需独立验证，#299 阶段验收尚未完成。

节点场景在同一个固定 `ICoreReadView` 对象下，只读取一次本节点聚居地完整投影，每个建筑和停放车辆的实例投影也只读取一次，包括 Missing 结果。换读视图对象时整体替换缓存，即使命令前后处于同一步；场景关闭时释放。该缓存只在执行 `Pump`／`Present` 的协调线程上读写；节点建筑和车体构建接收派工前取得的不可变实例，不访问该缓存。[#543 剖析](https://github.com/odradekk/train/issues/543#issuecomment-6210613211)中，两个开场构建窗口内每帧 7 次聚居地完整读取占 `Present` 累计耗时的 86.2%／83.8%；单帧接入 32–34 个部件时，`Attach` 的 p95 不到 0.3 ms。因此 #543 选择限制固定读视图下的查询次数，没有为 `Attach` 本身设置配额；距离优先、按键排序和两个构建槽立即补位的规则保持。#581 的节点接入批次针对另一处成本：宿主准备完整显示帧后才能原子提交，新静态几何同时进入过多会延迟可见结果，不表示上述 Core 查询问题重新出现。

节点流式构建的当前实现：全局布局、道床、高度、diagnostics 和边界先行构建并常驻；入口、站线、旁路线、回转线和停车线轨道按 64 米弧长分段，沿用线路的区间网格构建，相邻截面一致并保留分段端盖。轨道段按自身包围盒与地形区块共用近处优先的有界并行构建队列，按到焦点的距离、再按部件键派工；每个节点场景单独计数，上限沿用线路的 `RailwayCoordinates.MaxConcurrentBuilds`（2），已取消但尚未退出的任务继续占槽。Pump 刷新范围和待建优先顺序；部件完成或取消后退出时立即按最近一次优先顺序补位，不等待下一帧，场景取消后停止派工。后台仅构建部件。按 #581 已批准的节点方案，完成结果进入待接入队列，由协调线程在 Pump 中按距离、再按部件键接入；每批暂定最多 48k 个新顶点和 64 个新静态 visual，单个完整 Part 超限时独占一批，不拆分 Part。近处操作区首次补齐前，`Loading` 下与焦点周围 32 米范围相交的已完成 Part 不受批量限制，圈外结果排队；首次补齐后，每批发布后等待既有 `displayedFrame` 回传已显示帧，再接入下一批。只有接入时才分配对象身份并发布缓存；未接入结果移出 96 米保留范围时丢弃。这里只调整节点接入时序，不改变线路或公开契约，也不在发布帧时另行过滤对象；宿主每帧 4 毫秒软预算保持不变，批量参数尚待真实测量验证，预取提前秒数和上限等后续条件步骤仍由测量决定。预取周边并卸载保留范围外部分；边界格网整件常驻。Follow 使用被跟随车辆焦点；Location 在首个相机采样前以 `NodePanBounds` 中心为焦点，与 `WorldCamera.InitialFocus` 一致，之后使用 `SceneFrameRequest.Camera.Focus`，按来源帧 Origin 换算为节点坐标。地形雾按行合并连续区块，最多 102 个盒；待建轨道段按自身包围盒显示雾；待建建筑和车辆各自显示随位姿更新的雾。全局前置件不参与区块卸载。

全局边界件和 diagnostics 保持前置件的立即接入、整件常驻规则，不进入流式等待队列。首次显示帧包含这些边界件和近处列车，48k／64 并非首次显示帧的资源总上限。未接入的流式结果不进入 #498 闲置缓存；场景关闭时直接释放。

当前节点加载状态在近处操作区第一次补齐前为 `Loading`；首次补齐后，即使焦点移动导致近处再次未齐，也返回 `Partial`。显示范围内地形、轨道段、建筑和车辆全部就绪时返回 `Ready`。该状态是 Scenes 构建状态，宿主资源接入及首个可操作状态仍需独立确认。

按 [#248 批准方案](https://github.com/odradekk/train/issues/248#issuecomment-6135067760)，Cube 表现且 Shape 为 null 或 `"cube"` 时生成立方体几何并参与遮面；其他形状及模型保留占格和拾取，不遮挡邻面，几何待 #388。战斗的初始生成在后台抛指向 #353 的 NotImplementedException，Present 接入结果时报告 Faulted／scene_internal_fault；OpenEditor、PreviewTemplate 分别抛出指向 #333、#389 的 NotImplementedException。

线路按 64 米分段后台构建，分段依实际读取值核对并复用未变化的不可变几何，后台构建并发有界；相机采样先从来源帧的根空间转换到线路空间，再确定焦点与预取分段。线路生成输出地形柱、地貌过渡、削坡填方、水面、带键随机装饰、按铁轨数选择的桥梁与隧道口、钢轨和轨枕。河流与湖泊识别 Demo 清单的 `river`／`lake` 特征 id。线路、节点及入口接缝的道床使用铁路表现投影的必填 `BallastVoxel`，对应内容字段 `appearance.ballast_voxel`，只接受不含 `simulation` 的场景体素，没有地貌 `RockVoxel` 回退；道床上层 19 格、下层 21 格，顶面位于轨面下 1 格以支撑轨枕；装饰平整地形时保留铁路净空和水域。中心线依固定输入和铁轨上限预留走廊，当前铁轨数只决定以 34 格中心距对称放置的铁轨；长度由圆弧与直线构造，短节点间距或坡度使地图直线距离不可用时采用 [#315 批准规则](https://github.com/odradekk/train/issues/315#issuecomment-6135918111) 的场景弦长。节点基准高程统一为 0，地图 X／Y 映射到场景 X／Z；端点地形按节点入口偏移平移到节点局部坐标，使用共享采样。节点入口内侧延续线路端部的占格相位、地貌混合和道床采样；同面入口边界条带的每列归最近的实际铁轨线路，距离相同时取最小 EdgeId。调整线路弦长不会改变边界的同一采样点。走廊地形基准跟随最近弧长处的轨面纵断面，隧道与路堤只由地貌噪声和起伏产生。越过场景边界的车辆沿相邻场景的实际铁路摆放：节点入口边界外及 L 外取相邻线路的 1 号轨；线路端点外取该端节点同一入口的共用引入线，出站后部按共用段反向摆放。伸入节点分岔之后的部分属于下述车长限制。
按 [#326 批准方案](https://github.com/odradekk/train/issues/326#issuecomment-6195122195)，聚居地节点以 `SettlementId` 查询内容侧保存的 `SettlementLayoutProjection` 副本，保留模型和地块的原坐标及朝向；核心 `PlotView.TemplatePlotNumber` 联结内容 `SettlementPlotLayout.Number`，不按数组顺序配对，也不回读源模板蓝图。模型的占格、根及嵌套 flatten 区域、地块、停车线、入口走廊和所需回转线共同确定节点范围；回转线在最终范围与入口直线之前确定，各入口位于最终范围边缘；`NodePanBounds` 随 Origin 换算。空节点和生物聚落保留默认地形与交汇铁路，不合成站台。

站台外观只来自已建站点实例的真实设计，不扫描 Concrete 体素，也不另外生成固定长度站台。small_station 槽位为地块本地 Z=−40／40，large_station 为 −80／−40／40／80，站线沿地块本地 X。以最小模板地块号的站点确定站轴；其他站点轴向不同则报告 `station_axis_mismatch` 并省略其槽位。同一直线、同高度的槽位合并为贯通站线，各地块仍保留自己的停靠中心。每帧从站点设计的完好 Platform 部件及其场景位置映射最近槽位，等距取较小 LocalZ，去重后按地块号、LocalZ 排序，对应核心 `PlatformNumber - 1`。映射数量与当前核心节点 `Platforms` 不符时报告 `station_platform_mismatch` 并返回空映射，不猜停靠位置。

入口沿地图相邻节点的方位布置，按与站轴的点积选择站线一端；垂直时固定取正端。站线先沿轴伸至模板整体范围外 32 格，再以不小于铁路规则最小半径的两段反向圆弧及中间直线连接，入口保留 16 格直线。入口的横移和外移由构造决定，使转弯留在模板范围外；模板范围内的沿轴延长段不得穿普通地块，是模板布局约束。生产实现不增加普通地块障碍检测，也不因这类冲突报告 `build_failed`；轨床或净空覆盖场景模型时同样不额外诊断。入口与线路端点的 X/Z 差保持整数格；范围和入口依赖节点及相邻节点坐标、邻接 EdgeId、铁轨上限、线路长度与起伏、铁路最小曲线半径和最大坡度，以及模板副本的布局范围。`NodeLayout.ReadInputs` 不含核心 `Platforms`，站台数变化通过实例和站台映射对账，不触发静态布局重建。

建筑按 `BuildingId` 每帧对账，用地块位姿摆放当前实例设计，异步构建并发有界；未变设计与已毁部件集合复用原网格和对象身份。重建期间保留旧表现，首次构建保留稳定根身份；后台结果接入前核对当前实例，删除或迟到的旧结果不复活对象。`Construction` 地块按空地处理，不调用 `FindJob`，工地表现留给 #345。建筑和停放车辆复用实例构建池，候选节点仅围绕交接入口预建；建筑和停车实例按旋转后的完整包围盒与焦点的预取、保留范围筛选，超出保留范围后释放，单池并发上限保持 2。停放车辆先按全局规则排位，再按包围盒筛选；车辆池按 VehicleId 排序最多显示前 8 辆。两条停车线沿站轴，长度取模板整体范围在站轴上的投影长度，位于模板本地 −Z 一侧外 32 格，线间距 40 格；车辆首尾间隔 4 格，先试第一线，再试第二线，都放不下则不显示该车。车身与轮对复用现有车辆构造。

资源是按货物和候选号保持身份的独立对象，不并入地形网格。每种资源使用世界种子、节点和货物稳定哈希生成 8 个候选，候选位置首次使用时计算并缓存，避开地块及轨床混合带（轨心外至少 22.5 格）；可再生资源按 Quantity／Maximum 比例决定显示候选数，不可再生资源只要 Quantity>0 就保留固定露头。外观只查询 `GoodId.Voxel` 自身的 `FindVoxelAppearance`，缺失报告带已知来源的 `content_missing`，不虚构替代体素。数量变化不改变静态布局输入，保留下来的对象复用网格。

节点列车按 [#443 批准计划](https://github.com/odradekk/train/issues/443#issuecomment-6206892373)消费核心唯一位置，具体路径与排队规则见[节点内列车路径与进度](../design/01-voxel-engine-and-scenes.md#节点内列车路径与进度)。A/D 保留 80 米，核心 0/W/S/T/L 分别映射入口边界、按列车自身长度确定的 W 显示点、站内线中心、站台段末端、出口边界；四段按实际三维弧长线性映射，P=0 合并 W/S/T。场景以米计量的四段速度比分别为 a/A、2b/P、2c/P、d/D；Demo seed=40 初始世界对 26／32／52 米编组分别测量，四项范围合计为 0.4145–10.7019、6.6125–27.0404、2.6667–27.0404、0.4145–70.2513；按车长的范围与公式见上述设计，几何修订后需重测。有站台布局 P>0 且半列长 H 小于公共引入线长度 I 时，W 显示弧长 w=I−H（均以格计），所有列车均用同一规则，等候或进站申请者获站台时整列不换路径。a 随车长变化；按已确认的超长编组规则，H≥I 时取 w=I，保持正向进站、不冻结，越过分岔的成员获站台时可能换路径。中心 S 前不读取 NextEdge，同入口公共引入线末端前共线；超过 T 的前部成员沿当前 NextEdge 的出站曲线或同侧回转线，无 NextEdge 或原路返回尚未 Departing 时沿站轴直线延长；原路返回沿原路反向，同侧不同边走包络外共用回转线；s 侧有至少两条入口，或节点包含 Settlement 且 s 侧有至少一条入口时，才在 −s 端建回转线；条件不依赖已建铁轨数。单颈复用 −s 端已有入口扇区，该端无入口时另建站轴外侧连接段接入单颈回转线；新增段不交叉其他轨道。有效站台号保持原站台中心；无号列车固定走旁路或 P=0 公共贯通线，无进入历史取最小 EdgeId 的已建入口，无已建入口取站轴虚拟直线。W 队列首尾相接，静止非申请者在前按 TrainId 排序，申请者在后按公开队龄及 TrainId 排序；旁路线 S 不排队，静止列车重叠；进站申请者渐进后排，途经不受申请队位偏移。未知成员长度沿用缺失表现和诊断，不推测成员位置。

按[已确认的超长编组规则](https://github.com/odradekk/train/issues/443#issuecomment-6208794644)，保证范围为：列车总长严格小于该节点最短共用引入线长度的两倍（以米计，最短值包含未铺轨入口）。满站获站台不横移及单线边界的位置、方向、高度连续，均受此范围约束。保证上限不含等号；运行时的 I 取当前入口，H≥I 时取 w=I，避免冻结整段进站。超限时只有越过分岔的成员可能在获站台或驶入节点时横移并转向，混排按实际队位差前移。Demo seed=40 的 14 节点实测表统一见[节点内列车路径与进度](../design/01-voxel-engine-and-scenes.md#节点内列车路径与进度)；测量范围及原始数据见 [Issue #443 完成评论](https://github.com/odradekk/train/issues/443#issuecomment-6212761838)。

前部成员已经超过 T 时，重选出线、计划完成置空或新计划改变 NextEdge 会使这些成员瞬时换路径，T 及之前的部分和仍在 S 前的中心不动。已知限制另包括超出车长范围的列车获站台时越过分岔的成员换路径、跨边界伸入分岔后的成员切换路径，以及上述设计中的前车离队后按其全长前移（H<I 时，含超限列车按实际队位差）、暂停清除核心队龄、恢复或换计划后按核心新队龄及 TrainId 重排，以及 W 处静止非申请者变化使其他列车后移、非队首起步及超长队列退行。运动列车在共用引入线、旁路线、回程线和出口连接上可能穿过其他列车；持有站台的列车在同侧回程经过旁路线；旁路线 S 处和在 L 等同一出线的静止列车重叠。另有 #481 决定 8 晚申请获预约时横移，以及多线边界横移。节点路径只接最小编号铁轨，多线边界由 [#541](https://github.com/odradekk/train/issues/541)解决。相邻步仅在路径、编组、朝向和队位一致时插值核心进度后映射；跨边界、换线、队位变化、原路返回起步使用当前步；渲染、拾取及 FindPose 共用姿态。

跟随切换保持 Request，增加 Space，完整替换帧并使旧命中失效；新 Origin 使边界同一实际点保持显示坐标，线路和节点空间只差平移。节点内按连续路径显示，#316 的节点位置跳变例外已由 #443 取代；上述已知限制记录已接受的离散变化；跨边界车辆沿相邻实际铁路摆放，伸入分岔之后的部分属于车长限制。世界会话只保留当前场景及一个候选：线路前方节点沿实际方向、按 #315 的速度×显示倍率×PrefetchSeconds 分段预取范围触发；节点只根据 NextEdge 预建入口附近线路，为空不猜路；预建节点时焦点取将进入的最小编号铁轨边界 0 点。候选失效后取消，迟到结果不接入、不发布缓存，当前 Present 不等待候选。雾覆盖尚未构建及主动卸载的区域。新绑定重开会话，节点地形区块、各入口和模板模型按实际读取值复用；节点活动场景和候选保留范围内的流式部分及常驻件不计入闲置预算；离开后按内存预算保留。聚居地建筑和停放车身的实例缓存只保留当前与候选范围内部分。列车车身的值缓存跨绑定保留。车辆核对、构建、未知车长诊断和加载雾由线路与节点共用，车体由会话持有并按值复用；切换空间保留已完成车体，后台构建并发有界，每帧按设计哈希和已毁部件核对车体，值键仅在首次后台查键或这些值变化时计算。

线路显示各铁轨上的全部列车；仅相邻完成步之间插值，运动和浮动原点平移复用网格，FindPose 与拾取共用显示姿态。车长取设计 VehicleLengthCells；编组存在未知车长时，不推测成员位置：缺失或失败的设计在权威编组中心显示 Missing，转发内容诊断并报告带已知 Package 的 content_missing；有效设计保留带 Subject 的空对象，FindPose 可用。当前阶段用 vehicle_length_unknown 报告设计存在但车长未知的成员，线路和节点入口均按创建该场景时的读视图中的铁轨数构建（包括预建候选）；会话内铁轨数变化不清空现有场景，相关列车用指向 #345 的 railway_update_pending 报告尚未更新的铁路表现。站台号映射按当前实例和核心平台数每帧核对，不冻结开场平台数。轮对按根网格 Z 行生成，档位轨距为 3／7／15 格，半径为 0.5／1／2 格、轮宽为 0.25／0.5／1 格，均为集中定义的暂定数值；成员排列和轮对转角使用所在铁轨的带符号弧长，车辆切线取同一偏置曲线。按批准决定 12，直线和圆弧统一用 1−κo 的闭式弧长比例；有坡度时保留其与真实三维弧长的有限误差，中心线长度仍严格按构造成立。Locate 和 TerrainHeight 仅在已接入的节点地形或线路分段提供映射。灯光、特效集合仍为空，非节点帧的 NodePanBounds 为 null。世界帧已按 DebugLayers 生成区块边界、线路分段、浮动原点、拾取射线与中心线。这些是阶段实现状态，下面的完整目标契约保持不变。

区块图层显示本帧实际占格的 32³ 区块边界；线路分段图层显示已接入分段的起止横截线，线路中心线为这些分段内的零偏置曲线，末段止于线路实际长度。节点中心线显示创建时入口铁轨数对应的入口直线、连接、模板贯通站线、旁路线和回转线，不按构建进度过滤；节点帧不生成线路分段线。浮动原点图层显示本帧根零点的三条 32 格轴线。所有线段使用本帧根坐标；None 时世界帧的开发调试线为空，图层开关不改变其他帧内容或只读拾取，编辑覆盖层仍不依赖开发图层开关。

#498 的节点闲置缓存预算为 32 MiB，按保留数组载荷估算，包含网格顶点／索引、拾取格网、外观数组、边界依赖和诊断路径数组；估算不含字典节点、字符串和对象头。Node2 诊断样本的缓存根可达对象图约 39.44 MiB，相对 31.77 MiB 的数组估算约高 24%；该对象图包含共享引用，不等于排他新增内存，也不表示完整托管堆或进程占用。活动场景和候选不计入这份闲置预算。节点离开时先整体淘汰最早离开的闲置节点；剩余节点先保留常驻前置件，再按流式部件包围盒到初始焦点（`NodePanBounds` 中心）的水平距离从近到远保留，同距按部件键排序。单件超过剩余预算时跳过，固定边界数据超过预算时不保留该节点；无可复用数据的节点不留空条目。缓存仅保留实际输入值键、初始焦点、可重新绑定局部对象编号的不可变几何和边界，不持有布局、模板、快照、读视图或会话对象编号。布局不复用；内容代数变化而所读值不变时仍可共享几何，实际输入变化后必须与新输入的冷构建一致。关闭和被替代的 owner 不能发布迟到结果。

Follow 单候选的布局和准备在后台完成。当前场景仍有等待中或进行中的部件、建筑、停放车辆或本帧实际请求的车身构建时，候选不启动新构建；离场车身不留下待建请求，已在建任务可完成，已取消未退出的任务仍占槽。当前帧开始前暂停候选的自动补位，完成当前场景对账后再决定本帧是否放行。只有已有候选预取范围参与，不预测地图打开目标。候选布局未就绪而列车已越界时，按当前场景的正常打开路径构建，以保留交接坐标和首个有几何帧的 `NodePanBounds`；候选因让行而来不及就绪时仍显示加载雾，实际越界就绪与帧间隔由正式测量报告。宿主 GPU 资源生命周期、保存／重放状态与 GC 策略不变。

宿主关闭场景时释放相机持有的 CPU 帧引用，保留相机姿态和跟随平滑余量；重开首帧属于新会话，沿用跨会话的相机接入分支。

## 坐标与身份

- 场景以格为单位，一格 0.5 米、一个 Godot 单位；`+X` 右、`+Y` 上、`+Z` 前。核心长度仍是米，换算只发生在表现边界。格 `(x,y,z)` 占据 `[x,x+1] × [y,y+1] × [z,z+1]`；正交朝向绕格中心旋转。
- `ScenePoint` 为当前节点或线路空间中尚未减浮动原点的双精度坐标，不是宏观地图坐标。`ISceneFrame.Origin` 与单精度显示坐标相加才得到该空间内的位置。不同 `Space` 不能直接相减。
- `ScenePose` 为单位四元数及平移，无缩放或剪切；根相对该帧浮动原点，子对象相对父对象。所有向量和标量有限；射线方向归一化，长度为正；集合不可为 default。
- `SceneBinding` 由宿主在运行会话或有效内容更换时重新分配，不是存档 UUID。`SceneSessionId` 由体素创建；同一绑定可以关闭后重开场景，产生新的会话身份，二者不是一一对应。`SceneRequestId` 区分显式观察请求，`SceneSpaceId` 区分节点、线路及编辑空间；这些都是运行身份，不入权威存档。
- 帧修订在会话内单调增加；对象、效果身份在会话内不复用。稳定对象更新继续使用原 ID，不以重建批次冒充业务身份。`WorldObjectId`、设计、部件及内容身份沿用各自契约。

宿主传入的 `SceneWorldSnapshot` 来自同一完整边界，核心 `InputIdentity` 与内容 `Core.Identity` 相同。同一有效世代中，本局已保存草稿或新聚居地模板副本可以增加 `PersistentRevision`；只要业务输入及世代仍匹配，就能交入新的固定视图。体素不得把不同边界查询拼成一次快照。OpenWorld 在创建前检查初始核心视图与内容业务输入身份，不匹配时抛 ArgumentException，不创建会话。

生物按核心查询或本次事件的 `Definition`，从配对固定内容视图的 `FindCreature` 取得当前种类外观；核心不提供生物设计哈希。生物死亡后的瞬时表现也按事件保留的种类解释，不要求死亡个体仍在查询结果中。车辆和建筑仍按实例或事件中的设计身份取得对应布局。

## 世界场景会话

一次调用顺序如下：

1. `OpenWorld(binding, snapshot)` 轻量创建，不等待场景生成。随后 `RequestView` 选择地点、指定列车中的车辆或战斗。地点可含线路弧长，用作初始观察中心；不是要求生成一个单独世界位置。跟随车辆必须属于指定列车。
2. 宿主在命令或模拟完成后串行 `Observe(snapshot, newEvents)`，交入本次新事件。它不触发同步大场景构建，也不接受倒退的模拟位置。事件必须有序、不重复，且不晚于输入边界。绑定、内容世代或业务输入身份不匹配、模拟位置倒退以及事件乱序、重复或超出边界均违反接口前提，必须在接入前检查并抛出 ArgumentException，保留原输入，不返回业务失败码。
3. 体素自行安排首次构建、线路分段与至多一个下一场景预建。宿主逐显示帧调用 `Present`，取得当前可显示部分、加载状态与诊断；核心继续推进，不等待构建。
4. Godot 准备最新帧需要的资产与资源，在帧之间完整应用资源更新，成功后才把它记为网格基准帧。以 D 请求的准备期间旧几何按最新帧更新姿态，相机和拾取也使用最新帧；传 null 时旧画面和相机保持不变直到提交，样本仍使用 D；下一次 `Present` 的网格基准仍是最后完整接入帧，具体限制见[Godot 契约](godot.md#显示帧相机与输入)。
5. 观察目标切换调用 `RequestView`。新目标无效时返回 Failure，旧请求保持；成功产生新身份，即便目标值相同也使旧请求失去接入资格。跟随中的边、节点切换由体素处理，不要求宿主发区块命令。
6. 不再显示或活动绑定更换时关闭会话。`DisposeAsync` 调用即撤销输入与交互资格，然后等待内部任务退出；可先打开新会话，不能为了旧任务退出暂停新核心。

会话变更操作在宿主同一协调线程串行调用，禁止并发和重入；`DisposeAsync` 的等待不占用该线程执行构建。体素工作线程只读已固定输入，完成后由 `Present` 接入。普通模拟推进不废弃所有在建工作：体素核对依赖，补齐当前损伤、对象存在性、设计及铁路变化，必要时只重建受影响部分。取消、关闭或跨绑定的迟到结果只能丢弃，不能复活已删除对象或旧拾取。

`Loading` 表示目标尚无可显示内容，`Partial` 表示部分空间未就绪，`Ready` 表示当前需要范围完整，`Failed` 表示目标构建失败。未就绪区域显式列在 `FoggedRegions`，不能伪装成空地。一次 Present 返回 Faulted 时宿主报告表现故障并停止该会话的交互，不回滚或冻结核心；可重开场景。正常目标消失通过 `target_missing` 报告，宿主按相机规则选择下一目标。

跟随切换遵守[场景切换](../design/01-voxel-engine-and-scenes.md#跟随列车时的场景切换)：依次经过线路、节点、线路，不跳过节点；不知道下一线路就不猜，预建来不及用雾收住。核心公开世界种子、所选铁路规则、节点进入/下一线路与编组正反，详见[核心查询](core.md#读视图查询与事件)。更换有效内容时重开场景会话；实现可共享未变化的不可变几何，仍须只重建受影响对象和区块，不能把重开理解为一律重算整个场景。

## 显示更新与资源

`ISceneFrame` 是可保留的不可变显示边界，包含同一时刻的姿态、拾取、空间映射和显示更新。帧身份统一使用 `Update.Frame`。`Present` 的 `displayedFrame` 必须是已经完整接入 Godot 的最后一帧 D，作为网格基准；不能传仅计算或准备过的帧。以 D 请求的准备期间姿态、相机和拾取使用最新返回帧 P，不使 P 成为网格基准；传 null 时保持旧画面和相机直到提交，样本仍使用 D。`Update.Base=null` 唯一表示完整替换：首次、传 null 或空间变更时返回该帧的全部对象。增量更新的 Base 必须等于 D 的 `Update.Frame`。

Godot 按以下语义准备并一次接入资源更新：完整替换时移除旧场景；增量相对 D 给现存根加 `ShiftExistingRoots`，再删除 Removed、加入或替换 Upserts，最后替换 Environment。准备期间已显示对象可先按 P 更新姿态；锁定候选 C 的 Base、Session、Request、Space 变化时取消准备，否则完成 C 后提交，并在提交同帧重施最新 P 姿态，不能重复叠加平移，规则见[Godot 契约](godot.md#显示帧相机与输入)。Upserts、Environment、效果和调试线已经使用新原点；父子关系无环，每个存活对象的父对象必须存在。移除包含不再存在的子对象，Godot 不猜测级联业务语义。同一更新内 ID 不重复且不同时出现在删除与更新中。

浮动原点平移不重建网格；运动只更新姿态并复用原不可变几何。`FindPose` 返回合成到当前根空间的显示姿态，相机与渲染共用它。`SceneCameraSample` 携带焦点所在的来源帧及焦点；以 D 请求的准备期间为 P 和 P 根坐标中的焦点，传 null 时仍为 D 和 D 根坐标中的焦点，不要求来源帧等于网格基准 D。体素负责转到稳定空间并沿线路定位。线路 `Location` 帧没有同空间相机样本时，`Origin` 为请求点在线路空间中的位置。`Locate` 给出业务地点，`TerrainHeight` 返回相对本帧原点的格高度，尚无几何映射时为 Missing。

世界请求的 `SceneFrameRequest.PickRay` 为可选 `ScenePickRaySample`，携带最近一次实际传给 `ISceneFrame.Pick` 的帧（以 D 请求的准备期间为 P，传 null 时仍为 D）和射线；命中、未命中及 NotReady 都可提供样本。射线使用来源帧根坐标，不依赖 `Present` 的 displayedFrame，因此完整替换时仍可提供。仅开启 PickRay 且来源与新帧的 Session、Request、Space 都相同时，DebugLines 中输出一条射线：起点为来源 Origin 加射线 Origin 再减新帧 Origin，方向不变，长度为 MaximumDistanceCells；不额外执行拾取，不按命中距离截短。未开启、无样本或旧 Request／Space 时不输出射线。外会话样本或非法射线在修改会话前抛 ArgumentException；数值沿用有限、单位方向和正有限长度的射线前提。宿主在目标请求、会话或显示空间切换时清空旧样本。样本及调试线不改变 Pick 的只读语义，已返回帧仍不可变。

`NodePanBounds` 由体素给出节点场景完整的水平相机范围，分量为本帧根空间的 X、Z 格坐标，随浮动原点一起换算；不是当前已生成网格的包围盒。节点的 Partial／Ready 帧必须提供，Loading 尚未确定时可为 null；非节点帧为 null。Godot 只限制节点自由环绕的焦点，同空间后续帧范围缺失时保留焦点，不猜边界；跟随相机继续使用显示对象姿态。此字段由[Godot 宿主契约](https://github.com/odradekk/train/issues/290)补齐已有的相机规则，不冻结具体场景尺寸。

Base 不匹配或适配失败时不应用资源更新。资源尚未准备好时，不部分接入新资源，也不把 P 设为 displayedFrame，但允许按上述规则更新旧几何姿态、相机和拾取；新对象等待资源就绪。下一次仍以最后完整接入帧 D 请求；必要时传 null 获取完整替换。绑定切换后旧画面失去交互资格，即使为过渡暂时保留，也不能继续拾取。GPU 资源的创建、原子接入和退役由 Godot 契约落实。

显示值及其全部集合元素不可变，调用方可以跨更新或关闭保留，不需要归还缓冲；不再使用时释放引用，由 GC 回收。关闭会话不会释放 Godot 的纹理、网格或材质。双方可共享不可变值，不要求每帧深拷贝全部世界；不公开租借期限、引用计数或区块释放协议。

### 网格、模型与效果数据

| 数据 | 格式与责任 |
| --- | --- |
| `SceneMesh` | 对象局部格坐标，顶点法线归一化，三角形索引合法且个数为三的倍数，从外侧看逆时针；Godot 转换引擎绕序 |
| `SceneVertex` | `readonly record struct`，字段及顺序保持 Position、Normal、TextureUv、FaceUv、ExposedEdges、RelativeHeight、Damage；TextureUv 为已计算的贴图坐标，可超出 `[0,1]`；FaceUv、外露边标志、相对高度、损伤供着色器使用，高度与损伤比例在 `[0,1]` |
| `SceneMaterial` | 面贴图只含资产修订、材质类别及可选涂装；钢轨、轨枕、水面和施工表现使用项目自带材质 |
| `SceneVisual.Model` | 一格一个原始模型引用，材质次序沿用内容元数据；对象 Pose 已包含格放置和绕格中心的朝向。Godot 只将模型米坐标换为格，不额外适配尺寸。相对高度平面把模型局部格坐标换成所属对象高度比例，用于积灰 |
| `Wheelset` | 体素给出位置、轴向、尺寸和转角，Godot 提供轮对模型；轴为对象局部 X，转角为弧度，尺寸为正数格 |
| `SceneLight` | 位于所属对象的局部原点，额外灯位使用子对象；范围为正数格，损伤比例 `[0,1]`；颜色与随机键交给 Godot |
| `PersistentSceneEffect` | 当前状态派生的烟、火等，位置相对对象，强度 `[0,1]`；对象移除同时结束其持续效果 |
| `SceneEffectCue` | 实际新事件产生的一次性效果，位置相对帧原点，稳定 ID 防重复；可带来自内容的碎片碰撞类别，不含 GPU 粒子资源 |
| `TerrainCollisionPatch` | 近似地形高度场，X 最快的行优先数组，长度 Width×Depth；高程相对 Patch.Origin，间距正数格。只供相机之外的碎片等表现碰撞，不做逐体素刚体 |

立方体贴图按体素的 24 种局部朝向选面：局部 +Y、-Y 分别用 Top、Bottom；局部 +Z 在 Front 与 Side 的 `AssetRevision` 不同时用 Front，其余面用 Side。侧面和 Front 的图像上方朝局部 +Y，顶面、底面朝局部 +Z。`TextureUv` 的 `(0,0)` 是图像左上角，U 沿「图像上方 × 外法线」增大，V 沿图像上方的反方向增大，从面外看图像不镜像。

Top、Bottom、Side 沿贴图轴以对象网格的整数坐标作向下取整的取模，按跨度 1／2／4／8 选取图中的子块；负坐标沿用同一规则。Front 与 Side 的资产修订不同时，Front 使用跨度 1；相同时视为没有 Front，局部 +Z 使用 Side 并参与平铺。内容侧在缺省 Front 时须保持 Front = Side。单格面仍使用原坐标；合并矩形从首格的整数取模相位连续增加 `TextureUv`，可超出 `[0,1]`，由宿主重复采样衔接，不能先将远坐标转成低精度浮点再取模。

[#495 批准决定](https://github.com/odradekk/train/issues/495#issuecomment-6195218048)将 `SceneVertex` 从 `sealed record` 改为上述值类型，`SceneMesh` 的 `ImmutableArray` 及跨更新保留所有权不变。无磨损合并矩形的四边在单位格点分段，以中心扇形三角化；1×1 面保留四顶点、两三角形。`TextureUv`、`FaceUv` 和 `RelativeHeight` 在矩形内仿射插值，四角 `FaceUv` 为 0／1，`ExposedEdges` 为 None；`FaceUv` 与 `ExposedEdges` 仅在 `WearEnabled=true` 时参与着色，有磨损面保持逐格坐标与外露边。合并范围和不可合并条件见[区块面合并](../design/01-voxel-engine-and-scenes.md#区块面合并)。

体素只生成标准形状、铁路等自己的几何，不接收像素或导入模型几何。模型纹理、材质、磨损图案、粒子实现和缺失标记外观归 Godot，见[资产交接](README.md#表现资产的交接)。

体素保存最近两个相邻已完成模拟步的输入；同一步的命令更新当前边界，跨步缺失时只用当前值，不伪造中间运动。`Interpolation` 为 `[0,1]`，只在相邻边界插值，不外推未来；`SimulationSeconds` 是本帧对应的模拟表现时间。节点等离散转换不能把不同空间的坐标直接插值。

车辆、炮塔、生物、烟火和碎片均跟随这个时间，暂停时固定；相机和 UI 不受影响。Godot 将该时间用于自身粒子/碎片，不借真实帧增量继续播放世界效果；倍速下仍遵守[真实时间闪烁上限](../art/06-wear-damage-and-motion.md#特效的强度上限)。瞬时效果只来自收到且处于已观察场景中的事件，资源准备重试使用相同 ID；错过的旧事件、场景关闭期间的事件或已经结束的效果不补演。持续状态可从当前查询重建。效果按所属会话和 Space 清理，不跨场景残留。

## 拾取与命中有效性

`ISceneFrame.Pick` 使用该帧的网格与对象姿态，射线、命中点、法线和距离都在该帧根空间。Cell、Face 则属于命中对象自身格网，NestedObjectPath 指向嵌套对象；DDA 始终按完整格，与楔形、空心模型或视觉凹槽无关。距离最近的可拾取格优先；先进入未构建区域时返回 NotReady，不把它当透明空白。

钢轨、轨枕、水面及粒子不是可拾取体素，不阻挡射线；铁路施工仍从地图或面板指定线路与断点。缺失单格保留原格占位；缺失功能复合体占格未知，只在放置点显示标记，通过诊断定位，标记不拦截 DDA。

世界命中携带核心对象、设计及部件身份；地形命中携带业务地点。编辑命中携带编辑会话、修订及内部元素身份，不把编辑位置当成核心 PartId。`Resolve` 在当前世界输入下核对请求、空间、对象存在性与设计/部件是否仍适用；普通模拟推进本身不让所有命中失效，已毁部件、旧设计或旧观察请求则明确拒绝。它不执行任何核心命令，也不是之后命令的业务许可；宿主仍走正式命令入口。

旧帧在会话关闭后仍可用于历史显示或只读拾取，不能重新取得当前交互资格。编辑选择前，宿主核对命中的 EditSessionId 和 EditRevision 与 Read 相同；Apply 还会核对预览基准，不能只靠 UI 按钮拦截。

## 设计编辑会话

`OpenEditor` 接收固定有效内容与 Complete 或 Partial 评估；宿主保证初始评估由这份内容产生。无需合法设计，Partial 始终具有承载已知布局、元素和锁的 Scene，但 Scene.Design 可以没有规范哈希。Failed 没有可解释草稿则拒绝。打开时建立自己的工作副本，初始无未保存修改；新建草稿是否需要先提示命名由宿主决定。一个会话始终使用该份有效内容，[结束编辑后再发布](editing.md#编辑会话与保存边界)，不提供会话内内容重绑定。

`Read` 返回不可变 EditState，`Capture` 返回整份固定草稿与 EditStamp；后续修改不影响它们。Elements 是当前固定修订的可定位元素清单，内部 ID 跨不改身份的操作保持，删除后不复用；诊断路径和数组下标只对应本修订。体素实现按原缺失引用维护锁，不等待迟到的完整内容评估才执行锁定。

`Select` 替换选区；`Enter` 只能进入可编辑的组装体/场景模型副本，null 回根。封闭功能复合体不能进入。切换层级清空选区及未应用预览；选取、相机、平面、剖切均不修改草稿修订、脏状态或撤销栈。框选遇到封闭复合体按整件处理。

所有操作坐标属于当前进入对象。Properties 改该对象文字与同类别参数，不偷偷转换设计类别。PlaceNested 使用内容公开的副本或封闭引用；体素解析自己的工作布局进行编辑，但不重做内容哈希、BOM 或完整合法性。CaptureObject 导出可编辑嵌套副本在自身坐标中的独立草稿；它不改变宿主设计，不给封闭引用解封，也不能绕过缺失项的复制锁。另存蓝图仍须完整校验，并在结束编辑后由内容发布。

格范围包含两端；Move/Copy 的 Offset 是整数格偏移。RotateSelection 绕正轴按右手规则旋转指定的 90° 次数，Pivot 指定格的中心。Stroke.Samples 是每次立方笔刷的最小角格，覆盖各点起始的 BrushWidth³ 格后合并去重；宿主连续采样，不把离散采样间未覆盖的格隐式连线。笔刷预览与实际提交共用这些定义。

### 预览、提交与撤销

`Preview` 固定操作、选区、当前进入对象和 EditStamp，不修改草稿。区域覆盖去重、上限、确认门槛沿用[编辑规则](../design/15-design-editor-and-tools.md#编辑)。CoveredCells 是覆盖格数，AffectedCells 是实际将改变的格数，SkippedCells 是空格或无变化等不适用格数，不能把冲突计为跳过后部分提交。未知占格时 OccupancyComplete=false，不能声称已完成完整冲突检查。

Conflicts 提供具体格或元素及原因。HighlightCells 在当前进入对象坐标中表示 RotateSelection 离散 90° 编辑动作的扫过范围、放置/替换/移动/复制的目标覆盖，其余为操作范围；Godot 画覆盖层，不自行算扫掠。工作平面与包络分别来自 EditViewOptions 和内容评估，Godot 可按这些公开几何值画线框。体素只做动作约束，内容诊断负责完整设计合法性；草稿暂时不连通或不合法仍可保存。

设备 rotation 行为的全角度范围与冲突格读取当前评估的 Scene.RotationSweeps，不能用 HighlightCells 代替。按 NestedItemIndices 匹配选中对象（空路径为根），体素用已有层级放置与本帧原点变换生成覆盖线框，经 Present 返回帧的 DebugLines 交出；这些编辑线框不要求开启开发调试图层。Godot 直接绘制帧中线框，不转换嵌套设计坐标或重算内容合法性几何。SweptCells 与 ConflictCells 的 Known/Unknown 分别显示，未知提示读取 CurrentEvaluation，不能将未知冲突显示为完整无冲突。AcceptEvaluation 拒绝的迟到结果不能更新这些覆盖层；草稿改变后随 CurrentEvaluation 清空，不能保留旧范围冒充当前结果。

`Apply` 只接受本会话产生的当前预览。新预览、切换进入对象、草稿改变或关闭后旧预览失效；选择改变不重定向已固定的预览。RequiresConfirmation=true 时必须显式 confirmed=true；否则返回 confirmation_required。已知冲突导致整笔拒绝，草稿、修订与撤销不变。未知引用保留并锁定，父级、选区、移动、旋转、复制、替换等均不能间接改变它；允许编辑其他已知部分不意味着未知处被推定为空。

一次成功修改整笔入栈，草稿修订增加；无变化操作不制造修订或历史。Undo/Redo 同样产生新的编辑修订，恢复对应工作值，不能使旧异步结果重新有效；新编辑清空重做。撤销不限步数但只活在本会话中，不进存档。体素内部用不可变共享或其他实现控制成本，不把存储结构列入契约。

### 校验与保存完成

宿主 Capture 后把 Draft 交给固定内容的 EvaluateDesign，可在后台运行；回到协调线程调用 AcceptEvaluation。宿主负责把原请求标识与结果成对保留，并保证计算使用的内容世代等于 EditStamp.Content；DesignEvaluation 本身不携带来源证明，不能把另一份内容的结果重新贴上当前标识。会话核对请求中的会话、修订、内容世代及结果草稿与当前值相符才接入，返回 true。草稿匹配必须递归比较全部字段及集合中的内容，不能用默认 record 的 == 或 Equals 代替深层内容比较；迟到或关闭返回 false，不覆盖当前诊断、缺失锁或按钮状态。每次草稿变化后 CurrentEvaluation=null，原结果不能冒充当前结果；旧内容评估故障按原请求报告，不污染新请求。

MarkSaved 只在对应保存目标成功后调用：本局草稿内容记录已提交就成功，用户/包草稿须写盘成功。它确认捕获版本，而不是宣布游戏已经存盘；期间新增修改仍脏，旧会话通知返回 false。撤销恢复到已确认保存的同一工作值时可以清除编辑脏标记，不依赖业务设计哈希。保存失败不调用它，保留活动草稿和旧记录。

设计保存、蓝图发布及核心提交由内容/Godot 负责，体素没有文件写入或核心提交方法。关闭前的保存/放弃/取消由宿主执行；Dispose 不自动保存，立即使预览、校验接入及修改入口失效，重复 Dispose 无副作用，保留的快照和帧仍不可变。

## 只读设计预览

图标与设计缩略图使用 `PreviewDesign(content, initial)`，无需打开编辑会话。宿主保证评估来自这份固定内容；与 OpenEditor 一样，Complete 或 Partial 可以预览，Failed 没有可解释草稿则拒绝。返回 `IDesignPreview`，只提供内容世代、`Present` 和 `Dispose`，不建立撤销、编辑修订、选区或脏状态。

`Present` 使用与世界、编辑及模板预览相同的体素网格生成规则，返回时间为零的完整替换帧。缺失引用保留已知部分和明确诊断，不把预览成功当成设计合法。这个入口只承诺固定设计显示，不新增通用预览框架；网格、材质引用、坐标和不可变值责任沿用本页的显示契约。调用同步完成，不启动需要宿主轮询的后台任务。Dispose 结束预览资格，重复关闭无副作用，关闭后的 Present 抛 ObjectDisposedException；已返回帧仍可保留，Godot 自行持有和释放渲染资源。

货物图标按 `FindGood(good)` 的 `DisplayDesign` 调用 `FindDesign`，再创建只读预览并 `Present`。宿主无需读取布局或重新选择同构成的设计；无显示设计的货物走其已有图标入口。可编译调用见消费样例的 `DesignIconConsumer`。

## 开发模板预览

聚居地模板由 Godot 持有 `SettlementTemplateDraft` 表单；PreviewTemplate 接收固定草稿、修订及内容，生成场景模型、已知预建建筑与地块显示资料。它不需要创建虚假核心世界，不修改表单，不拥有第二套撤销或发布流程。可在后台调用，仅结果仍匹配该表单修订和内容时接入。

ITemplatePreview.Frame 是完整替换帧；Plots 提供地块局部范围及在预览空间中的姿态。DraftIndex 使用固定数组下标，草稿里重复的地块编号不会错误定位另一个条目。PickPlot 单独拾取地块占地，最近者优先、等距离按下标；普通体素拾取仍用 Frame.Pick。Godot 根据拾取结果修改公开表单字段，再请求预览，不自行遍历场景模型布局或摆放建筑几何。

缺失模型或建筑时返回已知部分与明确诊断，不虚构引用的内容；无法解释的输入返回 Failure。预览成功不代表模板合法，完整规则及发布校验仍归内容。结果为不可变值，无需 Dispose；旧结果只可保留展示，不能覆盖更新的表单。

## 失败、线程与验证

SceneResult.Success 表示本次操作正常完成，包括仍在加载的帧和含无效设计的编辑状态。Failure 表示预期拒绝，至少一条 SceneProblem；Faulted 表示体素内部故障，宿主报告并停止故障会话的可变调用，不影响核心。缺失内容本身是诊断和占位，不强制变成整个场景故障。正常输入的生成算法失败必须报告，不能偷偷换种子或篡改核心长度。

稳定错误码至少覆盖 `target_missing`、`stale_request`、`stale_hit`、`content_missing`、`build_failed`、`edit_locked`、`invalid_operation`、`region_limit`、`occupancy_conflict`、`stale_preview`、`confirmation_required`、`scene_internal_fault`。Godot 不解析 Detail 分支；SceneProblem.Content 和 Package 保留引用及已知来源包，内容提供了来源时不得丢弃，确实未知时 Package 为空。宿主据此同时在界面与控制台显示缺失资料，不按设计哈希猜包名。绑定、内容世代或业务输入身份不匹配、Observe 位置倒退及事件顺序或重复错误属于接口前提违反，抛 ArgumentException，接入前仍须检查；真实交互过期继续返回 stale_hit、stale_request 或 stale_preview。default 集合/非有限数/无效枚举等编程前提错误抛 ArgumentException；关闭后的修改调用抛 ObjectDisposedException，AcceptEvaluation/MarkSaved 则按约定返回 false。

工厂无可变调用会话状态，可独立创建多个候选；世界和编辑会话的变更只在各自协调线程串行执行。只读设计预览的 Present 和 Dispose 在调用方协调线程串行调用。固定帧、输入快照与模板预览可并发只读。体素背景线程不调用 Godot 或内容加载器，不读文件、不回调宿主；内部任务完成状态只经 Present 暴露。

[消费样例](../../prototypes/scenes-contract/README.md)证明公开面可调用，不提供生产算法或复制业务规则的替身。后续共享契约用例须对真实实现及有限情景替身分别执行：

| 输入场景 | 输出断言 |
| --- | --- |
| 固定核心/内容与相邻步 | 同帧姿态和拾取一致；不外推，暂停、倒车、编组中心和读档重建一致 |
| 分段未完成、跟随切换、旧任务晚到 | 进度与雾明确，旧请求不能接入，删除对象不复活，不等待核心 |
| Base 不符、准备重试、浮动原点平移 | 不部分接入资源；准备期间姿态、相机和拾取使用 P，完整替换可恢复；平移及效果不重复 |
| 保留旧网格/帧后更新或关闭 | 旧值不变，无显式归还义务；新交互拒绝旧绑定 |
| 缺失单格/未知范围复合体 | 前者原格占位，后者放置点标记且不拦截 DDA；诊断可定位 |
| 编辑区域、嵌套副本与封闭引用 | 原子提交、门槛确认、拒绝无写入、锁不能绕过、导出副本可交给内容 |
| 新编辑后校验/保存迟到、撤销、关闭 | 不启用旧结果，不清除新修改；显式保存版本与整局落盘分离 |
| 模板缺失或重复地块编号 | 已知部分可预览，按数组下标定位，预览不承担发布校验 |

实际隔离仅提供目标契约/样例和允许的 Core、Content 契约，不提供产品实现源码或程序集。真正模块独立测试按[验证规范](testing.md)另行实现；真实 Godot 的资源、绕序、Custom Mesh 轴向、相机、闪烁与碎片时间，以及视觉观感均须在那里验证，不能用纯数据测试替代。

区块边长、分段长度、预取距离、单帧重建预算、内存峰值和 GC 成本不在此冻结。实施时测量首次进入、长编组跨分段/原点、局部破坏和大尺寸编辑；按已有 Demo 负载验证后决定预算。若普通不可变数据不能满足实测要求，再按受控变更流程修订，不预建缓冲池公共协议。
