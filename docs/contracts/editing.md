# 编辑草稿、设计提交与创作包写入

本协议依据[设计编辑器的草稿、校验、发布与改装接口](https://github.com/odradekk/train/issues/285)的 Q1–Q8，补充[公共约定](conventions.md)和[跨层事务](transactions.md)。玩法规则以[设计编辑器](../design/15-design-editor-and-tools.md)、[设计合法性](../design/03-vehicles-buildings-and-designs.md#设计合法性)及[改装](../design/14-construction-refit-and-deconstruction.md#refit-job)为准，本页规定模块怎样交接这些操作。

本页按[契约审计修订 #296](https://github.com/odradekk/train/issues/296)收缩开发包写入保证，并改为同步核心命令；历史决策出处保留。

编辑器与创作包写入已接入；可编译声明与调用样例见[核心契约](core.md)、[内容契约](content.md)和[体素契约](scenes.md)。本页规定协议，不表示全部范围已验收。

## 四种操作的边界

| 用户操作 | 结果 | 是否改变实例 |
| --- | --- | --- |
| 保存草稿 | 保存一份可继续编辑、可以不合法的快照；不加入有效内容 | 否 |
| 保存蓝图 | 把完整合法的设计存进选定蓝图库，成为模板 | 否；已有实例拥有自己的设计 |
| 立即应用或正式改装 | 面板明确提交核心命令，使用经过校验的目标设计 | 是；立即应用更新设计引用，正式改装在任务完成时更新 |
| 创作模式包写入与重载 | 在开发构建中发布一个 `core` 或 Mod 包的修改，校验包、依赖与运行中引用并重载 | 按内容更新规则适配；不是对某个实例提交改装 |

创作修改可涉及定义、蓝图、资产及适用的 manifest，编码补丁只列出修改与明确删除，不重写未修改文件。普通玩家编辑器保存蓝图仍走独立路径。

## 所有权与公开责任

| 模块 | 负责 | 交接边界 |
| --- | --- | --- |
| 体素 | 活动编辑会话、可变工作草稿、选取、预览、网格操作、撤销重做 | 接收内容契约中的草稿值，产生不可变快照；不持久保存、不计算经济和设计规则、不调用核心修改入口 |
| 内容 | 已保存草稿记录及修订、草稿的编码与恢复、合法性报告、设计计算、蓝图和包的发布准备 | 接收不可变输入，返回诊断、设计身份和各层投影；负责格式与业务规则，不把这些工作交给 UI |
| Godot 宿主 | 输入和界面、来源与保存目标选择、暂停、后台调度、文件访问、提交协调、诊断展示 | 通过模块契约接入结果；不解析内部草稿字段、复制校验算法或直接修改核心状态 |
| 核心 | 立即应用、建造、改装等命令的接收、业务条件、结果及录制 | 只接收自身契约中的设计身份、属性和必要对应关系，不读取布局、文字、形状或涂装 |

完整草稿数据和诊断类型属于内容契约，编辑会话及编辑操作属于体素契约；设计哈希、构成哈希和部件编号的值类型继续属于核心契约。具体声明由各模块接口票确定，不为同一类型建立重复 DTO，也不因草稿由体素编辑就把其持久化格式放进体素层。

开发工具中的非网格表单输入由 Godot 持有，通过内容契约形成草稿快照；不会为了填写一个定义字段而建立体素场景。网格草稿与表单草稿共享“显式保存、校验后发布”的边界，不共享一套强制的通用编辑框架。

设备 rotation 行为的扫过范围与冲突格由内容随 `DesignEvaluation.Scene.RotationSweeps` 一次交出，沿用对象路径及 `ComputedValue<T>`；坐标和未知语义见[内容契约](content.md#设计计算和场景查询)。体素按选中对象消费并转换显示坐标，通过既有 `Present → ISceneFrame.DebugLines` 交出覆盖线框，Godot 直接绘制，不重复合法性几何。它与 `RotateSelection` 离散 90° 编辑动作的 `HighlightCells` 分开；缺失占格不能用空冲突集合宣称检查完成。范围、冲突和未知提示都只随 `AcceptEvaluation` 接受的当前评估更新，草稿修改或迟到结果不能继续显示旧结果为当前结论。

## 编辑会话与保存边界

进入设计编辑器前，宿主在完整边界暂停世界，并在编辑期间禁止其他入口修改世界；编辑、查询和草稿操作仍可执行。退出恢复原暂停或倍速设置，不追赶真实时间、不解除故障冻结。暂停属于宿主运行控制，不改变核心的模拟算法；不引入编辑期间的世界并发合并机制。

经[体素公开契约](https://github.com/odradekk/train/issues/289)确认，编辑会话从打开到关闭始终使用同一份有效内容。热重载或发布有效内容之前先结束编辑，沿用保存草稿、放弃、取消流程；取消就不继续发布，保存失败不关闭。明确保存的草稿在发布失败后仍保留，不在打开的会话中切换内容、清空撤销或重新合并。保存有效蓝图也先固定目标草稿并结束编辑，再提交内容变化；本局草稿的保存只改变持久记录，不属于有效内容发布。创作模式包写入与重载仍须取得[技术操作锁](transactions.md#技术操作锁与线程)。

新建改装草稿以实例当前设计为起点，不复制实例运行状态；重新打开已保存草稿则读取它的保存版本，不悄悄用当前实例覆盖。实例身份是保存目标的关联，不是设计内容。跨次编辑期间实例可能已变化，面板提交仍检查当前对象和业务条件，旧校验结果不构成永久提交许可。

| 草稿来源 | 明确“保存草稿”后的归属 | 写入游戏存档 |
| --- | --- | --- |
| 实例改装 | 内容管理的本局草稿记录，与实例关联，每实例最多一份 | 是，下一次保存游戏时写盘 |
| 本局蓝图库 | 内容管理的本局草稿记录 | 是，下一次保存游戏时写盘 |
| 用户内容库 | 内容编码、宿主写入 `user://authoring-drafts/`，与对应蓝图或新草稿关联 | 否 |
| 创作模式的包 | 内容编码、宿主写入 `user://authoring-drafts/`，记录目标包和编辑所依据的源文件版本 | 否；草稿不写入有效包目录 |

保存草稿只要求可编码、可恢复，不要求完整建造合法性。保存失败保留旧记录和当前编辑，不能先覆盖旧记录再报告文件失败。本局记录保存成功后增加内容的持久状态修订，使整局变为未保存；用户或包草稿保存成功不凭空制造核心命令或本局进度。

活动编辑的未保存判断与整局未保存判断分别维护。保存游戏和自动存档只捕获已明确保存的本局草稿，不捕获活动工作副本。关闭脏编辑提供保存、放弃、取消；保存失败留在编辑器，放弃只丢弃未保存修改。选取、相机、预览和撤销栈不持久化，重新打开不恢复撤销历史。

## 局部编辑、校验与结果接入

选取、预览、笔划、区域修改和撤销重做是体素会话内操作，按既有规则形成一次编辑；拒绝的局部操作不改变草稿或撤销栈。编辑可使草稿在玩法上不合法，例如暂时不连通；不要求每次编辑都先成为可建造设计。

内容负责完整合法性、属性、BOM、设计哈希、构成哈希和部件对应计算。体素可以约束编辑动作及显示冲突预览，但预览不能替代内容校验。计算不完整时区分已知结果、未计算项和错误，不把未知值显示为有效的零。

每次校验或保存固定不可变草稿快照及其编辑修订，连同所用内容版本交给内容。内容计算在调用线程完成，不自行调度后台工作；Godot 可在所需宿主接口支持的线程上调度，体素的活动编辑只在其指定协调线程修改，不让后台任务读取可变草稿。

- 诊断包含稳定错误类别、对象或定义身份、字段或嵌套位置及阶段，按[公共约定](conventions.md#失败与诊断)解释。Godot 负责 UI 定位和控制台输出；业务拒绝、文件失败和内部故障分别显示。
- 校验结果绑定编辑会话、草稿修订和内容版本。草稿已修改、会话已关闭或内容已切换时，迟到结果不能覆盖当前提示、启用提交按钮或重新发布；重新请求当前版本的校验。
- 保存成功只确认所捕获的版本。期间新增的修改仍未保存，旧会话的完成通知不清除新会话的脏标记。
- 关闭、取消和场景切换沿用[操作身份与取消](transactions.md#候选准备激活与放弃)规则。校验可取消或废弃；已开始的单文件替换须报告实际结果；取消多文件写入时须报告已经完成与尚未执行的项。

## 设计身份、限制与核心提交

哈希和编号规则只由内容实现一次，见[设计格式](../content/blueprint.md#设计对象)。编辑位置或会话内选取标识不是核心部件编号，编辑后不能复用旧编号解释新设计。内容提供设计与部件的对应资料，体素据此定位，核心把编号当标识；调用方不得复制遍历和哈希算法。

玩家可编辑的组装体副本、只允许整件操作的功能复合体，以及缺失引用的锁定规则见[设计编辑器](../design/15-design-editor-and-tools.md#编辑)。契约必须能区分它们，并保留嵌套位置及原引用，不能仅靠 UI 隐藏按钮来防止绕过封闭边界。被锁定的缺失条目不能被选区或父级操作间接修改；缺失功能复合体的占格未知时仍须报告不完整。游戏界面和控制台均列出缺失定义、所属包及被阻止的操作。

保存有效蓝图、立即应用和正式改装都先完整校验目标设计，再准备对应操作。原实例缺内容或因内容更新已不合法也不例外。成功的预览报告不是发布凭证：提交使用固定输入和相符的内容版本，不在提交途中重读另一份草稿。

- **保存蓝图**：内容准备有效设计及目标库的变化；本局库更新内容记录，用户库先由宿主完成文件发布再切换已准备记录。失败保留草稿和旧蓝图。覆盖、复制和跨库新身份沿用[草稿与保存](../design/15-design-editor-and-tools.md#草稿与保存)，不改已有实例，也不生成核心命令。
- **立即应用**：内容确认只有名称、说明、形状或涂装变化、构成未变，并准备新设计身份和必要投影。面板同步 `Submit(command, source)`，命令携带固定业务投影，设计引用和相应内容记录在同一完整边界生效。设计哈希改变仍是核心引用身份变化，不能当作只更新渲染资源而跳过命令和录制。
- **正式改装**：含构成变化的整份目标携带固定业务投影，由面板同步 `Submit(command, source)` 提交，成本、任务、锁定与完成规则见[改装任务](../design/14-construction-refit-and-deconstruction.md#refit-job)。内容提供目标属性和部件对应，核心处理当前实例及损伤，不让草稿携带运行状态覆盖实例。

核心正常拒绝时按[跨层协议](transactions.md#内容发布拒绝与录制)保留旧业务状态并记录拒绝；准备失败不伪造核心命令。核心内部故障遵循冻结语义，不能一概声称所有失败都会回滚。

## 创作模式包写入与重载

这条路径只用于开发构建的创作模式。输出沿用[既有包格式](../content/README.md)，不新增整包事务、发布记录或恢复框架；源码 `core` 必须是明确可写的开发输出，导出 PCK 只读。

1. **固定来源与草稿**：记录打开或重新载入时的完整源包基准，草稿记录目标包与此基准。内容把固定草稿编码为补丁，明确写入及删除项；不删除补丁未涉及的文件，也不误删共享资产。
2. **校验与复核**：使用固定来源、依赖和补丁校验候选包及运行必需引用。写入前完整比较目录项和文件字节，不能只比较时间戳或长度；外部修改则拒绝覆盖，保留草稿，提示开发者重新载入、处理修改后重新校验。不自动合并。
3. **逐文件写入**：宿主按补丁在目标同目录临时写完整、关闭并校验，再替换对应文件；删除只按明确删除项执行。最终复核至写入完成期间采用单一写入者约定，外部编辑器、同步工具与其他宿主不得同时写同一包；不承诺强制阻止违反约定的外部程序。已开始的文件替换结果须报告，不能因取消或会话切换丢弃。
4. **失败与修复**：文件失败或进程中断可能留下部分文件已更新。进程存活时停止后报告已完成项与未完成项，保留草稿由开发者修复；不承诺回滚完整旧包，不切换当前有效内存内容。不保证进程中断后仍能恢复具体完成清单；重启正常加载诊断，实际磁盘状态由开发者检查，不能凭缺失的完成报告猜测文件未写入。
5. **普通重载**：写入完成后走普通内容重载，成功才激活候选；需要核心适配时，同步 `Submit` 携带固定 `CoreContentProjection` 的 `PublishContent`。重载或命令拒绝时旧内存内容不变，磁盘修改仍保留并报告，草稿不丢失。启动正常加载并校验当前磁盘内容，不自动整包恢复；无效内容按既有加载规则报错。

这是开发创作工具的有限保证，不以 Git 代替未提交文件或 Mod 的恢复，也不声称多文件原子性。玩家保存草稿、蓝图及实例改装沿用各自的单文件和内存一致性边界，不因这条路径放宽。

## 后续契约与验证

四份模块接口及[契约原型](https://github.com/odradekk/train/issues/292)按[共享用例和隔离规则](testing.md)落实以下可观察承诺；原型替身通过不等于真实文件、真实设计计算或产品联调通过。

| 场景 | 必须观察到的结果 | 责任 |
| --- | --- | --- |
| 编辑、撤销与关闭 | 编辑期间世界不推进，编辑不下核心命令；局部拒绝不改草稿；退出正确恢复运行设置 | 体素与 Godot |
| 保存草稿后继续编辑，再保存游戏、读档 | 只恢复明确保存的版本；未保存工作、选取与撤销栈不入档；保存失败保留旧记录 | 内容捕获与编码，Godot 协调及真实文件 |
| 缺失引用、封闭功能复合体、嵌套选区操作 | 原引用保留、锁定不可绕过、可以保存草稿；不合法目标不能成为蓝图或核心目标；两处诊断可定位 | 内容、体素与 Godot |
| 四类立即应用与含构成变化的目标 | 合法且构成不变才立即应用；核心保留损伤和运行状态；含构成变化全部正式改装；正确记录设计身份 | 内容与核心，Godot 提交协调 |
| 校验或保存结果迟到 | 旧草稿、旧内容、旧会话结果不能启用提交或清除当前脏标记 | 体素结果消费与 Godot 调度 |
| 蓝图覆盖和跨库复制失败 | 不改实例；身份沿用既有规则；失败保留旧库和草稿 | 内容与 Godot |
| 外部修改、文件占用、包校验失败和各发布阶段中断 | 拒绝静默覆盖；逐文件失败报告完成项与未完成项，保留草稿及旧内存内容；普通重载成功才激活，启动不自动整包恢复 | Godot 用真实 Windows 文件系统验证单文件替换与部分写入；内容验证包及依赖 |

[核心契约](https://github.com/odradekk/train/issues/287)落实命令输入、损伤保留与录制；[内容契约](https://github.com/odradekk/train/issues/288)落实草稿、诊断、计算与发布准备；[体素契约](https://github.com/odradekk/train/issues/289)落实编辑会话、快照和限制；[Godot 契约](https://github.com/odradekk/train/issues/290)落实暂停、界面、文件写入与重载。完整设计编辑器仍在 Demo 内，创作与调试工具按开发需要分批实现。
