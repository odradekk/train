## 目标项目布局

路径相对仓库根目录。`Contracts/` 只是集中存放契约的目录，不是程序集，也不是第五个业务模块；每份契约由对应模块负责。

| 目录 | 项目 | 用途 |
| --- | --- | --- |
| `Contracts/Core/` | `Train.Core.Contracts` | 核心公开契约 |
| `Contracts/Content/` | `Train.Content.Contracts` | 内容公开契约 |
| `Contracts/Scenes/` | `Train.Scenes.Contracts` | 体素公开契约 |
| `Core/` | `Train.Core` | 核心实现 |
| `Content/` | `Train.Content` | 内容实现 |
| `Scenes/` | `Train.Scenes` | 体素实现 |
| 根目录 | `Train` | Godot 项目；源码仍按 `App/`、`Rendering/`、`Ui/` 划分 |

契约项目沿用 .NET 10、C# 12，不引用 Godot。命名空间沿用“项目名.项目内目录名”。新增项目时隔离源码编译范围，不能让根项目或实现项目再次编译契约源码。现有测试项目已按 Core、Content、Godot 宿主拆分；目标入口及允许依赖见[测试组织](testing.md#模块测试的组织与入口)。

## 依赖与装配

下表是第一方项目引用的允许范围，不要求为了对称而添加不使用的引用。实际程序集依赖也受同一方向约束；不能通过间接引用绕过。

| 项目 | 允许引用的第一方项目 |
| --- | --- |
| `Train.Core.Contracts` | 无 |
| `Train.Content.Contracts` | `Train.Core.Contracts` |
| `Train.Scenes.Contracts` | `Train.Core.Contracts`、`Train.Content.Contracts` |
| `Train.Core` | `Train.Core.Contracts` |
| `Train.Content` | `Train.Content.Contracts`、`Train.Core.Contracts` |
| `Train.Scenes` | `Train.Scenes.Contracts`、`Train.Content.Contracts`、`Train.Core.Contracts` |
| `Train` | 三个契约项目；真实实现项目只用于下述装配例外 |
| `Train.Cli` | Core、Content 的契约与实现项目；真实工厂只在 `Tools/Cli/Composition.cs` 调用 |

核心在编译时看不到布局、体素朝向、表现资产和显示文本。内容按读取方提供投影；体素可以读取核心查询和内容契约，宏观地图及管理界面可以直接使用核心查询，不需要经过体素。

各实现类型默认 `internal`，实现程序集只额外公开少量创建工厂。工厂的参数和返回值使用公开契约，不泄露实现类型；工厂是受控的装配入口，同样纳入文档、公开面检查和变更基线。既有 `public` 类型不自动成为新契约，不承诺保留通用模拟框架的全部构造和扩展入口。

Godot 只有 `App/Composition/` 可以调用真实创建工厂；其他宿主流程、渲染和界面接收装配好的契约接口。独立测试替换装配入口并注入替身，仍执行同一份 Godot 生产代码。暂不引入依赖注入容器、插件扫描或反射装配框架。

`Tools/Cli/` 是纯 .NET 宿主工具，不是新的业务模块，不引用 Godot 或 Scenes。只有其 `Composition.cs` 调用真实 Core／Content 工厂，其余代码接收契约。工具链接 `App/Assets/DiskContentFiles.cs` 同份文件端口源码；源码归属检查按精确文件允许共享，不开放整个宿主目录。

不为 Godot 对称地增设第四个契约程序集。下层需要的文件读取、PNG 解码、资源提交等宿主接口由需要它的模块定义，Godot 实现；下层不引用 Godot 类型。Godot 的接口文档仍须说明这些适配、装配、交互和资源责任。

## 跨模块类型归属

每种跨模块类型只声明一次，消费者引用其契约，不复制同形类型。类型的所有者不一定是值的计算者；强类型身份可供多层使用，但不因此携带布局或加载实现。

| 所有者 | 类型范围与限制 |
| --- | --- |
| 核心契约 | 世界对象身份、模拟位置、命令及结果、查询与领域事件；核心需要的定义标识、设计哈希和构成哈希的值类型、部件编号、设计属性、能力、BOM 等输入类型 |
| 内容契约 | 内容包与来源、内容世代、资产修订、完整设计与布局、显示资料、加载与设计校验结果 |
| 体素契约 | 场景和编辑会话、拾取结果、场景更新及交给渲染层的数据 |
| Godot 内部 | Godot 节点、纹理、材质、输入事件、窗口与界面状态，不进入前三者的契约 |

设计属性的声明归核心契约，计算归内容实现。设计哈希的值类型供核心引用，哈希算法、布局遍历、部件编号生成及设计合法性计算只由内容实现负责；核心把哈希和编号当标识，不读取布局。具体规则引用[设计与部件](../design/03-vehicles-buildings-and-designs.md#部件与结构)，不在契约项目重做一份计算。

内容世代归内容契约，是发布序号，不是持久身份，也不能替代语义指纹。设计哈希、构成哈希、语义修订与资产修订继续承担各自的身份职责，见[内容版本与哈希](../design/02-definitions-and-content.md#三种内容版本)。核心只接收自己需要的业务投影，不接收完整内容目录；跨世代配对、运行会话身份与存档 UUID 的区别见[活动组与身份](transactions.md#活动组与身份)。

## 跨层工作的责任

| 工作 | 责任 |
| --- | --- |
| 核心状态与确定性 | 核心捕获、编码、校验和恢复核心状态，记录命令、生成检查点、执行确定性重放；重放计算可在无 Godot 的测试中运行 |
| 内嵌内容 | 内容捕获和恢复设计、蓝图库、草稿与模板，解析外部定义并提供各读取方的投影 |
| 完整存档与复现包 | Godot 宿主组合完整容器、访问文件、调度自动存档、组装复现包，在候选会话成功后整体切换；不拆开核心状态自行编码，也不重新计算设计属性 |
| 场景生命周期 | 体素不加入权威存档；会话切换后重新构建场景 |
| 表现资产 | 内容读取原始字节、计算资产修订、执行全部资产规则；体素只按资产修订引用贴图和模型；Godot 实现文件读取和资产检查，持有并释放全部运行资源，见[表现资产的交接](#表现资产的交接) |
| 诊断日志 | Godot 宿主负责输出、文件保留和展示；其他模块通过自己的结果、事件或必要的诊断接口报告，不依赖日志实现 |
| 控制台 | Godot 宿主解析文本并分发已解析命令，与界面、自动测试使用同一核心命令入口；核心命令记录、确定性摘要和稳定故障信息仍归核心 |

宿主内部的纯 .NET 代码可以独立测试；涉及引擎的行为仍用真实 Godot 验证。日志搬迁不等于立即重写实现。新局／读档使用候选激活，核心命令同步提交，保存与录制使用一致捕获；时序见[跨层协议](transactions.md)；不能把所有故障都理解成回滚。数据和玩法规则仍见[存档](../design/09-persistence.md)、[录制与复现](../design/04-deterministic-simulation.md#录制与复现)。

## 表现资产的交接

由[资产访问与导入：内容、体素和 Godot 的交接契约](https://github.com/odradekk/train/issues/286)确认，取舍见 [ADR-0017](../adr/0017-hand-off-presentation-assets-as-raw-bytes-keyed-by-asset-revision.md)。资产的身份、校验和失败规则见[设计 02 的资产的交接](../design/02-definitions-and-content.md#资产的交接)，代码自带和程序生成的表现资源归属见[设计 07 的总体策略](../design/07-rendering.md#总体策略)。具体声明由内容、体素和 Godot 的契约票写进各自的接口文档。

| 数据 | 所有者与生命周期 |
| --- | --- |
| 原始字节 | 内容通过宿主文件接口读取，随内容世代不可变，世代不再被使用后由垃圾回收释放；其他模块只读 |
| 元数据与校验结果 | 内容；元数据来自宿主的资产检查接口 |
| 解码后的像素、模型数据、纹理、网格、材质 | 只在 Godot 内部，不进入任何契约 |
| 体素交给渲染层的网格数据 | 体素生成，只用资产修订引用贴图和模型，附材质类别和涂装颜色，不含像素和模型几何；按[体素契约](scenes.md#显示更新与资源)使用可保留的不可变值，无需归还缓冲 |

- **资产检查接口**：内容契约定义，Godot 实现。输入原始字节和资产种类，返回元数据或失败种类。接口只报告事实，规则全部在内容实现里；纯 .NET 测试用替身返回元数据。Godot 可以在内部按资产修订缓存解码结果，这不属于契约。
- **线程**：内容加载器在调用方的线程上同步执行，只在调用期间使用宿主的文件和检查接口，返回后不再调用，自己也不开线程。加载和热重载在哪个线程运行由 Godot 决定，Godot 的宿主实现须在它选的线程上可用。已发布的内容世代及其字节不可变，任何线程都能读。热重载仍然禁止并发和重入。
- **世代与旧资源**：体素和 Godot 各自记住正在使用的内容世代。新世代发布后，体素重建受影响的区块和对象；Godot 先为新的资产修订创建资源，在帧之间换上重建好的网格，再释放不再被引用的资源。资源创建不参与能否发布的决定；活动绑定失效、候选取消及旧资源退役按[跨层协议](transactions.md#场景接入与资源退役)处理。
- **验证**：测试的组织见[四模块独立构建与契约验证](testing.md)，需要覆盖的情况如下：
  - 内容规则用替身做纯 .NET 测试；
  - Godot 的检查实现在真实 Godot 中用样例文件核对元数据，样例包括合格和损坏的 PNG、合格的 `.glb`，以及带动画或骨骼、半透明混合、外部贴图、超出格的 `.glb`；
  - 内容导出检查从 PCK 读取 Keep File 导入的内置 `.glb`，Mod 导出检查从 `user://mods` 读取 `.glb`；
  - [契约原型](https://github.com/odradekk/train/issues/292)在 Godot 4.7.2 上验证 `.glb` 的 Keep File 导入，以及按资产修订把字节建成纹理。
