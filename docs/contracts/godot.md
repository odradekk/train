# Godot 宿主公开契约

本页落实[Godot 层公开契约：宿主适配、资源与交互接入](https://github.com/odradekk/train/issues/290)。职责和依赖见[契约索引](README.md)，玩法仍以[设计文档](../design/README.md)为准；会话与持久化使用[跨层协议](transactions.md)，编辑与发布使用[编辑协议](editing.md)。

当前交付是宿主接入规范和[可编译消费样例](../../prototypes/godot-contract/README.md)，不是生产宿主实现。根项目仍引用旧结构，内容、存档、日志和控制台尚未完成迁移。样例编译不证明真实 GPU、Windows 文件发布或四模块联调正确；验证范围见文末。

## 装配与可调用入口

Godot 消费其他三个模块的契约，并实现内容要求的宿主端口，不另建第四个契约程序集。Godot 节点、纹理、材质、窗口和输入事件留在本模块；普通 .NET 契约类型不继承 `GodotObject`。

只有 `App/Composition/` 引用和调用真实创建工厂，取得 `ICoreFactory`、`IContentFactory`、`IScenesFactory`。其余 App、Rendering、Ui 代码接收这些接口及会话，不调用实现静态入口。测试只替换这处装配和实现项目引用，仍执行同一份宿主生产代码；不增加依赖注入容器或反射扫描。

| 调用场景 | 使用的声明与适配 |
| --- | --- |
| 内容发现、固定候选与设计计算 | [IContentFactory](../../Contracts/Content/Lifecycle.cs)；`Discover`、`PrepareLoad`、`EvaluateDesign`、`PrepareEdit` 等返回候选或不可变结果 |
| 文件与资产检查 | [IContentFiles、IAssetInspector](../../Contracts/Content/Sources.cs)，由 Godot 实现；具体线程及失败见下文 |
| 新局、恢复、核心命令与录制 | [ICoreFactory、ICoreSession](../../Contracts/Core/Lifecycle.cs)；写入口只由宿主协调处调用 |
| 地图、面板和报价 | [ICoreReadView](../../Contracts/Core/Queries.cs)，直接查询同一份读视图，不绕体素层 |
| 世界、编辑和模板预览 | [IScenesFactory](../../Contracts/Scenes/World.cs)、[编辑会话](../../Contracts/Scenes/Editing.cs)、[模板预览](../../Contracts/Scenes/Authoring.cs) |
| 渲染、相机和拾取 | [ISceneFrame、SceneUpdate](../../Contracts/Scenes/Rendering.cs)；接入成功的帧才成为显示及交互基准 |

[HostConsumer](../../prototypes/godot-contract/HostConsumer.cs)给出装配数据、候选准备、查询、命令和逐步推进的实际调用签名；[ResourceConsumer](../../prototypes/godot-contract/ResourceConsumer.cs)给出 Godot 资源转换调用。样例中的 `HostComposition` 和 `IFrameDisplay` 只说明宿主内部接入位置，不是下层模块的新依赖，也不把它们冻结成生产类名。

宿主对 UI、控制台和测试暴露同一组应用操作：新建／读档、保存／另存为／导出、提交核心命令、设置暂停／倍速、切换观察目标、编辑草稿与发布。应用操作负责身份、忙和取消判断，再调用上表入口；不要求 UI 手工激活候选或依次切换三个模块。打开面板、相机移动和宿主暂停不是核心命令。

## 协调线程与帧驱动

协调线程采用 Godot 主线程，沿用当前 App 的串行接入方式。核心写入口、内容候选激活、体素会话入口、活动组切换及 UI 状态更新都在这里完成。禁止在模块调用中重入宿主操作；通知回调只更新表现，不在分发过程中递归提交命令。

主线程按完整边界处理一帧：

1. 接入后台完成结果，逐个核对操作身份、运行会话和基准；取消或失配结果只清理。准备完成不等于允许提交，技术锁和最终裁决仍遵循跨层协议。
2. 按收到的顺序处理用户应用操作；命令立即在当前完整边界裁决，结果携带的新事件立即分发。技术锁期间明确返回忙，不把修改隐式排队到解锁后执行。
3. 按真实帧间隔、当前倍速和不足一步的余量算本帧额度。每次调用 `Advance(1)`，处理结果和通知策略后才决定下一步。事件要求暂停或降速时，不继续使用旧倍速的剩余额度；故障立即停止驱动。预算只在完整步之间判断，不能中断半步。
4. 每个成功的命令／步边界，把固定核心读视图、配对内容和本次新事件交给活动体素会话 `Observe`。地图及所有面板在本次 UI 刷新中共用最后一份读视图，不能各自读取不同步；不为画地图复制核心计算。
5. 未最小化时取得场景帧，准备资源并完整接入；相机和拾取使用实际显示帧。最小化仍处理输入、后台完成、模拟、通知和自动保存调度，只停止渲染及相应显示提交。恢复后从当前状态继续，不补演错过的短时效果。

60 Hz、倍速、掉帧不追赶以及实际速度显示以[时钟规则](../design/04-deterministic-simulation.md#时钟与倍速)为准。使用单调时间测工作预算与实际速度；保存日期使用真实日期。测试可向宿主注入帧间隔和计时来源，核心与内容不新增时钟、调度或回调接口。每帧预算及平滑统计窗口由 Profiling 决定；现有 App 的 5 ms 是旧实现暂定值，不是本契约承诺。

暂停的来源分别保留：玩家／通知、失焦、编辑、技术操作锁及核心冻结。玩家继续可解除玩家和通知暂停，不能绕过其他阻止原因；重新聚焦只解除失焦暂停。通知暂停优先于同一步的降速，降速不解除暂停。编辑结束与技术操作结束按各自协议恢复设置，不能清除期间仍有效的其他暂停原因；新局／普通读档仍以暂停开始。暂停时固定世界表现的插值，UI 和相机照常响应。

后台只处理不可变输入：内容准备、核心候选准备、编码和文件写入可由宿主调度；活动会话不交给后台修改。体素自己管理构建与取消，宿主不接管区块队列。主线程不通过 `.Wait()`／`.Result` 等待后台工作。

## 文件与资产端口

`ContentRoot` 是宿主登记的根句柄，内容不解释绝对路径。根映射到内置 `res://builtin/core`、Mod 根或用户库；读取导出内置包使用 Godot `FileAccess` 的原始字节入口，磁盘目录使用本地文件接口。内置 PNG／GLB 必须按 Keep File 导入，不能把导入后的纹理或模型资源当作源内容。

`Enumerate` 返回直接子项，保留 File／Directory／Link 区分；`Read` 返回上限内完整且固定的字节。磁盘适配器逐段检查真实根及路径，拒绝链接穿越，不以字符串前缀代替；结果区分 Missing、LimitExceeded、LinkedPath、Inaccessible，不把占用或权限错误说成缺文件。内容负责排序和格式识别。端口返回后不留下调用方必须关闭的流；只读字节不随文件后续变化而改变。

`IAssetInspector.Inspect` 同步接收固定原字节：PNG 解码获得宽高；GLB 通过 `GLTFDocument` 从缓冲取得场景事实，报告节点数、各表面透明方式、变换后米制包围盒及骨骼、形变、动画、相机、灯光、外部图片标记。外部引用不能触发额外磁盘／网络读取。检查器报告解码或不支持的失败，合法性规则仍由内容判断；不能在宿主重写贴图尺寸、占格、材质数量等规则。

初始接入方案把 Godot 文件及解码 API 操作串行放在主线程：后台内容加载经宿主端口发送这类调用并等待结果，主线程继续泵送这些请求，不同步等待加载任务。纯本地文件 I/O、哈希和纯 .NET 准备可留在后台。取消后仍保证已经开始的端口调用结束，结果失去发布资格并释放临时 Godot 对象，不强行终止线程。若以后证明某种 API 在所用 Godot 版本的单工作线程上安全，可在宿主内部调整；不改变同步端口和不重入承诺。

这项安排不承诺每次解码都在一帧预算内。大资产解码、首次导入、候选缓存和取消延迟必须测量；不能靠假设所有 Godot API 都线程安全来宣称无卡顿。官方[线程安全说明](https://docs.godotengine.org/en/4.7/tutorials/performance/thread_safe_apis.html)也区分场景树、资源与 GPU 操作；本票尚未提供逐 API 的真实线程验证。

## 活动组与应用操作

运行会话身份、内容绑定、候选操作和保存目标的含义沿用[活动组与身份](transactions.md#活动组与身份)，不再定义同形跨模块 ID。宿主内部持有当前完整组及自己的状态；UI 绑定中保留所属组，不能拿旧面板里的实体 ID 向新局提交。

| 操作 | 宿主必须完成的交接 |
| --- | --- |
| 启动 | 先恢复未完成的包发布，再发现安装内容；初始化宿主端口和日志，失败明确显示；没有活动会话也能返回菜单查看诊断 |
| 新局 | 固定安装内容，创建生成输入，准备核心候选，按其最终聚居地 ID 准备模板副本；完成全部配对后激活最终候选，生成新运行身份及存档 UUID，暂停显示地图 |
| 普通读档 | 解开外层存档，把不透明载荷交还各所有者解码；按公开引用清单准备内容、确认固定缺失清单并准备核心恢复，再一次切换；不解析核心 JSON 寻找布局或修补字段 |
| 热重载／有效内容发布 | 先结束编辑，固定候选和引用；需要核心命令时准备并统一裁决，正常拒绝与核心故障分开处理；纯表现或无变化遵循既有分类 |
| 建城／实例目标 | 核心准备提供最终身份／结果，内容准备实例模板副本或合法目标设计；同边界提交相关内容与核心结果，不提前把未受理设计留进本局记录 |
| 严格重放 | 独立会话，只驱动包内输入；不能复用当前游戏的定义适配或接受玩家命令；导出的可编辑副本另走普通读档 |
| 关闭／返回菜单 | 先解决未保存的编辑工作，再按整局未保存保护处理；等待不可取消的文件发布给出结果，后台取消和资源清理有明确所有者，不用进程退出冒充清理成功 |

候选提交只做已准备状态的交接，之后才通知、建场景及资源。对于已返回的核心准备内部故障，取消也必须交回原会话裁决，不能通过丢弃候选解除冻结。普通取消的迟到结果不影响新局；旧写盘仍可以完成其文件，但不能改新局的未保存标记。

## 界面、命令与诊断

界面输入先解析为明确的命令值；提交时带所属活动绑定，宿主复核后经唯一核心入口执行。UI、控制台、自动测试只在来源标记上不同；拒绝不自动重试、不更换目标，也不撤销前一独立命令。界面可以据查询禁用明显不可用操作，但核心仍进行正式裁决。

市场显示核心返回的报价、可交易量、限制及现车损伤，标注报价不锁定。手动提交数量及整单最大付款／最低收款，自动规则提交逐件限价与显式顺序；不在 Godot 重算边际价格、需求、容量或部分成交。执行拒绝后保留用户输入、刷新当前报价并显示原因，不在新价格上悄悄重试；自有留货风险明确展示。自动执行的未完成原因和净现金流报告读取核心记录，不能拿通知历史重建经营账目。业务规则见[市场与交易](../design/19-markets-and-trading.md)。

每次 `Submit`／`Advance` 的事件只分发一次，保持核心顺序。通知策略在继续推进前执行，显示消费者不重新决定模拟结果；通知和战报不入权威存档，保留数量仍由测量决定。消费者异常单独诊断，不回滚成功命令；后续消费者仍应获得本次事件。遗漏的瞬时表现不能从当前状态猜回历史。

缺失内容、候选拒绝、核心冻结、文件失败和表现失败各自保留其所属模块错误码与定位，不制造统一全局错误枚举。界面负责可读文字，控制台／日志保留操作、阶段、会话、对象／包／文件／字段等已有资料；来源未知时明确未知，不猜包。缺失定义及被阻止的操作必须同时在游戏与控制台显示。

世界场景失败时关闭该场景并返回地图，保留核心和有效内容，玩家可以重新打开。编辑表现失败时保留现有编辑会话和工作草稿，关闭场景交互但允许捕获、保存与退出；重试表现不能新建一份空草稿。若会话本身已无法捕获，保留已有捕获和诊断并明确说明，不能把空数据保存成成功。无自动重试循环。具体用户可见规则见[场景切换](../design/08-window-and-ui.md#场景切换)。

## 显示帧、相机与输入

`Present` 的输入是实际显示帧，返回值只是待接入帧。先区分调用的 Failure／Faulted，以及 Success 内的 `Readiness.Failed`：三者都按故障入口处理，Failed 帧不能成为显示或拾取基准。正常帧先检查 Base／绑定和完整资源依赖，再在不被渲染观察到中间状态的阶段应用整个更新；成功才替换 displayedFrame。资源尚在准备时保留上一完整帧；明确准备失败或实际接入异常则立即隐藏并停止该场景交互，按故障入口处理，不能展示半帧或把它记为成功。

浮动原点变化同步作用于现存根、相机焦点和跟随状态；新 Upserts 已在新坐标中，不重复平移。空间变化时不直接插值旧空间位置。相机跟随取 `FindPose`，节点自由环绕用 `NodePanBounds` 限制水平焦点；还没有范围就不平移。防穿地形查询用同帧 `TerrainHeight`，不能用下一帧未显示的高度约束当前画面。

坐标与[体素契约](scenes.md#坐标与身份)一致：一格为一个 Godot 单位，物理意义是 0.5 米。SceneMesh 和 Pose 不再乘 0.5；GLB 原始米坐标统一乘 2，随后使用体素给定的格放置及朝向，不重新适配尺寸。保持 +X 右、+Y 上、+Z 为内容正面；Godot 相机自身的朝前轴不改写内容约定。体素三角形从外侧看逆时针，转换 Godot 网格时交换两个索引，法线保持外向。引擎绕序依据 [ArrayMesh](https://docs.godotengine.org/en/4.7/classes/class_arraymesh.html)。

鼠标射线从当前相机换入 displayedFrame 根空间后调用 `Pick`；命中再由 `Resolve` 核对当前目标。UI 遮挡处不发世界选择，NotReady 不能当作空地穿透。铁路、水面和粒子不新增引擎物理拾取旁路。编辑命中另外核对编辑会话及修订；模板预览按固定表单修订使用返回下标。按住拖动时，UI 将明确采样到的格交给体素编辑操作，不在 Godot 重写占格、锁定或撤销规则。

## 运行资源与退役

所有纹理、模型、网格、材质、离屏视口、粒子及引擎对象由 Godot 持有，创建、场景树接入和最终释放在主线程协调。缓存按资产修订及用途区分，不能只按路径缓存；调用 `FindAsset` 使用固定世代的同一份原字节，不能重读磁盘。检查用的临时场景、解码对象和缓存也要清理，但候选取消不能删掉活动组共用的资源。

渲染接入包括 SceneVertex 的贴图、面内坐标、外露边、相对高度、损伤等通道，以及模型的相对高度平面、涂装、灯光与效果；不能因消费样例只展示位置／法线／UV，就省略其余表现数据。内置材质、着色器、磨损图案、天空、粒子、轮对和缺失标记是本模块资源，不塞进 Mod 契约。

体素网格及帧是普通不可变值，Godot 可保留引用；上传后不要求体素归还或复用缓冲。运动只改姿态，浮动原点只移根，尽量复用已有几何。旧显示组失去交互资格后，从场景树分离并释放它独占的运行资源；共享资源等所有使用者结束再释放。异步关闭必须被宿主观察其完成与异常，但不能阻止新活动组继续模拟。

车辆、炮塔、生物、持续烟火和一次性特效按 `ISceneFrame.SimulationSeconds` 推进，暂停时固定，不能用 Godot 自动真实时间播放绕过暂停。世界特效的闪烁仍遵守真实时间上限；相机和 UI 动画可以使用真实时间。效果身份用于防止同一资源准备重试重复播放；不补演场景未观察期间的旧效果。

复合体图标使用 `FindGood`／`FindDesign` 的固定设计，以 `OpenEditor` 和 `Present` 取得只读展示所需网格，再在离屏视口渲染。图标会话不接收编辑操作，不触发玩家编辑暂停；它不是一个已打开的玩家编辑窗口。缓存键是设计哈希及内容世代，完成后关闭会话，像素只存内存。模板空间预览使用 `PreviewTemplate`，不由 Godot 遍历蓝图生成布局。

## 存档、录制与单文件写入

路径及格式沿用[存档设计](../design/09-persistence.md#文件身份与写入)：`user://saves/<UUID>/save.json`，单 JSON、头部先写，当前格式从版本 6 开始；自动存档为每局 3 个独立轮换位置。头部摘要从同一捕获边界取得。核心及内容各自 `Encode`／`Decode`，宿主只组合容器、头部和公开引用，不把字符串重新解释为业务字段；外层字段编码在实现时落实并与存档版本一起管理，不影响模块载荷归属。

普通保存先短暂固定完整组、公开引用及各自修订，后台只编码捕获。成功仅确认捕获版本；同会话和同目标串行，自动请求只合并一个待捕获请求。保存／另存为／导出／导入的身份及离开保护不在这里另定，见[一致捕获](transactions.md#一致捕获与文件写入)。外部草稿由内容编码后写 `user://authoring-drafts/`，用户蓝图由 `RequiredWrites` 指定内容写入 `user://content-library/`；目标成功后才接入对应内容候选或确认保存修订。

单文件写入在目标同目录创建唯一临时文件，写完整、关闭并按目标格式校验后，最后检查取消，再替换目标；失败保留原有效目标。替换后的清理失败另报，不把已成功写入改称取消。每种可写目标只有一个宿主写入者；文件占用等预期 I/O 失败明确返回。发布阶段不能被新会话或关闭操作悄悄丢弃。具体 .NET／Windows 调用及持久性须用真实文件系统验证，不能以纯协调替身证明。

录制内容按 `ReadRecording` 的公开清单绑定历史内容；同一核心输入可能对应多个持久修订，不能提前丢掉实例模板副本。写出新起点及全部依赖后才 `ConfirmRecordingStart`，失败不裁旧证据。复现 ZIP 的内容、命令和检查点组成沿用[录制规则](../design/04-deterministic-simulation.md#录制与复现)，导出不读取变化中的安装目录补齐历史。

## 整包发布与恢复

此路径只用于开发构建的创作模式。玩家保存蓝图、保存草稿和改装不走整包发布。有效包位置不变：明确可写的开发 `builtin/core`，或本地 `user://mods/<目录>`；导出内置 PCK 不可写。操作使用本地同卷目录，不用跨卷复制伪装最终改名；不满足这些条件就明确拒绝。

每个可写包所在父目录放一个保留的 `.train-publish/`，宿主在枚举包之前排除它。该目录内以目标目录名建立发布位置，保存 `publish.json`、完整 `candidate/` 和改名后保留的完整 `old/`；目录名只是恢复定位，包身份仍来自 manifest。发布权使用此位置内一个由宿主持有独占文件句柄的锁文件，同一目标的第二个宿主明确报告忙；进程退出释放句柄，残留锁文件本身不表示仍有持有者。多个目标可以各有记录，不互相清理。所有恢复路径由登记的包根与合法相对名拼成，不执行记录里的任意绝对路径。

发布记录是宿主内部 JSON，包含独立 `formatVersion`、操作 ID、目标目录与包 ID、源基准、旧／新目录项清单和每个文件的 SHA-256、阶段（Prepared／Completed）。清单包括未编辑文件和空目录；禁止链接。`PackageSourceVersion` 由完整规范清单及文件字节摘要形成，只在宿主解释，内容回传作基准。写记录也用同目录临时文件完整替换，不把不完整 JSON 当成某一默认阶段。

在[单一写入者约定](editing.md#创作模式整包发布)内执行：

1. 打开时固定完整来源快照。开始发布操作时先取得宿主发布权并处理该位置的未完成记录，全程持有到发布／恢复及清理结束；不能让另一个宿主改写 candidate 或记录。把来源快照复制到扫描范围之外的 candidate，应用 `PackageWritePlan`，保留所有未编辑文件；不覆盖有效包。草稿独立保留。
2. 候选内容、资产、依赖、核心适配及相关内存记录全部准备完成。依赖使用同一批固定输入；核心的可执行、拒绝、故障结果先分清，只有可提交结果才进入文件发布。
3. 完整复核源包仍等于打开基准，并核对本次依赖基准。复核至发布／恢复结束，外部编辑器和同步工具停止写同一个包；发布操作使用已固定依赖，不在末尾重新读取另一份输入。冲突保留草稿并拒绝，不自动合并。
4. 写好并校验 Prepared 记录，最后检查取消。进入不可取消阶段后，把有效目录改名为 old，再把 candidate 改名为有效目录。两个改名之间路径可能不存在，宿主禁止内容扫描经过这个阶段；不向外部观察者承诺目录连续存在。这不是一个原子的整目录替换。
5. 复核新有效目录与已校验候选完整清单一致，然后写 Completed。该记录是文件发布完成点；成功后只切换已经准备好的内存组。Completed 写入失败按未完成处理并恢复旧包；恢复也失败就禁止扫描、保留材料并明确报告。
6. 完成后清理 old 及不再需要的材料，最后删除记录。清理失败保留 Completed，下一次启动按已完成发布核验和继续清理，不改称发布失败。未知记录版本、损坏记录或无法确认的目录不自动删除。

Windows 的目录改名要求同卷，`MoveFileEx` 的替换选项也不能覆盖已有目录，见 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)。本方案用记录覆盖两个改名之间的进程中断，不宣称多文件原子性或突然断电的绝对持久性。锁文件只协调遵循协议的宿主，不能强制阻止任意外部编辑器改子文件；这是已确认的范围限制。

启动或下一次打开相关包时，先取得同一发布权、停止扫描，再按记录恢复：

| 可核验状态 | 处理 |
| --- | --- |
| Prepared，旧包仍在有效路径且符合旧清单 | 保留旧包，清理未发布候选与记录；不把候选当成成功 |
| Prepared，old 完整，候选尚在或已改到有效路径 | 验证有效路径若存在只包含已知新包，再移开新包、把 old 恢复并验证；不覆盖未知外部文件 |
| Completed，新有效包完整且与已校验清单一致 | 使用新包，继续清理；包括写盘完成、尚未切换内存就中断的情况 |
| 清单、记录或目录不能确认，恢复失败 | 停用该包，游戏与控制台报错，保留全部材料；不加载混合文件，也不自动挑一个看似能用的版本 |

恢复移动新包时复用已空出的 candidate 位置；该位置已有不符材料就停止，不能覆盖。Prepared 时既没有原路径的旧包也没有完整 old，不能用新包冒充恢复成功。正常包扫描不删除没有记录的孤立材料。恢复之后仍经过内容模块的正式加载校验；包有效性不由文件清单取代。

宿主独立验证继续使用[统一测试入口](testing.md#模块测试的组织与入口)，目标为 `-Module godot -Correctness`，该选项及隔离装配尚未实现。测试目录只放 Godot 的同一份生产宿主／渲染／UI、三个契约、有限情景替身及必要资源；不提供其他模块实现。真实装配也须在正常构建编译，不能靠隔离装配隐藏不兼容。

| 验证层次 | 必须覆盖的结果 |
| --- | --- |
| 可编译调用 | 三工厂和内容端口可装配，固定视图查询、逐步事件接入、显示基准、网格与纹理 API 可组合 |
| 宿主协调与输入 | 第 2 步触发暂停后不执行第 3 步；降速不解除暂停；失焦恢复不清其他暂停；旧绑定输入、取消结果和旧保存完成不能影响新局 |
| 真实 Godot | PNG／GLB 元数据、Keep File 的 PCK 及 Mod 读取；网格绕序、材料通道、原点移动、相机范围、同帧拾取、暂停特效、整帧更新和资源退役；必要视觉检查使用真实渲染窗口，headless 启动不能证明画面 |
| 真实 Windows I/O | 占用／权限／超限／链接、发布前来源冲突；各持久阶段进程中断及恢复；无混合包、未知材料保留、保存身份不被迟到写盘改变；用独立测试目录，不操作正常用户数据 |
| 完整联调及测量 | 四个真实模块、完整容器往返和复现、标准 Demo 负载、8×／60 FPS、长测与人工验收；不由契约样例替代 |

异步检查用可控完成顺序，不靠睡眠或随机竞争。测试专用违规替身只检验宿主防御，不能当作生产接口的允许行为。外部写入者违反已约定的独占使用范围不作为强一致性验收承诺；能够检测到的冲突仍须保留材料并报告。
