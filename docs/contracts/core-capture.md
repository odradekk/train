# 核心模拟层：状态捕获与编码

本页记录状态捕获与编码，与[契约目录](core.md)一起使用。

## 捕获、编码与录制

`Capture(Save)` 只捕获完整边界并拒绝冻结会话；`Capture(Diagnostic)` 用于故障资料。捕获返回持久修订、位置、输入身份、引用清单、检查点和不透明载荷，后台只对它调用 `Encode()`。宿主组合内容与元数据，不遍历内部状态。持久修订覆盖核心可保存变化，不被仅有位置的比较替代；内容与存档元数据修订仍分别由其所有者管理。

人口状态保存精确执行参数、有效进度、累计应需与满足量、按货物身份保留的消费剩余量、人口变化余量、短缺与可用性状态及最近一次结算；普通恢复和严格重放使用同一份生产推进。当前规则缺失或本期必需货物缺失时停用人口，保留这些状态；新局仍须有有效规则。燃料余量必须为有限非负数，新局为零，保存、恢复、检查点、严格重放及内容发布保留其电量，不反推已消费燃料。生产状态保存完整冻结批次、输出缓冲和上一步工作、供电与劳动分配结果；解码拒绝非有限或负的实际劳动占用，以及非法进度、系数、数量、排序、设施行与已有计划的建筑／能力配对不一致，及同时存在批次与缓冲。批次流程可以与当前计划流程不同。诊断消息和堆栈不进入载荷。内部字段布局由编码器维护，宿主只通过公开契约取得所需资料。

格式 8 的聚居地模板副本保存 `platform_length_meters`；站台段 P 在建立聚居地时就已固定，不随源模板变化重算。

格式 14 的 `WorldState.ConstructionJobs`（`construction_jobs`）保存活动任务，`Next.Job`（`next.job`）保存下一任务编号；任务包括设施、聚居地、目标设计／修理车辆、优先级、规则身份与启动修订、冻结总工作量和电力／劳动系数、投入及实际来源消费、进度、主状态、上一步工作速率、限制及阻塞。每座聚居地保存 `LastConstructionPowerDemand`、`LastConstructionActualSupply`、`LastConstructionAllocatedLabor`（线格式为对应 snake_case 字段），即使本步最后一个任务完成并移除，也保留最后一步汇总，下一无请求步骤归零。这些状态参加捕获、校验、恢复、引用、检查点与严格重放。格式 15 在任务中增加 `Funding`（`funding`），世界增加 `UnassignedServicePayments`（`unassigned_service_payments`）；NPC 队列由活动任务的设施与编号派生，不另存队列，后继排队任务必须进度为零。

格式 16 将任务目标车辆统一保存为 `Vehicle`（`vehicle`），并保存 `Kind`、`RetainedParts`、`RemovedItems`、`ReturnInventory`（对应 snake_case 字段）。实例在完工前保留原设计，不另存原设计或锁。返还库存中的预留按任务编号唯一保存 `ExpectedReturns` 与容量；任务和预留严格双向配对，无预计返还不建预留。自有任务的返还库存必须是设施所在自有聚居地库存，委托任务则必须是该聚居地的玩家租库；已有预留不因租约到期或冻结失效。解码检查任务种类、玩家实例和唯一锁目标、保留与移除部件引用及不重叠、合法暂停与零工作量，以及库存预留配对。冻结移除项的货物、结构货物和缺失定义进入引用清单；上述资料均参加普通捕获、恢复、检查点与严格重放。

格式 19 用可空 `Instance`（`instance`，`vehicle` 或 `building`）取代 `Vehicle`，并增加可空 `Plot`（`plot`）。有地块且无实例的任务是建筑建造；有实例的是既有车辆或建筑；二者皆无且设计为大型设备时，目标为 `NewAssembly`，否则为新车辆。工地由建造任务的地块派生，不另存。建筑身份在完工时分配。大型设备的返还库存必须是设施所在自有库存，预留一件成品。


格式 21 增加 `railway_jobs` 与 `automatic_rail_repairs`。任务保存编号、线路、种类、可空断点、材料来源、冻结工期、已用步数、已投入货物和阻塞；不保存轨号、规则身份或修订。世界铁路规则仍是 `WorldSummary.RailwayRule`。自动修复按线路编号排序，来源为玩家聚居地。已投入 Rail 进入引用清单，路径为 `World.RailwayJobs[<编号>].InvestedGoods`。保存的线路 `works` 仍必须为空。这些状态参加捕获、校验、恢复、引用、检查点与严格重放。

格式 22 增加 `creature_groups`、`next.creature` 和 `next.creature_group`。格式 23 增加每座聚居地的 `morale` 和 `surrendered`。生物群保存编号、可空聚落、地点、方向、活动、活动开始步、可空目标和成员；成员保存编号、定义和生命。每个聚落最多一个 `Guarding` 群。没有聚落的群只能游荡、战斗或撤退，且没有目标。线路战斗里的列车和车辆只需在同一条边上，生物必须停在战斗距离上。生物定义引用的路径是 `World.CreatureGroups[<群>].Creatures[<生物>].Definition`。这些状态参加捕获、校验、恢复、引用、检查点与严格重放。

顶层载荷包含格式版本、位置、下一命令编号、修订、当前输入身份、故障、`world` 和 `references`。`world` 保存完整生成来源 `source`（含种子、生成器版本、生成内容语义修订、解析配置及开局输入）、图与资源、聚居地与生物聚落、聚居地模板业务副本和地块、实例耐久、列车、战斗、库存、资金、全部下一身份编号，以及实际设计投影和衍生货物。实例只保存 `DesignHash`，引用同一 `world.designs` 中的投影，不在每个实例重复设计。实例和库存位置由所有者派生，不进载荷。

铁路新增权威字段全部进入捕获、检查点和解码一致性检查：列车的唯一 `position`（节点或线路、轨号、方向、中心距离）、`activity`、`speed_meters_per_second`、`plan`、`next_stop_index`、`remaining_dwell_steps`、`stop_requested`、`engagement` 和可空 `retreat_destination`，以及节点位置内的进入线路及铁轨、下一线路及铁轨、阶段、节点距离、预约站台号与正反标记；聚居地的 `parked_vehicles` 是未编组车辆的唯一停放归属，`engagement` 保存其交战规则。成员、库存所有者和下一身份编号沿用原世界状态。解码检查位置范围、节点/线路变体及节点阶段、距离和预约一致、活动与速度及计划进度匹配、暂停停留余时、停车请求与当前阶段相容、计划目标存在、Station 货物规则合法且同站货物唯一、循环不退化，以及车辆与列车或停放清单的双向唯一归属。有计划但已完成的列车，只允许活动为 `Stopped`，或活动为 `Running` 且 `stop_requested = true`；后一种情况覆盖出站、线路行驶和下一节点进站，不按位置变体枚举。撤退目的地只在撤退中出现，必须是现存节点。能力、Blockers 和预测距离均为查询派生，不增加持久副本。

#311 另外保存 `TrainState.QueueEnteredStep`（首次排队步）、`WorldState.TrackHandoffs`（线路、轨号、交让方向）、`WorldIdentities.Break`（下一断点编号）和 `TrainState.ReturningFromBreak`（实际掉头所对应的断点）；线格式分别为 `queue_entered_step`、`track_handoffs`、`next.break`、`returning_from_break`，可空或空集合也必须出现。已有 `EdgeMapItem.Breaks` 保存断点。四项及断点、编组方向全部参加捕获、检查点和严格重放。方向锁与站台占用按上述规则派生，不增加权威副本。

解码要求交让按线路、轨号排序唯一，方向有效且指向现有空轨；断点按编号排序，编号全世界唯一非零且小于 `next.break`，轨号存在、距离有限且在线路范围内。同轨列车须同向；不另作全量同轨间距校验。排队步非空只允许合法的节点等待站台或出口等待铁轨状态，不晚于捕获的已完成步号，可保留合法 Station 停留余时；返程标记非空只允许线路上的 `Running`，且对应断点属于同轨。保存的线路 `Works` 必须为空。进行中的扩建与修复只保存在 `railway_jobs`，自动修复来源保存在 `automatic_rail_repairs`；地图、`FindEdge` 和 `WorldSummary` 查询时由任务算出 `Works`。修复任务的轨号取断点轨号；加轨任务的轨号为 `Tracks + 1 + 同一条边上编号更小的进行中加轨任务数`。未开工只表示为阻塞非空，且投入为空、已用步数和冻结工期均为 0。阻塞码只允许 `insufficient_goods`、`content_missing`、`object_missing`、`not_owned`，字段非空，相关身份已给出。未开工任务所在的边必须有自动修复设置，且来源与任务相同。已开工任务阻塞为空，冻结工期为正，已用步数小于冻结工期，已用步数不晚于捕获的已完成步数，投入恰好一种数量为正的货物；解码不辨认该货物是不是 Rail。加轨任务必须已开工且断点为空，进行中的加轨数加上现有轨数不超过上限。修复任务的断点必须在该边，每个断点至多一个任务。来源必须是玩家聚居地。`Next.Job` 必须大于施工、建城和铁路任务编号。

`world.definition_dependencies` 保存当前世界使用的规则、类型及流程等外部依赖身份和字段路径，在生成时建立、接受内容发布时按候选重算，使无内容解码仍能重建引用；它不是冻结执行参数。顶层 `references` 是交接清单，生成候选、捕获及恢复候选都由同一 [WorldReferences](../../Core/World/WorldReferences.cs) 从状态计算。`Templates` 按最终聚居地所有者排序且唯一，包含源模板和本地地块号／尺寸；`Designs`、`Definitions` 覆盖实际依赖，`Inputs` 使用对应候选或捕获的当前输入身份。新局缺少所需投影即配置失败，成功候选没有缺失项。

检查点包含位置、下一命令编号、故障全部字段及全部 `world` 字段；修订和当前输入身份仍在检查点之外，生成内容语义修订作为世界来源的一部分保留。文本对 UTF-8 求 SHA-256，取大写十六进制。捕获、引用和检查点在会话推进及释放后仍有效。

`DecodeState` 不做内容适配，保留保存时的身份、位置、修订、引用和检查点；`Encode()` 按状态重新规范编码，编码器产生的规范载荷往返后逐字节相同。确认格式版本受支持之前的错误返回 `unsupported_format`：JSON 无法解析、根不是对象、缺少版本、版本不是无符号整数或版本不受支持，定位到根或版本字段。确认版本受支持后，字段缺失、多余、重复、类型、范围或身份格式错误返回带字段路径的 `invalid_state`；`world` 必须是完整世界对象，不能为 `null`。世界校验还检查有限连续量、规范集合顺序、唯一身份、图及所有者引用、模板地块和实例设计配对、下一身份编号大于现存最大编号，以及顶层引用清单与状态一致。不要求保存时的生成器版本仍可用于新局；解码及恢复不重新生成世界。后续领域一致性检查随领域实现补入。

`PrepareRestore` 使用调用方固定的当前投影。身份相同则适配报告为空；身份不同时候选改用当前输入身份，报告恰好一条 `CoreProblem("content_changed", "InputIdentity", null, [旧身份, 新身份])`。两种情况都保留修订、下一命令编号及世界业务状态，不重新生成世界或重算人口进度与余量；节点内列车的位置与速度按当前节点尺度和限速适配：静止在 W、S 的列车移到新对应点，`Departing` 且活动为 `Waiting`、已有 `QueueEnteredStep` 的列车移到新 L，其他 `Departing` 列车及行驶中的列车保留距离并截到新 L 内，不依赖旧内容投影；进站越过新 S 及限速变化的处理同上文铁路规则。#382 在独立候选中按当前人口规则更新该规则的货物依赖，冻结期和物理余量仍保留原引用；同投影且依赖未变时检查点不变，依赖发生变化时新清单随候选捕获保存。候选 `References.Inputs` 使用候选身份。`MissingReferences` 按传入投影中已知缺失标注及字段路径产生，也识别当前人口规则与其实际必需货物的缺失，不能等到激活后推进才发现未声明的人口依赖；不负责重新计算保存的初始世界。原捕获不变。普通保存或普通恢复遇到故障返回 `Failure(frozen, "Fault")`，诊断载荷仍可解码；外部自行实现的 `ICoreCapture` 传入恢复属于编程错误，抛 `ArgumentException`。

严格重放复用同一解码器，从捕获恢复完整世界和原输入身份，不走普通恢复的内容适配。测试覆盖公开新局创建、共享捕获情景、跨进程生成、保存恢复及生产重放路径；调度测试覆盖非默认排队、交让、断点编号及返程标记的捕获恢复、独立进程同后缀和断点命令严格重放，起点由生产捕获生成，没有另行提交起点载荷文件；#350 覆盖战斗进行中的捕获、恢复、检查点、严格重放、跨进程同后缀和畸形战斗状态拒绝。#298 的真实四模块交接仍待验证。
