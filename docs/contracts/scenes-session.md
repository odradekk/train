# 体素引擎：世界会话与输入

本页记录世界会话与输入，与[契约目录](scenes.md)一起使用。

## 公开面与责任

声明项目为 [Train.Scenes.Contracts](../../Contracts/Scenes/Train.Scenes.Contracts.csproj)，只引用核心和内容契约。

| 声明 | 调用方使用的内容 |
| --- | --- |
| [Values.cs](../../Contracts/Scenes/Values.cs) | 运行身份、坐标、结果、诊断与命中 |
| [World.cs](../../Contracts/Scenes/World.cs) | 工厂、世界快照、观察目标与场景会话 |
| [Rendering.cs](../../Contracts/Scenes/Rendering.cs) | 不可变显示帧、增量、网格、实例和特效 |
| [Streaming.cs](../../Contracts/Scenes/Streaming.cs) | 可选流式记录观察器、构建尝试身份与固定地形覆盖查询 |
| [Editing.cs](../../Contracts/Scenes/Editing.cs) | 编辑修订、操作、预览、选取、撤销与固定快照 |
| [Authoring.cs](../../Contracts/Scenes/Authoring.cs) | 只读设计预览、固定聚居地模板的空间预览与地块拾取 |

实现程序集只公开 `Train.Scenes.ScenesFactory.Create(ISceneStreamingObserver? observer = null)`，返回 `IScenesFactory`；其余实现类型为 internal。Godot 的 `App/Composition/` 调用真实工厂，其他代码只接收契约。体素实现负责地形与铁路生成、网格与遮面、对象姿态、逐格拾取、编辑动作及内部任务；不把区块、中心线算法、重建队列、线程池或缓存策略交给宿主配置。

核心负责世界规则，内容负责设计计算、外观定义与资产原始字节。Godot 负责输入、相机控制、界面覆盖层、文件、日志和真实渲染资源；它不遍历设计布局生成场景，也不计算设计哈希、部件编号或路线。宏观地图与管理面板可直接读取核心，场景接口不是这些查询的中转层。

## 可选流式记录

流式记录声明见 [Streaming.cs](../../Contracts/Scenes/Streaming.cs)，变更经 [#740 用户决定](https://github.com/odradekk/train/issues/740#issuecomment-6378866039)确认。正常游戏向工厂传 null；测量宿主才传入观察器。记录不改变场景调度、帧内容或接入资格，Scenes 不负责读时钟、写文件或统计。

`SceneStreamingSceneId` 区分会话以及同一地点并存的活动、候选、后继场景。创建时发出 `Opened`，候选角色为 `Candidate`；晋升活动时保留同一身份并发出 `Activated`，候选取消按关闭发出 `Closed`。部件类型区分线路分段、节点准备任务、节点地形、节点轨道和节点边界；`Key` 是不透明身份，调用方只比较相等，不解析。取消后重建增加尝试编号，迟到结果仍关联旧尝试。

`Changed` 的 `Needed`／`DemandEnded` 表示进入／离开需求范围；`Queued` 表示入队（线路是提交线程池）；`Started`／`Built` 表示任务体开始／几何完成；缓存复用发出 `CacheHit`，不补造构建阶段；`Admitted` 表示获准接入，`Objects` 提供该部件的对象 ID，供宿主关联资源准备和提交；其他阶段的 `Objects` 为空。`Cancelled`／`Failed` 分别表示取消／失败。取消后迟到的 `Built` 可以继续被记录，但不恢复接入资格。

`Started` 和 `Built` 在构建任务体内由 worker 线程发出，其他事件在发生处的线程发出；不承诺跨线程的全局顺序。观察器必须线程安全、不阻塞、不抛异常，并在回调入口自行读取单调时钟；不能在回调中重入场景操作或执行文件 I/O。

每个世界场景帧（包括 `PresentCandidate` 返回的候选更新帧）在返回调用方之前通过 `SceneStreamingScope.Frame` 发出一条 `Frame`，`Stamp` 对应该帧，`Parts` 列出帧中实际接入的构建尝试，包括保留对象所属的尝试；不只列本次新增。移除由相邻帧的集合差推出，不增设退役阶段。`Coverage` 为 null 表示布局尚未准备好；非 null 时绑定该帧固定的布局与 Origin，只读且可在后续更新、晋升或 `Closed` 后继续查询。调用方释放引用即可，不需要归还。

`FindTerrainParts(x, z)` 接受对应帧根局部 X、Z 格坐标，与该帧 `TerrainHeight` 使用相同坐标；输入必须有限。返回预期地面所属部件，不受其需求、构建或显示进度影响；空数组明确表示在生成器预期地面域之外。线路按生成器实际体素列判断，包括弯道和端点；同一列中的点归属一致。所有返回集合不可为 default。查询只供测量使用，不能由缺少地形反推该点必在预期域内。宿主测量只保留已提交帧和当前准备帧的查询对象，不逐帧累积布局。

共享支持见 [StreamingScenario.cs](../../Tests/ContractSupport/Scenes/StreamingScenario.cs)：观察器可接收并发回调，固定覆盖替身只接受显式配置的点（配置空数组表示域外，未配置则失败）；`AssertFrameMatches` 可由真实实现和替身共用，检查帧与场景／尝试身份对应。实际构建线程、缓存、取消与迟到完成仍由 Scenes 受控构建用例验证，替身自测不代替生产证据。

## 坐标与身份

- 场景以格为单位，一格 0.5 米、一个 Godot 单位；`+X` 右、`+Y` 上、`+Z` 前。核心长度仍是米，换算只发生在表现边界。格 `(x,y,z)` 占据 `[x,x+1] × [y,y+1] × [z,z+1]`；正交朝向绕格中心旋转。
- `ScenePoint` 为当前节点或线路空间中尚未减浮动原点的双精度坐标，不是宏观地图坐标。`ISceneFrame.Origin` 与单精度显示坐标相加才得到该空间内的位置。不同 `Space` 不能直接相减。
- `ScenePose` 为单位四元数及平移，无缩放或剪切；根相对该帧浮动原点，子对象相对父对象。所有向量和标量有限；射线方向归一化，长度为正；集合不可为 default。
- `SceneBinding` 由宿主在运行会话或有效内容更换时重新分配，不是存档 UUID。`SceneSessionId` 由体素创建；同一绑定可以关闭后重开场景，产生新的会话身份，二者不是一一对应。`SceneRequestId` 区分显式观察请求，`SceneSpaceId` 区分节点、线路及编辑空间；这些都是运行身份，不入权威存档。
- 帧修订在会话内单调增加；对象、效果身份在会话内不复用。稳定对象更新继续使用原 ID，不以重建批次冒充业务身份。`WorldObjectId`、设计、部件及内容身份沿用各自契约。

宿主传入的 `SceneWorldSnapshot` 来自同一完整边界，核心 `InputIdentity` 与内容 `Core.Identity` 相同。同一有效世代中，本局已保存草稿或新聚居地模板副本可以增加 `PersistentRevision`；只要业务输入及世代仍匹配，就能交入新的固定视图。体素不得把不同边界查询拼成一次快照。OpenWorld 在创建前检查初始核心视图与内容业务输入身份，不匹配时抛 ArgumentException，不创建会话。

生物按核心查询或本次事件的 `Definition`，从配对固定内容视图的 `FindCreature` 取得当前种类外观；核心不提供生物设计哈希。生物死亡后的瞬时表现也按事件保留的种类解释，不要求死亡个体仍在查询结果中。车辆和建筑仍按实例或事件中的设计身份取得对应布局。

## 世界场景会话

一次调用顺序如下：

1. `OpenWorld(binding, snapshot)` 轻量创建，不等待场景生成。随后 `RequestView` 选择地点、指定列车中的车辆或战斗。地点可含线路弧长，用作初始观察中心；不是要求生成一个单独世界位置。跟随车辆必须属于指定列车。
2. 宿主在命令或模拟完成后串行 `Observe(snapshot, newEvents)`，交入本次新事件。它不触发同步大场景构建，也不接受倒退的模拟位置。事件必须有序、不重复，且不晚于输入边界。绑定、内容世代或业务输入身份不匹配、模拟位置倒退以及事件乱序、重复或超出边界均违反接口前提，必须在接入前检查并抛出 ArgumentException，保留原输入，不返回业务失败码。
3. 体素自行安排首次构建、线路分段与至多一个下一场景预建。宿主逐显示帧调用 `Present`，取得当前可显示部分、加载状态与诊断；核心继续推进，不等待构建。
4. Godot 准备最新帧需要的资产与资源，在帧之间完整应用资源更新，成功后才把它记为网格基准帧。以 D 请求的准备期间旧几何按最新帧更新姿态，相机和拾取也使用最新帧；传 null 时旧画面和相机保持不变直到提交，样本仍使用 D；下一次 `Present` 的网格基准仍是最后完整接入帧，具体限制见[Godot 契约](godot.md#显示帧相机与输入)。
5. 观察目标切换调用 `RequestView`。新目标无效时返回 Failure，旧请求保持；成功产生新身份，即便目标值相同也使旧请求失去接入资格。跟随中的边、节点切换由体素处理，不要求宿主发区块命令。
6. 不再显示或活动绑定更换时关闭会话。`DisposeAsync` 调用即撤销输入与交互资格，然后等待内部任务退出；可先打开新会话，不能为了旧任务退出暂停新核心。

会话变更操作在宿主同一协调线程串行调用，禁止并发和重入；`DisposeAsync` 的等待不占用该线程执行构建。体素工作线程只读已固定输入，完成后由 `Present` 接入。普通模拟推进不废弃所有在建工作：体素核对依赖，补齐当前损伤、对象存在性、设计及铁路变化，必要时只重建受影响部分。取消、关闭或跨绑定的迟到结果只能丢弃，不能复活已删除对象或旧拾取。

`Loading` 表示目标尚无可显示内容，`Partial` 表示部分空间未就绪，`Ready` 仅表示当前需要范围内的 L0 精确地形、轨道和实例完整；可见远景不参与就绪判定，`Failed` 表示目标构建失败。未就绪区域显式列在 `FoggedRegions`，不能伪装成空地。一次 Present 返回 Faulted 时宿主报告表现故障并停止该会话的交互，不回滚或冻结核心；可重开场景。正常目标消失通过 `target_missing` 报告，宿主按相机规则选择下一目标。

节点打开后建立聚居地时，替换场景满足近处必要 L0 即接替，不等待远景。瓦片按实际读取的生成输入复用，布局影响范围外已显示的远景在交接时继续显示；输入变化的旧瓦片也保留到新瓦片或完整 L1 组接替显示。静态 L0 生成域在精确地形和远景均未显示时保留构建雾。该交接条件不改变活动帧 Ready 仅计 L0 的规则。新生成的远景须留出小幅净空，严格低于同一输入的 L0 顶面；高度变化后的重建期间允许旧远景暂时高出新 L0，直到替换显示，见[设计 01](../design/01-voxel-engine-and-scenes.md#远景地形)。

跟随切换遵守[场景切换](../design/01-voxel-engine-and-scenes.md#跟随列车时的场景切换)：依次经过线路、节点、线路，不跳过节点；不知道下一线路就不猜，预建来不及用雾收住。核心公开世界种子、所选铁路规则、节点进入/下一线路与编组正反，详见[核心查询](core-queries.md#读视图查询与事件)。更换有效内容时重开场景会话；实现可共享未变化的不可变几何，仍须只重建受影响对象和区块，不能把重开理解为一律重算整个场景。
