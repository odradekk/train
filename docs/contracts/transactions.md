# 存档、内容发布与会话切换

本协议由[存档、内容发布与会话切换的跨层事务](https://github.com/odradekk/train/issues/284)的 Q1–Q25 确认，落实[模块责任与类型归属](README.md)。它规定调用方可依赖的时序、身份、所有权和失败结果，不规定模块内部状态布局，也不新增通用事务框架。

这是目标契约，尚无对应的可编译声明或产品实现。四份模块接口、调用原型、独立模块测试、真实文件与 Godot 验证仍由后续任务交付；本文的时序和算例不是这些测试已经通过的证据。

业务规则的唯一来源仍是[内容](../design/02-definitions-and-content.md)、[确定性与录制](../design/04-deterministic-simulation.md)、[存档](../design/09-persistence.md)、[人口](../design/18-population-and-labor.md#内容缺失与更新)和[市场](../design/19-markets-and-trading.md#内容更新与恢复)。本页引用规则，不重新定义消费、定价、设计计算或生产算法。

## 公开责任

| 模块 | 对调用方承担的责任 | 不交给调用方的工作 |
| --- | --- | --- |
| 核心 | 捕获、编码与读取核心载荷；声明所需引用；校验和适配候选核心状态；提供命令结果、记录、检查点及持久状态修订 | 内部字段布局、状态遍历、规则执行与适配算法 |
| 内容 | 捕获和恢复内嵌内容；根据引用补齐所需设计与模板；固定候选定义和资产字节；提供各层投影、内容修订、缺失与校验报告 | 包解析、依赖解析、设计哈希、部件编号和合法性计算 |
| 体素 | 根据配对的核心快照和内容构建场景，检查后台结果适用性，更新受影响部分，使旧拾取失效 | 宿主自行比较布局、重建场景或修改核心状态 |
| Godot 宿主 | 组装完整存档与复现包、文件访问、候选协调、技术操作锁、用户确认、活动组切换、结果接入和资源退役 | 读取其他模块内部字段、复制业务规则或把 Godot 类型带进下层 |

核心通过公开契约给出恢复和捕获需要的引用；内容通过公开契约补齐内容及投影。宿主不得解析核心内部 JSON 字段来推断实例设计、任务目标或冻结执行参数的引用。捕获须覆盖实例、在途任务、本局蓝图库、草稿及已有聚居地的模板等持久数据，不能只收集当前画面中的对象。可保存的草稿不等于可建造的设计；创作内容与运行必需引用分别校验。

## 活动组与身份

宿主持有一个活动组：活动核心会话、与它配对的内容和显示资料，以及对应的宿主绑定。这里的“组”是协调责任，不是第五个业务模块或要求统一各模块内部容器。

| 标识 | 作用 | 不能替代什么 |
| --- | --- | --- |
| 存档 UUID | 持久存档身份及保存目标 | 运行会话身份 |
| 运行会话身份 | 区分每次新建、读档和进入重放；同一存档重新打开也不同 | 核心实体 ID、确定性输入 |
| 操作标识与基准活动绑定 | 判断某次候选、保存或场景请求是否仍属于当前操作 | 内容语义身份、模拟位置 |
| 内容世代 | 区分有效内容的运行时发布版本 | 语义修订、资产修订或持久身份 |
| 模拟位置 | 确定核心命令与快照的完整边界 | 本局蓝图库、草稿及存档元数据的修订 |

运行会话身份、操作标识和绑定校验属于宿主协调；核心不为此引用内容契约中的世代类型。内容世代只在有效内容成功变化时递增，无变化和拒绝不递增。运行绑定标识不进入核心确定性状态。

提交候选、接入后台结果、处理保存完成时，必须核对所属操作、运行会话和所依赖的版本。失配的结果不得改绑到当前会话。特别是旧存档写完，不能清除新局的未保存标记或改变新局的存档 UUID。

## 准备、提交与放弃

```text
取得操作权 → 固定输入 → 校验引用、准备投影和状态适配
                                  │
                         必要的缺内容确认
                                  │
                       候选整体准备完成
                         ┌────────┴────────┐
                     失败／取消          统一提交
                         │                 │
                   放弃候选，保留旧组    通知、构建表现、退役旧组
```

1. 准备阶段不修改活动业务状态，不预先发布某个模块的新目录。所有正常可失败的解析、引用检查和适配先完成；准备结果绑定其基准输入，不要求调用方复刻模块内部检查。
2. 同一宿主一次只允许一个替换活动组的操作。重复请求明确报告忙，不隐式排队；用户可以先取消，再发起另一操作。已捕获快照的独立写盘不因此作废。
3. 候选固定所用定义和资产字节。缺内容确认只批准这一候选及其缺失清单，不成为全局忽略许可。重新扫描产生新候选；缺失情况改变须重新确认，确认后不能偷偷重读一批新文件。
4. 准备结果只能提交一次或放弃。提交前接受取消后即失去发布资格；后台计算可能尚未退出，迟到结果只能清理，不能发布。提交与取消由宿主串行裁决，提交后不再声称取消成功。
5. 内存提交只切换已经准备好的完整状态、内容绑定和相关记录，不执行文件读取、解析、业务适配或任意订阅回调。各模块不能先各自发布，最后再靠逐个回滚恢复一致。
6. 统一切换后再通知订阅者；通知失败单独报告，不撤销已完成的提交。旧组立即停止接收新请求，资源清理不得成为重新发布旧组的理由。

资产有效性检查属于准备；纹理、模型等 Godot 运行资源创建不成为发布条件，见[资产交接](README.md#表现资产的交接)。内容加载器仍可按该契约同步执行、不自行创建线程；后台调度与取消资格由宿主负责，不把逻辑取消解释成强制中止线程。

## 技术操作锁与线程

读档、替换当前对局、热重载期间，宿主在完整边界停止驱动模拟，禁止改变世界和本局内容的操作，但允许查询、显示进度和取消。技术操作锁不同于玩家暂停：玩家暂停通常仍允许命令，技术操作锁期间不接收这些修改。

- 正常失败或取消恢复原暂停／倍速设置，不累计或追赶等待期间的真实时间。
- 新游戏和普通读档成功后暂停；热重载成功后恢复原运行设置。
- 普通保存只锁住一致捕获，不锁后台写盘。
- 进入离开确认流程时停止可保存状态的变化；选择保存后保持锁直到成功再离开。失败或取消留在原局并恢复原设置；选择不保存才明确丢弃进度。
- 核心内部故障仍按冻结规则处理，不能以“恢复操作前设置”解除冻结。

核心驱动、命令接入和活动组提交在宿主的单一协调线程串行完成。后台工作使用固定的不可变输入，不直接调用活动会话的修改入口。具体引擎资源的线程约束由 Godot／体素接口说明；本协议不改变资产加载接口的同步语义。

## 一致捕获与文件写入

在一个完整边界同时固定核心状态、所需内嵌内容、外部引用信息和头部摘要。捕获不额外推进模拟；后台编码和写盘只使用捕获值，不重新查询正在运行的世界。

未保存判断覆盖核心、本局持久内容与存档元数据，各所有者公开自己的修订信息。仅比较模拟位置不够：暂停时修改蓝图库或草稿也可能需要保存。未提交的面板输入不自动进入存档；相机、面板及不入档的显示资源变化不制造未保存进度。

同一会话的保存／另存为串行，同一目标文件也只有一个写入者。手动冲突明确报告忙；自动保存最多保留一个待执行请求，轮到时重新捕获最新状态，所属会话离开后该请求失效，不积压旧快照。已经捕获的旧会话保存仍可完成其文件。

成功只证明捕获时点已保存，捕获后的修改继续标为未保存。“另存为”在文件发布成功且原运行会话、预期保存目标仍匹配时才切换 UUID；导出不改变 UUID，也不清除未保存标记。失败保留原有效文件和当前身份。

### 持久发布的不可取消阶段

单文件保存与复现包先写临时文件并校验，再发布目标。最后一次取消检查在最终文件发布之前；进入最终发布后，不再报告取消成功，而是报告文件发布结果。

对既要写文件又要发布当前内容的操作，校验、适配、相关内存记录及临时写入先准备完成。文件发布失败不切换内存；成功后完成预备好的内存切换，不追加正常可失败的业务工作。这是文件发布和内存发布的有序交接，不是跨进程分布式事务。

若进程在文件成功发布后、内存切换前崩溃，下次启动验证已发布文件，不承诺自动撤销磁盘更新，也不把遗留临时文件当成成功版本。不承诺突然断电后的绝对持久性或任意多文件原子性。创作模式的整包暂存、发布与恢复由[编辑器接口](https://github.com/odradekk/train/issues/285)和[宿主接口](https://github.com/odradekk/train/issues/290)落实；单文件保存验证不能证明包级发布安全。

## 新游戏、普通读档与严格复现

| 操作 | 输入与检查 | 成功后的状态 |
| --- | --- | --- |
| 新游戏 | 当前有效内容、生成配置和种子；必须有有效人口与市场规则；在候选中生成和验证世界 | 新运行会话及存档 UUID，暂停；不继承旧局录制或操作结果 |
| 普通读档 | 当前格式、内嵌内容、当前安装的外部定义；必要时确认占位，再完成状态适配与一致性检查 | 新运行会话，保持存档内部身份和模拟位置，暂停并报告适配 |
| 严格复现 | 原构建、语义内容、模拟配置和兼容环境；只用包内原输入；缺依赖或不可理解的记录拒绝 | 隔离重放会话，只执行记录；不接受外来的玩家／调试修改或安装目录热重载 |

进入重放也经过离开保护，候选成功才替换；Godot 不额外常驻原局供一键返回，同一时刻只驱动一个活动会话。允许观察、检查和把边界导出为普通存档；可编辑副本必须另按普通读档打开，不能把原重放直接解锁为编辑模式。核心重放本身仍能在无 Godot 环境独立测试。

保存格式、命令格式和契约基线仍各自管理；本协议不更改只读当前存档格式的策略，不实现旧版本迁移。

## 内容发布、拒绝与录制

| 操作结果 | 核心与内容的可观察结果 |
| --- | --- |
| 核心输入或其引用身份改变并成功提交 | 一条核心内容发布命令，状态适配、记录和对应内容一起生效 |
| 已进入核心入口后被正常拒绝 | 保留旧业务状态、内容与世代；命令编号、步内序号等按既有拒绝规则前进，保留拒绝记录 |
| 纯表现更新，核心输入及其引用身份不变 | 发布内容世代、记录观察信息，不消耗核心命令编号或改变核心检查点 |
| 有效内容完全没变 | 不发布，不增加世代，不生成核心命令 |
| 形成可提交候选之前的文件、解析、资产准备失败或取消 | 宿主诊断，保留原组；不伪造核心拒绝记录 |

混合玩法和表现变更仍然整组成功或失败；不能仅凭字段被称为“外观”就跳过核心输入及身份的比较。内容世代与运行操作标识不替代可复现的输入身份。

核心状态、命令结果与对应内存记录在同一完整边界生效。复现需要的新旧内容必须绑定记录并保留，不能在导出时靠重新读取安装目录补齐。录制持久化失败不倒退已发生的操作：保留旧有效证据、标明不完整与缺口；建立新可用起点只恢复之后的连续范围，不填平此前缺口，也不能提前裁掉旧证据。容量与裁剪数值仍待测量。

## 占位与状态适配

占位保留原始身份及可解释的状态，不删除部件记录、库存、未完成进度或余量。其无能力、不可使用／交易等业务行为按设计文档处理，不由宿主另算。不支持的格式或无法解释的状态仍然失败，玩家确认缺内容不能绕过它们。

热重载可原样保留或恢复已经由读档确认的缺失，允许部分恢复；不能让原有效的运行必需引用变为缺失，也不能借已有缺失新增非法运行状态。缺 A、B 时补回 A 可以发布；同时移除原有效 C 则整次拒绝。新内容包自身仍须通过自洽校验，不能因为世界已有占位就允许包带悬空引用。

人口的本期执行参数和仍需使用的引用也是权威状态，保存、读档、暂停、恢复与发布失败均按[人口更新规则](../design/18-population-and-labor.md#内容缺失与更新)处理。市场重评、现车名额、租约、已受理委托及历史账目按[市场更新规则](../design/19-markets-and-trading.md#内容更新与恢复)处理。适配只在候选中执行，未提交的适配不能提前扣货、结算人口、收费或归集报告。

## 场景接入与资源退役

提交不等待完整局部场景构建。提交前保留旧显示；提交时使旧场景的活动绑定、拾取及面板绑定失效。新表现未就绪时明确显示加载状态，不把旧画面当作新世界继续交互。纹理或场景创建在提交后失败时报告引擎／表现故障，不回滚核心、不静默换成 Cube 冒充成功。

同一会话和内容绑定下，普通模拟推进不自动使所有场景工作过期。体素层检查所依赖对象的适用性，补齐状态或重建受影响部分；已销毁的对象不能重新变成可操作对象。会话、内容绑定或场景请求不匹配则直接放弃，不能借追赶状态跨世代混用。普通场景构建不冻结核心等待；跟随场景的预建与雾中缺段仍沿用[局部场景规则](../design/01-voxel-engine-and-scenes.md#跟随列车时的场景切换)。

候选拥有准备资源，放弃时清理，提交后交给活动组；丢弃的资产检查结果包括为该候选准备的 Godot 内部缓存，不误删活动组仍使用的资源。旧组不再接收新请求，但待使用它的任务和明确借用结束后才退役相关资源。普通不可变返回值不会因切换而改变或失效；有期限的缓冲必须按具体接口声明释放责任。Godot 运行资源始终由 Godot 持有和释放，内容字节按不可变世代共享，见[资产生命周期](README.md#表现资产的交接)。

## 失败分类与验证矩阵

独立新建／读档候选失败不冻结旧局。当前核心已经受理的发布命令发生内部故障时，保留命令前业务状态与旧内容，按核心规则记录故障并冻结；不能恢复成可运行旧组来掩盖故障。宿主／内容准备异常、核心正常拒绝、核心内部故障、提交后的通知／表现故障须分别诊断，带操作、阶段、对象或字段定位，不建立全局错误枚举。

以下是后续验证要求，不是执行记录。各模块用公开接口验证自身承诺；宿主用可控完成顺序和失败情景验证协调，真实 I/O 与 Godot 行为另行验证。证据分类、替身责任和统一入口遵循[独立构建与契约验证](testing.md)。

| 情景 | 必须断言的外部结果 |
| --- | --- |
| 引用校验、资产检查或适配失败 | 旧业务数据及内容世代保留，无候选资源泄漏，无部分发布 |
| 缺内容确认后磁盘修改、重新扫描 | 原确认只用于原候选；新缺失清单不得沿用旧授权 |
| 取消 A，再打开同一 UUID 的 B，A 最后返回 | A 不能挂接场景、修改 B 的身份或清除 B 的未保存标记 |
| 核心拒绝与故障 | 拒绝保留业务状态但保留命令记录；核心故障冻结；独立读档失败不冻结旧局 |
| 纯表现发布与无变化重载 | 前者增加内容世代但核心检查点不变，后者两者都不变 |
| 暂停时改蓝图、写盘期间改草稿、旧局写盘迟到 | 捕获版本准确，后续修改仍未保存，旧完成通知不影响新局 |
| 最终文件发布前取消、发布失败、发布后取消 | 分别为取消且旧文件保留、失败且旧文件保留、成功而非伪取消；另存为身份只在有效成功后改变 |
| 录制落盘失败、起点轮换、复现导出失败 | 缺口明确，不提前裁剪旧证据，不回滚游戏或覆盖旧有效包 |
| 人口周期缩短／延长、零进度、期末消费 | 已开始一期按原参数完成，零进度用新参数，末次消费计入本期且只结算一次 |
| 非零消费及人口余量，旧期依赖缺失后恢复 | 原身份和数量无损；停用期间无需求或时间债务，恢复接续而不跳期 |
| 自动重评中途换间隔、停用后离站、现车上限降低 | 保留本轮剩余时间、不追做旧站交易、不刷新车辆或独立名额余额 |
| 租约参数／实际容量变化、已受理委托和运行报告恢复 | 旧合同不追价，入库不越过真实容量，已付金额和报告不重复结算 |
| 场景构建期间推进模拟、删除对象、切内容世代 | 同绑定补齐有效状态；旧实体不可操作；跨绑定结果弃用，核心不等待场景 |
| 提交后订阅者或运行资源创建失败 | 新权威组仍有效，报告故障并按所有权清理，不回滚或静默显示替代内容 |

## 后续接口的交付边界

[核心契约](https://github.com/odradekk/train/issues/287)与[内容契约](https://github.com/odradekk/train/issues/288)提供候选、引用声明、捕获、适配结果和记录的可编译公开操作；[体素契约](https://github.com/odradekk/train/issues/289)与[Godot 契约](https://github.com/odradekk/train/issues/290)落实版本配对、结果适用性、线程与资源交接。它们须实现本协议的语义，而不是要求宿主自行拼接模块内部事务。

本票不先造一套占位 C# 接口冒充成熟声明，不改变已确认的契约项目依赖。具体签名、冻结状态编码、整包持久发布方案与调用样例仍须在所属票解决，再由[契约原型](https://github.com/odradekk/train/issues/292)验证；后续发现协议冲突须按受控变更流程确认，不能由单个模块自行解释。
