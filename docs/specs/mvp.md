# 自动跑商核心循环 MVP 规格

状态：**已批准**  
对应 Wayfinder：[制定自动跑商核心循环的 MVP 验证规格](https://github.com/odradekk/train/issues/1)  
最终批准票：[批准 MVP 规格与个人试玩计划](https://github.com/odradekk/train/issues/10)

## 1. 目的

在最多 4 人周内实现一个 Windows/Godot C# MVP，验证以下核心循环是否值得继续投入：

> 配置贸易环线与交易规则 → 观察自动运行 → 从结果中发现问题 → 修改方案 → 再运行。

本 MVP 通过个人内部机制闸门，不证明外部玩家理解、喜欢或存在市场需求。

## 2. 成功闸门

一次试玩最多 30 分钟，从固定初始场景和有缺陷的预置贸易方案开始。

一次策略迭代只要求：

1. 看出一个具体问题；
2. 修改贸易环线或交易规则；
3. 跑完一个运行圈；
4. 看出修改带来的变化。

每次只在游戏外记录一行：

```text
改了什么 / 为什么 / 结果怎样
```

**通过**：30 分钟内自然完成至少 3 次策略迭代，并且结束时仍想继续调整贸易方案。

**失败**：满足任一条件：

- 不知道下一步能改什么；
- 修改后的影响无法理解；
- 三次修改主要是为了凑次数；
- 30 分钟内未完成 3 次策略迭代。

基线运行不计作策略迭代。技术故障修复后可以立即重试，不建立正式研究协议、录像或版本仪式。

## 3. 范围

### 3.1 包含

- 12 个固定站点和固定双向铁路网。
- 3 种货物：粮、煤、茶。
- 单列车、80 初始资金、8 格货舱。
- 自由选择并排序交易停靠站形成贸易环线。
- 每个“交易停靠站 × 货物”最多一条自动交易规则。
- 确定性的供给、需求、价格、交易和市场恢复。
- 地图优先的贸易方案编辑页。
- 平衡分屏的简化 3D 运行观察页。
- 每圈运行报告及与上一圈的最小对比。
- 固定场景重置。
- Windows x86_64 debug/release 构建。

### 3.2 不包含

- 采集、加工、战斗、员工、自由车厢设计、离线收益。
- 战役、解锁、永久成长、多列车、跨会话经济和正式存档。
- 正式版固定车头视角。
- 完整 12 站 3D 世界、正式体素资产、自由相机和驾驶。
- 完整教程、无障碍矩阵、本地化、手柄或移动端。
- 外部玩家测试、公开 Demo、商店发行、成就、云存档、社区和遥测。
- 代码签名、安装器、Steam/itch 集成。
- 应用内试玩记录；测试者在游戏外手记一行。
- HTML 原型中的“快速修正”和“运行已修正规则圈”等测试夹具。

## 6. 市场模型

每个“站点 × 货物”只有两个动态非负整数：

- 供给量：当前可卖给玩家的单位数。
- 需求量：当前愿意从玩家收购的单位数。

每个市场刻结束时：

```text
供给量 = min(供给上限, 供给量 + 供给恢复量)
需求量 = min(需求上限, 需求量 + 需求恢复量)
```

编辑、暂停和查看报告时市场冻结。不模拟 NPC 贸易、腐坏或其他自然变化。

价格公式：

```text
供给比例 = 供给上限 == 0 ? 0 : 供给量 / 供给上限
需求比例 = 需求上限 == 0 ? 0 : 需求量 / 需求上限
原始价格 = 基准价格 × (1 + 敏感度 × (需求比例 - 供给比例))
价格 = clamp(round_away_from_zero(原始价格), 最低价, 最高价)
价格 = max(1, 价格)
```

C# 必须使用：

```csharp
Math.Round(value, MidpointRounding.AwayFromZero)
```

不能使用默认银行家舍入。

## 7. 贸易环线与运行圈

### 7.1 有效贸易环线

- 至少 2 个不同的交易停靠站。
- 不允许重复站点。
- 第一个交易停靠站是起点。
- 列表顺序决定运行方向。
- 最后自动返回起点。
- 最短路径可以经过未加入贸易环线的站点；这些站点只中转，不停靠、不交易。
- 最短路径也可以提前经过一个稍后才排到的交易停靠站；该次经过仍只算中转。只有当前分段的列表终点才停靠交易，稍后按列表顺序真正到达该站时再交易。

### 7.2 圈前调度与运行圈边界

列车具有当前位置，初始位置为西仓。返回规划页时保留圈末位置。

- 如果贸易环线首站就是列车当前位置，直接开始运行圈。
- 如果玩家把首站改成其他站点，启动后先按确定性最短路径进行**调度空驶**。
- 调度空驶不执行任何交易，但逐刻恢复全部市场；途经任何站点都只作中转。
- 调度空驶显示在运行进度中，并在报告中单列调度路径与调度耗时。
- 调度耗时不属于运行圈的 6 刻等路线耗时，也不计入圈利润；它会改变运行圈开始前的市场状态。
- 到达新首站且尚未交易时，运行圈正式开始。
- 起点立即执行一次交易。
- 每段行驶逐个推进完整市场刻。
- 抵达列表中的当前交易停靠站后，按玩家排序逐条执行规则。
- 每个交易停靠站每圈恰好交易一次。
- 从最后一个交易停靠站返回起点。
- 抵达起点但尚未再次交易时结束，生成报告。

### 7.3 事件顺序

```text
若首站变化：调度空驶并恢复市场（不交易）
→ 到达新首站
→ 运行圈起点交易
→ 行驶市场刻并恢复全部市场
→ 中转经过事件（包括提前经过稍后排到的交易停靠站，均不交易）
→ 抵达当前分段终点交易停靠站
→ 逐条交易
→ ...
→ 返回起点
→ 运行报告
```

模拟结果先产生，3D 动画只表现既定事件。动画、速度、跳站和快速完成不能改变模拟结果。

## 8. 交易规则合同

每个“交易停靠站 × 货物”最多一条规则：

```text
动作 + 价格阈值 + 目标持有量
```

- 买入：当前价格 `≤ 最高买价` 时执行。
- 卖出：当前价格 `≥ 最低卖价` 时执行。
- 阈值为必填正整数。
- 买入目标范围 `1..8`。
- 卖出目标范围 `0..8`。
- 不支持无条件交易、价格区间、百分比、复合条件或规则嵌套。

期望成交量：

```text
买入期望量 = max(0, 目标持有量 - 当前持有量)
卖出期望量 = max(0, 当前持有量 - 目标持有量)
```

买入实际量：

```text
min(期望量, 站点供给量, 货舱剩余容量, floor(资金 / 报价))
```

卖出实际量：

```text
min(期望量, 站点需求量)
```

每条规则开始时读取一次价格，整批同价，不做逐单位滑点。结算原子且立即生效，后续规则能看到更新后的资金、货舱、供需和价格。

结果状态：

- 成交：实际量等于期望量且大于 0。
- 部分成交：`0 < 实际量 < 期望量`。
- 未成交：实际量为 0。

单一主因：

- 价格条件不满足；
- 目标已满足；
- 供给不足；
- 需求不足；
- 货舱不足；
- 资金不足。

判断先后：价格条件 → 目标 → 数量约束。买入多个数量约束并列时，主因优先级为供给 → 货舱 → 资金。

同站规则由玩家明确排序，从上到下执行。不同货物的买入目标之和可以超过 8，但 UI 必须持续显示“容量竞争”。

## 9. 默认场景与预置方案

初始列车：

```text
资金：80
货舱：8
粮/煤/茶：0/0/0
```

预置贸易环线：

```text
西仓 → 南市 → 西仓
```

最短路径经中枢，单程 3 刻，整圈 6 刻。

预置规则：

```text
西仓：粮价 ≤ 18，买入到目标 8
南市：粮价 ≥ 17，卖出到目标 0
```

该方案故意有缺陷：南市粮初始价格为 16，且粮最高卖价只能达到 16，所以卖出门槛 17 永远无法满足。

未经修改连续五圈的验收利润：

```text
-48, 0, 0, 0, 0
```

第一圈后货舱为 `8/8` 粮，方案停滞但不是技术软锁。

从新场景只将南市卖粮门槛改为 12 后，前三圈验收利润：

```text
80, 54, 54
```

第二圈粮价必须为 15；这依赖 AwayFromZero 舍入。

## 10. 规划界面合同

采用地图优先布局。

### 10.1 结构

- 主区：12 站铁路地图。
- 右侧：选中站点检查器。
- 地图下方：有序贸易环线、完整最短路径、分段耗时、整圈耗时。
- 地图 HUD：资金、货舱容量、买入目标占用和整圈耗时。

### 10.2 输入

- 点击地图站点选中。
- 检查器加入或移出贸易环线。
- 使用上移、下移、删除按钮排序；不要求拖拽。
- 已加入环线的站点可以添加、替换、删除和排序规则。

### 10.3 规则表单

字段：货物、买/卖、价格阈值、目标持有量。

持续显示：

- 当前贸易方案摘要；
- 将要保存的规则；
- 保存后的方案预览；
- 当前价格是否满足门槛；
- 各货物买入目标和容量竞争。

默认值：

- 已有规则：载入已有值。
- 无规则：选择该站支持的动作；阈值默认为当前价格；买入目标 8；卖出目标 0。

### 10.4 校验

错误靠近表单显示：

- 少于 2 个交易停靠站；
- 重复站点；
- 无供给站点买入；
- 无需求站点卖出；
- 阈值非正整数；
- 目标超范围。

容量竞争不是保存错误，只是持续警告。

唯一操作说明：

> 先选站组成环线，再为停靠站配置规则，最后运行一圈。

正式 MVP 不包含“快速修正”按钮。

## 11. 运行观察合同

采用平衡分屏：约半屏简化 3D，约半屏实时运行信息。

### 11.1 实时信息

- 当前所在位置和下一交易停靠站；
- 整圈进度、速度和暂停状态；
- 资金；
- 货舱占用与粮/煤/茶数量；
- 有序站点进度：交易停靠、中转经过、返回起点；
- 最近一条交易事件；
- 当前交易规则的报价、期望量、实际量、状态和主因。

运行中不能修改贸易方案。

### 11.2 控制

- 启动一整个运行圈；
- 暂停 / 继续；
- `1×`、`4×`、`16×`；
- 跳至下一交易停靠站；
- 快速完成整圈；
- 重置固定场景。

跳站越过普通中转站但仍按顺序推进模拟事件。快速完成处理全部剩余事件并打开报告。圈结束后所有推进控制失效。

### 11.3 简化 3D

- 固定 Camera3D。
- BoxMesh 占位列车、纯色材质、基础灯光。
- 3D 不复刻完整 12 站世界。
- 使用可复用的通用行程段表现当前两个交易停靠站之间的行驶；站名、方向、行驶刻和中转事件由当前路线驱动。
- 对预置路线，表现西仓 → 中枢 → 南市和返程。
- 无碰撞、Navigation、自由相机、正式体素资产、粒子、后处理和环境细节要求。

## 12. 运行报告合同

圈结束自动打开报告，右侧实时区域替换为报告，3D 保持结束背景。

至少包含：

- 圈利润、资金前后、运行圈市场刻；
- 若发生调度空驶，单列调度起点、目标、路径和调度耗时；调度不计入圈利润或运行圈市场刻；
- 圈末粮/煤/茶和货舱占用；
- 每站规则结果：动作、货物、报价、期望量、实际量、状态、主因；
- 未执行交易摘要；
- 关键市场变化：只列本圈实际执行过规则的“站点 × 货物”，显示该规则执行前与执行后的供给、需求和价格；
- 与上一圈的利润、卖出量和压舱货物对比；
- 一条有限、确定性的下一步提示，不自动修改方案。

下一步提示算法：

1. 按交易停靠站列表顺序，再按站内规则执行顺序扫描本圈结果。
2. 找到第一个未成交或部分成交规则。
3. 显示站点、货物、动作、报价/阈值、期望量/实际量和单一主因；不生成具体新阈值、目标量或路线答案。
4. 若所有规则均完全成交，显示：`本圈无未完成交易；请自行比较利润、耗时和压舱货物。`

预置失败圈提示实例：

> 南市卖粮未成交：现价 16 低于门槛 17。

报告操作：

- 关闭报告并停留在结束态；
- 返回地图优先编辑页。

正式 MVP 不包含“运行已修正规则圈”按钮。

## 13. 应用状态

```text
Planning
  └─ StartLoop
       ├─ 首站 == 当前位置 → Running
       └─ 首站 != 当前位置 → Repositioning
Repositioning
  ├─ Pause ↔ Repositioning
  ├─ ResetScenario → Planning（恢复全部初始状态和预置方案）
  └─ ArriveNewStart → Running
Running
  ├─ Pause ↔ Running
  ├─ ResetScenario → Planning（恢复全部初始状态和预置方案）
  └─ LoopFinished → Report
Report
  ├─ CloseReport → FinishedObservation
  └─ ReturnToPlanning → Planning（保留圈末市场、资金、货物、位置和当前贸易方案）
FinishedObservation
  └─ ReturnToPlanning → Planning（保留圈末状态与位置）
```

正常完成一圈后继续经营状态；只有明确重置才回到固定初始状态和预置方案。

## 15. 验收测试

### 15.1 工具链

- `global.json` 选择 SDK `9.0.316`。
- `dotnet restore` 和 `dotnet build TrainMvp.sln` 成功。
- Godot `--build-solutions` 成功。
- Windows x86_64 debug/release 导出成功，无 error/warning。
- 导出产物能启动并进入规划页。

### 15.2 路线

- 0/1 站不能启动。
- 重复站不能加入。
- 西仓到南市最短路径为西仓 → 中枢 → 南市，耗时 3。
- 预置整圈耗时为 6。
- 中枢经过但不交易。
- 构造“北矿 → 东茶 → 北驿”环线：北矿到东茶路径提前经过北驿时，北驿只记中转；到列表中的北驿分段终点时才交易。
- 每个交易停靠站每圈交易一次，返回起点不再次交易。
- 连续经营中把首站从当前位置改为另一站：先按最短路径调度空驶，逐刻恢复市场、全程不交易，到达后才开始运行圈。
- 调度空驶不会改变圈利润计算，但报告单列调度耗时。

### 15.3 经济

- 初始西仓粮价为 6，南市粮价为 16。
- 预置首圈利润为 -48，圈末粮 8、资金 32。
- 未修改五圈利润为 `-48,0,0,0,0`。
- 门槛改为 12 的新场景前三圈利润为 `80,54,54`。
- 粮煤复合方案目标 `8+6` 时煤因货舱不足不成交。
- 粮煤目标改为 `4+4` 时一圈利润为 112。
- 所有重复运行在相同初始状态和事件序列下结果完全一致。

### 15.4 规则

- 买入/卖出阈值包含等号。
- 价格不满足时未成交并显示正确主因。
- 目标已满足时未成交。
- 部分成交按最小约束计算。
- 卖出释放的资金和空间可供同站后续规则使用。
- 同站规则重排会确定性地改变结果。
- 容量目标合计超过 8 可保存且显示容量竞争。

### 15.5 UI 与运行

- 12 站和铁路在常用桌面窗口中可查看。
- 资金、容量、目标占用和整圈耗时不会因滚动离开主要视野。
- 运行中不能编辑。
- 暂停不推进模拟。
- 三档速度只改变表现等待。
- 跳站落在下一交易停靠站。
- 快速完成生成与逐事件运行相同的报告。
- 圈结束后不能继续推进。
- 报告按执行顺序提示第一个未成交或部分成交规则；预置失败实例明确显示南市现价 16 低于门槛 17。
- 所有规则完全成交时，报告不推荐具体优化答案，只提示比较利润、耗时和压舱货物。
- 关键市场变化只包含实际执行过规则的站点×货物。

## 16. 实施计划与砍线闸门

批准 4 人周完整基线，目标 `14.5–20` 个工作日。

| 阶段 | 目标 |
|---|---|
| 第 1–5 日 | 正式 C# 项目骨架、Resource 数据、纯模拟、预置失败/修正 smoke |
| 第 6–10 日 | 地图优先规划页达到可编辑、可启动整圈 |
| 第 11–15 日 | 报告、平衡分屏运行、控制和占位 3D |
| 第 16–20 日 | 集成、个人试玩、阻断缺陷、Windows release 构建 |

砍线闸门：

- **第 5 日**：模拟未通过固定数值验收时，暂停 UI/3D，先修模拟。
- **第 10 日**：规划页尚不能完成环线与规则编辑时，3D 立即降为三点直线移动。
- **第 15 日**：尚不能完整执行编辑 → 运行 → 报告 → 编辑时，删除次要实时字段和报告中的供需/价格市场细项表，只保留成功闸门必需信息。规则结果、单一主因和确定性下一步提示不能删除。

固定砍线顺序：

1. 不做应用内日志；
2. 3D 降为三点直线 Tween；
3. 运行中只显示最近一条规则结果；
4. 删除报告中的供需/价格市场细项表，并将上一圈对比缩为利润、卖出量、压舱货物；保留当前规则结果、主因和确定性提示；
5. 1× 只做粗略移动。

不能砍：

- C#；
- 12 站任意成环；
- 确定性市场与规则合同；
- 地图优先规划；
- 报告中的规则结果、单一主因和确定性下一步提示；
- 暂停、4×/16×、跳站、快速完成；
- 30 分钟个人试玩闸门。

## 17. 个人试玩脚本

1. 在游戏外准备三行空白记录。
2. 启动 release 构建并重置固定场景。
3. 获得控制时开始 30 分钟计时。
4. 阅读唯一操作说明，查看预置方案。
5. 运行一圈基线；基线不计迭代。
6. 根据报告自行选择修改，不使用作弊按钮或预先写好的答案。
7. 每完成一次“发现问题 → 修改 → 跑一圈 → 看出变化”，记录一行。
8. 完成第三次迭代或达到 30 分钟时停止。
9. 回答：如果没有测试要求，是否仍想继续调整？
10. 按第 2 节判定通过或失败。

## 19. 最终就绪判断

本规格没有会使实现者自行决定并改变成功闸门的产品 TBD。

允许实现者自行决定的局部事项，仅限不改变合同的实现细节：

- 节点名称与内部文件拆分；
- 字体、纯色、边距等最小视觉样式；
- 通用 3D 行程段的具体几何尺寸；
- 自动停靠的短暂停顿时长；
- C# 测试框架选择或 console smoke 形式。

若实现过程中需要改变固定数值、规则语义、12 站范围、主要 UI 布局、运行控制、报告字段或成功闸门，必须停止并重新做产品决策，不得由实现者静默修改。
