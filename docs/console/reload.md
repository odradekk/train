# `reload`：重载内容

[返回命令索引](README.md)

```text
reload
```

参数：无。不接受文件路径、包名或定义 ID，也不是重载场景的命令。

使用方法：修改当前内容源中的定义或资产后，在 Debug 构建中执行 `reload`，检查内容扫描、诊断及重载汇总日志。它调用正式内容重载入口，重新构建并校验候选目录。

- 体素目录有有效变更并发布后，Catalog Generation 递增；仅聚落变更或没有有效变更时不递增。
- 已进入体素开发场景时，重载会基于候选当前定义校验全部占用实例、已有车辆、零件、存活碎块、必要存档内定义、接触绑定、已提交铁路编组和 World Grid 引用，并准备同一次适配。全部成功后才原子发布目录、Generation 和实例变化；不得先发布目录再分批修正车辆。缺必需定义、核心标签／身份规则或其他约束使已有状态无法保留、或当前朝向不再被允许时整次拒绝，目录、Generation、世界和车辆保持旧状态。多个目标中只有一个不兼容也不能部分提交。
- 已有体素和车辆零件按 DefinitionId 采用当前 Mass、Value、耐久上限和碰撞规则；LastUsedRevision 只识别变化，不锁旧 Mod。绝对耐久在新上限升高时保持，降低时夹到新上限，不按比例换算或自动回血。占用、零件 ID、车辆身份、实际坐标／朝向／Transform 和未超界运行状态保留，不重建世界或用更新后的外部蓝图覆盖已有车辆。`voxel collide` 与 Godot 派生碰撞在成功发布后采用新规则，包括 `none` / `full_box` / 单个 `local_box` 及其几何；领域查询在发布当下即可读到。
- 已提交编组按当前目录独立校验运行条件，不沿用存档或已脱离车头的旧参数副本。`Running` 编组必须仍能解析活动车头及其 propulsion / control；无动力滑行编组（`Running=false` 且速度大于 0）必须仍能从本编组成员解析当前 `track_contact` 减速度。缺成员、缺动力控制或无法解析滑行减速度时整次拒绝，不改目录、编组姿态或速度。零速停放编组不要求活动动力。非法候选减速度同样在发布前拒绝。
- 受损车和存活碎块按当前 Runtime Identity／Operational Condition 适配，不要求重新满足全部 Construction Validity。缺少两个接触点的碎块保持 `Disabled`，不会被自动删除、重造或补回接触点。外部零件更新不递归改变自定义布局自身的 Semantic Revision；新制造使用新模板。
- 纯显示文字、Cube 资产或绑定变化可以更新已有体素和已有车辆的查询与画面，不因此改变 Semantic Revision，也不改变碰撞命中。无有效变化不递增 Generation。Collision 是语义数据，模型或图片更新不能自行改物理形状。
- 内置内容错误或候选校验失败时拒绝发布，保留原目录、世界、车辆和已发布碰撞。`local_box` 在局部 double 区间合法、但碰撞适配转换后不再保持正体积时，同样在发布前拒绝，不替换已发布的有效形状。非法 Mod 可以整包排除后继续校验剩余候选，但排除后若运行中实例缺必需定义，整次仍然拒绝。
- 已有重载正在进行时，新请求会被拒绝。
- 非 Debug 构建执行该命令会提示 `reload is only available in debug builds.`。

读档后的车辆走同一适配入口：保留实际改装 / 断裂布局，不按 Blueprint 名称重造。已有完整存档内自定义定义时，外部 Composite 条目可以缺失，仍按该定义与当前零件/Archetype 适配；没有内嵌定义的库存车仍要求外部 Composite 存在。需要丢弃当前布局并重建初始开发世界时使用 `voxel reset` 或 `composite reset`。
