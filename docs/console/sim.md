# `sim`：调试核心模拟

[返回命令索引](README.md)

`sim` 只由 Debug 游戏宿主提供，用于观察和控制当前活动模拟会话。它不会创建世界、玩家、存档或模拟会话；没有会话时报告“没有活动模拟会话”。发布构建不注册该命令。

```text
sim
sim status
sim pause
sim resume
sim speed 1|2|4|8
sim step [N]
sim checkpoint
```

`sim` 与 `sim status` 输出当前位置、模拟秒、暂停状态、设定与实际倍速、帧余量和故障。预算内未执行的整步额度不会跨帧补算，只保留不足一步的余量。`pause` 与 `resume` 修改宿主调度状态，`speed` 只接受 1、2、4、8，最高档暂定，须经性能实测确认。

`step` 默认推进一步，`N` 必须是大于零的十进制 `UInt64`。手动推进只允许在宿主已暂停时执行；运行中会报告 `simulation_requires_pause`，不会隐式暂停。手动步同步执行，不受自动推进的每帧预算限制；较大的 N 会占用当前帧。故障已冻结的会话不能继续运行或手动推进，命令会报告稳定故障代码和阶段。

`checkpoint` 只输出当前权威位置与 SHA-256 摘要，供确定性诊断使用；它不会写存档，也不会输出完整权威文档。

内部故障发生时，宿主会立即记录一次 `simulation_fault` 错误日志，包含异常详情并冻结会话。重复查询或操作冻结会话只报告当前状态，不再重复记录该故障的错误日志。

参数形状在访问会话前严格检查。多余 token、未知子命令、零、负数以及不支持的倍速都会输出用法警告，不修改宿主或模拟状态。所有结果通过共享日志的 `simulation` 分类输出；数值使用与系统区域设置无关的格式。
