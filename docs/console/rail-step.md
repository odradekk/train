# `rail step`：正式推进指定模拟步

[返回命令索引](README.md) · [场景前提与参数](README.md#使用前提与通用参数) · [结果与错误处理](README.md#结果与错误处理)

```text
rail step
rail step 300
```

无参数推进 1 步；一个十进制整数 `n` 推进 `n` 步。成功输出 `Rail Advanced step <now> advanced <n>.`。`n=0` 为成功空操作。无法解析的文本回到用法提示。

步号加 `n` 会超出 `ulong` 时整批拒绝，输出 `Rail StepOverflow.`，不回绕、不推进。每步先按编组身份稳定顺序积分全部已提交编组，再把时钟加一、边界序号归零，并按接受顺序执行目标为新步的全部[世界修改](voxel-edits.md)——体素、载具、铁路施工/修复、编组与 [`rail start`](rail-start.md) / [`rail stop`](rail-stop.md) 同在这一个队列里，不存在单独的列车命令队列。有活动动力且仍具备 control 的编组继续牵引；无活动动力且速度大于 0 的编组按当前有效 `track_contact` 减速度沿原方向滑行，零点分段。每个编组检查全部必要接触点在本步完整明确路径上的最早缺口或末端，按入侧边界限位并零速；不能只看车头或目标点，也不能用未刷新派生图或 10⁻⁸ 容差跨过缺口。当前接触已失去支撑时，只冻结该编组并保持最后已提交姿态，其他独立编组继续。从 `MaxValue - 1` 推进一步会到达终态步并执行目标为 `ulong.MaxValue` 的修改；时钟已在 `MaxValue` 时再推进仍为 `StepOverflow`。每个运动步不增加事务计数。暂停不阻止本命令；单步、`n` 步与主机自动推进走同一推进入口，结果与每帧折算多少步无关。无编组时仍推进时钟。

到期修改的预期拒绝（例如起停目标编组已消失、启动条件不满足、目标格已被摧毁）只让那一条记为 `rejected` 并出队，推进照常继续，输出仍是 `Rail Advanced ...`；拒绝结果用 [`voxel edits log`](voxel-edits.md) 查看。已执行的修改在其边界提交，不因后续步撤销。修改执行中的内部故障，或编组积分破坏内部不变量，都会把会话停在最后一个完整边界并锁定：输出 `Rail SimulationFaulted step <now> advanced <k>.`，其中 `<k>` 是已完成的步数；运动故障不带修改编号，[`voxel edits fault`](voxel-edits.md) 显示为 `motion`。

固定 60 步/秒、目标速度 4、加速度 2、无动力滑行减速度 1。第 0 步 [`rail start`](rail-start.md) 后再 `rail step 300`，车头前接触应为 96、后车前接触 87、速度 4。车钩断开后再 `rail step 30`，前车 98、后车 88.875 / 3.5。
