# 07 渲染

> **所属层**：体素引擎层与渲染层。

> 决策出处：转录 Q126–Q143、Q179。线路分段、浮动原点、铁轨渲染、列车插值的位置来源、拾取与碰撞，由[局部场景的生成与表现](https://github.com/odradekk/train/issues/210)于 2026-10-05 确认，取代了视觉驻留、全局渲染原点、按物理轨段派生轨道网格和逐格碰撞的规则。标准形状、自定义模型的贴图和严格内接由[非立方体形状与构造语言](https://github.com/odradekk/train/issues/245)于 2026-10-09 确认。磨损叠加和轮对由[磨损、损伤、动画与特效](https://github.com/odradekk/train/issues/251)于 2026-10-09 确认。

## 边界

本文定义局部场景和设计编辑器的表现策略：三路体素表现、区块网格、自定义静态模型、铁轨渲染、对象渲染、增量重建、LOD、列车插值、拾取与碰撞。所有内容都是核心状态与内容的派生结果，不改变模拟。场景怎样生成见 [01](01-voxel-engine-and-scenes.md)，相机见 [08](08-window-and-ui.md)。

## 不变量

- 渲染与 Godot 碰撞都是派生缓存；核心状态不保存 Godot 网格或碰撞形状。
- 表现层的任何优化只改变表现，不改变模拟。
- 车辆、建筑和生物移动时只更新根变换，绝不因为移动重建内部网格。
- 线路场景的浮动原点移动时只平移场景对象，不改变核心状态、存档或模拟结果。

## 规则

### 总体策略

领域世界和表现路径分开。Voxel Presentation 分为三路：Cube（含内置的标准形状）、CustomStaticMesh、Specialized。

体素引擎层交出的网格数据只用 Asset Revision 引用贴图和模型，另带材质类别和涂装颜色，不含像素。Godot 的 AssetResolver 把 Asset Revision 换成纹理、模型和材质，怎样打包（纹理数组、图集、按材质分批）由 Godot 决定；资产怎样从内容层交到 Godot 见 [02 的资产的交接](02-definitions-and-content.md#资产的交接)。由场景数据算出的几何（标准形状、钢轨和轨枕、轮对的位置）由体素引擎层算成纯数据；着色器、材质类别的视觉参数、磨损和损伤图案、粒子、天空、轮对模型和缺失内容的占位外观属于 Godot 项目本身，不在内容包里，Mod 不能修改，也不随内容热重载更新。

### Cube Voxel Rendering

- Demo：Chunk → Face Culling → Chunk Surface Mesh，只生成未被视觉完全遮挡的面；是否占格或有碰撞盒不等于完全遮挡。非满格 Custom Mesh 和镂空材质默认不遮住整个邻面，不能从占格或碰撞盒推断视觉上完全遮挡。不使用 one MeshInstance per voxel。
- 阶段 2 接入无磨损立方体面的有界 Greedy Meshing，不改变 World、Chunk 或逐格拾取语义；范围及材质／涂装、贴图资产、UV 轴／跨度、法线／平面、透明／损坏和拾取边界条件统一见 [01 的区块面合并](01-voxel-engine-and-scenes.md#区块面合并)。当前 Glass 不透明，独立 Front 使用跨度 1，二者不另行排除；透明路径仍不在本次合并范围。
- 面贴图：顶面、底面、四个侧面分别使用 `faces.top`、`faces.bottom`、`faces.side`；体素的 Forward（局部 +Z）面有 `faces.front` 时使用它，字段见[体素定义的格式](../content/voxel.md#presentation立方体)。侧面图的上方朝体素的局部 +Y，顶面和底面图的上方朝 Forward；贴图随体素朝向一起转。平铺跨度 N 大于 1 时，一张图覆盖 N×N 格，位置按体素所在对象的网格坐标计算（车辆和建筑用自身网格，场景用场景网格），所以贴图随对象移动、相邻同种体素连续；独立正面图每格使用完整图，跨度为 1。合并面仍按原跨度重复采样，贴图坐标从首格整数取模相位连续增长，可超出 `[0,1]`，不用远坐标浮点取模。采样在近处用线性过滤，远处用 Mipmap 加各向异性过滤。这些规则由[立方体体素的面贴图形式](https://github.com/odradekk/train/issues/243)于 2026-10-09 确认。
- 标准形状：设计的每一格从体素定义允许的形状（Cube 表现的 `shapes`）里选一种，形状取自游戏内置的形状目录及其标准变体（半块、楔形、梁、圆柱等，见[美术 01](../art/01-construction-language.md#形状)），不选时用 `shapes` 的第一项。形状来自设计的格子，不由定义固定。形状沿用同一套面贴图、平铺跨度和材质类别，贴图按对象网格投影到形状表面，斜面按法线最接近的轴取图，正好在两轴之间时取顶面图或底面图。每种形状记录它的哪几面完全盖住所在格的面，区块网格据此剔除面。历史首切片仅支持立方体；Demo 按[开发阶段](00-product-and-core-loop.md#开发阶段)接入标准形状，不沿用这个限制。
- 磨损叠加：着色器在面贴图上叠加和部位有关的磨损：按体素在所在对象中的高度给下部积灰，朝上的面落尘，外露的棱边掉漆，再加一层低频杂色，随机种子取实例身份。高度按对象网格计算，车辆和建筑用自身网格，场景模型用它摆放时的范围；外露的棱边由网格构建时按相邻格写入每个面。Custom Mesh 只叠加下部积灰和杂色。不属于场景模型的场景体素（地形、道床）不叠加磨损；铁轨断点范围内的道床和地面叠加焦黑，见[美术 06](../art/06-wear-damage-and-motion.md#铁轨断点与修复中的工地)。表面损伤用同样的方式叠加共用的损伤图案（[01](01-voxel-engine-and-scenes.md#场景中的结构破损)）。画法见[美术 06](../art/06-wear-damage-and-motion.md#磨损的画法)。

### Custom Static Mesh

- Demo 的 Custom Static Mesh 支持静态模型、基础颜色与贴图、正常光照和阴影，以及不透明和镂空裁剪材质。模型是 `.glb`，单位为米，原点在格的底面中心，+Y 向上、正面朝 +Z，见[体素定义的格式](../content/voxel.md#模型文件的约定)；体素按定义允许的正交朝向放置，24 个朝向都绕格中心旋转。
- Custom Mesh Voxel 按 Chunk + Mesh + Material 进行局部批处理或实例化。体素引擎层只交出模型实例的列表（模型的 Asset Revision、所在格和朝向），不读取模型几何；Godot 解析模型并决定怎样批处理。Demo 只要求 LOD0；未来 Custom Mesh LOD 属于 Presentation Asset Metadata，而不属于 Gameplay Definition。
- 标准形状和 Custom Mesh 必须完全位于自己的格内（严格内接）；以后加入模型内部动画时，会动部分的运动范围也必须在格内。需要真正跨格的视觉结构由多个体素组成，或进入 Specialized Renderer。
- Custom Mesh 用模型自己的 UV 贴图，基础贴图密度 32 px/格；一个模型可以有几个表面，每个表面选一个表现材质类别，见[美术 02](../art/02-materials-and-textures.md#形状与自定义模型)。模型按原尺寸使用，不缩放或剪切。

### 铁轨渲染

- 需要领域专用视觉的内容使用独立 Renderer，首要例子是 TrackRenderer。钢轨和轨枕是沿线路中心线（[01](01-voxel-engine-and-scenes.md#中心线)）生成的网格，不占体素格，所以弯道上轨枕始终垂直于钢轨；道床是体素。轨枕改为网格由[首个切片的场景美术规格](https://github.com/odradekk/train/issues/247)于 2026-10-09 确认，外观见[美术 04](../art/04-world-assets.md#铁路)。
- 铁轨网格按线路场景的分段构建。铁轨数变化或出现断点时，只重建受影响的分段。断点显示为实际缺口，剩余部分不移位。
- 节点进站区域的道岔只作表现，连接方式由节点场景生成。
- 不能只在渲染时平滑阶梯状轨道，或缩放、剪切、弯曲车体来掩盖路径错误。

### 对象渲染

- 车辆、建筑和生物不进入地形区块网格。每个对象统一使用 { Cube Batch, Custom Mesh Batch, Specialized Visuals }。
- 移动时只更新根变换。损伤、改装、建造完成以及引用的表现资产变化，只标记受影响的对象并批量更新；单个对象变化不能触发全部对象重建。
- 轮对：车辆的车轮是专用表现，按转向架体素的位置生成，按列车插值得到的显示速度转动，可以跨格；转向架体素的贴图不画车轮。历史首切片把车轮画在贴图上的方案不再沿用；轮对随基础列车表现接入，三台样机、模型与涂装在第三阶段验证，全部正式车辆外观在第六阶段补齐，见[开发阶段](00-product-and-core-loop.md#开发阶段)。转向架制作遵循[排布约定](../content/voxel.md#转向架排布约定)，暂定尺寸与表现待看图确认，外观见[美术 06](../art/06-wear-damage-and-motion.md#动画)。
- 未来可以针对大量静态对象增加只作表现的烘焙优化。

### 列车插值

- 列车在核心中的位置（线路、铁轨号、方向和距离）换算成该铁轨中心线上的弧长位置。显示在相邻两个已完成的模拟状态之间插值，不外推未发生的运动，正常运行接受最多一个模拟步的显示延迟，见 [ADR-0008](../adr/0008-simulate-the-world-in-a-voxel-free-core-and-build-voxel-scenes-as-presentation.md)。
- 各节车辆按编组顺序沿中心线排列，车体朝向取所在位置的路径切线；车体是刚性的，转弯时不弯曲或拉伸。
- 列车的核心距离对应整列长度中心，各节车辆按自己的长度围绕该中心排列。路径切线的正反由核心保存的编组正反标记和实际行驶方向共同确定，不能只看速度方向。线路上倒车保持车体朝向和车辆排列；跨节点沿接续路径保持同一首尾关系，原路返回表现为推送。重新打开场景或读档直接由当前快照恢复，不依赖上次观察历史。成员被毁后的收拢按[位置规则](06-railway.md#位置)处理。
- 显示结果不回写核心状态；Godot 变换只是派生表示。
- 相机与车体使用所选车辆的同一份显示位置和车体朝向，不直接跟随跳动的模拟步位置，也不以行驶方向代替车体朝向，见 [08](08-window-and-ui.md#线路场景的相机跟随)。
- 真实 Godot 观感检查覆盖弯道、坡道、较长编组、跨分段和浮动原点移动时的连续性。headless 检查通过不替代人工观感。

### 表现时间

世界中的车辆移动、炮塔与生物动画、烟火和碎片均随模拟时间推进。暂停或技术操作锁停止推进时，世界表现一起停住，相机与界面仍正常响应；倍速改变模拟时间的推进速度。闪光和闪烁仍遵守[按真实时间计算的强度上限](../art/06-wear-damage-and-motion.md#特效的强度上限)，不能随倍速提高单位真实时间的闪烁频率。未观察到的历史事件不在恢复渲染后补演。

### 显示数据的所有权

紧凑顶点采用保留全部字段及顺序的 `readonly record struct SceneVertex`，网格仍以 `ImmutableArray<SceneVertex>` 交接；关闭磨损的矩形面使用矩形四角 `FaceUv` 和 None 外露边，这两个通道仅在开启磨损时参与着色。

体素交给 Godot 的网格和其他显示数据采用不可变值语义，接收方可以保留，后续更新不改写旧数据；不再使用时释放引用，由垃圾回收处理。暂不公开缓冲借用与归还协议；内部可共享不可变数据。若实测的分配、复制或内存成本不满足预算，再按契约变更流程调整，当前选择不是性能已经达标的证据。具体交接见[体素契约](../contracts/scenes.md#显示更新与资源)。

### 增量重建

- 场景中的变化不逐体素立即重建网格：标记受影响的区块或对象 → 合并 → 一次重建。
- 区块边界的修改要同时考虑相邻区块的暴露面变化。
- 场景首次构建和线路分段构建在后台线程进行（[01](01-voxel-engine-and-scenes.md#场景的存储与构建)）。场景打开后的局部重建，Demo 可以同步进行，出现实际卡顿后再改为异步。

### LOD 与远景

- Demo 不实现体素几何 LOD。场景范围有限，远处用雾和场景边界收住；线路场景超出已构建分段的部分显示为雾。
- 后期性能需要时再增加 Custom Mesh LOD、Voxel Geometry LOD；阶段 2 的有界面合并见上文。

### 坐标

- 节点场景以节点为原点，线路场景使用浮动原点，见 [01](01-voxel-engine-and-scenes.md#场景的存储与构建)。场景范围有限，加上浮动原点，单精度浮点足以保持显示精度；转录 Q179 否决用 Godot 双精度构建的结论继续有效。
- Demo 的逻辑单位 1 Voxel Unit = 1 Godot Unit，但概念上保持解耦。

### 拾取与碰撞

- 拾取沿射线在场景体素数据和对象网格上逐格前进（DDA），不为每格建立 Godot 碰撞形状，见 [01](01-voxel-engine-and-scenes.md#拾取)。
- Godot 物理只用于碎片等表现效果。碎片需要的地形碰撞，用按区块合并的少量形状，例如高度图；形状数量随场景范围增长，不随体素数增长。
- 相机按地形高度避免穿进地形。

## Demo 范围

区块网格（遮面剔除及阶段 2 的无磨损面合并）、标准形状、Custom Static Mesh 批处理、AssetResolver、增量重建、TrackRenderer 与线路分段、对象渲染、磨损叠加、轮对、列车插值、浮动原点、逐格拾取。

## Demo 之后

Voxel Geometry LOD、Custom Mesh LOD、异步 Meshing、静态对象的只作表现烘焙；半透明玻璃、骨骼动画、模型内部机械动画、任意自定义着色器。

## 开放问题

- 区块边长、分段长度、预取距离、单帧重建预算等数值，由[新阶段：下一个里程碑的范围与验收](https://github.com/odradekk/train/issues/212)安排实测后确定。
- 地图迷雾（不立票）：Custom Mesh LOD 距离、Voxel Geometry LOD 距离、额外的批处理或存储优化；实测表明需要后再评估，不预先承诺。
