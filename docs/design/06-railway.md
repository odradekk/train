> [#33](https://github.com/odradekk/train/issues/33) 确认编组运动、稳定沿轨引用、断裂与断轨处理、双车头换端、插值及恢复规则，见 [ADR-0007](../adr/0007-drive-connected-assemblies-from-physical-rail-positions.md)。

## 边界

本文定义铁路的 Domain：轨道体素与拓扑、RouteState、逻辑图、运营层、施工、净空、桥隧、列车运动、多接触点约束、碰撞、脱落。轨道视觉（TrackRenderer）见 [07](07-rendering.md)；相机跟随见 [08](08-desktop-window-and-camera.md)。

## 不变量

- Physical Rail State（轨道体素、连续几何及明确连接）是铁路 Runtime Truth；Logical Rail Graph 是派生索引，不允许长期保留不存在的连接。
- RailPosition 是列车权威位置，World Transform 是派生结果。
- 世界编辑器、控制台、世界生成器，以及以后的玩家和 AI 施工，统一调用 RailConstructionPlan。

## 规则

### 设计地位

铁路与火车的机械运行是游戏核心视觉体验之一。即使首版铁路控制系统被简化，也不能把以下问题视为可以永久接受的临时表现：火车突然转向、轨道接缝明显、车厢切角、坡道姿态跳变、火车穿过错误道岔、长车厢明显脱离轨迹。铁路拥有独立的 Domain 与 Presentation 系统。

### Rail Voxel

- 首版只有一种基础 `core:rail`。长期采用混合模型：Rail Definition = 轨道的种类、属性与能力；Track Topology = 当前实例的空间连接。
- 未来可以新增 heavy rail、high-speed rail 等；但直线、曲线、坡道、道岔、交叉不作为独立 Definition。
- Rail 是可生产、可库存、可交易的 Voxel Good（Structural Metal → Rail）；Rail Definition 只表达轨道种类，直线、曲线、坡道等是实例空间拓扑，不产生不同 Rail 商品，见 [11](11-goods-and-production-network.md)。

### Track Topology

- 不使用不断膨胀的简单 Shape Enum 作为长期核心。保留 Track Ports + Internal Connections 表达明确连接，但不再以单格正交端口或面中点规定连续曲线的形状。
- 本阶段支持直线、连续水平弯道、带坡顶坡底过渡的缓坡及弯坡叠加。总方向可改变 90°，但不存在瞬时直角转向，也不让列车沿体素阶梯逐格转向。
- 两段轨道相邻或空间接近不代表连通；连接必须由物理轨段的明确连接决定，并具有一致的接续几何。基本道岔纳入本阶段，几何布置限制见下文验证契约；拓扑、切换与通行遵守下文网络运行契约，复杂交叉继续延后。

### 连续几何与物理状态

- 先设计连续线路，再派生轨道占格与空间连接登记。空间不足时调整线路或拒绝生成，不缩小到单格急弯，也不只在表现层假平滑。
- 物理轨段保存曲线参数及端点连接，轨道体素关联所属轨段。仅凭占格列表无法唯一恢复曲线；几何是物理状态的一部分，不是可任意重新猜测的渲染缓存，见 [ADR-0006](../adr/0006-preserve-physical-rail-geometry-and-local-breaks.md)。
- 渲染网格、行驶路径查询、弧长采样表和压缩路网由同一物理状态派生。读档恢复原有形状；保存与重建遵守 [09](09-persistence.md)，不保存 Godot Mesh 作为权威数据。
- 水平弯道平滑进入、退出曲率；坡道平滑改变倾角，坡顶坡底需要实际过渡空间。不再默认 1:1 坡，也不把 gentle_slope 作为观感不好时才补的选项。
- 原型采用曲率渐变段连接圆弧、倾角渐变段连接直坡；具体数值算法与采样策略在实施时选择，必须满足本节已定分项误差门槛，并遵守 [04](04-deterministic-simulation.md)。不能把穿过阶梯状 Port 中点的任意样条当成已满足半径与净空约束。

### 轨道占格

- 按钢轨、轨枕等实际轨道结构沿曲线形成的实体体积登记占用，不能只登记中心线经过的格子。被占用的轨道格关联其支撑的曲线区间；占格与区间关系在生成时建立。
- 车辆通行净空单独检查，不把整片净空登记为轨道体素。桥梁等支撑结构仍与轨道正交。
- 首版不允许两条独立轨道共占一格；生成器须调整线路或拒绝方案。轨段的技术切分不应人为制造独立线路或额外连接。
- 占格与区间映射、边界相交的数值处理属于实施验证内容；视觉装饰不能独立决定占格或连通性。

### RouteState

区分 TrackTopology（理论上可以怎样连接）与 RouteState（当前实际允许怎样连接）。本阶段三端道岔具有公共端、直股端、侧股端，状态仅允许公共端与直股端、或公共端与侧股端相通，不允许直股端直接通向侧股端。各允许路径仍须满足连续几何、真实占格及有效支撑约束，不能只在逻辑图或显示中添加连接。

授予通行权时原子设置路径上的道岔并锁定；逻辑转换瞬时完成，本阶段不模拟转换耗时与设备故障。人工扳道走同一保护规则，被占用或锁定的道岔拒绝切换，车尾未清空不得解锁。人工设置不构成永久保持命令，后续自动通行仍可在合法条件下改变方向。正常路径与拆分后的释放条件见下文网络运行契约。

### Physical Rail 与 Logical Rail Network

- 破坏一格，仅令依赖该格的曲线区间不可通行，不因存储时将曲线划成很长的物理轨段而整段失效。
- 两侧完好部分保持原位置和曲率，不重新平滑，也不跨缺口自动连接；渲染须显示实际缺口，不能继续绘制完整铁轨。
- 原曲线参数可用于定位剩余部分，但不能证明缺失区间仍有轨道。有效通行区间必须结合当前轨道体素判断。
- Physical Rail change → mark rail network dirty → incremental graph update；派生图未完成更新时也不能授权跨越实际缺口。已有列车的定位与停车遵守下文 RailPosition 及断轨规则。

### Compressed Rail Graph

- 不会把每个 Rail Voxel 当 Graph Node。只有重要位置作为 RailControlPoint，首版：Station、Junction、Endpoint；未来：Signal、Block Boundary、Special Track Device。
- 连续普通轨道压缩成 Edge：Control Point → Compressed Edge → Control Point。Edge 记录或引用实际 Physical Rail Path。

### 站点接轨接口

- 聚居地 Layout 中的 RailSocket 描述站点的接轨位置与方向，一个站点可声明多个接口；它不等于物理轨道的 Track Port，也不直接生成铁路连接或 RailControlPoint。
- 物理轨段的明确连接与当前有效区间决定实际物理连通性，Station 是压缩图中的重要位置。站点存在、有接轨接口、已接入铁路网络是不同事实；具体归属见 [05](05-world-generation-and-settlements.md)。
- 多个 RailSocket 不引入首版多站台运营或复杂调度要求。

### Rail Operational Layer

- 物理轨道描述几何可能性；单向、封锁、信号、Reservation 等属于 Operational Rail Layer。例如 Physical A ↔ B，Operational A → B allowed、B → A forbidden。
- 本阶段默认所有轨道双向，但不代表单车头可以倒行：反向运行须使用下文的双车头换端。运行计划、区段独占、完整路径预留、车辆实际占用与最小通行仲裁纳入本阶段；完整信号与复杂调度仍延后。

### 本阶段网络运行契约

出处：[确定分支道岔、选路与多列车冲突防护的最小规则](https://github.com/odradekk/train/issues/94)，用户确认 Q1–Q11。本节定义目标行为，不表示当前直轨实现已经具备这些能力，也不决定具体数据结构或算法。

#### 计划、路径与等待位置

- 每个编组可执行按站点顺序排列的单次或循环运行计划，逐站配置停留时长与是否允许换端。开始执行即视为用户允许正常停站、交通等待结束及符合计划的停稳换端后自动继续；每次进入线路仍须另行取得通行权；单次计划完成后停车，循环计划继续。交易、时刻表及经营优化不在本阶段。
- 站点停靠与交通等待分开：站点承担计划中的访问；等待位置可以在站外，但必须容纳整列并避开其他合法路径的车体扫掠范围，不能只检查车头或轨道中心线。停站时长按模拟时间计算，开始停留前整列须停稳并处于该停车空间内。
- 合法路径须同时满足明确物理连接、当前有效轨道、道岔拓扑允许的端点连接、车辆机械约束、行驶方向与整列等待空间。授予通行权时，道岔须已对准所选路径，或能在未占用、未锁定时由本次授权原子设置；不能仅因当前方向不同就把可切换支路判为不可达。换端仅在计划许可、整列停稳且两端朝外车头及反方向校验均满足时自动执行；单车头不得倒行。
- 只在等待位置、下一次通行权尚未授予时根据交通情况选择可行路径；以可行路径距离最短为优先，同距使用显式稳定顺序。允许走可用会让线；没有可授权路径时等待。授权后本次路径和道岔方向固定，不因临时拥堵在车下改道。

#### 完整授权与车尾释放

- 进入前必须一次取得通往下一处可容纳整列的等待位置的完整通行权，包含沿途区段、道岔及目标停车空间；不能先进入再争抢出口，也不能通过逐项占锁来等待其余必要空间。
- 正常进入时，同一通行区段只授权一个编组。不同区段可有同向跟车；同一冲突范围不能同时授权迎面、汇入或相交扫掠路径。实际车辆占用、未来通行预留和轨道实体占格是三个不同事实。
- 释放沿途区段和道岔必须以整个相关车体清空保护范围为依据，车头越界不代表车尾清空。停车、计划停止、牵引关闭或轨道缺损均不能直接清除实际占用及仍必要的保护；未进入且已不再需要的未来预留才可安全撤销。
- 有动力运行、无动力滑行和人工调试推进均受通行边界与实际车体防碰撞约束。检查本步移动路径，不能因一步位移过大越过许可终点；必要时限制位移并停车，安全限制优先于自然滑行，不引入事故伤害或刚体碰撞响应。
- 多车竞争在当前仲裁中可完整授权的请求之间按等待先后处理，等待最久者优先；同一模拟步提出请求时按稳定编组 ID 排序。相同等待请求在候选路径重算或读档后不能丢失等待顺序。暂时无法完整授权的请求保留等待顺序但不占取部分路径，不因其期望资源与其他请求重合就阻止其他可完整授权的通行；不加入货物、客运、速度或手工优先级。

#### 拆分、故障与命令语义

| 事件或操作 | 结果与保护要求 |
| --- | --- |
| 开始执行计划、普通交通等待结束 | 校验当前运行资格与通行权后推进；正常等待不要求每次手工启动。 |
| 停站完成、计划允许的换端 | 满足停留时间和整列停稳条件后继续；换端原子转交活动车头、参考位置与控制，不改变实际车体位置。 |
| 人工停车或停止计划 | 保持停车意图，不由普通等待自动恢复绕过；当前简化停车仍立即清零速度。实际占用与必要道岔锁保留。 |
| 区段内编组拆分 | 按子编组实际车体位置与已有路径原子继承或分配占用、预留和道岔锁，不先全部释放再重新申请。多个子编组可留在同一原独占区段；这是拆分后的物理事实，不是向其他列车开放共同进入。 |
| 拆分后的通行 | 原保护范围对外部冲突列车持续封闭，直到相关车体全部清空才释放。子编组之间也防碰撞；前部停车时，后部滑行须受限或停止。新编组 ID 不产生额外的独立冲突通行权。 |
| 拆分后的计划 | 仅保留原活动车头且仍具备运行资格的子编组继续原计划；其他部分不复制计划，不自动激活备用车头。原活动车头毁坏或失去资格则计划中断，须显式重新分配；无动力部分仍按既有规则滑行并受安全约束。 |
| 前方断轨、车下支撑失效、姿态求解故障 | 沿用下文运动规则安全停车并给出原因。修复后须重新校验并显式恢复，读档或重新规划不能自动解除故障停车。车辆仍在原处时占用不能消失。 |
| 无合法路径、停车空间不足、相互等待 | 分别诊断，显示关联编组、位置和阻塞原因；不能把不可达、长度不合或故障都伪装成正常排队。人为破坏、超长或故意堵塞可以安全停车后由人工调试恢复。 |

本节的编组拆分保护补充下文独立运动规则，不要求所有子编组一律冻结，也不允许无动力部分越过通行界限。世界暂停与显式单步继续采用既有模拟语义，单步不能绕过以上保护。

#### 安全、持续通行与验证

约定的标准网络、计划和负载必须让跟车、迎面会让与汇入持续取得进展。只证明不碰撞、却让所有车永久等待，不算通过。此保证不扩大为任意拓扑和任意列车数量下的自动解锁：缺少会让空间、负载塞满全部等待位置或人为阻断时，应提供可定位的诊断与人工恢复入口。

| 必验场景 | 通过条件 |
| --- | --- |
| 同向跟车、长编组尾部跨区段 | 允许分区段前进；后车不能进入尚未由整列清空的冲突范围。 |
| 单线迎面与会让线 | 合规停车空间及负载下双方最终通过；不各自进入后才发现无处会让。 |
| 同步汇入竞争、三端道岔两种路径 | 同步请求按等待顺序及稳定 ID 仲裁；合法路径可通过，直股与侧股之间不能直接穿越。 |
| 道岔跨占、人工扳道、候选路改变 | 车尾未清空时禁止切换；已有授权不被改道；未授权时可改选可用路径；保护解除后，自动授权可合法覆盖先前人工设置并原子改向。 |
| 长度超过候选等待空间、方向不可达 | 不进入容纳不了整列的空间，不用单车头倒行掩盖无路，输出明确诊断。 |
| 单次与循环计划、停留和双车头换端 | 按序访问，遵守停留时间与换端许可；单次结束停车，正常循环无需重复启动。 |
| 授权后断轨、车下失去支撑、修复 | 仍按实际有效轨道限制移动；停车车辆继续阻塞，修复不自动恢复。 |
| 区段或道岔内拆分，前部停车而后部滑行 | 保护不出现释放空窗，外车不能进入，子编组互不穿透；只有符合资格的原活动车头子编组继承计划。 |
| 排队、停站、授权途中、拆分后保存恢复 | 与不中断运行对照；计划进度、剩余停留时间、等待顺序、路径、道岔锁及拆分保护保持语义一致。 |
| 枚举顺序、显示帧率、暂停与单步变化 | 同步输入在相同模拟步产生相同授权和权威状态，遵守 [04](04-deterministic-simulation.md)。 |

生成契约须为声明支持的编组长度、行驶方向及负载提供可执行路径、足够的站点/等待空间与会让条件；图连通不等于可运行。具体生成配置由[地图与铁路生成契约](https://github.com/odradekk/train/issues/95)确定，实际经过路径、授权/锁、故障冻结姿态及恢复失败规则已由[存档契约](09-persistence.md#列车与轨道引用恢复)确定，负载、观测时长和性能目标由[性能验收](https://github.com/odradekk/train/issues/98)确定，具体数值经[实测与参数冻结](https://github.com/odradekk/train/issues/119)确认；本节不虚构未经验证的列车数量或等待上限。

### Rail Construction

RailConstructionPlan（连续几何、连接与占格方案）→ Validate → RailEditTransaction → Physical Rail State Changes → Rail Graph Update。几何、连接与体素修改原子提交。本阶段由世界编辑器、控制台和生成器共用这一入口；以后加入正式游戏的玩家铺轨、AI 铺轨和地形破坏施工时，也不建立另一套铁路修改规则。编辑器中的修改规则见下节。

### 编辑器中的铁路与车辆修改

> 决策出处：[世界创作工具与铁路编辑的统一交互](https://github.com/odradekk/train/issues/140) Q7–Q10。编辑器界面与操作流程见 [15](15-world-editor.md)；本节规定这些修改须遵守的铁路规则，编辑器不因可以免费、即时修改而放宽本文的几何、占格、净空、通行保护和故障恢复规则。

- **新建线路**：由起终点、方向、高度约束及中间控制点确定连续线路，可从空白位置起线，也可接到合法的接续端点。实际占格、净空和连接按正式施工规则校验，不能提交任意非法样条；没有合规结果时不写入世界。水平三端道岔单独放置，明确三端及连接，遵守本阶段道岔规则。
- **改线与拆除**：改线明确替换范围、接续端点和受影响对象，整体校验后原子替换；拆除明确涉及的轨段和连接。若列车实际占用、通行权、道岔锁等保护，或列车必要的定位引用会因此失效，整次拒绝，不挪动车辆，也不清除保护。
- **伤害与修复**：与改线、拆除分开处理。断轨测试使用正式伤害，保留轨段身份和定位依据，再用正式修复恢复；不能用删除引用伪造故障。修复后的启动遵守下文断轨停车与恢复规则。
- **车辆放置与重定位**：沿轨放置时校验整列姿态、接触点、车钩与净空。已有车辆或编组只有实际停稳才能重定位，并须通过路径、占用和引用校验；世界暂停不等于停稳。编组内的单车须先显式解编，或随整列一起移动；制造、连接、解编、起停和换端是不同的修改，不按距离接近自动连接。
- **站点接轨**：站点与铁路只通过正式施工连接，轨道靠近站点不会自动接通接轨接口。
- **运行计划**：可以修改编组的单次或循环站序、停留时长与换端许可；替换已有计划前须先显式停止原计划并让整列停稳。新计划提交后不自动启动，显式启动后从第一个目标站开始。计划引用的站点不存在时拒绝提交；临时断路、占用或停车空间不足须给出明确诊断，不能靠删车、改道或清除保护让计划显得可以运行。修改计划不解除故障停车。

### 铁路净空

- 游戏存在统一的 Track Gauge 与 Loading Gauge / Clearance Envelope，当前数值见下文首批铁路几何与机械参数。
- 所有合规车辆都应能通过正常生成且完整的线路。首版不设仅允许小车或大车的线路等级；尺寸档位不等于线路兼容等级。
- 玩家设计的车辆必须满足合法 Rail Contact、净空限制、车辆几何约束。RailConstructionPlan 同样验证整条线路的车辆 Swept Clearance，而不只检查 Rail Cell 本身。
- 静态 Building Composite 的实际体素占用与碰撞纳入统一查询：轨道不能与建筑体素占同格，车身经过的净空也必须检查。建筑修改或破坏后查询随之更新；登记不复制体素或改变所有权。

### 单节车辆尺寸

单位为体素格；每个车头或车厢 Composite 单独声明档位，不限制整列长度。尺寸是允许包络的上限，可以不填满，不能自动升档。

| 档位 | 长 | 宽 | 高 |
| --- | --- | --- | --- |
| 小型 | 8 | 5 | 6 |
| 中型 | 12 | 7 | 6 |
| 大型 | 16 | 9 | 8 |
| 超大型 | 20 | 11 | 8 |
| 泰坦 | 24 | 13 | 10 |

- 所有车体体素、附加模块与实体装饰都必须在声明包络内；任一方向越界即非法，改装整体拒绝并保留原车辆状态，见 [03](03-composite-and-behavior.md)。
- 包络相对车辆与接触点基准固定，不只比较可任意平移的包围盒尺寸。原型纵向以两接触点中点为基准，横向对称限制为 ±宽/2；满宽车体侧移同样越界。底高与接触点配置遵守下文首批机械规则，正式实现仍须完成连续机械约束验证。
- 尺寸须支持可进入的内部空间，而非只供外挂模块。原型的一格厚外壳与内部尺度是布局验证，不代表角色、门洞、楼梯或可达性已实现；正式设计器与相关玩法仍延后。
- 尺寸合规只是车辆合法性的必要条件，还须满足接触点、车钩、净空及车体不相交等机械约束。档内任意接触点布置不因此自动合法。

### #32 验证结论与边界

- 用户确认二维观感及 Three.js 简单体素三维观感，五档尺寸（包括泰坦）正式确定。三个原型最初由 `b7a8391` 收入，现统一归档：[几何比较](../../archive/prototypes/rail-geometry.prototype.html)、[车辆包络](../../archive/prototypes/rail-envelope.prototype.html)、[Three.js 三维](../../archive/prototypes/rail-3d.prototype.html)。它们保留为验证资料，不作为正式产品代码。
- 历史二维原型起始参数：水平半径 R = 192 格、期望缓和长度 L₀ = 160 格、坡角 10°、左右各 8 格净空、顶部净空 12 格。它们只通过了当时的二维采样，后续三维原型发现失败；当前标准见下文首批参数。160 格不表示每个水平弯都具有相同的实际缓和长度。
- 水平弯沿用包络与 Three.js 原型的对称曲率渐变规则：对每个非零单弯转角 θ（取绝对值，单位为弧度），入口和出口缓和段各长 L = min(L₀, R×|θ|)，中央圆弧长 R×|θ| − L。两段缓和段合计转角为 L/R，因此该取舍保持指定总转角与半径，并保证中央圆弧长度非负；达到上限时省去中央圆弧。反向弯逐弯计算，不把左右转角抵消后计算。R = 192 时，45° 单弯的 L 约为 150.8 格，90° 单弯的 L 为 160 格。此规则仅解决水平弯的几何取舍，不代替净空与车辆约束验证；坡道原型的坡端倾角过渡仍使用 160 格，不套用水平转角公式。
- 二维固定参数复核覆盖水平弯、反向弯、坡道三个独立案例 × 25 种满尺寸有序双车组合 × 321 个位置，共 24,075 个姿态样本，未发现超净空、侵轨、车体相交或连接缺失；固定轴距与车钩长度误差小于 0.000000004 格。采样通过不等于连续区间的数学保证。
- Three.js 验证了空间尺度、内部展示与刚性车体姿态；三个运行案例仍各处于一个平面，不构成水平弯与坡道叠加的验证。显示只做平移旋转，不能缩放、剪切或弯曲车体来掩盖约束错误。
- 原型接触点间距为车长减 2、前后各悬伸 1、车钩长 1；轨距、轮组、底部高度等也只是实验配置，不自动成为正式规格。
- 实施阶段须补齐实际轨道占格与局部断轨、存档恢复、档内允许设计的机械约束、弯坡叠加、多节编组、双车头换端、两个等效接触点的机械范围、连续扫掠与 Godot 集成验证。本阶段不要求三个以上独立接触约束；#33 不允许单车头倒行，取代早期提及的倒车验证方向。未验证的线路组合不默认开放给生成器；原型不证明所有合规车辆已经能通过所有线路。

### 首批铁路几何与机械参数

[三维弯坡与混编车辆参数决策](https://github.com/odradekk/train/issues/108)已确认 Q1–Q11：原型三维转向、俯仰与停车换端观感符合预期，以下参数和门槛成为本阶段实施目标。决策完成不表示正式引擎、整个连续参数范围或所有线路组合已经通过验收。

- 前后两个等效接触点位于车体纵向中心平面内，在车体自身坐标中同高；轴距与前后悬伸可以调整，包括前后不对称配置。横向错位及高低错层的接触点本阶段不纳入。
- 五档车辆的车钩接口均位于端部横向中央，相对接触点基准采用统一安装高度；连接长度及允许转角采用下述统一标准。车底高度可以不同，车钩接口不能任意上下/左右移动。
- 若候选机械配置与当前起始线路参数冲突，优先保留车辆设计余量，允许适度扩大半径、过渡长度或净空；具体增幅经原型比较与用户确认。不能通过取消已定五档、混编或三维弯坡要求解决冲突。
- B 从实验基准提升为首批线路设计标准，具体下限及净空见下表。历史 A 仅保留为反例对照，不能继续作为正式生成器的兼容标准。
- 坡度过渡长度按水平投影距离配置；实际三维弧长单独计算，不能混用。坡角使用度数，不是坡度百分比。
- 原型独立保留，不合并为正式铁路求解器；采样、用户观感与正式领域/Godot 验收分别记录。

**参数表**（长度单位均为体素格）：

| 项目 | 首批标准 |
| --- | --- |
| 前、后悬伸 | 每端独立允许 0.5–2，可不对称。 |
| 车体底高 | 相对等效接触点基准为 0.5–1。 |
| 轴距 | 声明档位的包络长度减去前、后悬伸；五档分别为 4–7、8–11、12–15、16–19、20–23。 |
| 车钩 | 统一连接长 1、安装高 1；钩向与相应车端纵轴的空间夹角不超过 15°，不是偏航和俯仰分别允许 15°。 |
| 轨距 | 统一为两条轮轨参考线之间 1.5；不等同于轨道实体宽度、道床宽度或行车净空。 |
| 水平半径 R | ≥288。 |
| 期望缓和参数 L₀ | ≥240；逐弯入口和出口各取 L=min(L₀,R×\|θ\|)，中央圆弧长 R×\|θ\|−L，θ 用弧度。短弯的实际 L 可以小于 240。 |
| 坡角与过渡 | 坡角绝对值 ≤10°；水平至最大坡角的过渡 V≥240，+10° 至 −10° 至少 2V=480；长度按水平投影计算。 |
| 净空 | 沿局部无侧倾轨道截面，中心线左右各 9、轨面基准向上 13。 |

坡度变化沿用原型的平滑曲线：单向坡的坡端以 `smoothstep(t)=3t²−2t³` 插值；坡顶/坡谷先在 V 内从水平过渡至 ±g，再在 2V 内按余弦从 ±g 过渡至 ∓g，最后在 V 内平滑回到水平，其中 `0≤g≤10°`。较小坡角沿同类曲线配置，不允许在相同过渡长度内集中形成突变。道岔仍整体水平；其内部合法路径、外接直线间隔和相邻弯坡必须一起验证，不能仅凭满足参数下限就开放任意接续。

**分项精度与安全余量**：

| 检查项 | 验收门槛 |
| --- | --- |
| 接触点贴轨、轴距、车钩长度 | 对权威几何分别检查，各误差 ≤0.00001 格。 |
| 车钩角度计算 | 误差 ≤0.001°，计入 15° 上限，不能作为额外可用角度。 |
| 正常轨段接续 | 位置差 ≤0.00001 格、切向夹角 ≤0.001°；位置和切向连续。 |
| 渲染、碰撞及扫掠近似几何 | 相对权威曲线，位置偏差 ≤0.01 格、切向偏差 ≤0.01°；不放宽接触求解的权威几何残差标准。 |
| 跨段、停稳换端、原点切换的显示连续性 | 同一逻辑姿态切换前后的额外位置差 ≤0.01 格、朝向差 ≤0.01°；正常逐帧行驶位移不属于该误差。数值检查与真实 Godot 人工观察均须通过。 |

安全判断须扣除完整保守误差上界，包括位置近似、角度误差对整个包络的放大以及扫掠区间误差；扣除后，车体之间、车体与非预期障碍或侵轨边界之间仍须保留至少 0.05 格分离余量。预期轮轨接触和车钩连接界面除外。数值分类容差不构成穿透额度；原型使用的 0.0001 格容差不是正式允许侵入量。不能证明安全时继续细化或拒绝候选；目标范围在正式实现中失败须修复或重新决策，不能暗中缩小已批准车辆范围，也不能把停在最后有效姿态当作通过验收。

**原型证据与正式验收的边界**：

- 历史 A（R192/L₀160/V160）的默认机械矩阵为 582/585 项通过；弯中坡谷的泰坦双车、4/8 节泰坦发生盒交叠，8 节加密后最大约 0.283 格。历史 B 默认矩阵为 585/585 项通过；每项 65 个离散姿态。
- 第二轮覆盖四类重点线路的 464 项结构化逐车边界组合、弯中坡谷 25 种有序双车×64 种机械角点组合及 8 项加密复核，共 2,072 项、69,400 姿态通过；不是整个机械区间的连续证明。
- 第三轮修正线路位置积分的步内朝向偏差，重跑第二轮案例，并以已批准车钩参数补齐 15 类线路×39 种默认编组；共 2,657 项、107,425 个范围内姿态通过，两个底高为零的范围外反例仍侵轨失败。线路细分前后最大位置差从约 0.177 格降至约 0.00072 格，说明求解残差与线路近似误差必须分开检查。
- 当前测量的最大钩角约 7.53°、单侧包络约 6.730 格、顶部约 11.076 格、最小底部余量约 0.424 格；最紧张泰坦双车的正分离轴间隔约 0.099245 格，加密后基本一致。这是采样姿态的分离下界，不是连续扫掠保证。
- 补存了非法初始定位（后方轨道长度不足以容纳轴距）及越界紧弯/急坡导致的接触或车钩搜索失败。数值搜索失败仅表示本次算法未找到解，不等同于数学无解证明；这些反例不构成合法完整线路的运行失败。
- 归档的[原型](../../archive/prototypes/rail-mechanics-108.prototype.html)及[原始测量](../../archive/prototypes/rail-mechanics-108.measurements.json)（原始提交 `2f0698a`）分开保留各轮配置、逐车机械参数、采样密度和失败记录。原型的距离残差相对于折线几何计算；分辨率减半的结果接近也不等同于权威曲线误差上界证明。
- 正式实施必须补齐连续参数和扫掠的保守安全判定、实际轨道实体占格与支撑区间、轮轨与车钩接口、跨段接续、局部损伤、存档及真实 Godot 验收。原型中的 15° 道岔分支角最初只是实验配置；后续[生成契约](05-world-generation-and-settlements.md)已将其确定为首批水平左、右三端道岔的模板目标。该选择不等于正式模板已经验证通过，水平进出段、与弯坡的间隔及完整编组路径仍须按本节标准验证；可调输入 UI 不构成全部输入均获批准的证明。

### 本阶段几何与车辆验证契约

本节记录[铁路几何验证决策](https://github.com/odradekk/train/issues/93)。五档尺寸与正常完整线路共用的兼容标准不变；参数原型、正式领域验证和真实 Godot 验收分别提供不同证据，不能相互替代。

**允许的几何与机械模型**：

- 必须支持转弯同时上坡或下坡，以及弯道中的坡顶、坡底过渡。车体同时转向和俯仰；本阶段不加入铁路超高或车体侧倾。
- 每节刚性车辆采用前后两个等效轨道接触点。轴距、前后悬伸和底部高度等允许在验证后的范围内配置，不固定为原型的唯一数值。多个轮组可由这两个点等效表达，三个以上独立接触约束和铰接车体延后。尺寸合规但机械配置非法的 Blueprint 仍须拒绝。
- 五档采用上述统一车钩连接标准：连接后长度固定为 1 格，在 15° 空间夹角上限内允许相对转动，不模拟弹性伸缩、缓冲器或受力动力学。
- 道岔接入水平直线路段，与弯坡过渡保留经验证的间隔；不把整组道岔布置在既有弯道或坡道上。道岔内部的分支曲线仍须连续，所有允许通行的路径满足同一五档车辆约束。复杂交叉延后；本节不决定道岔切换与多车竞争规则。

**最小验证矩阵**：

| 维度 | 必须覆盖的代表案例与结果 |
| --- | --- |
| 线路 | 左右弯、反向弯、上下坡、坡顶坡底、转弯升降与弯中坡顶坡底、连续轨段接续、水平道岔所有允许路径；车体姿态与连接连续，无缩放、剪切或弯曲补偿。 |
| 尺寸与混编 | 五档全部动态运行；短编组覆盖相邻两车的五档 5×5 有序组合。总计 4 节、8 节（均含车头）的较长编组，各自覆盖同档、大小交替和两端朝外车头。它们是验证负载，不是整列长度上限，不要求穷举所有长编组排列。 |
| 标准生成地图的列长能力 | [生成契约](05-world-generation-and-settlements.md)追加 10 节泰坦（含车头）的服务能力目标，直线名义长度 249 格；补验全路径、站点、等待区、会让、换端和车尾清空保护。停车余量与弯道占用另算，不替换原有 4/8 节矩阵，也不回写历史原型通过数。 |
| 机械参数 | 轴距、前后悬伸、底部高度、车钩长度/转角均覆盖批准范围内的代表配置、边界及越界反例；固定包络、接触点距离和车体不相交分别检查，不能只跑五种默认 Blueprint 就宣称范围内所有设计合规。 |
| 占格与净空 | 由钢轨、轨枕等实体形成占格及支撑区间；检查实际地形/建筑占用与车辆扫掠净空。中心线采样格不能代替实体占格，净空不能登记为轨道体素，局部删除只损坏相关区间。 |
| 连续路径检查 | 覆盖步内跨段、步内经过窄缺口或障碍以及端点合法但中途非法的情况；所有必要接触点与车体均受约束。离散姿态采样本身不能证明连续空间安全，正式校验须有保守判定或等效的不漏检保障。 |
| 状态转换 | 起停、双车头停稳换端、车钩/车体断裂、独立滑行、前方缺口、车下支撑失效及修复后显式启动；沿用既有状态规则并覆盖新增几何和较长编组。 |
| 确定性与恢复 | 同一按步输入在不同显示调度下结果一致；运行、换端后、滑行及断轨停车的保存恢复与不中断分支对照。图重建、显示插值和相机切换不改变权威位置。 |
| 真实表现 | Godot 中人工观察弯坡、车体刚性、车钩、轨道接缝/缺口、事件后的插值和同姿态相机跟随。原型观感或 headless 成功不替代该项。 |

矩阵按能力交叉选取代表案例，并在规格中记录覆盖关系；不要求所有维度的笛卡尔积。多列车竞争场景由[网络运行规则](https://github.com/odradekk/train/issues/94)补充，负载上限及性能门槛由[性能验收](https://github.com/odradekk/train/issues/98)确定。

**参数与数值门槛**：

- 上述首批参数与分项门槛是当前实施目标；R192 等起始值仅保留为历史对照，不再作为生成标准。历史原型约 4e-9 格的观测误差不是统一产品门槛。
- 原型采样通过不授权正式生成器开放对应组合；还须通过实体占格、连续路径检查、局部损伤、存档与真实 Godot 验收。未经验证的组合不得默认开放。正式范围内出现失败时记录并修正，不能靠事后放宽门槛掩盖错误。

**非法方案与未预期失败**：

- 生成、制造或改装阶段发现非法方案，拒绝整项原子方案，保留原状态并报告原因；生成器可按既定有限重试规则提出新的方案。
- 运行中未能求出合法姿态时，拒绝该次移动，保留该次移动前最后合法姿态，停止受影响编组并输出可复现的故障信息；不得拉伸车体、跳轨或穿透继续。正常合法线路和车辆触发此处理仍判验收失败，安全停止不是成功运行的替代品。
- 上述故障处理不改变已定的断轨、支撑失效和加载失败语义，也不取消已提交的其他合法操作。故障诊断状态与恢复的具体表达由[确定性和存档恢复契约](https://github.com/odradekk/train/issues/97)接续。

### 桥梁和隧道

- Bridge 与 Tunnel 与 Rail Definition 正交：Bridge Structure + Rail Voxels，而不是 bridge_rail；隧道是 Terrain excavation + Tunnel structure + Rail。桥梁可以没有铁路，铁路也可以不在桥梁上。
- 首版世界生成器不自动生成桥梁和隧道，见 [05 的自动施工范围](05-world-generation-and-settlements.md#本阶段无资源生成契约)。

### Rail Movement

本节及下文是编组运动、断开与滑行、断轨停车与恢复的权威规则；[07 的列车插值](07-rendering.md#列车插值) 只补充显示契约，[09 的列车与轨道引用恢复](09-persistence.md#列车与轨道引用恢复) 只补充保存、重建与加载校验契约。

- 列车是 Path-constrained / Kinematic Entity，而不是 RigidBody 驱动（转录 Q144：RigidBody 会脱轨抖动、穿透、破坏确定性）。
- 每个实际连接、具备沿轨运动条件的 Train Assembly 统一管理运动，由一个参考接触点的 RailPosition 驱动；各车厢或接触点不各自独立推进距离。各节车体的 World Transform 由接触点约束解派生。
- 有活动车头时以其前接触点为运动参考。换端或编组断开时，参考点可转交，但须从事件发生时已有的接触点状态建立，保持实际位置、姿态及运动连续性，不能重新摆车或从渲染位置反推权威状态。
- 没有活动车头的脱离编组仍需自己的定位参考及速度状态，以支持沿轨滑行；保留接触点求解结果不代表允许各接触点独立控制运动。

### 现有直轨实现

- 出处：[#70](https://github.com/odradekk/train/issues/70) / 合并提交 [`8d60d46`](https://github.com/odradekk/train/commit/8d60d46cf24452b4f2d1df05502bab8f84227998)。以下记录现有直轨实现的有动力运动，不表示弯坡、双车头换端或最终动力参数已完成验证。
- 依照 [04](04-deterministic-simulation.md) 使用固定模拟步长；当前 `SimulationClock` 为 60 Tick/秒，Δt = 1/60 秒。速度单位为格/秒、加速度为格/秒²，每 Tick 积分得到沿轨位移，再统一求解编组位置。1× 主机时钟累积显示帧耗时并转换为完整模拟步，余时用于 [07](07-rendering.md) 的沿轨显示插值；不按每个渲染帧直接推进固定距离。
- 有效活动车头提供目标速度和加速度；当前按恒定加速度向目标速度逼近（高于目标时按同一加速度幅值减速）。未在步内达到目标时，以该步首尾速度的平均值乘 Δt 求位移；步内达到目标时，分别累计加速或减速阶段与剩余匀速阶段的位移。当前默认目标速度为 4 格/秒、加速度为 2 格/秒²，属于内容默认值，不是最终平衡参数。
- [`rail start`](../console/rail-start.md) 与 [`rail stop`](../console/rail-stop.md) 作用于指定编组，可指定当前或未来模拟步；同一步按入队顺序执行，在该步运动积分前生效。当前步命令立即执行，但命令本身不推进 Tick 或积分位移。启动检查动力、控制及轨道条件，开启牵引并保留当前速度，静止编组随后从零加速；停车立即清零速度并关闭牵引，不保留待恢复的旧速度。这是当前简化停车语义，不是无动力滑行或完整制动模型。
- 单车头不能通过负速度倒行，到线路末端停车且不自动反向。断轨、支撑失效及修复后显式启动遵守下文规则；速度、牵引状态及待执行命令属于恢复所需的模拟状态，保存与恢复遵守 [09](09-persistence.md#列车与轨道引用恢复)。

### RailPosition 与物理引用

- RailPosition 描述物理轨段稳定 ID、沿该轨段的距离和朝向；不是压缩图 Edge 引用，也不是 Cell 加格内进度。朝向表达参考车辆纵向与轨段方向的对应关系，不是“给单车头负速度即可倒行”的许可。
- 逻辑图拆边、合边或重建不改变 RailPosition。局部断轨不重新编号剩余区间，也不移动沿程原点；能定位与能通行是不同事实。
- 只要仍有列车引用，就保留轨段身份及定位所需几何；即使所有实体轨道已被破坏，也只表示其有效通行区间为空，不删除被引用的定位依据。
- 修复原轨段后可以重新校验；另建轨道具有新的身份，不因空间接近而自动接替旧引用。引用的保存、重建与加载失败处理见 [09](09-persistence.md#列车与轨道引用恢复)。

### 多接触点车辆约束

- 车辆不使用单个中心点切线决定姿态。Composite Definition 定义前后两个等效轨道接触点（Front Contact 与 Rear Contact / Bogie Anchors），分别计算对应 Track Path Point；车体位置与姿态由两点约束共同决定。本阶段机械边界见[验证契约](#本阶段几何与车辆验证契约)。
- 前后接触点须保持车体中的固定空间距离，不能直接用相同数值的轨道弧长差代替；沿弯道两者不同。按编组车辆顺序、各车接触点间距和车钩约束，从参考点求出其余接触点及各车刚性姿态，不能仅以“车头沿程减去车长”排列车辆。
- 求解沿编组所处的同一条连续物理轨道路径进行，不能按世界坐标逐个寻找最近轨道。跨轨段时须沿明确连接接续；具体数值求解、精度与恢复同一约束解的验证在实施切片完成。

### 编组断开与无动力滑行

- 单节 Composite 断裂先按 [03](03-composite-and-behavior.md) 处理连通碎块及身份，再依据仍然存在的车辆、接触条件和车钩连接确定实际编组。主碎块继承身份不代表能保留已经断开的物理连接。
- 例如车头—A 与 B—C 之间断开后，两部分若仍具备沿轨运动条件，就分别拥有运动状态与参考点；后段不再跟随原车头，也不被隔空牵引。断开瞬间的位置、姿态与运动连续，不将新编组速度简单重置为零。
- 前段若仍有有效动力、控制与轨道接触条件可以继续行驶；后段没有活动车头牵引时按可配置减速度沿当前运动方向逐渐停稳。首版不模拟完整制动管路、复杂阻力或坡道反向溜车。
- 后段即使包含另一端车头，也不自动激活；须停稳后显式启用并校验新方向。无动力滑行不是主动倒车，沿途仍适用断轨安全处理，以及[网络运行契约](#本阶段网络运行契约)的通行边界、实际占用和子编组防碰撞约束。
- 断裂后的车壳不能自动当成完整车厢继续沿轨。失去车辆存活条件的碎块走已有脱落流程；车辆身份、实际连接和沿轨运行资格仍分别判断。

### 单向牵引与双车头换端

- 车头只能朝自身前方牵引，单车头列车不能倒行。需要反向运行时，编组两端各有一个朝外车头，通过另一端车头前进实现。
- 同一编组任一时刻最多一个活动车头提供牵引；另一车头不同时提供动力，只随编组被牵引。轨段沿程正负方向与车头能否倒行不能混为一谈。
- 整列停稳后才允许换端；原子解除旧车头牵引、转交参考点与控制，再允许新车头启动。新方向须通过轨道、连接与车辆约束检查，不能在两个车头同时运行的中间状态下推进模拟。
- 换端不翻转车辆或改变实际连接关系，也不自动切换相机目标。此规则取代讨论中曾提出的“保留固定首车参考、负速度倒车”及“单车头倒车退出断口”。

### 断轨停车与恢复

- **前方出现缺口**：检查整个编组所有必要接触点在本次移动中经过的路径，在任一点进入缺口前限制整列本次移动并停车。不能只看参考点或 Tick 终点而越过缺口。
- **当前接触点下的轨道被破坏**：受影响编组立即暂停沿轨运动，速度归零，保留当前模拟位置与姿态并明确显示“轨道支撑失效”。不瞬移到附近轨道，也不自动切换到刚体脱轨；其他独立编组继续按自身状态运行。
- 两类断轨停车都不保存等待恢复的旧速度。支撑失效暂时可能呈现车辆悬停，这是首版调试安全处理，不是真实制动或事故模拟，后续事故系统再接管。
- 修复后重新检查支撑、连接及运动约束，通过后也只变为可启动；必须显式启动，从零速度重新加速。读档不会自动解除停车；恢复校验见 [09](09-persistence.md#列车与轨道引用恢复)。
- 仅前方受阻、当前支撑完整时，可在满足双车头规则的前提下停稳换端并校验另一方向；不存在单车头倒车脱困。支撑失效时不能通过换端绕过当前支撑校验。
- 本阶段由世界编辑器和控制台的正式修复与启动操作提供恢复入口，不要求实现正式游戏的玩家修轨玩法或运营 UI。

### 沿轨渲染插值

- 沿编组实际经过的物理轨道路径求显示参考位置，再按接触点和车钩约束求整列刚性姿态；跨轨段时沿明确接续路径求解，不能直接混合不同轨段的沿程数值，也不能独立直线插值各车世界坐标而切角或破坏连接约束。
- 编组断裂、换端或支撑失效时结束旧状态插值，按已提交的事件后关系重新建立显示状态；不在旧车头和新车头的位置之间拉出过渡，也不把不同编组约束混在一起。位置依据为已提交的模拟状态，不是上一渲染帧。
- 显示的时间边界、派生状态与相机衔接统一见 [07 的列车插值](07-rendering.md#列车插值)。

### #33 实施验收边界

本节确定契约，不宣称已有运行实现。对应切片须验证：压缩图重建不改变位置；跨物理轨段与双车头换端连续；断裂后独立滑行及牵引互斥；大 Tick 移动不越过缺口；车下断轨与显式恢复；被引用的全毁轨段读档可定位但不可通行；缺失引用报错；改变渲染帧率不改变模拟、车体刚性与相机目标不随换端翻转。测试基于实际命令和状态，不依赖渲染帧回写。

### 碰撞

事故碰撞触发伤害的玩法留到后续版本；首版通过 [03](03-composite-and-behavior.md) 的调试伤害操作验证损伤与断裂。以下为后续事故系统的边界，不构成首版实现要求。

- 正常列车运动不使用刚体物理求解。发生事故：Movement → Swept Collision Detection → Collision Event → Deterministic Collision Resolver → Damage Transaction。
- Godot Physics 可以辅助检测，但不成为正常列车位置和 Gameplay Damage 的权威来源。视觉层可以自由播放非确定性的粒子碎片，只要不改变 Simulation 结果。

### 动态 Voxel 脱落

移动 Composite 中的 Voxel 或 Fragment 脱落后，需要从连续空间回到整数 World Grid，采用逻辑 Snap + 视觉动画补偿。对整个 Fragment：

1. 获取当前连续 World Transform；
2. Rotation Snap 到最近正交方向；
3. Anchor Snap 到 World Grid；
4. 根据 Local Grid 得到全部目标 Cell；
5. 检查冲突；
6. 在有限半径内按确定性顺序寻找完整可放置位置；
7. 成功后整体 ownership transfer；
8. 如果无法完整放置则销毁；
9. Presentation 播放自然的坠落或碎裂动画。

不逐 Voxel 独立 round。

## 首版范围

物理轨段连续几何、明确连接、实体占格与局部断轨；直线、连续水平弯、平滑缓坡及弯坡叠加；五档动态验证与跨档混编、前后等效接触及固定长度可转动车钩；水平基本道岔的合法路径；compressed graph、稳定 RailPosition、编组约束运动、断开后独立滑行、双车头互斥换端、断轨停车与显式恢复、沿轨插值。所有轨道默认双向；单车头不能倒行；世界编辑器、控制台与生成器共用同一施工事务入口，编辑器中的铁路与车辆修改遵守上文规则。站点顺序运行计划、三端道岔控制、完整路径授权、区段独占与车尾释放、确定性通行仲裁及拆分后的持续保护纳入本阶段，遵守上文网络运行契约。
