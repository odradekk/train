## 不变量

- 列车在世界图上的位置是权威位置，场景中的位置由它派生。
- 列车只在节点等待。在线路上不中途停下，减速只因跟车、前方限速或停车点，前方断轨和遭遇战斗时例外。
- 同一条铁轨上，同一时间只有一个方向的列车。
- 通行结果不由列车的遍历先后决定：等待按先后，同时到达按稳定编组 ID。
- 线路的铁轨数只由扩建改变；断点只由生物袭击线路或调试命令产生，由修复消除。

## 规则

### 列车编组

- 列车（编组）是由编组命令组成的一组车辆，在世界图上作为一个整体运行。成员只在编组、解编命令下变化，或因车辆被摧毁而减少，见 [03](03-vehicles-buildings-and-designs.md#损伤与战斗事件)。
- 编组和解编只能在玩家自己或非敌对的聚居地进行，列车须停在该节点。编组命令给出有序的车辆列表；顺序只影响场景显示，车头可以放在任何位置。不同档位的车辆可以混编。
- 不在编组中的车辆停放在所在的聚居地，新建的车辆出现在建造它的聚居地。停放容量见 [16](16-settlements.md)。
- 列车的牵引、选路和战斗不受车体朝向限制，在节点可以从任何一条线路离开。核心只保留一个供场景还原的编组正反标记，表示有序车辆列表的首端还是末端沿最近实际行驶方向在前；编组后默认首端在前。这个标记随存档保存，不参与上述玩法计算。线路上倒车时切换该标记，车辆列表和中心位置不变，场景表现为推送运行。经过节点继续向其他线路行驶时保持标记，沿进入线路原路返回时切换；只改变待选路线或等待状态不提前切换。
- 列车能开动，须编组中至少有一个完好的控制部件，总牵引力大于 0，并且加速度不低于下文的下限（[合法性规则：通用规则、类别声明与行为附带的规则](https://github.com/odradekk/train/issues/263)）。单辆车没有控制或动力不算不合法，只是不能自己行驶。

### 位置

编组中心与显示正反由[体素引擎公开契约](https://github.com/odradekk/train/issues/289)确认；它们使倒车、重新打开场景与读档后的排列保持一致。

- 列车要么在节点，要么在线路上：
  - **在节点**：记录节点编号、实际进入线路 `EnteredFrom` 及进入铁轨 `EnteredTrack`、已决定的下一线路 `NextEdge` 及驶出铁轨 `NextTrack`、阶段 `Phase`、编组中心沿节点运行路径的距离 `DistanceMeters` 和可空站台号 `PlatformNumber`。这些字段构成唯一权威位置，不再另存节点转场对象。
  - **在线路上**：记录线路编号、铁轨号、行驶方向（正或反），以及整列长度中心到线路起点沿正方向的距离，范围为 0 至线路长度。距离以米为单位，使用 `double`。正方向和断点的记法见 [05](05-world-graph-and-generation.md#世界图)。
- 列车长度等于各节车辆长度之和，按车辆设计属性中的车辆长度（格）乘 0.5 米计算，用于跟车间距及场景排列。车辆被毁后保留幸存车辆的顺序、中心和编组正反标记，按新总长度围绕中心收拢；全部被毁时移除列车。
- 中心到端点时，整列切换为节点状态；从节点进入线路时，中心置于入口端点。显示长度可以伸出线路端点，但核心不记录车尾跨线路占用，也不等待车尾清空才释放旧线，保留列车作为一个整体在图上运行的抽象。

### 速度

- 单位为米、秒、米/秒、米/秒²、吨、千牛。
- 动力部件的定义给出牵引力和额定速度。列车的总牵引力是全部车辆中完好动力部件的牵引力之和，被毁的部件不提供牵引力。
- 最高速度取完好动力部件额定速度中的最小值。
- 加速度 = 总牵引力 ÷ 总质量，在 Demo 中恒定，不随速度变化。总质量是各车辆的设计质量与所载货物质量之和。
- 制动减速度是内容常量。列车会提前制动，以便满足节点限速、停车点和跟车间距约束。
- 加速度低于内容设定的下限时，列车不能启动，并报告超载。
- Demo 中线路不限速，地形已经通过绕行系数计入线路长度。

每步按加速、巡航、制动三段精确积分。对前方距离 d、目标速度 u 的每个约束使用制动包络 `v² ≤ u² + 2bd`，取最严格者；非零终速的峰值为 `v_peak² = (2abd + b·v0² + a·u²) / (a + b)`，再受最高速度限制。节点内最高速度取车辆能力与站区限速的较小值，前瞻距离计入各节点实际长度。

需要站台的列车每步根据步开始时已提交状态预测：已持预约，或空闲站台数大于排在它前面的等候列车数，以 S 为停车点，否则以 W；进入节点才正式预约。已定驶出铁轨按已提交状态不可进入，或尚无可定铁轨时，以 L 为停车点提前制动。预测不登记驶出线路的首次排队步；只有中心到 L 正式入线检查失败才登记 `QueueEnteredStep`。预测失效且来不及制动时才使用强制停车例外。

强制停车例外指来不及制动时，在该步写入零速度，并将列车停在应停点。到达线路端点或节点出口 L 的步骤截断于端点，舍去该步剩余时间。

### 铁轨与通行

- 一条线路有 0 到铁轨上限条铁轨，从 1 起编号，每条都可以双向使用。线路上没有闭塞分区。
- **方向锁**：第一列车进入一条空铁轨时，这条铁轨锁定为它的方向；铁轨上没有列车后解锁。
- **同向跟车**：两列车的中心间距不小于两列长度之和的一半加最小间距，最小间距是内容常量；入口是否有空间使用同一条件。后车追上前车时减速跟随，不能在线路上超车，也不能中途换轨。
- **选轨**：进入 `Departing` 时确定驶出铁轨 `NextTrack`：中心在 S 或之后且本步实际移动，包括途经越过 S 和停靠后的首次实际起步；内容适配使已越过新 S 的进站列车转为出站时也确定。启动命令或停留结束不提前转换阶段；转换前仍按整条下一线路预测可进入性，转换后只检查固定铁轨。按顺序选择：
  1. 已锁定为本方向、入口处跟车间距和制动距离足够，且满足对向等待与交让规则的开放铁轨；
  2. 空的开放铁轨；
  3. 都不可进入时，取编号最小的开放铁轨，驶到 L 后等待它可进入。

  同一类中选编号最小的。预选时，同一驶出线路上其他 `Departing` 列车已定的驶出铁轨视为入口处已有列车，既不作为空轨，也不作为可跟车铁轨；这不提前占用铁轨或锁定方向。原路返回同样按此规则选择，不强制使用原进入铁轨。
- **选轨快照**：每次 `Advance` 的每个模拟步以步开始时已提交的 `WorldState` 为准，读取线路占用、对向等待、交让和其他列车已定驶出铁轨，不计同一步更早的新选择。因此同一步同时确定的列车仍可能选到同一条轨。命令中的选择读取命令前已提交边界，内容适配中的选择读取适配前快照。L 点正式入线仍按原有串行仲裁检查固定铁轨，同轮后授予的请求看到先授予的占用和入口空间。
- **保持与重选**：停车、换计划不改变已定驶出铁轨。固定铁轨因断点或修复施工关闭，或因铁轨数减少被删除时，按上述规则重选；没有开放铁轨时，原铁轨仍存在则保留，否则 `NextTrack` 为空。初次出站没有开放铁轨也为空，出现开放铁轨后重新选择。非 `Departing` 阶段的 `NextTrack` 为空；非空时须有 `NextEdge`，轨号在当前铁轨数内。失效重选可能使节点内路径瞬时切换，这是已知例外。进入线路后直到下一节点前不换轨。

- **防止饿死**：只要有对向列车在节点等待进入这条线路，本方向的新列车就不再进入。清空的铁轨只交给已定驶出铁轨就是该轨的对向等待列车；交让仅在该方向仍有等待该轨的请求时保留，L 点不换轨。
- **等待顺序**：先到先得，同一步到达按稳定编组 ID 排序。等待顺序随存档保存。
- 有断点或正在修复的铁轨不能进入，见下文断轨。

### 节点与站台

- 节点上停留或经过的列车数量不设上限。节点内每列车各走一条站内线，互不跟车、互不阻挡；预约站台号就是该列车的站内线，无站台号的列车所走的线由场景分配（#443）。
- 节点沿运行路径分为进站段 A、站台段 P、出站段 D；等候点 W = A，停站点 S = A + P / 2，出口 L = A + P + D。A、D 和站区限速来自铁路规则，初值分别为 80 米、80 米、15 米/秒。P 来自该聚居地保存的模板副本：Content 按设计 16 的站点包络投影站点地块沿轨长度的最大值，无站点地块为 0；空节点、生物聚落的 P 为 0。Core 不重复定义包络常数。
- 只有非敌对聚居地的 Station 停留需要预约站台；途经及其他节点的停留不预约，站台号为空。站台数量由站点建筑提供，见 [16](16-settlements.md)。进入节点时正式申请，按申请先后、同一步按稳定编组 ID 分配可用站台，从 1 起取最小空闲号；站台占用由预约派生。
- 预约从获准起一直保留到中心驶出 L，或列车删除、解编；节点内停车、换计划、出站和等铁轨均不释放。站台数减少时不重排已有预约，已有编号可以超过新容量，占用可以暂时超过新容量，新申请等待。

| 阶段 | 位置与转换 |
| --- | --- |
| `Approaching`（进站） | 从线路进入时距离为 0，发 `TrainArrived`；需要站台时正式预约，无预约则制动到 W |
| `Waiting`（等候） | 在 W 等预约，获准后转回 `Approaching` 向 S 行驶；只有需要站台的列车受无预约不得越过 W 的限制 |
| `Docked`（停靠） | Station、计划终点、停车及原路返回在 S 停稳；Station 在停稳且已获所需预约的当步进入 `Servicing`，设置完整停留余时，下一步开始递减 |
| `Departing`（出站） | 中心在 S 或之后且本步实际移动时进入，并消费途经目标；需停车者在停稳、完成停留或启动后的首次实际起步时进入。出口不可进入时停在 L，活动为 `Waiting`，仍持预约；进入此阶段时确定 `NextTrack`；中心到 L 时只检查固定铁轨，不临时换轨，获准后转入线路位置并释放预约 |

- 生成或编组的列车位于 W，阶段 `Waiting`、活动 `Stopped`，没有进入线路及铁轨、下一线路及铁轨和站台号，不发 `TrainArrived`；首次出发或本站停留走正常进站过程。
- 换计划或启动时才新增本站 Station，若进站列车已过 W 但尚未越过 S，或已静止在 S，则立即按产生该需求的模拟步申请；申请不到也不拒绝命令，制动到 S，以 `Docked`、空站台号、活动 `Waiting`、原因 `platform_wait` 等候，获预约后才开始停留。已越过 S、处于 `Departing` 的列车（包括停在 L 等铁轨的）仍保留已定驶出线路，先驶出，返回本站时再预约和停留。
- `PublishContent`、`PrepareRestore` 不因节点尺度或限速变化拒绝，也不新增保存字段。静止在 W、S 的列车移到新对应点；`Departing` 阶段且活动为 `Waiting`、已有 `QueueEnteredStep` 的列车正在 L 等铁轨，移到新 L；其他 `Departing` 列车（包括失去动力停在中途或在 L 为 `Stopped` 的列车）及行驶中的列车保留距离并截到新 L 内，不依赖旧内容投影；必须停车但已越过新 S 的进站列车置于 S、速度归零；不必停车且已越过新 S 的进站列车转为 `Departing`，并依序消费当前节点的途经点。超出新限速时按正常制动减速度减速。
- 空节点只能经过和等待，不提供服务。生物聚落和敌对聚居地不向玩家提供服务，玩家列车到达时会开战，见下文战斗中的列车。

### 运行计划

- 运行计划由有序的停靠站和途经点组成，可以是单次或循环。停靠站和途经点都是节点。
- 每个停靠站设一个停留时长，按模拟时间计算。列车在 S 停稳且已获所需预约的当步开始停留，设置完整停留余时，下一步开始递减；交易规则在停留期间执行。
- 途经点只经过、不停车，用来指定路线，例如避开危险的线路。
- 单次计划走完后，列车停在最后一站并发出事件；循环计划继续运行。出站换计划时若当前节点的途经点被依序消费后单次计划已完成，则按下述停车规则处理。

### 选路

- 列车每到一个节点重新选路，线路中途不改道。目标是计划中的下一个停靠站或途经点。
- 选预计用时最短的路径，按线路长度和列车最高速度估算。只考虑至少有一条可进入铁轨的线路，不考虑拥堵。用时相同时，按线路编号的稳定顺序选择。
- 敌对聚居地和生物聚落不作为中间节点，只有它本身是计划中的下一个停靠站或途经点时才进入。
- 没有可达路径时，进站列车停在当前节点的 S，阶段为 `Docked`；从 W 生成或编组后出发的列车停在 W，阶段为 `Waiting`。两者活动均为 `NoRoute`，发出“无可达路径”事件。铁轨数或断点变化后，自动重新选路。

### 命令

列车与线路的命令包括：编组、解编、设置或替换运行计划、启动、停车、扩建线路、修复断点、设置自动修复。机制与编码见 [04](04-deterministic-simulation.md#命令)，字段在代码重构时定义。

- 替换计划立即生效，从新计划的第一站开始，保留节点内位置和已有预约；进站时可重选下一线路，出站时保持已定线路。正在线路上的列车先开到前方节点。出站阶段（含停在 L）的列车依序消费新计划开头指向当前节点的途经点；本站 Station 仍先驶出再返回。若消费后单次计划完成，仍在行驶的列车保留已定驶出线路，设置停车请求，继续驶出并在下一节点 S 停稳后转为 `Stopped`；已静止在 L 的列车原地转为 `Stopped`，清除停车请求和排队步。仍在行驶的列车若到 L 正式入线检查被拒绝，也立即原地转为 `Stopped`，清除停车请求和排队步，不转为 `Waiting`；保留预约和下一线路，预约仍到实际驶出、删除或解编时才释放。
- 停车命令让线路上的列车在前方节点 S 停稳；节点内进站阶段制动到 S，来不及时使用强制停车例外；已过 S 的继续驶出并在下一节点停车，静止列车原地停车。启动继续执行计划。原路返回必须先在 S 停稳，反向起步时才切换 `OrderFacing`。
- 编组、解编的条件见上文。

### 断轨

- 断点记在某条铁轨上，见 [05](05-world-graph-and-generation.md#世界图)。一条铁轨上只要有断点，整条就不能进入，直到所有断点修好。
- 已经越过断点的列车不受影响。前后按列车的权威中心位置判断，沿用图上整体定位，不增加车头或车尾跨断点占用。
- 前方有断点的列车在断点前停下，掉头开回出发的节点，再重新选路。跟在它后面的列车同样掉头，前后顺序保持不变，方向锁随之反转。
- 断点由生物袭击线路产生，见 [17](17-combat.md#世界生物)，也可以由调试命令产生。普通战斗不产生断点。

### 战斗中的列车

- 列车遇到敌对单位时开战。线路上参战的列车按正常制动减速度停下；战斗结束前不能离开，撤退除外；战斗结束后继续执行原计划。开战、加入和交战规则见 [17](17-combat.md)。
- 撤退的列车在线路上掉头开回出发的节点，同一铁轨上跟在后面的列车一起掉头，方式同上文断轨；在节点上则开往按用时最近的自有或非敌对聚居地。到达后停车并发出事件。
- 运行计划可以把敌对聚居地列为停靠站或途经点，用于进攻或围困。到达后开战；停留时长照常计算，但不能交易、装卸或使用服务。

### 修建、扩建与修复

- **扩建**：每次让铁轨数加 1；新建线路就是从 0 加到 1。铁轨数加上进行中的扩建任务数，不超过铁轨上限。消耗的 Rail 货物等于线路长度 × 每米用量，工期与长度成正比，完工后新铁轨可用。
- **修复**：每个断点固定消耗一定数量的 Rail 货物，工期固定。修复期间这条铁轨保持关闭。
- **材料来源**：玩家指定一个自己的聚居地，开工时从它的库存一次扣除；不足就拒绝开工。不需要运送材料，也不需要工程列车或设施。
- **自动修复**：玩家可以设置自动修复并指定来源聚居地。出现断点后，材料足够就自动开工；不足就发出事件，等材料够了再开工。
- Demo 不做拆除铁轨。
- Rail 是可生产、可库存、可交易的货物，见 [11](11-goods-and-production-network.md)。每米用量、每个断点的用量和工期是内容数值。

### 场景中的线路与列车
