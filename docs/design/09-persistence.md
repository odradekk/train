# 09 存档

> 决策出处：转录 Q29、Q42、Q79–Q88；2026-09-05 #34 确认无状态随机与浮点往返要求；[#35](https://github.com/odradekk/train/issues/35) 确认当前外部定义绑定与落盘方式，见 [ADR-0005](../adr/0005-resolve-current-definitions-and-separate-content-versions.md)。

## 边界

本文定义存档的组成、世界重建方式与兼容策略。Save-local Definition 的来源规则见 [02](02-definitions-and-content.md)；Stateful RNG 与运行时 ID 见 [04](04-deterministic-simulation.md)；资源与生产系统各 Job 的语义见 [10](10-resources-and-extraction.md)、[13](13-production-runtime-and-facilities.md)、[14](14-construction-refit-and-deconstruction.md)。

## 不变量

- 基础世界通过 Seed + GeneratorVersion + 完整生效生成配置 + 有效生成语义内容重建，之后应用 Runtime Delta。固定配置使用独立来源身份；生成输入见 [05](05-world-generation-and-settlements.md#复现输入与输出)，基底、版本与封装要求见下文本阶段契约。
- 所有主要格式从现在开始保留 Version 字段。
- Next Transaction ID、Next Entity ID、Save-local Definitions 必须进入存档；首版只有无状态随机，不需要保存可推进的 RNG State。后续添加有状态随机流时，其完整状态必须进入存档。
- 旧 Save 不能因为 Generator 更新而偷偷使用新算法重新解释世界。

## 规则

### 首版存档

```text
Save
├─ SaveFormatVersion
├─ WorldSeed
├─ World Source（生成器版本，或固定配置 ID / 版本）
├─ Effective Source Configuration + Content References + Base Fingerprint
├─ Runtime Delta
├─ Simulation Step + Boundary Operation Sequence + Pending Commands
├─ Next Transaction ID
├─ Next Entity ID
├─ External Definition References（DefinitionId + 上次使用的 Revision）
└─ Save-local Definitions
```

上图为本阶段逻辑组成，具体字段编码随实现规格冻结。Runtime Delta 须保留本节确定的实际结构、铁路路径与保护、故障、建筑修复目标和残块来源等事实；不能将 Seed 和 GeneratorVersion 视为充分重建输入。普通存档、世界来源与复现包分别按各自格式/规则版本解释，外部 Semantic Revision、Asset Revision 和运行时 Catalog Generation 的职责继续遵守 [02](02-definitions-and-content.md)，不能用目录发布计数代替持久版本身份。

后期如果加载性能出现瓶颈，用 Snapshot + Delta 作为优化。首版不做完整 Event Sourcing。

连续量以可无损往返的 JSON 数值保存，使用与文化无关的 round-trip 表示，恢复相同的 `double` 值；不截断小数位，不允许非有限值。在有效语义内容相同的前提下，验收须比较中途保存恢复与不中断运行的结果，详见 [04](04-deterministic-simulation.md)。

物理轨道的连续曲线参数、明确连接、轨道体素及其对应关系属于待恢复的领域状态，见 [06](06-railway.md)。基础部分可由相同生成基底精确重建，修改与缺损由 Runtime Delta 恢复；不能只保存剩余占格后重新拟合曲线。恢复后须保持原有形状与缺口，渲染网格、弧长采样表和压缩路网仍是派生数据。

### 本阶段保存与复现契约

[确定性和存档恢复决策](https://github.com/odradekk/train/issues/97)已确认 Q1–Q15。以下是实施目标，不表示正式实现已通过验收。稳定身份与确定性证据矩阵见 [04](04-deterministic-simulation.md)；录制容量、起点间隔及开销须按性能实验冻结。

#### 生成基底与来源身份

- 普通存档继续采用重建初始世界后应用 Runtime Delta 的方式，记录完整生效生成配置及可核验的基底指纹。指纹覆盖解释 Delta 所必需的生成布局、稳定身份和结构关系，须明确编码范围；不能仅用现有简单体素布局指纹代表完整生成网络。
- 先确认生成器支持并核验重建基底，再应用 Delta 和当前定义的状态适配。无法一致解释原状态则整次失败，不静默生成另一张地图，也不新增全世界快照作为旧档兼容兜底。
- 不改变基底解释且通过适配校验的外部零件数值更新仍可生效；实际布局和绝对耐久等状态继续按既定规则保留。基底一致性校验不能取代实例状态保存，也不把所有外部 Revision 变化一概判为不兼容。
- 固定 Playground 配置以自身标识、版本、生效配置及内容依赖描述来源，不能冒充 GeneratorVersion；生成地图与固定配置均须提供足够的重建依据。

#### 普通读档与严格复现

- 普通读档采用当前安装的定义，报告内容变化与状态适配，遵守下文定义绑定规则。
- 严格复现独立入口须核验原游戏构建、有效语义内容、模拟配置及 [04](04-deterministic-simulation.md) 的兼容环境，不能自动使用更新内容。
- 一键复现包包含起始存档/快照、后续操作序列、数据内容副本、必要表现资产、版本与环境清单及校验信息。它在隔离会话中使用，不改写当前安装的 Mod；复现专用内容副本不改变普通存档“不内嵌旧外部定义”的规则。
- 游戏程序、Godot 和 .NET 运行环境由清单定位，不自动打包；依赖或构建缺失、不适用时明确拒绝。领域重放与显示问题复现分别核验所需依赖，不承诺 GPU 像素一致。

#### 复现录制范围与内容切换

- Playground 建立或恢复会话后默认录制，以可恢复起点及其后有序输入组成有容量上限的复现窗口，并显示实际可复现的起止位置；不承诺无限历史。
- 周期性在完整提交边界建立新起点，确认可用后才按配置容量裁剪旧记录，不能只删日志而留下不可重放的片段。故障资料保留窗口内故障前的起点与触发输入；起点本身仍须携带当前依赖及尚未执行的输入。
- 记录容量和起点间隔由[性能验收](https://github.com/odradekk/train/issues/98)通过实测冻结。预算不足或新起点建立失败时明确标记录制不完整并提示，保留已有完整资料；不把不完整包标为完整复现，也不因录制失败回滚游戏世界。
- 内容发布尝试作为有序外部输入，记录执行位置、此前生效内容、候选内容及接受/拒绝结果。成功发布记录新内容版本及实际状态适配；失败保留原世界与内容，并保留重现拒绝所需资料。纯表现资产切换也记录显示复现所需前后依赖。
- 内容切换仍在保留窗口内时，不能仅留下更新后的起点而丢失引发故障的切换过程。跨版本内容计入复现容量；随窗口正常裁剪时，剩余起点与输入仍须完整可用。
- 生成或加载成功切换世界后开始新会话记录；切换失败仍附着原会话，保留失败输入及诊断。

#### 复现包格式与完整性

- 交付单个带格式版本清单的 ZIP，包含起始存档、JSON Lines 有序输入、必要内容与资产、配置/构建/环境清单、检查点摘要及诊断，可附截图。观察/原点操作与领域输入分别标识，不能让显示记录决定领域仲裁。
- 清单记录可定位的游戏构建/提交、生成器或固定配置版本、完整生效配置、语义内容与资产修订/校验值、模拟配置、OS/架构、.NET 与 Godot 版本，以及实际记录范围。它不代替必要内容本身，也不扩大既定兼容环境承诺。
- 导入前核验文件完整性、必要依赖及适用版本，不能静默跳过无法理解的领域输入。文件字节校验检查包的完整性，语义及权威状态校验检查输入与模拟一致性，二者不互相替代。
- 导出先完整写入并校验临时结果，再发布目标文件；失败明确报告并保留已有文件，不留下貌似成功的半包。不因此增加完整历史回放或自动安装运行环境。

#### 保存边界与待执行输入

- 只在完整模拟步或完整暂停事务结束后捕获；结构结算、身份/所有权变更及必要通行保护均已完成，不保存半次修复、拆分或授权。
- 运行时保存请求在完整提交边界捕获，不为保存额外推进模拟；暂停时可直接保存最近完整事务后的状态。
- 已接受但尚未执行的命令及其目标步、顺序须随存档保存，恢复后仅在原定位置执行一次，不为保存提前执行或清空队列。未提交的面板输入不属于世界状态。
- 暂停修改及同一步边界内的操作按 [04 的输入顺序](04-deterministic-simulation.md#本阶段输入边界与顺序)记录、保存和重放，不能仅凭 Tick 或墙钟日志猜测顺序。

#### 候选世界恢复与校验

恢复在候选会话中依次完成：

1. 核验格式、版本及必要内容依赖。
2. 重建并校验来源基底。
3. 应用保存差异及当前定义的合法状态适配。
4. 恢复实际布局、唯一身份、所有权、物理轨道及领域姿态。
5. 重建占用等查询，交叉校验授权、锁及必要引用，完成一致性检查。

全部通过后才整体替换当前世界；进入 Playground 默认暂停自动推进，保留速度、计划和故障状态。合法受损、暂时没有可用路径或等待修复不直接判为坏档；必要事实无法解释、非法占用或冲突授权则明确失败。诊断须给出失败阶段、对象及具体关系，不通过删除或偷偷修补事实使其通过。

严格复现核对原输入及状态；普通读档发生合法内容适配时记录变化，不以旧状态哈希要求适配后结果完全相同。有效待执行命令的目标在执行前被销毁，不与必要世界引用损坏混为一谈：允许恢复该输入，在原定执行位置重新检查、记录拒绝并出队，后续独立命令继续；具体语义见 [04 的命令失效规则](04-deterministic-simulation.md#命令失效与内部故障)。

### 列车与轨道引用恢复

运行语义统一引用 06：[RailPosition 与物理引用](06-railway.md#railposition-与物理引用)、[编组断开与无动力滑行](06-railway.md#编组断开与无动力滑行)、[断轨停车与恢复](06-railway.md#断轨停车与恢复)。本节只定义这些状态如何保存、重建与校验，不重新定义滑行、停车或启动条件。

- 保存实际编组、车辆连接与朝向、活动车头、参考接触点及其 RailPosition、速度和停车状态，以及恢复同一沿轨状态所需的物理轨道信息；保存权威引用，不保存派生压缩图 Edge 作为位置依据。
- 按保存的物理轨段身份重建定位所需几何和明确连接，再结合恢复的轨道体素与缺损派生有效通行区间；覆盖 06 规定的仍被引用的全毁轨段，不能把这类定位依据作为可丢弃缓存。
- 恢复保存的运动状态，并基于恢复后的实际世界重新检查阻塞原因；状态是否合法遵守上述 06 规则。缺少当前支撑但定位依据完整的合法停车状态，不作为缺失引用而拒绝加载。
- 无法恢复必需物理轨段引用或解释编组状态时，明确加载失败；不吸附到最近轨道，不以删除车辆掩盖错误。
- 显示缓存按 [07 的列车插值](07-rendering.md#列车插值) 从恢复的模拟状态重建，不作为列车运动恢复输入。正常行驶、断开滑行、换端后和断轨停车均须通过 [04](04-deterministic-simulation.md) 的存档恢复一致性验收。

#### 实际经过路径与通行决定

- 除编组参考 RailPosition 外，保存当前整列定位和车体占用所需的有序物理轨段路径、方向、接续选择及沿程范围，与前方尚未走完的授权路径分开。车头已出道岔、车尾仍在侧股时，不能根据当前道岔方向或重新求最短路猜测车尾位置。
- 只保留当前定位、占用/保护及授权仍引用的路径和几何，不保存整趟旅行历史。换端或拆分沿同一物理事实重新建立引用，不挪动车体；全毁但仍被引用的轨段继续保留定位依据，不因此变为可通行。
- 显式保存运行计划与进度、剩余停站时间、等待请求身份与首次等待步、已授权完整路径及其剩余有效范围、目标停车空间、道岔当前状态、授权与锁的归属，以及拆分后的共同保护归属和释放条件。
- 上述关系引用稳定物理对象与路径范围，不能依赖易变的压缩图 Edge 编号；恢复时交叉校验，不重新排队或重新申请已有授权。损伤导致暂时不可运行，不自动撤销仍必要的保护。
- 实际车体占用由恢复的领域姿态和布局重建；压缩路网、候选路径查询及反向占用/锁索引是派生数据。重建查询索引不能丢失已作出的通行决定，恢复后继续遵守 [06 的网络运行契约](06-railway.md#本阶段网络运行契约)。

#### 合法故障冻结状态

- 保存故障原因、尚需显式恢复的标记，以及故障冻结时的最后有效领域姿态和物理定位依据；这不是保存显示插值姿态。
- 正常可求解状态按权威路径及机械条件恢复并校核。支撑失效或姿态求解故障状态，只要身份、定位依据和冻结姿态能够一致解释，就允许以故障停车恢复；不能为使读档成功而吸附到轨道、移动列车或自动启动。
- 必需引用缺失、数值非法或无法解释的保护冲突导致整次加载失败。诊断文本可以重建，但故障尚未解除的事实不能被重新求解几何覆盖；故障列车仍按恢复后的实际车体保持占用保护。

### 定义绑定与恢复

以下外部定义绑定原则不允许用最新版 Blueprint 重写实际实例或建筑修复目标；建筑两类布局状态的保存要求见下节。

- 普通存档中的外部定义只保存 DefinitionId 和上次使用的 Revision，后者用于识别变化；不嵌入旧外部定义副本。普通读档时按 ID 使用当前安装的内置、Mod 或外部 Blueprint 定义；严格复现使用上文隔离复现包中已核验的原内容。
- 玩家自定义车辆的布局及其所需的其他存档内定义内嵌保存；其中的外部零件按 ID 引用当前定义，不固定目标 Revision。世界实际布局、实例身份与运行状态从存档恢复，不被更新后的设计模板覆盖。
- 当前规格变化时保留状态绝对值，仅按新的允许范围修正，重新计算相关能力；耐久上限升高不自动修复、上限降低时截断。具体规则见 [02](02-definitions-and-content.md)。
- 缺失必需定义或无法解释保存的状态时明确加载失败；这也包括缺失 Mod 或必需资产导致所需内容包无法通过校验的情况。不自动替换、删除或回退到旧定义。更新 Mod 数值后产生不同模拟结果是预期行为，不属于无损往返失败。
- 若生成内容更新改变了重建基底，使旧 Runtime Delta 无法正确恢复原实际布局，按不兼容读档失败处理；不能把旧 Delta 静默应用到不同布局后当作成功恢复。

### 静态建筑与修复目标恢复

[03 的建筑契约](03-composite-and-behavior.md#本阶段静态建筑契约)定义建筑的单一身份、断裂失效、原位碎块与完整修复。恢复须覆盖实际部件布局及身份/耐久、四向落位、核心与失效状态、聚居地/站点引用、实际部件绑定的接轨接口，以及该建筑最后确认的完整修复目标。修复目标不能从受损布局或更新后的外部模板重新猜测；目标中的零件定义仍按当前有效内容解析，不冻结为旧零件数值。

普通存档直接保存实例最后确认的完整修复目标，包括必要的局部格、零件 DefinitionId、朝向等设计内容，允许在存档内去重引用；不能只存外部 Blueprint 的 ID/Revision，也不复制旧零件数值。实际受损布局、零件身份与耐久、建筑断裂失效标记、站点及部件绑定另行保存，不能从修复目标代推当前状态。

原位世界残块保留可验证的来源建筑、零件身份及回收匹配依据，不凭材质相同反推归属。来源建筑已毁坏的历史来源记录允许存在，但不能复活旧建筑。恢复须核验唯一身份与所有权；合法受损建筑可以有多个不连通但有核心的部分，仍是同一失效建筑，不能按车辆规则拆成多个建筑、丢弃部分、自动修复或解除失效。

静态占用索引、碰撞和显示按恢复后的实际所有权与布局重建；修复目标不是当前实体占用，不为已缺失部分保留虚假占格。若目标位置后来被其他对象占据，读档仍可恢复合法受损状态，后续修复按占用冲突拒绝。恢复遵守上文候选世界校验流程，跨进程对照纳入 [04 的验收矩阵](04-deterministic-simulation.md#确定性验收)。

### 视觉驻留与渲染原点

[表现验收契约](07-rendering.md#本阶段表现验收契约)要求读档后从恢复的权威世界及当前有效内容重建所需视觉、碰撞与查询适配。驻留集合、渲染网格、局部坐标和 RenderOrigin 不能作为世界位置或模拟恢复的权威依据；切换原点不修改存档中的绝对位置、RailPosition、Seed 或领域状态。复现资料可以记录相机与原点操作以重现显示问题，但它们不决定领域结果，按上文复现包契约分别标识；不保存完整 GPU 状态或承诺像素一致。

### 资源与生产状态恢复

资源与生产系统的以下状态都是权威 Runtime State，进入 Runtime Delta，不是渲染缓存，也不能读档后重置：Production Plans、ActiveBatch（含 FrozenExecutionSnapshot 与 StartedFromRevision）、Facility OutputBuffer、ExtractionJob、RecoveryJob、ConstructionJob、RefitJob、DeconstructionJob、Spatial Reservations、Storage Reservations、Power Equipment 的 CurrentFuelEnergyRemaining、库存中的 ItemInstance 及 Job 选定的 ItemInstances / identity mapping、各 Job 的 ProgressWork 与 priorities。Save → Load → Continue 必须与不中断运行在相同语义内容和命令输入下产生一致结果；Batch 的冻结执行契约随存档恢复，外部 Definition 仍按 DefinitionId 解析当前定义。资源系统实现切片接入存档时纳入这些状态。

### 文件位置

- 存档：`user://saves/<存档 UUID>/save.json`。
- Blueprint：`user://blueprints/<蓝图 UUID>.composites.json`，复用 Composite 定义格式。
- 文件名中的 UUID 稳定不变，显示名称保存在文件内；重命名不改变身份或引用。Save-local 不作为独立内容目录扫描。

### 存档兼容

- 开发阶段不保证存档兼容。
- 进入正式发行阶段后，存档向前迁移成为硬性约束；届时可采用保存旧 Generator、Migration、Snapshot 等方式保证兼容。

## 首版范围

Save-local Definition、Runtime Delta、完整世界来源、稳定身份与输入序号、生成基底核验、铁路/建筑权威状态恢复、double 无损往返；完成 Save → Quit → Load → Continue 及跨进程对照。普通读档与严格复现分开，有界录制、内容切换记录、隔离 ZIP 复现包及原子失败保护纳入本阶段。

## 明确延后

Snapshot Save Optimization、正式版本 Save Migration；缺失 Mod 的兼容与回退（转录 Q42、Q88）。
