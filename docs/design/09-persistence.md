## 边界

本文定义存档的组成、世界重建方式与兼容策略。Save-local Definition 的来源规则见 [02](02-definitions-and-content.md)；Stateful RNG、运行时 ID 以及录制与复现见 [04](04-deterministic-simulation.md)；资源与生产系统各 Job 的语义见 [10](10-resources-and-extraction.md)、[13](13-production-runtime-and-facilities.md)、[14](14-construction-refit-and-deconstruction.md)。

## 不变量

- 基础世界通过 Seed + GeneratorVersion + 完整生效生成配置 + 有效生成语义内容重建，之后应用 Runtime Delta。固定配置使用独立来源身份；生成输入见 [05](05-world-graph-and-generation.md#复现输入与输出)，基底、版本与封装要求见下文本阶段契约。
- 所有主要格式从现在开始保留 Version 字段。
- Next Transaction ID、Next Entity ID、Save-local Definitions 必须进入存档；本阶段只有无状态随机，不需要保存可推进的 RNG State。后续添加有状态随机流时，其完整状态必须进入存档。
- 旧 Save 不能因为 Generator 更新而偷偷使用新算法重新解释世界。

## 规则

### 世界编辑器存档工作流

> 决策来源：[以存档为中心的新建、打开、生成与保存流程](https://github.com/odradekk/train/issues/139)的 Q1–Q17 已逐项确认，Q18 已确认完整规格定稿。本节描述目标行为，不表示现有 UUID 输入框、固定配置或保存命令已经实现这些流程。编辑器与其他模式共用的校验和提交边界见 [00](00-product-and-core-loop.md#本阶段范围)，核心模拟层不提供撤销与重做，见 [04](04-deterministic-simulation.md#命令)。

#### 入口与当前世界

主菜单只有一个“世界编辑器”入口，首先显示存档工作区，不自动建立测试世界或恢复上次存档。用户可新建、打开已有存档、从示例创建副本，以及导入本地存档；列表显示名称、最近保存时间和必要的版本、依赖提示，不要求记住 UUID。一次只编辑一个世界，所有入口进入同一个编辑环境。

| 入口 | 成功后的当前世界 |
| --- | --- |
| 新建空白世界 | 指定受支持的空间范围和世界种子，初始不含地形、建筑、轨道或车辆；尚未保存，默认暂停。具体尺寸档位由容量测量确定。 |
| 程序生成 | 使用选择的生成配置与种子，在候选中生成、校验后建立未保存世界，默认暂停。 |
| 打开已有存档 | 按正式恢复流程重建实际世界、模拟状态和待执行命令，保留存档身份，默认暂停。暂停不清除列车速度、运行计划或故障。 |
| 从示例创建副本 | 按普通存档恢复示例的实际世界、模拟位置和待执行命令，默认暂停；首次保存获得独立存档身份，原示例不被覆盖。 |

“无车辆直轨”仍有轨道，属于示例，不是空白世界。生成世界是建立新世界，不是合并或局部覆盖当前世界；局部生成作为编辑工具另定。候选生成失败、取消或预算耗尽都保留当前世界；成功且完成离开保护后才整体切换。若此前已成功保存原世界，随后生成失败，这次保存仍有效。

#### 保存、另存为与重新加载

新世界首次保存前显示“未保存”。首次保存成功才建立工作存档身份，之后“保存”更新同一存档；显示名改变不改变身份。保存失败不切换身份、不清除未保存标记，也不损坏上一份有效文件。

“另存为”成功时建立新存档 UUID，并将其作为当前编辑对象；原存档保留。复制实际世界、模拟状态及待执行命令，不重新生成地图，也不重新编号世界内部实体。写入失败则当前身份和未保存状态保持原样，不能先解除旧身份后再尝试写文件。

整个存档的另存为及导入也保留内嵌定义标识和引用，存档内内容按各副本隔离解析，不因存档 UUID 改变而重编。显式将某份内容另存副本或复制到另一范围则产生新内容身份，两者不同，见[内容身份规则](02-definitions-and-content.md#内容身份与跨范围依赖)。

用户界面区分以下操作，不用含义模糊的“重置”代替：

- **重新加载已保存版本**：恢复当前存档最近成功保存的内容，目标是该操作发起时的存档身份；尚未首次保存的世界不能执行。存在未保存修改时提供“另存当前修改后重新加载／放弃修改并重新加载／取消”，不先覆盖想恢复的原文件。另存成功后仍加载原目标；如果加载失败，当前世界及已保存副本都保留。
- **重新生成**：明确显示来源配置与种子，生成一个新的未保存世界，不沿用旧存档身份。仍走候选生成和离开保护。
- **重新从示例开始**：再次从原示例创建副本。

旧 `reset` 命令与自动测试用途在迁移时处理；本节不把尚未实现的界面名称当作现有命令。

#### 离开保护、临时草稿与执行期间状态

新建、打开、重新生成、重新加载、返回存档工作区、返回主菜单及正常关闭程序，都经过统一离开保护。未首次保存的新世界也受保护；世界编辑、模拟推进或待执行命令变化导致当前待保存状态与保存点不一致时，必须标为未保存，不能只检查手工编辑。单纯观察或暂停不算世界修改。普通离开提供“保存后继续／放弃／取消”；重新加载使用上文专用选项。保存失败或取消首次保存，均留在当前世界。

首批不持久化世界中的临时放置和线路预览草稿。普通保存、另存和导出仅包含已提交世界，存在草稿时明确提示未包含；离开前可以返回继续编辑，或明确放弃草稿。保存世界不等于同意丢弃草稿，可在同一离开对话中合并处理。蓝图、Layout 与体素定义的独立创作文档可以单独保存草稿，切换世界或退出前处理其未保存修改，具体规则见 [02 的内容创作流程](02-definitions-and-content.md#世界编辑器内容创作流程)；保存草稿不发布内容，也不清除世界未保存标记。

从开始处理切换或退出的未保存确认，到保存、候选加载或生成及最终替换完成，明确暂挂模拟推进与新的世界修改。界面显示正在切换，提供进度和取消；不能让已确认的世界在等待期间继续变化。取消或失败后恢复原先运行／暂停状态，不补算等待时间、不执行额外模拟步；已成功写出的存档或副本仍有效。成功进入新世界时按入口规则默认暂停。

尚未导出的保留故障片段也纳入离开保护，提供导出、放弃或取消，并与世界／草稿提示合并；普通保存不替代片段导出，导出失败或取消保留资料并留在当前会话。普通滚动录制不触发每次离开的确认。内部故障会话仍保持冻结，取消离开不能使其恢复模拟。

普通面板查看、单独保存、另存或导出不因此自动暂停；捕获仍发生在完整事务边界。保存点只对应成功写出的捕获状态，捕获之后的新变化继续标为未保存；失败不能清除未保存状态。暂挂是世界切换流程的明确状态，不是打开任意面板就自动暂停。

#### 本地导入与导出

普通存档使用单个带格式版本的 JSON 文件，包含来源配置、基底指纹、世界差异、模拟状态、待执行命令、必要的存档内自定义定义与外部内容引用。它是可恢复状态的封装，不表示脱离生成来源和外部内容也能恢复。

- **导入**：用户通过浏览器等工具获取文件，再选择本地文件；完整检查格式、支持的来源、基底、必要依赖和世界状态。校验通过后建立新的本地存档 UUID，保留世界内部实体 ID、模拟位置和待执行命令；原文件不改动，不按原 UUID 或名称覆盖已有存档。同名存档允许并存，由列表信息区分。成功后加入存档列表；打开再走统一离开保护，导入本身不替换当前世界。失败不留下貌似成功的存档条目。
- **导出**：在完整事务边界捕获当前已提交世界，而不是复制磁盘上的旧版本。未首次保存的世界也能导出；导出不绑定或改变当前工作存档身份、不覆盖工作存档、不清除未保存标记，也不包含临时草稿。导出文件提供普通存档恢复所需的有效身份信息，重新导入时仍建立独立本地副本。
- 文件写入先形成完整候选并校验，再发布目标；取消或失败保留当前工作与既有目标文件。覆盖已有导出文件须明确确认；该确认不将导出变为覆盖当前工作存档的途径。
- 普通存档不附带旧 Mod、游戏程序或表现资产；必要内容缺失或不兼容时报告可定位的原因，不自动安装 Mod。普通加载仍按当前有效定义合法适配并报告变化，依赖检查不等于锁定所有旧 Revision。

携带原始内容、必要表现资产和输入记录的 ZIP 仍是[故障复现包](04-deterministic-simulation.md#录制与复现)，不是普通存档格式。首批不建设内置下载站、账号、云同步或分享服务，也不承诺自动存档和崩溃恢复。

#### 来源、示例维护与模式兼容

普通存档继续采用可重建来源基底加 Runtime Delta。空白世界也具有明确的来源版本、范围和世界种子；生成世界保存完整生效输入及基底指纹。恢复时先重建、校验基底，再应用实际修改和模拟状态，不能用新版生成器偷偷重新解释旧世界，也不增加全世界快照作为兼容兜底。

示例标明用途、适用版本与内容依赖。固定配置仍可用于自动测试和制作、更新示例，但不再作为独立人工入口；每次打开走正式存档恢复，不运行制作示例的演示操作序列。必要来源重建不等于重跑演示脚本，制作完成也不等于实际文件已经通过恢复验证。示例或恢复依赖变化时，验证随附文件在新进程中打开并继续代表性操作；测试按[最小充分覆盖标准](../implement-sop.md#testing-standard)选择，不复制一套无关矩阵。边界值、损坏存档和内部故障夹具保留在自动测试数据中，不进入正常示例列表。

开发阶段可明确停止支持旧来源或存档版本，但须说明不兼容原因、保留原文件，不静默转换、删掉必要事实或重生成另一世界。[迁移退役决策](https://github.com/odradekk/train/issues/144)已确认：首批迁移示例优先从正式空白来源制作并保存实际差异，示例和通用恢复脱离旧切片身份；退役时公布并停止支持旧切片／旧固定配置来源的开发档，不承诺批量转换。必要个案另列迁移工作，加载不支持来源时保留原文件和当前会话，仍受支持的普通来源不因删除菜单而失效。具体清单与证据见[旧切片退役](https://github.com/odradekk/train/issues/118)，不承诺永久保留旧配置和生成器。

编辑器和正式游戏读取同一种普通存档，由打开入口决定操作模式；世界、模拟状态及必要玩法状态共用格式，无须另行转换成“游戏地图”，不因曾被编辑就自动禁止正式游戏打开。进入编辑器默认暂停，未来正式游戏按自身运行入口恢复；权限和建造流程由宿主施加。具体玩法状态随系统交付，缺失或不兼容时明确失败，不悄悄补造。本节不要求提前实现未来玩法。

#### 交付验证与后续决策

相关能力交付时，应能够通过编辑器自行建立案例、编辑和运行，保存后退出，在新进程打开并继续修改和运行，不增加专用场景或改代码才能复现。证据覆盖本次交付的存档身份与副本隔离、成功恢复，以及受影响的保存／加载／生成失败和取消保护；涉及草稿或切换暂挂时，验证提示和运行状态恢复。现有领域、真实 Godot、跨进程和人工验证按实际边界选择，不要求每个验收点都增加独立测试。

本节确定产品流程，具体控件、快捷键、存档字段编码和实现分期未冻结。创作交互、独立内容文档、诊断复现、性能与旧场景退役继续由各专门决策细化；最终统一重整实施票。本轮不实现功能、不改写现有控制台手册来冒充功能已交付。

### 存档组成

```text
Save
├─ SaveFormatVersion
├─ WorldSeed
├─ World Source（空白来源版本、生成器版本，或固定配置 ID / 版本）
├─ Effective Source Configuration + Content References + Base Fingerprint
├─ Runtime Delta
├─ Simulation Step + Boundary Operation Sequence + Next Command ID
├─ Next Transaction ID
├─ Next Entity ID
├─ External Definition References（DefinitionId + 上次使用的 Revision）
└─ Save-local Definitions
```

上图为本阶段逻辑组成，具体字段编码随实现规格冻结。Runtime Delta 须保留本节确定的实际结构、铁路路径与保护、故障、建筑修复目标和残块来源等事实；不能将 Seed 和 GeneratorVersion 视为充分重建输入。普通存档、世界来源与复现包分别按各自格式/规则版本解释，外部 Semantic Revision、Asset Revision 和运行时 Catalog Generation 的职责继续遵守 [02](02-definitions-and-content.md)，不能用目录发布计数代替持久版本身份。

后期如果加载性能出现瓶颈，用 Snapshot + Delta 作为优化。Demo 不做完整 Event Sourcing。

连续量以可无损往返的 JSON 数值保存，使用与文化无关的 round-trip 表示，恢复相同的 `double` 值；不截断小数位，不允许非有限值。在有效语义内容相同的前提下，验收须比较中途保存恢复与不中断运行的结果，详见 [04](04-deterministic-simulation.md)。

### 本阶段保存契约

[确定性和存档恢复决策](https://github.com/odradekk/train/issues/97)已确认 Q1–Q15。以下是实施目标，不表示正式实现已通过验收。稳定身份与确定性证据矩阵见 [04](04-deterministic-simulation.md)，录制与复现见 [04](04-deterministic-simulation.md#录制与复现)。

#### 生成基底与来源身份

- 普通存档继续采用重建初始世界后应用 Runtime Delta 的方式，记录完整生效生成配置及可核验的基底指纹。指纹覆盖解释 Delta 所必需的生成布局、稳定身份和结构关系，须明确编码范围；不能仅用现有简单体素布局指纹代表完整生成网络。
- 先确认生成器支持并核验重建基底，再应用 Delta 和当前定义的状态适配。无法一致解释原状态则整次失败，不静默生成另一张地图，也不新增全世界快照作为旧档兼容兜底。
- 不改变基底解释且通过适配校验的外部零件数值更新仍可生效；实际布局和绝对耐久等状态继续按既定规则保留。基底一致性校验不能取代实例状态保存，也不把所有外部 Revision 变化一概判为不兼容。
- 固定世界编辑器配置以自身标识、版本、生效配置及内容依赖描述来源，不能冒充 GeneratorVersion；生成地图与固定配置均须提供足够的重建依据。

#### 保存边界

- 只在完整模拟步结束后，或暂停时一条完整命令结束后捕获；损伤结算、身份与所属关系变更均已完成，不保存半个事务。
- 运行时的保存请求在当前步结束后的边界捕获，不为保存额外推进模拟；暂停时直接保存最近完整边界的状态。
- 存档中没有待执行命令，见 [04](04-deterministic-simulation.md#模拟位置与执行时机)。存档保存模拟步、步内序号和下一个命令编号，使读档后的命令继续保持全序。未提交的面板输入不属于核心状态。

#### 候选世界恢复与校验

恢复在候选会话中依次完成：

1. 核验格式、版本及必要内容依赖。
2. 重建并校验来源基底。
3. 应用保存差异及当前定义的合法状态适配。
4. 恢复实际布局、唯一身份、所有权、物理轨道及领域姿态。
5. 重建占用等查询，交叉校验授权、锁及必要引用，完成一致性检查。

全部通过后才整体替换当前世界；进入世界编辑器默认暂停自动推进，保留速度、计划和故障状态。合法受损、暂时没有可用路径或等待修复不直接判为坏档；必要事实无法解释、非法占用或冲突授权则明确失败。诊断须给出失败阶段、对象及具体关系，不通过删除或偷偷修补事实使其通过。

严格复现核对原输入及状态；普通读档发生合法内容适配时记录变化，不以旧状态哈希要求适配后结果完全相同。

### 列车状态恢复

> 决策出处：[列车在图上的运行与调度](https://github.com/odradekk/train/issues/203)，2026-10-05。

以下列车与线路状态是核心状态，随存档保存，读档后不重新推算：

- 每列车的成员与顺序、位置（节点，或线路、铁轨号、方向和距离）、速度、运行或停车状态；
- 运行计划及进度：当前目标、剩余停留时间、单次计划是否已走完；
- 各条铁轨的方向锁，以及节点处进入线路和等待站台的顺序；
- 线路上进行中的扩建与修复任务及其进度，以及自动修复设置；
- 停放在聚居地的车辆。

读档后按原状态继续，结果与不中断运行一致，见 [04](04-deterministic-simulation.md#确定性验收)。

### 定义绑定与恢复

以下外部定义绑定原则不允许用最新版 Blueprint 重写实际实例或建筑修复目标；建筑两类布局状态的保存要求见下节。

- 普通存档中的外部定义只保存 DefinitionId 和上次使用的 Revision，后者用于识别变化；不嵌入旧外部定义副本。普通读档时按 ID 使用当前安装的内置、Mod 或用户内容库定义；严格复现使用上文隔离复现包中已核验的原内容。
- 玩家自定义车辆的布局及其所需的其他存档内定义内嵌保存；其中的外部零件按 ID 引用当前定义，不固定目标 Revision。世界实际布局、实例身份与运行状态从存档恢复，不被更新后的设计模板覆盖。
- 世界编辑器中已发布到存档内的车辆／建筑蓝图、Layout、体素定义及必要存档内依赖也随普通存档保存，不以是否已经实例化决定是否保留；未发布草稿另存独立文件。显式复制外部内容所得的新身份用户副本按其发布范围保存，不是普通读档暗中保留旧外部定义的兼容兜底；仍需满足外部引用和资产依赖。发布与副本规则见 [02](02-definitions-and-content.md#世界编辑器内容创作流程)。
- 当前规格变化时保留状态绝对值，仅按新的允许范围修正，重新计算相关能力；耐久上限升高不自动修复、上限降低时截断。具体规则见 [02](02-definitions-and-content.md)。
- 缺失必需定义或无法解释保存的状态时明确加载失败；这也包括缺失 Mod 或必需资产导致所需内容包无法通过校验的情况。不自动替换、删除或回退到旧定义。更新 Mod 数值后产生不同模拟结果是预期行为，不属于无损往返失败。
- 若生成内容更新改变了重建基底，使旧 Runtime Delta 无法正确恢复原实际布局，按不兼容读档失败处理；不能把旧 Delta 静默应用到不同布局后当作成功恢复。

### 静态建筑与修复目标恢复

[03 的建筑契约](03-vehicles-buildings-and-designs.md#本阶段静态建筑契约)定义建筑的单一身份、断裂失效、原位碎块与完整修复。恢复须覆盖实际部件布局及身份/耐久、四向落位、核心与失效状态、聚居地/站点引用、实际部件绑定的接轨接口，以及该建筑最后确认的完整修复目标。修复目标不能从受损布局或更新后的外部模板重新猜测；目标中的零件定义仍按当前有效内容解析，不冻结为旧零件数值。

普通存档直接保存实例最后确认的完整修复目标，包括必要的局部格、零件 DefinitionId、朝向等设计内容，允许在存档内去重引用；不能只存外部 Blueprint 的 ID/Revision，也不复制旧零件数值。实际受损布局、零件身份与耐久、建筑断裂失效标记、站点及部件绑定另行保存，不能从修复目标代推当前状态。

原位世界残块保留可验证的来源建筑、零件身份及回收匹配依据，不凭材质相同反推归属。来源建筑已毁坏的历史来源记录允许存在，但不能复活旧建筑。恢复须核验唯一身份与所有权；合法受损建筑可以有多个不连通但有核心的部分，仍是同一失效建筑，不能按车辆规则拆成多个建筑、丢弃部分、自动修复或解除失效。

静态占用索引、碰撞和显示按恢复后的实际所有权与布局重建；修复目标不是当前实体占用，不为已缺失部分保留虚假占格。若目标位置后来被其他对象占据，读档仍可恢复合法受损状态，后续修复按占用冲突拒绝。恢复遵守上文候选世界校验流程，跨进程对照纳入 [04 的验收矩阵](04-deterministic-simulation.md#确定性验收)。

### 视觉驻留与渲染原点

[表现验收契约](07-rendering.md#本阶段表现验收契约)要求读档后从恢复的权威世界及当前有效内容重建所需视觉、碰撞与查询适配。驻留集合、渲染网格、局部坐标和 RenderOrigin 不能作为世界位置或模拟恢复的权威依据；切换原点不修改存档中的绝对位置、RailPosition、Seed 或领域状态。复现资料可以记录相机与原点操作以重现显示问题，但它们不决定领域结果，按上文复现包契约分别标识；不保存完整 GPU 状态或承诺像素一致。

### 资源与生产状态恢复

资源与生产系统的以下状态都是权威 Runtime State，进入 Runtime Delta，不是渲染缓存，也不能读档后重置：Production Plans（含为选定 ItemInstance 绑定的一次性 Recovery 计划项）、ActiveBatch（含所引用的 Production 或 Recovery Process、FrozenExecutionSnapshot 与 StartedFromRevision）、Facility OutputBuffer、ExtractionJob、ConstructionJob、RefitJob、DeconstructionJob、Deconstruction 的主动暂停状态、UnderRefit / UnderDeconstruction 锁定、Spatial Reservations、Storage Reservations、Power Equipment 的 CurrentFuelEnergyRemaining、库存中各 Stack 的数量与 ItemInstance 及 Job 选定的 ItemInstances / identity mapping、各 Job 的 ProgressWork 与 priorities。Save → Load → Continue 必须与不中断运行在相同语义内容和命令输入下产生一致结果；Batch 的冻结执行契约随存档恢复，外部 Definition 仍按 DefinitionId 解析当前定义。资源系统实现切片接入存档时纳入这些状态。

### 文件位置

- 存档：`user://saves/<存档 UUID>/save.json`。
- 已发布用户内容：目标目录 `user://content-library/`，包含蓝图、Layout 与体素定义；独立草稿：`user://authoring-drafts/`，不参与有效内容扫描。
- 内容文件按稳定身份组织，显示名称保存在文件内；重命名不改变身份或引用。Save-local 内嵌普通存档，不作为独立内容目录扫描。
- 旧蓝图库 `user://blueprints/<蓝图 UUID>.composites.json` 的读取／迁移安排须在实施票中明确，保留原文件，不静默改身份或丢内容。以上是目标存储契约，不表示当前加载器已完成迁移。
