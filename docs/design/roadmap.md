# Roadmap：首版范围、明确延后、未冻结参数与实施顺序

> 本文会频繁变化；按 AGENTS.md，路线图是临时的，一个提出的方向不是实现承诺。

## 首版明确实现范围

首版目标是通过长期 Playground 与独立自动验证验收体素基础，具体条件见 [00](00-product-and-core-loop.md)。正式游戏场景与贸易玩法后续接入；达到验收条件即可进入游戏场景开发，不等待所有后续系统完成。以下保留基础能力及后续桌面产品能力的索引；本阶段新增契约见各专节，桌面停靠和资源生产不在本阶段完成门槛内。[#37](https://github.com/odradekk/train/issues/37) 确定的前四个端到端切片是历史交付，不代表以下能力均已完成。

- 有限 3D Voxel World
- VoxelDefinition
- JSON/Data Mod
- Definition、Revision、Instance
- World Chunk
- Composite
- 手写 JSON 车辆 Blueprint 的加载、校验与制造
- Construction Validation
- Refit：添加、移除、移动、旋转、替换体素，支持批量原子提交
- 基础 Damage 与 Fragmentation；调试操作对单个或多个地形、车辆体素施加指定伤害
- Behavior + Capability 基础
- Deterministic Simulation
- 连续量使用标量 double；无状态随机；确定性重复运行、存档恢复与渲染独立性验收（#34）
- Runtime Delta Save
- 读档与热重载采用当前外部定义并原子适配状态；语义、资产、目录发布版本分离（#35）
- Seeded World Generation
- Settlement Layout
- 数据驱动静态建筑与站点、断裂单一身份/整体失效、完整修复目标及残块来源
- 四站生成网络、10 节泰坦能力、三列联合运行及最小路径授权/冲突防护
- 长期 Playground、三种会话来源、配置与验证步骤分离、覆盖等价后的旧切片退役
- 默认有界录制、内容切换重放、隔离严格复现及带完整性清单的故障复现包
- 三维聚居地锚点与朝向、生成用途的 Archetype、实际建筑和资源派生统计、站点 RailSocket、静态建筑统一占用与净空查询（#36）
- 基础 Rail Network
- 连续物理轨段、明确连接、实体占格与局部断轨；直线、连续水平弯与平滑缓坡（#32）
- 五档单节车辆尺寸包络，五档共用正常线路；尺寸与机械约束共同校验（#32）
- Continuous Train Movement
- Multi-contact Vehicle Constraint
- 编组统一运动与断开后独立滑行；单车头不能倒行，双车头停稳互斥换端；稳定沿轨引用、断轨停车与显式恢复、沿轨显示插值（#33）
- TrackRenderer
- Chunk Rendering
- Dynamic Composite Rendering
- Visual Streaming
- 后续桌面产品能力：Bottom Dock Window（Windows AppBar）、Floating 与专门窗口测试场景；本阶段使用普通窗口，不以桌面停靠验收为门槛
- 失焦正常渲染、暂不检测遮挡、最小化停主窗口渲染且模拟继续；可配置渲染帧率上限
- Perspective Train Camera

改装入口覆盖全部所列操作，验收既有零件身份与状态保留、替换语义及非法改装整体拒绝；具体契约见 [03](03-composite-and-behavior.md)。后续选择实施 Docked 时，先通过独立窗口场景验证工作区预留与释放、模式切换、多显示器与混合 DPI、Godot 窗口消息共存，再接入体素场景，见 [08](08-desktop-window-and-camera.md)；该顺序不阻塞当前体素引擎阶段。

## 明确延后的 Feature

正式游戏场景、经济与自动贸易玩法、正式车辆设计 UI、事故碰撞等伤害玩法触发源、专门遮挡检测后续开发。Faction 的设计与实现整体延后，首版不保留占位字段；当前测试场景复用正式世界模型、模拟、渲染与存档代码，并提供开发测试所需操作。

TradeMetadata 的字段与实现、Mod 跨包覆盖与 patch 延后（#31）；Value 属于当前体素定义，继续保留。资源与生产系统（[10](10-resources-and-extraction.md)–[14](14-construction-refit-and-deconstruction.md)）的设计已定，其实现与相关 Runtime State 的存档接入不在当前四个切片，随后续切片安排；[#77](https://github.com/odradekk/train/issues/77) 已把可交易初级货物与聚居地种类集合改为 `raw_good`，[#78](https://github.com/odradekk/train/issues/78) 仍待实现 `resource_source` 与 ResourceSourceBehavior。

首版不实现有状态随机流或定点数体系；领域层暂不使用硬件宽度可变的向量计算，后续优化须经性能与确定性验证（#34）。

以下系统不是当前欠缺，而是刻意延后：Code Mod API、Offline Progress、Simulation LOD、Greedy Meshing、Voxel Geometry LOD、通用 Material System、复杂 Damage Types、World structural collapse、复杂重力系统、玩家铁路施工 UI、AI 铁路施工、复杂桥梁生成、复杂隧道生成、完整信号与联锁系统、复杂道岔控制、复杂车辆交通调度、Snapshot Save Optimization、正式版本 Save Migration。

本阶段已将水平基本道岔及多列车最小共线防护纳入，几何边界与验证矩阵见 [06 的本阶段契约](06-railway.md#本阶段几何与车辆验证契约)，站点顺序运行计划、三端道岔、到下一整列等待位置的完整授权、区段独占、车尾释放、确定性排队及拆分保护已由[网络运行规则](https://github.com/odradekk/train/issues/94)确认，见 [06 的网络运行契约](06-railway.md#本阶段网络运行契约)。这些最小占用与预留机制不在延期范围内；约定网络和负载须持续通行，不能仅以停车避碰通过验收。复杂交叉、坡上或弯道内道岔、超高/侧倾、三个以上独立接触约束和铰接车体继续延后；独立线路不能共占一格的规则不因纳入基本道岔而自动取消。

完整制动管路、复杂阻力、坡道反向溜车与刚体脱轨延后；#33 采用无动力沿轨减速和断轨安全停车，不提前实现完整事故动力学。

架构不能主动阻止这些系统未来加入，但首版不为其支付完整实现成本。

## 暂不冻结的参数

必须通过实际开发确定，进入 Config / Tuning 而不是架构不变量：Chunk Size、World Size、Simulation Tick Rate、Camera FOV、Zoom Min/Max、Render Residency Radius、Unload Radius、Directional Prefetch Distance、非车辆 Blueprint 尺寸限制、World Generation Retry Count、Meshing Threshold、Custom Mesh LOD Distance、Voxel Geometry LOD Distance、Window Default Height、默认渲染帧率上限。

资源与生产系统的未冻结参数（各 Resource Source 的 MaxDurability 与 Yield 比率、Cluster 分布、Extraction Range、WorkPerDamage、配方数量、WorkRequired、PowerPerWork、LaborPerWork、各设备 base capability、Storage Equipment capacity、FuelEnergyPerUnit、各类 WorkPerVoxel、Recovery BaseOutput、Site 条件阈值、Resource Renewal 触发规则、Facility Priority 默认值与 Resolver 调度参数）列于 [10](10-resources-and-extraction.md)–[14](14-construction-refit-and-deconstruction.md) 各文档的开放问题，通过实现、经济模拟和 Playtest 决定。

车辆五档尺寸已由 #32 确定，见 [06](06-railway.md)。[三维弯坡与混编机械参数决策](https://github.com/odradekk/train/issues/108)已确定首批机械实施目标：前、后悬伸各 0.5–2 格，底高 0.5–1 格，轴距为声明包络长度减去两端悬伸；统一车钩长 1 格、安装高 1 格、三维夹角上限 15°，统一轨距 1.5 格。B 已提升为首批线路标准：水平半径≥288 格、期望缓和参数≥240 格、水平至最大坡角的过渡≥240 格、坡角绝对值≤10°；左右各9格、上方13格净空。分项精度与扣除完整误差上界后至少0.05格的安全余量已确认，详见 [06](06-railway.md#首批铁路几何与机械参数)。历史 R192/L₀160/坡过渡160、单侧净空8/顶部12只保留为对照，不能据早期二维采样通过声称三维安全。水平弯仍按 L=min(L₀,R×|θ|)、中央圆弧长 R×|θ|−L 处理，坡度过渡按水平投影距离配置。弯坡叠加、多节编组、连续扫掠、实际占格与局部破坏以及 Godot 集成须在铁路切片补验，未验证线路组合不默认开放给生成器。

#70 / `df9a0eb` 的有动力运动已按固定步长实现，当前为 60 Hz、恒加速度趋近目标速度、停车命令立即清零速度；具体语义见 [06](06-railway.md)。最终有动力加速曲线、加减速度、目标速度与制动体验仍未冻结，当前默认值不作为产品不变量；#33 的无动力滑行减速度仍随实施调优；沿轨约束求解必须满足已确认的分项精度门槛。铁路切片还须覆盖双车头换端、断开后独立运动、断轨及修复后显式启动、全毁但被引用轨段的存档恢复和渲染帧率独立性；不能把 #32 的几何原型通过视为这些状态转换已获验证。

## 本阶段无资源地图生成

[生成契约](05-world-generation-and-settlements.md)已确定地形优先、有限整地、真实建筑与铁路落位及确定性工作预算；首批不自动生成桥梁或隧道。标准网络至少四站，包含跨三站环路、支线终点站及整列会让设施，按 10 节泰坦的列长能力验算；至少三列同时运行，分别为 10 节泰坦、4 节及 8 节跨档混编，验证追踪、会让、汇入竞争及持续通行。首批水平三端道岔以左、右 15° 分支模板为目标，必须验证其完整路径及与弯坡的间隔。完整复现输入包含 Seed、GeneratorVersion、生效配置及相关内容指纹。每张标准地图须有实际转弯和坡度，代表种子集合覆盖其余地形与线路组合；生成检查和运行验收分别报告。实施须安排生成实验，分离调参/独立验证种子，冻结标准配置、种子清单及成功率门槛后再做最终验收；具体规模、性能门槛及交付顺序由后续决策承接。此契约不表示生成器或模板已有正式实现。

## 本阶段静态建筑

本阶段静态建筑的身份、损坏与修复遵守 [03 的建筑契约](03-composite-and-behavior.md#本阶段静态建筑契约)：断裂保留单一建筑身份并整体失效，核心全毁结束身份；修复完整还原实例最后确认的设计及耐久，不能通过改装残缺设计绕过。数据驱动建筑/站点、静态占用和碰撞/铁路净空、实例内容适配与原子失败检查须进入对应端到端切片，资源和生产不随之纳入。

## 本阶段表现与跨区观察

[07 的表现验收契约](07-rendering.md#本阶段表现验收契约)确定三路表现的代表内容、最小静态资产范围、按当前观察范围驻留、跟随路径预取、主观察位置驱动 RenderOrigin，以及局部重建、内容原子失败和近/远坐标一致性矩阵。自动检查与真实 Godot 人工观察均为必需证据；远处模拟不随视觉卸载停止。具体半径、距离、触发条件、重建预算及资源稳定门槛由[性能验收](https://github.com/odradekk/train/issues/98)按实测收敛，优化技术不自动成为交付项。

## 本阶段确定性与存档恢复

[存档与复现契约](09-persistence.md#本阶段保存与复现契约)区分普通当前内容适配与隔离严格复现：完整来源和基底核验、步内输入顺序、待执行队列、实际铁路路径与通行保护、故障姿态、建筑修复目标及残块来源均纳入。恢复完整构造候选世界后原子替换，合法受损状态不当坏档；预期失效命令拒绝后继续独立操作。Playground 默认有界录制，保留内容发布过程，使用带版本/校验清单的 ZIP 复现包；容量、起点间隔及开销由性能实测冻结。跨进程重复、保存退出恢复、关键转换和外部观察变化按 [04 的证据矩阵](04-deterministic-simulation.md#确定性验收)验证，不能把已定契约当作已实现证据。

## 本阶段长期调试入口

[世界编辑器契约](playground.md)确定唯一存档工作区与编辑环境，新建、打开和示例副本共用正式能力；固定配置留作自动测试或制作示例，验证步骤与配置分开。旧四切片按[退役与案例迁移规则](playground.md#旧切片退役与案例迁移)逐组迁移，证据齐备后集中删除旧入口、场景及专用驱动。退役依赖实际迁移能力，不强制等待程序生成、完整 Benchmark 或目标实机通过；历史证据保留，旧开发档按明确来源／版本停止兼容并保留原文件。当前决策阶段不执行删除。

## 本阶段性能验收

[性能验收决策](https://github.com/odradekk/train/issues/98#issuecomment-5856117703)已确认测量方案及冻结流程；Q7 的首轮配置未采用，由 Q10 确定更低配置。以下为后续实施和验收契约，不代表现有代码已达到相应性能。具体数值由测量报告提交用户确认，目标实机验证仍是阶段完成关口。

- **基准设备**：本阶段固定 Ryzen 5 3600、桌面 GTX 1650 GDDR5 4 GB、16 GB 双通道内存、SSD、Windows 11 x64。用户要求比首轮 Ryzen 5 5600／RTX 3060 候选继续下探，因此采用此档；不随 Steam 月度榜单自动调整。目前暂无目标实机。当前 Ryzen 9 5900HX、约 32 GB、RTX 3080 Laptop 开发机只作开发和辅助测量环境，不能据其结果替代目标配置验收，也不因此宣称产品最低配置。所选配置参考 Steam 存量硬件，具体 CPU 与存储为工程选择；调查的分项分布不能直接推出一台统计上的平均整机或多数玩家覆盖率。
- **体验目标**：1920×1080、当前 Compatibility 渲染器、默认复现录制开启时，以正常交互 60 FPS 为目标，同时要求模拟持续跟上 1× 时间。目标不是已验证保证；具体帧耗时分位数、尖峰容忍和可支持负载经代表测量后冻结。
- **容量探索**：从满足已定铁路几何、四站网络及三列联合运行要求的标准地图起步。先固定三列增加世界与静态内容，再固定可运行网络增加列车，最后验证组合负载。加车前确认停车、会让及运行计划能够持续通行，不将运营堵塞误判为性能不足；地图尺寸和压力档位根据首轮实测冻结。
- **三类负载**：探索用于寻找可承载范围；固定验收冻结世界尺寸、种子、建筑／轨道／车辆组成、初始状态、相机路线、操作序列与重复次数；超额压力用于报告容量边界，其失败不冒充固定负载失败。生成调参种子与独立验证种子分离，独立验证清单及成功率门槛在最终验收前固定，不得看到失败后删种子。
- **正式测量与诊断**：正式体验验收采用目标配置实机、独立 Release 构建、真实 1080p 窗口及默认开启的复现录制。headless 领域吞吐、关闭录制或部分表现的对照仅用于定位开销，不能代替完整运行通过。记录实际 GPU、渲染器、帧率限制/VSync、驱动、供电及显示路径。暂无实机不阻塞规格与功能开发，但目标性能保持“待验证”，取得目标硬件测试证据前不能宣称达标；开发机限核、限内存或降频不视为等效实机。目标实机验证保留为阶段完成关口，当前不要求购买设备。
- **指标分工**：持续运行记录帧耗时 p50/p95/p99、最大值、卡顿次数、模拟步耗时及 1× 时间追赶情况，以及内存和对象数量趋势。生成、区域准备、批量修改、保存恢复、滚动录制起点和导出分别记录耗时及造成的最长界面停顿；不能仅看平均 FPS，也不将加载等待与日常帧耗时混为一项。具体通过阈值在代表负载实测后冻结。
- **测量时长**：短测每组预热至少 1 分钟后正式记录 5 分钟，独立重复 3 次。最终候选配置另做至少 2 小时联合长测，覆盖跨区观察、多列车持续通行、重复修改／破坏／修复、保存恢复及录制窗口滚动。冻结预热稳定条件与每类事件最低次数；若 2 小时不足以覆盖必要循环则延长，不能仅空闲挂机。
- **长期积累检查**：长测完成不少于 10 轮相同操作循环，并至少跨越 3 次录制窗口滚动。每轮回到相同观察位置与可比较的领域对象规模，比较托管堆、进程内存、可测显存及存活对象数；区分预热后趋稳的缓存与持续积累。稳定容差实测冻结，不要求每帧内存完全不变，也不能靠定期强制 GC 或重启掩盖问题。
- **数值冻结关口**：先实施最小标准地图与测量能力，再提交数据由用户确认地图／压力档位、帧耗时与卡顿门槛、模拟积压容差、操作最长停顿、内存稳定容差，以及 Chunk 大小、视觉加载／卸载半径、沿路径预取、近／远切换与原点切换触发／防抖、单帧重建预算、区域准备时间、录制容量和起点间隔。录制同时报告实际可保留时长与空间开销；测量环境、预热稳定条件和 VSync／限帧方式一并冻结。实施者不得自行放宽指标后宣布达标；开发机数据可以支持探索，但不能替代目标实机证据。
- **表现与复现开销**：沿用已定表现与保存契约，测量三路表现共存、局部修改、所有权转移、驻留边界往返、远处修改后返回、多列车聚焦／跟随、换端改道及近／远坐标下运行／暂停的原点切换。报告驻留 Chunk／组合体／轨道区段数量、加载／释放次数、实际重建数量与耗时、区域准备和原点切换耗时，识别局部更新退化与无效对象积累。默认录制、起点捕获／核验、内容更新与资产留存、候选恢复、ZIP 导出／校验、权威状态比较及差异诊断均计入相应操作耗时、内存、文件大小和长期增长；不通过漏存必要状态或输入降低成本。
- **未达标处理**：先定位瓶颈并修正实现。可缩减超出功能基线的压力负载或多余地图内容，但保留四站网络、三列联合运行、10 节泰坦能力、完整模拟与默认录制。若满足几何和功能的最小标准地图仍无法达到目标，明确失败并重新提出配置／范围取舍；不自动降低帧率目标、铁路标准或模拟精度。
- **停止与通过规则**：崩溃、世界状态错误、列车安全约束破坏、必要恢复／复现失败立即保留证据并停止该轮；持续模拟积压、内存持续增长及帧耗时越界按冻结门槛判失败。调度无法持续通行单列为运行验证失败，不据此推导性能容量。正式报告保留全部重复结果、失败与首次异常位置，修复后重跑受影响项目；最终通过须同时满足正确性、正常交互性能与长期稳定。目标实机缺失时保持待验证。

硬件选型证据（2026-09-27 查阅）：[Steam 官方调查](https://store.steampowered.com/hwsurvey/)当前显示 2026 年 8 月全平台汇总，16 GB 内存占 41.20%，1080p 占 50.52%，GTX 1650 占 2.37%，6 核与 8 核分别占 27.43% 和 28.04%。调查没有给出可据此认定的平均 CPU 型号或整机组合，不能将分项占比相乘或视为联合覆盖证据。具体型号由用户在 Q10 选定；[AMD 的 Ryzen 5 3600 资料](https://www.amd.com/en/support/downloads/drivers.html/processors/ryzen/ryzen-3000-series/amd-ryzen-5-3600.html)及 [NVIDIA 的 GTX 1650 资料](https://www.nvidia.com/en-ph/geforce/graphics-cards/gtx-1650/)用于核对产品规格，桌面 GDDR5 版本不与移动版或 GDDR6 版本混用。

旧切片报告只作原环境与负载下的历史观测，不外推为生成网络或长时稳定保证。正式测量须记录实际 GPU、驱动、显示与供电条件，并满足届时版本锁定的 SDK/Godot 环境；当前规划工作树要求的 .NET SDK 10.0.111 在本机缺失，须在运行正式验证前解决，本轮不修改环境或运行压力测试。

### 世界编辑器 Benchmark 工作流

[确定性能 Benchmark 与阶段收尾验收门槛](https://github.com/odradekk/train/issues/143)已确认十三项决定，并经完整规格确认定稿。以下扩展原性能验收契约，不表示测量工具或性能结果已经交付。

沿用上述目标设备及独立 Release、1920×1080、Compatibility、默认录制开启的条件，将正常交互 60 FPS 目标扩展到世界编辑器的观察与编辑；运行时全图模拟持续跟上 1×。生成、加载和大批量提交等单次操作另测总耗时及最长界面停顿，不要求瞬间完成。目标实机缺失时保持待验证，不阻塞功能开发，也不以开发机结果替代正式验收。

Benchmark 分为可独立选择的操作基准、真实窗口体验和长期稳定三部分，共用统一测试入口与报告，分别执行和下结论。操作基准测正式模拟、编辑事务、生成、保存恢复、内容发布和复现等代表能力的耗时、吞吐及可测分配；能在普通 C# 中验证的操作不强制启动 Godot，涉及引擎的测量经过真实 Godot。窗口测量覆盖渲染、输入响应和界面停顿，长测检查重复使用后的积累。单元测试总时长或无头吞吐不替代窗口体验，不为每个方法建立微基准。

保留四站、三列及 10 节泰坦的标准运行地图，新增编辑器负载以少量代表流程覆盖：体素区域编辑与撤销、建筑／铁路预览及提交、停稳车辆重定位、蓝图／Layout 创作和放置、定义发布适配、存档切换，以及录制滚动／片段留存／导出重放。按风险选择小型操作案例与联合场景，预览和提交分别测量；精确规模、编辑频率、内容数量和诊断图层组合在实测后冻结，不穷举工具组合，也不默认要求所有重型工具同时开启。

每项基准固定起始状态、正式操作与必要结果检查，记录存档／种子、内容、负载和操作序列版本。重复会修改世界的操作前恢复等价起点，分别记录准备时间与实际操作时间；端到端加载／生成基准仍包含其声明测量的完整过程。测量后检查必要结果，拒绝、少执行或错误状态不能算提速，不在计时区重复整套正确性测试。跨版本比较保持负载、环境和计量方式一致；必须改变这些条件时建立新基线，并说明不能直接比较。

测量时长按类型区分：上述至少 1 分钟预热、5 分钟记录、独立 3 次适用于正式持续窗口测量；最终联合长测仍至少 2 小时、10 轮可比较操作及 3 次录制窗口滚动，必要循环未覆盖时延长。操作基准根据单次成本及实测波动固定预热、批次与重复次数，不要求每个小操作都测 5 分钟；首次打开等冷启动成本单列，不隐藏在预热中。日常按风险运行相关短基准，不代替正式窗口或长测验收。

性能判定同时保留绝对体验门槛与相对基线回归。正式验收须满足冻结的帧耗时、停顿、模拟积压及稳定性门槛；同条件版本比较另报告耗时、吞吐和内存变化。首轮相对阈值尚未冻结时只报告变化及调查结论，不自动判通过；测量稳定后按代表用例确定允许波动与阻塞规则，提交用户确认。不统一套用单一百分比，也不通过更新基线抹掉退化；优化若损坏正确性，直接失败。

正式测量使用固定轻量采样配置，保留正常编辑器界面、默认录制和必要指标采集，记录图层、检查点频率及采样开关。详细追踪、全图图层或高频完整状态抓取只在指定案例中开启。通过有／无额外采样的对照估计测量开销，不关闭默认录制来宣布达标，也不从正式结果里随意扣除估计开销。无法采集的 GPU／显存等指标标为未采集，不能以 CPU 耗时替代。

结果复用统一机器可读摘要与简短报告，只增加性能比较所需信息：保留各次原始结果，记录受测构建、工作区状态、负载版本、环境、预热和采样方式，列出基线／当前值、绝对及相对变化、样本数和判据版本。持续帧耗时沿用 p50／p95／p99、最大值及卡顿次数；单次操作按样本量报告分布与范围，样本不足时不宣称尾部分位数具有意义。失败、取消、环境干扰与未采集项单列，不只保留最好一轮；无法区分变化与正常波动时标为需进一步测量。

开发机用于同环境下按风险执行相关操作基准及定位瓶颈；目标实机承担正式窗口和长期稳定验收。共享 CI 可显式运行少量基准，验证运行器、负载与报告是否可用，但其不稳定耗时不作为正式性能门槛，不默认每个 PR 运行 Benchmark。首批不建设专用性能服务器；环境或工具变化后重新建立可比条件，不跨机器直接比较绝对耗时。

长期积累检查在原有跨区、列车、修改及保存恢复循环中，加入代表性的创作视图开关、撤销历史更替、内容发布、故障片段保留与处理、导出和重放退出。每轮比较同时记录世界规模、草稿、撤销项、录制及保留片段的数量和空间，区分合理保留与资源泄漏。达到容量上限时验证对应的明确淘汰或拒绝规则，未处理故障片段不得静默删除。精确容量及循环组成随测量报告冻结，不靠强制 GC、重启或清除本应保留的数据掩盖增长。

预先声明的故障案例与正常性能负载中的意外故障分开判定。正常联合长测可通过显式保留片段、导出及重放已知案例验证资料处理和容量，不向当前正常世界注入内部异常。内部故障捕获另设隔离案例，预先明确预期故障、停止边界和结果检查，会话仍须冻结，不能强行继续。普通拒绝、合法损伤或重放中的已知故障仅在符合案例声明时算完成该项；其他崩溃、状态错误、安全约束破坏或必要恢复／复现失败仍立即保留证据并停止该轮，不能事后解释为预期结果。

旧性能脚本先登记再迁移，保留有价值的负载、原始数据及历史说明，逐步迁到统一入口与正式编辑器能力。代表测量、结果校验及报告贯通后再退役旧调用；新基线不能仅靠包装旧脚本宣称完成，也不以引入特定框架或重写全部采样代码为前置。旧切片的无头小负载及采集完成标记不等于正式性能验收，历史结果与新基线明确分开；旧场景删除仍受独立退役门槛约束。

Benchmark 按三个关口收尾：先交付可实际执行的代表基准与统一报告，再用实测提交编辑规模、操作频率、诊断组合、撤销／录制／片段容量及相应阈值供用户冻结，最后在冻结负载上完成正式窗口及长期验收。实现与集中测量可安排在阶段后段，早期仍按复杂度、内存或规模风险做定向测量。目标实机未取得时，可以分别报告工具与开发机工作完成，但整个阶段的目标性能仍待验证；规划、空入口或旧报告不算交付。整体实施票的拆分、依赖和验收改写由后续分期重组统一落实。

- 验证车辆及零件身份、耐久等运行状态保留；Composite 所有权与显示独立于世界 Chunk，不能重复拥有或重复渲染车辆体素。
- 通过正式伤害流程验证车体断裂、身份继承及碎块脱落，遵守 [03](03-composite-and-behavior.md) 的结构结算与所有权规则。
- 扩展切片 2 的存档能力，保存并恢复实际车辆布局、零件状态及破坏结果。不纳入沿轨运行、编组牵引或正式设计器。

### 切片 4：直线铁路运行与状态衔接

- 依赖切片 3。通过正式 RailConstructionPlan／Transaction 入口生成固定直轨，用一个车头和一节车厢验证统一编组牵引、接触点与车钩约束；轨道几何、占格和定位遵守 [06](06-railway.md)，不从显示节点推导运动。
- 提供启动、停车操作；单车头不能倒行，到线路末端停车，不自动反向。画面采用沿轨插值，相机跟随车辆的显示姿态。
- 运行中破坏轨道或车辆，验证任何必要接触点本次移动将穿过前方缺口时限制编组移动并停车、车下支撑失效只暂停受影响编组，以及编组断开后独立滑行和修复后显式启动；测试入口走正式伤害、结构结算与轨道修改流程。
- 保存运行中、滑行中与停车中的状态，按 [04](04-deterministic-simulation.md) 验证相同条件下读档继续与不中断运行一致。
- 弯道、坡道、双车头换端、五档组合矩阵和规模性能测试安排在后续铁路切片；桌面停靠另行验证。直轨通过不等于全部铁路几何或完整首版已经通过。

### 四个切片的验收分工

- **领域自动测试**：复用 `Train.Tests` 的无 Godot 测试边界，通过正式命令验证当前切片涉及的占用、伤害、改装原子性、身份继承、编组运动与存档恢复。只测试已经进入该切片的行为，不为后续系统建占位实现。
- **Godot 集成检查**：复用现有 `scripts/run-godot-*-smoke` 的组织方式，验证真实场景加载及领域状态到显示的接续；接入碰撞后同时检查修改时的碰撞更新。现有内容与日志冒烟不是体素世界验收的替代品。
- **人工观感检查**：检查当前切片的可见面，以及接入车辆后对应的刚性车体、车钩、插值和相机表现。自动检查通过不替代人工观感确认。
- 每个切片保留可重复运行的测试场景与操作步骤。测试入口调用正式逻辑，不另写一套仅供演示的世界修改、存档或运动逻辑。
- 四份 spec（汇总见 [#38](https://github.com/odradekk/train/issues/38)）已分别明确具体场景尺寸、输入序列、运行方式和通过条件；这些数值是可重复验收的固定夹具，不自动成为产品参数。每份 spec 区分本切片验收与尚未证明的能力，沿用同一正式领域边界及逐步扩展的 Godot 冒烟入口。

### 性能基线与后续验收

- 前四个切片各用固定场景、操作序列和固定且记录清楚的运行环境，持续记录体素数量、修改耗时、帧耗时与内存；接入存档后记录保存与加载耗时。跨切片比较时复用已有固定基线用例，新增能力另增对应场景，不把不同负载或环境的结果直接当作性能退化。
- 出现明显卡顿或性能退化，在当前切片排查，不等最后集中处理。不提前承诺未经测量的 FPS 或把小场景结果外推成规模保证。
- 大世界、高频修改、多列车压力测试安排在后续切片，结合实际测量确定正式规模与性能门槛。前四个切片完成不等于 [00](00-product-and-core-loop.md) 的全部首版验收完成。
- 后续仍需安排连续弯坡及车辆组合、双车头换端、完整世界生成与聚居地、桌面停靠专门场景、规模性能等能力的验证。保留在本文，待前面的切片交付后再选择和细化，不在 #38 一次发布全部后续实现票。

## 引擎能力分层参考

以下八个 Phase 仅保留为能力归类，不再表示实施先后顺序。例如切片 1 已同时涉及领域与渲染，切片 2 接入存档，不能等参考表的 Phase 8 才保存世界。

| Phase | 内容 | 目标 |
| --- | --- | --- |
| 1 Voxel Domain | VoxelDefinition、VoxelDefinitionId、RevisionId、Voxel storage、Chunk、Ownership、Durability；首个需要体素定义的切片一次性迁移根目录货物模型、目录、内容与引用到新 schema，不保留 goods 兼容层，归档 MVP 不变（#31） | 领域基础可用 |
| 2 World Rendering | Chunk → Face Culling Mesher → Chunk Mesh；Custom Static Mesh batch、AssetResolver、Dirty Chunk | 可以在 3D View 中稳定显示并破坏一个较大的 Voxel World |
| 3 Composite | CompositeDefinition、CompositeInstance、Local Voxel Grid、Archetype、Construction Validation、ownership、CompositeVisual、基础 Damage 与 Fragmentation、JSON Blueprint、完整 Refit 测试操作 | 可以加载设计、制造、改装、移动与破坏车辆，验证状态保留与事务原子性 |
| 4 Deterministic Simulation | SimulationClock、Command、Transaction、Evaluate、Resolve、Commit、Structural Resolution、Domain Event；建立 Determinism 测试 | 相同 Save + Input 可以稳定得到相同结果 |
| 5 World Generation | Seed、GeneratorVersion、Terrain、Resources、Settlement placement、Layout、基础 Rail Graph、Physical Rail | 给定 Seed 可以生成可重复、合法、可驾驶的世界 |
| 6 Railway Core | 连续物理轨段、明确连接、实体占格、局部断轨、平滑弯坡、五档车辆包络、compressed graph、RailPosition、multi-contact carriage movement、TrackRenderer | 验证已确认观感的正式实现，以及占格、破坏、存档和连续扫掠约束 |
| 7 Desktop Product Form | Primary 3D Window、Windows AppBar、Floating、Display selection、Focus behavior、Perspective Camera、Orbit、Zoom、target switching、minimized rendering suspension、可配置渲染帧率上限 | 窗口测试场景通过工作区、切换、多显示器、DPI 与消息共存验证后，接入体素测试场景验证桌面常驻 |
