## 不变量

- 同一 WorldSeed、GeneratorVersion、完整生效生成配置和有效生成语义内容，必须产生同样的世界图。版本、配置或生成内容变化后，不要求得到相同的地图。
- 生成使用无状态带键随机。结果只由 WorldSeed、用途、生成阶段、候选身份和重试序号决定，与调用先后无关；新增阶段或调整调用次序，不能改变其他阶段的结果。见 [04 的随机性规则](04-deterministic-simulation.md#随机性)与 [ADR-0003](../adr/0003-use-scalar-doubles-and-stateless-random-for-determinism.md)。
- 世界图的结构在生成后固定：节点和线路的集合、节点位置、线路长度、地貌概况和铁轨上限都不再变化。之后会变化的只有节点的占据者、线路的铁轨数与断点，以及节点资源。
- 同一对节点之间最多一条线路。线路之间不交叉，交汇只发生在节点上。
- 每个节点最多有一个占据者：聚居地或生物聚落。没有占据者的节点为空节点。
- 生成器的内部函数（例如噪声函数）只在生成阶段使用。生成之后，核心模拟层、局部场景和界面都只读取世界图中保存的字段。

## 规则

### 世界图

世界是一块宽 W 米、高 H 米的矩形地图，W 和 H 来自生成配置，地图不循环。核心状态里没有地图网格，世界图只保存以下数据：

| 对象 | 字段 |
| --- | --- |
| 世界 | 地图范围 W×H |
| 节点 | 编号、位置 (x, y)、地貌概况、占据者、资源 |
| 线路 | 编号、两端节点、长度、地貌概况、铁轨上限、铁轨数、断点 |

- 长度统一以米为单位。位置、长度、断点位置等连续量使用 double，见 ADR-0003。局部场景中一个体素格对应多少米，由 [01](01-voxel-engine-and-scenes.md) 决定。
- 节点编号和线路编号是稳定的身份，在生成时分配。

### 节点

- 节点的占据者可以是聚居地、生物聚落，或者为空。
  - 聚居地可以属于玩家，也可以不属于玩家。它与玩家的关系见 [00 的开局与聚居地](00-product-and-core-loop.md#开局与聚居地)。
  - 生物聚落是世界生物出发的地方。清剿以后，节点变为空。
  - 玩家可以在空节点上建立聚居地；有生物聚落的节点不能建立聚居地。
- 玩家建立聚居地时使用已有的节点，不新增节点。用于分岔的枢纽不单独设类型，就是空节点。

### 线路

- 生成时就产生全部可能的线路。
  - 铁轨数从 0 到该线路的铁轨上限；铁轨数为 0 表示这条线路尚未建成。
  - 修建新线路，就是把铁轨数从 0 提高上去。玩家不能在世界图之外新开线路。
- 线路长度单独记录，不小于两端节点之间的直线距离，用来表示地形造成的绕行。
- 铁轨上限由线路的地形决定，不超过全局配置的上限。
- 线路的正方向从编号较小的节点指向编号较大的节点。断点按“所在铁轨 + 从起点沿正方向的距离”记录，例如“A→B 方向 2 号铁轨 +200”。断轨对运行的影响，以及修复与扩建的规则，见 [06](06-railway.md)。
- Demo 中，线路上只有玩家的列车（世界生物另算）。不属于玩家的聚居地之间的贸易在核心模拟层中抽象结算，不派出列车。线路不属于任何人，修建、扩建和修复都由玩家出资。

### 地貌概况

- 每个节点和每条线路各有一份地貌概况，形式相同，包括三项：
  - 一个由内容定义的地貌类型，例如平原、丘陵、森林、荒漠、山地；
  - 一个起伏程度；
  - 少量地形特征，例如湖泊、河流。
- 地貌概况在生成时确定，有三个用途：选择聚居地类型；决定线路长度和铁轨上限；作为局部场景生成地形的输入。线路场景在两端按节点的地貌概况过渡。
- 具体取值由内容定义；场景怎样据此生成地形，见 [01](01-voxel-engine-and-scenes.md)。

### 世界生成流程

世界采用程序生成，必须能用 Seed 复现。生成依次经过下面七个阶段，每个阶段都按“生成 → 校验 → 成功或重试”进行：

1. **地貌**：生成器内部用由 WorldSeed 派生的噪声函数描述海拔和湿度，必要时再加温度。
   - 噪声函数的输入是地图上的任意一点，输出是一个平滑变化的数值。做法是：先在规则格点上用无状态哈希得到随机值，在格点之间平滑插值，再把几种尺度的结果叠加。
   - 地貌类型按阈值换算；起伏程度取一点周围的海拔变化；湖泊是海拔低于水位线的区域；河流是另一个噪声函数的窄带区域。不做水流模拟。
   - 噪声只用整数哈希和加减乘除实现，不使用超越函数，并以固定的测试向量锁定结果。
2. **节点**：
   1. 把地图划成边长为最小间距 d 的方格。
   2. 每个方格用自己的随机键，决定是否放一个候选点，以及候选点在格内的位置。落在湖泊里的候选点丢弃。
   3. 按格子编号的固定顺序，删掉与已保留的点距离小于 d 的候选点。

   这样任意两个节点至少相隔 d 米。节点的地貌概况在节点位置及其周围取样汇总得到。
3. **线路**：
   - 在节点之间建立一张不交叉的邻接图，按长度和地形删去一部分，并保证整张图连通。
   - 沿每条线路按固定间距取样，汇总出线路的地貌概况：主要地貌类型、最大起伏，以及是否跨过河流或湖泊。
   - 线路长度为直线距离乘以由起伏决定的绕行系数；铁轨上限由起伏和地貌决定。
4. **占据者**：按配置的比例和地貌，把节点分配给聚居地、生物聚落或空。聚居地再按地貌和配置权重选择聚居地类型，类型的含义见 [16](16-settlements.md)。
5. **资源**：为节点生成资源，见下文“资源”一节。
6. **初始铁路**：先用最少的线路连通全部聚居地，再按配置增加几条成环的线路，这些线路各设 1–2 条铁轨。其余线路的铁轨数为 0，包括通往空节点和生物聚落的线路。
7. **校验**：检查连通性、比例、间距等条件，并保证至少有一个非敌对的聚居地可以作为开局地点。

各阶段共同遵守以下规则：

- **噪声函数的使用范围**：噪声函数只在生成阶段调用，生成结束后不保留，任何代码都不再调用它。宏观地图如果需要连续的底图，由[窗口与界面的设计和规划](https://github.com/odradekk/train/issues/207)决定是从地貌概况推导，还是在生成时另存一张粗分辨率栅格；无论哪种，都不调用生成器的噪声函数。
- **随机键**：每个阶段的随机键由 WorldSeed、用途、阶段、候选身份和重试序号组成，编码随 GeneratorVersion 固定。不维护按调用顺序消费的随机流，也不用候选的枚举序号充当身份。
- **重试与预算**：
  - 重试必须有明确上限。生成器允许返回失败，不能无限循环。
  - 配置显式限制候选数量和搜索工作量。是否耗尽预算，以可计数的工作量为准，计数规则归属于 GeneratorVersion，不依赖机器速度。

#### 复现输入与输出

- **复现输入**：包括 WorldSeed、GeneratorVersion、完整生效生成配置，以及相关语义内容的指纹。配置要显式写出地图范围、地貌参数、最小间距、占据者比例、聚居地类型权重、初始铁路网要求和预算；默认值也要解析后记录，不能只保存 Seed。
- **成功输出**：世界图、稳定的节点和线路编号，以及生成报告。
- **失败报告**：保留同一组复现输入，以及失败所在的阶段、候选、违反的约束和已用的预算。报告要区分配置非法、候选不满足约束、预算耗尽和中断四种情况。搜索没找到结果，不等于证明无解。失败的结果不会替换当前世界。

### 资源

资源是节点的属性，在生成流程的第 5 步产生。资源的形式、是否耗尽或再生、怎样开采，由[资源与开采改为节点属性](https://github.com/odradekk/train/issues/205)确定。

## Demo 范围

Demo 的世界由程序生成，包括世界图、地貌概况、聚居地、生物聚落、空节点、节点资源和初始铁路网。地图的初始目标约 50 个节点，其中约一半是聚居地；具体数值在生成实验和试玩后冻结。

## Demo 之后

AI 势力的线路归属与通行费；非玩家列车；更大的地图规模和更多的地貌类型。

## 开放问题

- 地图尺寸、节点数、最小间距、地貌阈值、绕行系数、铁轨上限和预算等数值，通过生成实验和试玩确定后冻结。
- 新阶段需要什么样的标准测试地图，由[地图](https://github.com/odradekk/train/issues/193)迷雾“新阶段”确定。
