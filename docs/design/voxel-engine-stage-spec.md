## 本轮分期重组

> 已定稿：Q1–Q17 决定及 Q18 完整规格均经用户确认。本轮只整理规格与票据处置方案，不实现功能或自动派发。

起步顺序为统一测试执行与首批迁移 → 单一存档工作区 → 基础世界编辑工具，复用已交付的会话、正式命令、观察、保存恢复及权威检查点能力，不将旧通过证据当作新工作流已经完成。

| 交付片 | 前置与可操作结果 | 退出条件与边界 |
| --- | --- | --- |
| 统一测试执行与首批迁移 | 落实 SOP 的统一薄入口、严格选择、隔离和失败汇总、统一报告、轻量 Windows CI，贯通真实 MSTest 与代表性 Godot／跨进程检查。 | 作为后续编辑器扩展的共同前置；其余旧运行器登记迁移去向并随对应功能整理，不先重写全部旧测试。假运行器或脚本外壳不算完成；Benchmark 实现仍安排在后段。 |
| 单一存档工作区 | 在测试入口之后，贯通真正空白世界、普通示例副本、打开、保存／另存、导入导出及统一离开保护，进入同一个默认暂停的编辑环境。 | 基于现有会话、命令与恢复成果闭合正式工作流；程序生成待生成器可用后接入，不交付空壳生成能力。 |
| 基础世界编辑工具 | 在存档工作区之后，贯通工作平面、明确选择与局部层级、预览、单格／笔刷／区域编辑，以及这些操作的有限撤销。 | 作为后续建筑、铁路和创作视图复用的已验证基础，只建设当前操作所需能力，不先搭完整通用编辑框架。 |
| 建筑实例编辑与基础表现 | 基础世界工具之后，改写现有建筑票，保留单一身份、断裂整体失效、完整目标修复、残块归属及三路表现要求，接入模板放置、整体移动／旋转／复制／删除、局部改装、引用影响提示及对应创作操作的有限撤销。 | 使用已有合法建筑／站点模板，不等待蓝图创作界面、聚居地生成或连续曲轨；新增状态随片闭合保存恢复与必要验证。 |

建筑片之后，内容创作与铁路分别推进，不把完整内容创作设为铁路的硬前置。

| 工作线 | 交付顺序与闭合范围 | 依赖边界 |
| --- | --- | --- |
| 内容创作 | 车辆／建筑蓝图 → 体素定义 → Layout。蓝图先贯通独立草稿、校验、存档内／用户库发布、实例提取及实际使用；体素定义再交付表单与发布适配；Layout 创作安排在聚居地生成前。 | 从建筑片之后开始，身份、依赖复制、冲突及失败保护随首次用到的内容类型落实，后续类型复用；不先建设面向全部未来内容的框架，不按类型重复相同测试矩阵。 |
| 铁路 | 三维连续线路与五档单车 → 多节混编与双车头换端 → 道岔与站序／多列车网络。随片接入线路预览、施工／改线、沿轨放置与停稳重定位、显式编组和运行计划编辑，并闭合各自已约定的撤销边界。 | 建筑和基础编辑能力具备后即可推进，先使用合法模板；完整蓝图创作或体素定义表单不是铁路硬前置。保留固定四站三列、10 节泰坦能力及早期规模诊断，不因工具接入缩减原领域验收。 |

Layout 片在蓝图及体素定义创作之后，先在小型手工世界贯通编排、选中对象提取、草稿与发布、预览和原子放置，补齐所需聚居地实例、建筑归属及派生统计。实际建筑、道路及可选站点落位、有限整地和保存恢复随片验证，不等待整张地图生成，不自动连接铁路；后续生成器消费明确选中的已发布 Layout。

生成主线保留固定四站三列网络持续运行与早期规模诊断 → 视觉驻留、路径预取和原点切换 → 地形／聚居地生成 → 联合铁路生成。地形／聚居地片同时依赖已可用 Layout，生成可修改、可保存的真实世界；联合铁路片再贯通站址、朝向、合规选线、有限整地及三列验证。生成失败不替换当前世界，不把手工示例更换种子标签视为生成成果。

统一诊断在基础世界工具之后独立尽早交付：对象关联、命令状态和拒绝原因、已有空间图层、有限条件暂停，以及人工检查点／对照入口。铁路预留与道岔锁随网络片补齐，Chunk 驻留和原点随跨区片补齐。诊断调用正式查询与操作，不等待完整录制，也不为未实现系统提供假数据；性能概况仅显示实际可测指标，Benchmark 另行验收。

完整录制与隔离复现保留独立交付，默认在地形／聚居地生成与联合铁路生成之间，但前一片生成不是技术硬前置。它依赖已可用存档、正式输入及诊断入口，完整交付默认有界录制、内容留存、故障片段、ZIP 导出、隔离重放及普通编辑副本，允许按实际进度提前。后续新系统随片补齐录制与重放；最终生成／性能负载冻结前，届时所有正式操作均须覆盖，录制默认开启，早期证据不能代替新增操作的验证。

旧用例分成体素／边界、车辆、铁路三个独立验收组，依赖统一测试入口、存档工作区与实际所需操作，制作普通示例并迁移自动／人工步骤和有效旧性能用例。缺少的旧能力操作入口在对应迁移组补齐并供后续复用，不为此等待新的曲坡、多节或生成系统；个别实际依赖须在清单中明确。原退役票在三组证据齐备后集中删除旧入口与专用驱动，保留旧存档原文件及历史报告。

新增可执行 Benchmark 与比较报告实施片，接入统一入口，贯通操作基准、真实窗口及长测的代表运行与结果校验，覆盖届时编辑器及默认录制。可在后段完成，早期风险测量仍随功能进行，旧测量迁移不等待本片。原参数冻结票继续负责完整数据及参数建议的用户确认；原最终验收票继续负责冻结后的生成／编辑／运行／恢复复现及目标实机短测、长测，缺目标硬件时保持未完成。

保留建筑、三片铁路、跨区表现、两片生成、完整复现、退役、参数冻结与最终验收的现有 Issue 身份，改写范围、验收及前置并说明本轮调整，保留已有讨论和链接；缺少的工作另建票。标题使用描述性名称，不加阶段编号；编辑器接入不削减原领域验收下限。

原“建立长期 Playground 与共用确定性契约”父票按原范围核对已关闭七个子票、父票十一项 AC 映射及用户验收证据，发布汇总后以已完成关闭，保留原正文和子票历史，不改写成新的编辑器总票。若发现实际缺项则明确补验或另列工作，不仅凭子票状态判通过，也不重跑无关全套。资源源体素与确定性开采产出票保留开放，明确移出本阶段并取消当前可派发标记；未来经同一编辑器正式伤害／开采操作、定义表单和测试入口接入，不再要求专用场景，也不成为本阶段前置。选入后续阶段时重新核对规格及依赖。

### 派发状态与实施粒度

可派发标记仅赋予规格充分、原生阻塞已完成且所需代码与文档已在可用基线中的执行任务；其余票明确依赖和待满足条件，移除误导的 `ready-for-agent`，不以 `needs-info` 代替依赖阻塞。冻结和最终验收票明确用户决策／硬件关口，资料写完不等于可完成。本次重整不自动派发；派发前须确认所需规格已提交推送，且任务工作树已取得对应代码与文档基线，不能把本地规格视为其他工作树已具备的前置。

本轮票据是可验收的交付规格，须写明输入、正式操作、失败保护、保存恢复及退出条件。超出单次实施容量的复杂票，在派发前再拆为可独立验证的纵向子票；不拆成只有模型、只有 UI、最后才集成的长期半成品，也不强制简单票继续细拆。父票负责完整交付验收，子票局部通过不能提前关闭父票。

## 目标与范围

形成可分期实施、可逐片运行验证的体素引擎与世界编辑器规格，覆盖普通存档工作流、世界和内容创作、真实地图与铁路生成、多列车运行、可修改建筑、表现与碰撞、保存复现及统一测试。编辑器已纳入本阶段，不再沿用旧规格将正式创作界面排除的范围。资源、生产、库存、经济玩法、桌面停靠和多显示器产品能力不属于本阶段完成门槛。

各领域规则继续以对应设计文档为权威，本规格安排交付顺序、输入、可观察结果、验收和退出条件，不另建一套规则。

## 各片共同交付规则

每片在同一个编辑器中可操作、可观察、可恢复、可验证，不新增长期产品场景。采用当时已支持的真实内容，常用创作提供图形入口，精确批量和低频调试可用控制台；中间版本若暂用命令须列明后续图形交付归属，不能以假数据或空按钮宣称能力完成。

新增权威状态的字段、必要引用、来源／内容版本、ID 与规范编码、恢复校验和确定性证据随产生该状态的功能片闭合。复用现有命令顺序、稳定身份、随机键和黄金向量，不预先固定全部未来类名、文件布局或优化算法。建筑覆盖修复目标和残块来源，铁路覆盖实际路径、通行权、故障和待执行输入；按受影响契约做跨进程对照，不能积压到阶段末尾。

预览与独立创作草稿不冒充世界事实；草稿保存、普通存档和发布各守其边界。体素、建筑、铁路和车辆工具分别补齐已约定的反向事务，撤销不倒退模拟时间或 ID；运行、步进、世界切换与内容发布等历史失效边界按[交互契约](playground.md#有限撤销与重做)执行。常用创作不能全部标为不可撤销来逃避交付。

完整录制可后补或提前，未交付时明确诊断能力边界；一旦有录制，新系统随片接入输入、依赖及重放，最终冻结前覆盖全部正式能力并默认启用。普通恢复适配当前内容，严格复现使用核验后的原内容及兼容环境，分别报告，不能互相替代。

建筑片的 Specialized 表现先使用当前直轨；弯坡和道岔表现分别随对应铁路片补齐。建筑片建立站点结构与接口，网络片验证停靠及接口受损的运行影响，Layout 片补齐聚居地归属和派生统计，不反向依赖尚未实现的系统。

固定四站三列与 10 节泰坦网络通过持续通行后，测真实体素占用、全图模拟及可见区域内存与耗时，及早发现铁路几何带来的尺度问题，再扩大跨区和联合生成实验。这是开发机早期诊断，须列明当时的表现／录制能力，不替代生成证据、最终默认负载或目标实机验收。

## 配置与指标冻结关口

联合生成提供最小合法标准世界，完整录制默认启用，Benchmark 片已提供正式测量能力后，按[性能契约](roadmap.md#本阶段性能验收)进行探索并提交报告，由用户确认冻结：

- 完整标准生成配置：世界/Chunk 尺寸、地形起伏、站距、道岔及弯坡间隔、候选 Layout、列长能力、土方和稳定搜索预算。
- 调参与独立验证种子分离，冻结独立清单、成功率门槛、运行配置、初始泊位/计划/发车序列、相机路线、操作及检查点；保留全部失败，不事后删种子。
- 探索、固定验收、超额压力三类负载的界限；帧耗时/卡顿、模拟积压、操作最长停顿及内存稳定门槛。
- 驻留加载/卸载半径、预取、近远切换、原点触发/防抖、重建预算/区域准备时间、录制容量/起点间隔和可保留的实际时长。
- 构建/内容/环境清单，预热稳定条件、事件最低次数及 VSync/限帧控制方式。
- 代表编辑规模与频率、创作内容数量、图层和详细采样组合，预览／提交／发布等操作的独立指标；撤销、草稿、录制和保留片段的数量／空间，以及长期可比较循环。
- 操作基准的预热、批次及重复次数，冷启动单列；同条件相对回归的允许波动和阻塞规则，缺测／样本不足的结论边界。持续窗口短测和联合长测仍守已定时长，详细要求见[世界编辑器 Benchmark 工作流](roadmap.md#世界编辑器-benchmark-工作流)。

开发机可以提供探索数据，但不能替代目标实机结果。冻结以后更改配置、代码或依赖而影响某项结论，须重新记录受影响结果；改变验收门槛重新提交用户确认，不将门槛调到当前结果即可宣称通过。此关口确定后续测量输入和判据，不是测量已经通过。

## 最终联合验收与阶段完成

在冻结后的独立种子与负载上，生成检查和实际运行分别报告；成功种子按标准网络执行三列联合运行和 Godot 观察，另保留故意非法配置、约束冲突和预算失败证据。相同构建/内容/输入进行跨进程重复及保存退出继续对照，覆盖建筑、铁路、生成及编辑器创作／发布／切换等关键状态转换，并用已完成复现链定位首次差异。

正式性能环境固定为 Ryzen 5 3600、桌面 GTX 1650 GDDR5 4 GB、16 GB 双通道、SSD、Windows 11 x64，独立 Release 构建、真实 1080p 窗口、Compatibility、默认录制开启；目标 60 FPS 且完整模拟持续跟上 1× 时间。记录真实硬件、驱动、供电、显示路径与冻结环境。当前无目标实机，不能以开发机限核/降频或 headless 宣称等效通过，也不因此阻塞功能开发。

正式持续窗口短测每组预热至少 1 分钟后记录 5 分钟，独立重复 3 次；最终候选至少 2 小时联合长测、不少于 10 轮相同操作循环、至少 3 次录制窗口滚动，必要循环未覆盖则延长。覆盖跨区、多列车持续通行、重复修改/损伤/修复、保存恢复和录制滚动；回到同一观察点与可比较领域规模检查内存/对象趋势，不能靠定期强制 GC 或重启掩盖积累。

联合验收还覆盖冻结的编辑器代表流程：世界编辑及撤销、蓝图／体素定义／Layout 创作发布与实际使用、切换保护、诊断关联、片段留存及导出重放。长期比较记录草稿、撤销项、录制和保留片段的数量与空间，区分合理保留与泄漏。预先声明的合法拒绝、损伤或重放故障按案例结果检查；内部故障捕获单独隔离测量，正常长测不注入当前世界，意外错误仍按停止规则处理。

崩溃、状态错误、安全约束破坏、必要恢复或复现失败立即保留证据并停止该轮；帧耗时、积压和增长按冻结门槛判定。不能持续通行单列为运行验证失败，不用于推断性能容量。先修正瓶颈，可缩减超出功能基线的压力，但不删四站、三列、10泰坦、完整模拟或默认录制。最小合法标准地图仍失败时，明确失败并重新提出配置/范围取舍。

最终报告逐项区分功能交付、参数冻结、正式验收通过、失败和待验证。全部交付片、旧入口退役、参数冻结及最终验收所要求的正确性、交互性能与长期稳定均有证据才可称本阶段完成；目标实机缺失时只可报告已完成的功能与开发机观测，性能关口继续待验证。该状态不影响本次规划地图在规格确认后结束。

## 实施与交接边界

本文件中的切片是可观察交付与验收单元，不强制一个切片等于一个提交或 PR；更小实施工作仍须保留所属片的完整退出条件和明确依赖，不拆成长期无法运行的底层半成品。实际派发、独立工作树、审查、逐项验收和用户批准合并按[任务派发与验收流程](../dispatch-sop.md)执行；任务实现、测试和 PR 交付按[任务执行流程](../implement-sop.md)执行。本地图不自动启动实施、提交、推送或合并。

每片交付报告记录受测提交、内容/配置、命令、环境、原始结果、失败与首次异常位置。生产命令新增/修改同步更新 [console 手册](../console/README.md)。验证使用届时真实存在的命令和脚本；本规格中的拟实施配置标识不能冒充现在可执行的命令。历史报告输出路径不得作为新测试默认覆盖目标。

已定设计覆盖之外的性能实现选择、存储结构或优化，只有实际证据表明当前片需要时再决定。若出现会改变功能范围、铁路标准、确定性/保存语义或完成门槛的新问题，明确记录并取得相应决议，不以“实现细节”自行改写契约。资源生产和桌面产品能力仍留在本阶段之外。
