> 状态：已确认并发布实施规格。来源：[确定端到端实施顺序并收敛本阶段切片规格](https://github.com/odradekk/train/issues/99#issuecomment-5856447496)。Q1–Q10 已获用户确认，分期及验收划分通过规格评审；实施 Issue 使用描述性标题，不带切片编号。本文描述后续实施要求，不是已实现或已通过验收的报告，也不授权本轮直接开发。

## 目标与范围

形成可分期实施、可逐片运行验证的体素引擎规格，覆盖真实地图与铁路生成、多列车运行、可修改建筑、表现与碰撞、保存和复现，以及贯穿开发周期的 Playground。资源、生产、库存、经济玩法、正式玩家编辑器、桌面停靠和多显示器产品能力不属于本阶段完成门槛。

各领域规则继续以对应设计文档为权威，本规格安排交付顺序、输入、可观察结果、验收和退出条件，不另建一套规则。

## 实施基线与证据边界

规划工作树基线为 `47d7397885a1edd6e4a53cfa4403d940281eb77f`（0.0.27），2026-09-27 核对与当时远端 master 一致。下述是只读代码核查，不是重新执行验证所得结论；开始实施时须核对届时代码、设计文档与环境。

- 可复用正式世界会话、结构修改命令、普通保存/恢复及权威状态派生渲染的基础。当前人工和自动入口仍按四个切片及专用夹具分派，不能将改名当作迁移完成。
- `Domain/Rails/PhysicalRail.cs` 的线路类型和 `RailConstruction.cs` 的施工校验仍限定沿 X 轴直轨；`TrainAssembly.cs` 的装配请求仍限定机车与车厢各一。需要正式支持通用连续线路与编组，不能把类型或尺寸枚举存在当作运行能力完成。
- 旧验证报告仅证明其受测提交、环境和固定负载下的结果；直轨二车、小型体素夹具及 headless 批次耗时不证明生成网络、多列车或真实窗口性能。
- 验证环境遵守 [Windows 验证规范](../tickets-sop.md#local-validation-and-windows-builds)。规划时本机缺少工作树锁定的 .NET SDK 10.0.111；本轮未修改环境，也未运行游戏测试。目标 Ryzen 5 3600／桌面 GTX 1650 GDDR5 实机缺失，最终目标性能保持待验证。

## 已确认的交付安排

### 第一片：最小可用 Playground

首先接入现有正式世界和操作，提供固定配置、恢复存档、3D 自由观察、选择后的显式聚焦/跟随、运行/暂停/单步及保存切换保护；配置与独立自动验证步骤分开管理。

该片只开放已有能力，不能将空壳生成按钮或模拟数据作为交付。生成器可用后再接入生成来源。旧四切片及其驱动保留到覆盖迁移和验收证据齐备，不在第一片提前删除。

后续建筑、连续铁路和多列车能力直接在此长期入口中交付与观察，不再增加产品级切片场景。

### 建筑、铁路与跨区表现的顺序

以下顺序已确认。每片都产出 Playground 中可操作的结果，验证所新增状态的保存恢复与确定性；领域数学或离线报告不能代替真实 Godot 集成与必要人工观察。

S3–S5 是三个依次交付的铁路切片。所有线路与车辆均使用已确认的首批机械、几何及精度标准；原型观感认可和离散采样不能替代正式占格、保守扫掠、状态转换及 Godot 验收。S5 保留整列等待位置、实际占用与未来通行权的区分，实际测试安全与通行进展，不能以一直停车作为成功。

S6 完成后再扩大地形、站址、Layout 和铁路的联合生成实验，避免把跨区显示能力缺失混入生成器结论。

S7 → S8 → S9 是默认排期。Q6 允许完整复现与生成探索调整先后，但不改变硬前置：S7 的真实地形和布局能力先于 S9，S8 必须在最终生成/性能负载冻结前完成并默认启用。S7 的暂不含标准铁路网络状态必须通过明确来源/版本识别，后续版本不静默重解释其存档。

S2 的三路基础表现以当时已实现的正式直轨作为 Specialized 代表；弯坡和道岔分别在 S3、S5 补齐，不能要求 S2 先实现后续铁路。S2 建立建筑真实结构与接口内容，S5 验证站点停靠/接口损坏对运行的影响，S7 落实聚居地实例归属与派生统计，避免用尚不存在的系统证明验收。

### 保存恢复与确定性随功能交付

新增权威状态的保存、恢复校验和确定性证据进入产生这些状态的同一功能切片：建筑覆盖修复目标和残块来源；铁路与调度覆盖实际路径、通行权、故障和待执行输入。每片补充相应跨进程重复比较，不把恢复问题积压到阶段末尾。

有界滚动录制、隔离重放和完整 ZIP 复现包允许分后续切片补齐。中间版本明确未交付的诊断功能，不能宣称完整 Playground 已验收；最终默认录制及完整复现契约不变。

完整复现另作可验收切片，覆盖有界起点与滚动裁剪、内容切换及依赖留存、隔离重放和 ZIP 导出。它与生成探索的具体先后允许调整，但在冻结最终生成/性能验收负载之前必须完成并默认启用；最终测量包含真实默认开销，不沿用缺少录制的早期结果。

S1 先形成可执行的共用命令顺序/编码、来源及版本标识、稳定 ID、数值编码、随机键和状态校验规则，并保留黄金测试向量。后续切片在交付时补齐新增状态的必要字段、引用校验和失败诊断，连同恢复一起验收；不预先固定所有未来类名、文件布局或优化算法。

### 联合生成前的固定网络规模诊断

正式弯坡、道岔与多列车能力具备后，先用固定配置搭建满足四站、三列及 10 节泰坦能力的合法网络，测量真实体素占用、全图模拟和可见区域的内存及耗时，以发现铁路几何带来的地图尺度问题；随后开展地形、站址、Layout 与线路联合生成实验。

此诊断不是生成器验收，也不是最终性能验收。须报告当时已启用和未交付的表现/录制能力；开发机结果不能替代程序生成种子集、最终默认录制负载或目标实机证据。

## 每片验收与退出条件

每片以版本化配置、正式操作序列、自动断言和必要人工观察交付。领域检查、真实 Godot 集成、跨进程恢复及人工观感分别报告，不以采集成功代替断言通过。既有相关回归继续通过，合法用例和拒绝用例均有证据后，才可将该片标为功能交付；未实现或未验证项明确列出。

## 保存、输入与校验的交付清单

以下定义必须覆盖的信息；精确字段、枚举值及字节编码在所属片形成可执行契约和测试，不以临时日志或派生缓存代替权威状态。

| 所属片 | 必须明确并验证的技术契约 |
| --- | --- |
| S1 共用规则 | 区分固定配置来源和生成来源；来源/保存/输入版本、有效配置和内容依赖；完整提交步与边界内操作次序、目标步/稳定输入顺序、命令载荷及接受/执行/拒绝结果；无歧义数值与稳定集合编码；实体 ID 分配/回滚/不复用/溢出；随机算法及键编码；基底与权威状态哈希范围和首次差异输出 |
| S2 建筑 | 实际零件布局/身份/耐久/朝向、建筑单一身份和失效状态、实例完整修复目标、残块来源及唯一所有权；必要站点引用随相关能力补齐，外部模板不替代目标 |
| S3 线路与单车 | 稳定物理轨段身份、连续几何、明确连接及有效部分；沿轨位置、必要接触与合法故障姿态；被引用的全毁轨段仍保存定位依据，丢必要引用应失败 |
| S4 编组 | 实际车辆/车钩关系、活动车头、参考方向、各独立编组运动与故障状态、实际经过路径；拆分及换端后恢复同一约束解，不按最近轨道猜测 |
| S5 网络 | 站序/停留/换端计划及进度、实际占用、已授路径、排队、道岔锁、拆分持续保护和必要顺序；恢复不得重新寻路/抢权/排队替代原决定 |
| S7/S9 生成 | Seed、GeneratorVersion、已解析默认值的完整配置、语义依赖/指纹、稳定候选与重试键、工作预算计数规则；基底布局/稳定 ID/结构关系及运行配置的站点角色绑定 |
| S8 复现 | 起点、实际保留范围、JSON Lines 有序输入、内容发布前/候选/后状态、必要资产、构建及环境标识、检查点和 ZIP 文件完整性清单；领域输入与观察输入区分，内容仍在窗口内时不丢切换过程 |

S1 的黄金向量覆盖随机键及结果、规范化编码和状态摘要；后续每类新增权威状态提供恢复对照。关键检查点放在制造/修改/伤害/修复、拆分/换端、授权/释放/排队、生成发布、内容切换、保存捕获/恢复以及录制起点滚动的完整事务边界。保存时保留已接受未执行输入；预期失效命令在原定位置拒绝并出队、后续独立命令继续，内部不变量故障停止在最后完整提交点。

普通恢复采用当前内容合法适配；严格复现使用兼容构建及原有效内容。两种对照分开报告，不以内容适配后的不同哈希误报确定性失败，也不以当前内容偷偷重解释复现输入。

## G1：配置与指标冻结关口

S9 提供最小合法标准世界，S8 完整录制默认启用，并具备正式测量能力后，按[性能契约](roadmap.md#本阶段性能验收)进行探索并提交报告，由用户确认冻结：

- 完整标准生成配置：世界/Chunk 尺寸、地形起伏、站距、道岔及弯坡间隔、候选 Layout、列长能力、土方和稳定搜索预算。
- 调参与独立验证种子分离，冻结独立清单、成功率门槛、运行配置、初始泊位/计划/发车序列、相机路线、操作及检查点；保留全部失败，不事后删种子。
- 探索、固定验收、超额压力三类负载的界限；帧耗时/卡顿、模拟积压、操作最长停顿及内存稳定门槛。
- 驻留加载/卸载半径、预取、近远切换、原点触发/防抖、重建预算/区域准备时间、录制容量/起点间隔和可保留的实际时长。
- 构建/内容/环境清单，预热稳定条件、事件最低次数及 VSync/限帧控制方式。

开发机可以提供探索数据，但不能替代目标实机结果。冻结以后更改配置、代码或依赖而影响某项结论，须重新记录受影响结果；改变验收门槛重新提交用户确认，不将门槛调到当前结果即可宣称通过。此关口确定后续测量输入和判据，不是测量已经通过。

## G2：最终联合验收与阶段完成

在冻结后的独立种子与负载上，生成检查和实际运行分别报告；成功种子按标准网络执行三列联合运行和 Godot 观察，另保留故意非法配置、约束冲突和预算失败证据。相同构建/内容/输入进行跨进程重复及保存退出继续对照，覆盖 S2–S9 的关键状态转换，并用已完成复现链定位首次差异。

正式性能环境固定为 Ryzen 5 3600、桌面 GTX 1650 GDDR5 4 GB、16 GB 双通道、SSD、Windows 11 x64，独立 Release 构建、真实 1080p 窗口、Compatibility、默认录制开启；目标 60 FPS 且完整模拟持续跟上 1× 时间。记录真实硬件、驱动、供电、显示路径与冻结环境。当前无目标实机，不能以开发机限核/降频或 headless 宣称等效通过，也不因此阻塞功能开发。

短测每组预热至少 1 分钟后记录 5 分钟，独立重复 3 次；最终候选至少 2 小时联合长测、不少于 10 轮相同操作循环、至少 3 次录制窗口滚动，必要循环未覆盖则延长。覆盖跨区、多列车持续通行、重复修改/损伤/修复、保存恢复和录制滚动；回到同一观察点与可比较领域规模检查内存/对象趋势，不能靠定期强制 GC 或重启掩盖积累。

崩溃、状态错误、安全约束破坏、必要恢复或复现失败立即保留证据并停止该轮；帧耗时、积压和增长按冻结门槛判定。不能持续通行单列为运行验证失败，不用于推断性能容量。先修正瓶颈，可缩减超出功能基线的压力，但不删四站、三列、10泰坦、完整模拟或默认录制。最小合法标准地图仍失败时，明确失败并重新提出配置/范围取舍。

最终报告逐项区分功能交付、参数冻结、正式验收通过、失败和待验证。S1–S9、R1、G1 及 G2 所要求的正确性、交互性能与长期稳定均有证据才可称本阶段完成；目标实机缺失时只可报告已完成的功能与开发机观测，性能关口继续待验证。该状态不影响本次规划地图在规格确认后结束。
