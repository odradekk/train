# 05 世界生成与聚居地

> 决策出处：转录 Q89–Q95、Q102、Q178；2026-09-05 #30 确认 Faction 延后，[#36](https://github.com/odradekk/train/issues/36) 确认位置、生成分类、建筑与资源事实来源、接轨及静态占格。

## 边界

本文定义程序生成流水线、资源生成、聚居地的结构、聚居地与铁路的关系、Layout 放置。铁路的拓扑、图与施工见 [06](06-railway.md)；Resource Source 的开采、耗尽与 Resource Renewal 见 [10](10-resources-and-extraction.md)；聚居地的生产、库存与设施见 [12](12-inventory-and-storage.md)、[13](13-production-runtime-and-facilities.md)，市场与人口规则留待后续扩充；术语以 `CONTEXT.md` 为准。

## 不变量

- 同一 WorldSeed + GeneratorVersion + 完整生效生成配置 + 有效生成语义内容必须产生同样的初始世界；版本、配置或生成内容变化后不要求得到相同地图。
- 后续阶段新增 RNG 调用不能改变前面阶段的结果。
- Settlement exists ≠ Station exists ≠ Rail connection exists。
- 聚居地类型（SettlementArchetype）与空间布局（Layout）严格分离；首版 Archetype 只承担生成用途，经济行为延后。
- 聚居地位置只有一份三维体素锚点；建筑数量与资源种类反映实际世界，不由 Layout 模板另存一份权威清单。

## 规则

### 世界生成

世界采用程序生成 + 手工 Blueprint/Layout，而不是固定手工地图。世界生成必须使用 Seed 可复现。

### Generation Pipeline

下图保留包含资源阶段的完整生成方向；当前无资源阶段采用后文的阶段契约，不执行 Resource Potential、Actual Resources 或资源偏好筛选。

```text
WorldSeed
↓ Terrain
↓ Resource Potential
↓ Actual Resources
↓ Settlement Candidates
↓ Settlement Archetypes
↓ Logical Settlement Nodes
↓ Rail Connection Plan（生成期的连接意图）
↓ Layout Selection + Rotation
↓ Settlement Materialization
↓ Physical Rail Pathfinding
↓ Decoration
↓ Validation
```

- 每个 Stage 使用独立派生 Seed：Hash(WorldSeed, GeneratorVersion, StageId, RetryIndex)。
- 每个 Stage：Generate → Validate → Success / Retry。Retry 必须有明确上限；生成器允许返回 WorldGenerationFailed，不能无限循环。

### 本阶段无资源生成契约

[地图、聚居地与铁路生成决策](https://github.com/odradekk/train/issues/95)已确认以下本阶段契约。它定义实施目标和验收关口，不表示生成器、模板或验收负载已有正式实现。

- **地形范围**：有限世界中生成平原、缓丘、谷地及适合聚居地落位的平坦区域。允许通过高度场与材料分层构造，但结果必须落实为可修改的真实三维体素。自然洞穴、悬挑、水系及复杂生态分区不作为本阶段程序生成的必达内容；引擎的三维挖掘、悬空结构等能力仍由固定回归验证，数据模型不限制为高度场。
- **地形与选线**：先生成地形、筛选聚居地和站点候选，再规划站点连接意图，并联合调整 Layout 朝向和实际线路。允许配置限额内的站场整地、挖方和填方；不能大范围推平地图或降低已确认的铁路标准保证成功。空间不足时更换候选，仍不可行则明确失败。连接规划不是铁路运行事实；运行图只能从最终实际物理铁路派生。
- **无资源分类**：聚居地类型与 Layout 分离，按显式配置权重、地形条件和占地约束选择，暂停资源偏好筛选。城市、工业区等名称可保留，但本阶段仅决定生成内容，不产生虚构资源、产能或库存。既有静态人口字段及其约束不因此变成经济模拟。
- **标准网络验收配置**：至少四个应接轨站点形成同一物理连通网，其中三个构成跨站绕行环路，第四个为支线终点站；另有容纳声明整列长度的会让设施及共享冲突路段。会让线形成的小环不能替代跨站绕行环路。不同种子须能改变站点位置、布局和线路形状，不能只给同一手工网络换种子标签。无站或未要求接轨的聚居地仍合法，其验收可分布在样例集合中，不要求每张标准地图均有孤立聚居地。一般配置可选择更简单的网络，也可增加规模，但不能替代标准生成验收配置；具体空间规模由性能决策确定。
- **地图的列长能力**：生成配置显式声明支持的最大编组长度，据此验算站点、等待区和会让线。标准生成验收配置按用户要求扩大为 **10 节泰坦（总节数包含车头）**，直线名义长度为 `10×24+9×1=249` 格；停车余量、弯曲路径占用及整个车体离开道岔冲突区的空间另算，不能直接把有效停车区长度设成 249 格就视为通过。该数值是标准地图声明的列长能力，不是产品列车长度上限。实际列车、站序计划及并发数量由运行验证配置提供，不从当前画面中的已有车辆推断地图能力。
- **最小布局与站型**：每个聚居地落实普通建筑及道路；标准验收地图整体至少覆盖两种普通建筑 Blueprint、两种 Layout。站点支持通过式（两端接轨）和尽头式（单侧接轨），仍是一座实际建筑、一个停靠区；会让线不扩展为多站台运营。需从尽头站原路折返的计划使用双车头停稳换端，单车头可在能够持续前进的环路上运行，不新增单车头倒行或机车绕行功能。
- **自动施工范围**：首批仅生成地面铁路、受限路堤和路堑，不自动生成桥梁或隧道；铁路交会只使用已定合法道岔，不新增平面交叉。整地配置分别限制挖填高差、施工区域及土方总量，路基必须实际存在；超限则绕行、换址或明确失败。固定回归中的桥梁、悬空结构验证继续保留，不因此删除引擎能力。
- **重试范围**：一次生成请求的原始地形固定，只对站址、Layout 和选线做有预算的确定性重试。候选整地变更随失败尝试回滚，不能不断叠加到下一次候选中。预算耗尽则返回失败，不自动更换种子、重抽地形、删除必达网络特征或退回平地夹具。失败资料供诊断，沿用 Playground 的失败保持当前世界规则；不能将失败候选作为成功地图发布。
- **联合运行验证**：标准地图至少同时运行三列车：一列 10 节泰坦，另两列分别为 4 节、8 节跨档混编，总节数均含车头。覆盖单车头绕环、双车头支线折返，并安排同向追踪、对向会让及汇入竞争；同时验证安全与持续通行。运行验证配置明确初始停放位置、绑定站点角色的运行计划和发车顺序，不承诺任意计划或等待位置全占满时均无死锁。三列只是功能验收起点，压力上限、运行时长及性能门槛由性能决策确定。
- **首批线路与道岔模板**：采用已定直线、缓和段、圆弧及平滑坡度曲线族；水平三端道岔以固定 15° 分支角的左、右版本为首批模板目标。该角度由本决策提升为实施目标，仍须正式验证，不能把历史原型采样视为模板安全证明。道岔水平进出段及其与弯坡的间隔，依据实际完整路径和编组的保守扫掠检查确定；不通过时扩大间隔、改线或拒绝，不凭未经验证的统一间距或任意样条掩盖违规。
- **确定性工作预算**：配置显式限制候选数量、选线搜索工作量及整地数量。是否耗尽预算以稳定可计数的工作为准，计数规则归属于 GeneratorVersion，不依赖机器速度或实际耗时。仍记录耗时，但取消或执行超时单独归为中断，不能据此断言地形或选线不可行。具体预算值在代表性种子实验后、标准验收配置冻结前确定。

本阶段生成流程为：地形 → 聚居地/站点候选 → 铁路连接规划 → Layout 朝向与合规线路的联合取舍及有限整地 → 实际建筑和物理铁路落位 → 派生运行图并验证。重试只在上述已定范围内进行。所有铁路几何、机械兼容、净空和精度检查服从 [06 的首批标准](06-railway.md#首批铁路几何与机械参数)。10 节泰坦的地图服务能力还须补充相应长编组、站场与多车运行验证，不能把历史 4/8 节原型报告改称为 10 节已经通过。

#### 复现输入与输出

- 复现输入包含 WorldSeed、GeneratorVersion、完整生效生成配置及相关语义内容指纹。配置显式包含世界边界/尺寸、地形参数、分类权重、候选 Layout、拓扑要求、列长能力及预算，默认值也须解析后记录，不能仅保存 Seed。阶段随机隔离继续适用，工作预算的计数规则随 GeneratorVersion 解释。
- 成功输出真实初始世界、稳定对象标识和生成报告。运行验证配置单独记录版本及实际站点角色绑定，不把验收列车和发车顺序隐含在地图生成配置中。
- 失败报告保留同一组复现输入，以及失败阶段、候选、位置、违反的约束和已用预算；区分配置非法、候选不满足约束、预算耗尽及中断。搜索未找到结果不等于证明无解。失败候选仅供诊断，不替换当前 Playground 世界。
- 具体编码、内容依赖的封装与校验、版本适用范围及存档兼容由[确定性和存档恢复决策](https://github.com/odradekk/train/issues/97)承接。

#### 验收覆盖与成功判定

- 每张标准成功地图满足上述网络及建筑/Layout 多样性要求，实际可运行线路至少包含水平转弯和非零坡度，不能以全平直地图代替。
- 代表种子集合共同覆盖平原、缓丘、谷地、左右弯、坡顶/坡底、弯坡叠加、通过站/尽头站及有限挖填，不要求每张地图集齐全部极端组合。保留坏种子和预算耗尽案例，验证明确失败及旧世界保留。参数极限与故意非法配置另由固定回归验证，不能替代程序生成证据。
- 每次发布候选世界前，须验证实际占格与支撑、净空、几何/编组兼容、声明列长能力、实际网络连通，以及运行验证配置能否正确绑定站点、放置列车。全部通过后才可原子替换当前世界。
- “生成检查通过”与“运行验收通过”分别报告。交互生成不要求先执行完整长时多列车测试，未运行不能标为运行通过；标准验收种子集合须在实际领域模拟中通过约定三列联合运行，并完成真实 Godot 观察。地图修改后，旧报告不能继续代表当前世界。

#### 实验与配置冻结

- 后续实施规格必须包含明确的生成实验与配置冻结步骤，以已定铁路标准和 10 节泰坦为约束，实测选择世界尺寸、地形起伏、站距、道岔间隔、土方与搜索预算。
- 调参种子与预先固定的独立验证种子分开，完整记录成功率、失败分布、耗时及空间用量，不只展示挑选出的成功种子。
- 标准配置、验收种子清单与成功率门槛必须在最终验收前明确冻结；尚未冻结或尚未通过验收，不能宣布生成器完成。具体世界规模、性能门槛与测量方案由[性能验收决策](https://github.com/odradekk/train/issues/98)承接，实验依赖、交付顺序与冻结关口由[阶段切片规格](https://github.com/odradekk/train/issues/99)承接。

### 资源生成

- Resource Potential Field → Actual Resource Voxels。Potential Field 用于宏观判断资源分布并选择符合资源偏好的聚居地类型，不作为聚居地当前资源种类的事实来源。
- 实际资源体素是带 `resource_source` 标签、由 ResourceSourceBehavior 定义产出的 Resource Source Voxel；矿床、森林资源区只是 Source Voxel 的空间 Cluster，不建立第二份储量事实。不可再生资源耗尽后不在原地 Respawn，长期可持续由 Resource Renewal Event 在合格的未开发区域生成新 Cluster，其选择服从 WorldSeed 与稳定随机键，见 [10](10-resources-and-extraction.md)。
- 聚居地类型原则上响应自然资源，而不是为了聚居地类型强行生成资源；允许少量 Gameplay Validation 和保证性调整。

### 聚居地资源种类

- 资源种类从聚居地周边当前实际存在的 Resource Source Voxel 派生：nearby Resource Source Voxels → ResourceSourceBehavior → 可获得的 Raw Good DefinitionIds。不固定保存生成时的清单；Layout 不另行声明资源种类。旧的按 `natural_resource` 标签直接派生的规则废止。[#77](https://github.com/odradekk/train/issues/77) 已把聚居地内容与领域模型改为引用带 `raw_good` 的初级货物种类；[#78](https://github.com/odradekk/train/issues/78) 仍待实现 ResourceSourceBehavior，以及从周边资源源扫描派生该集合（[02](02-definitions-and-content.md)、[10](10-resources-and-extraction.md)）。当前实现仍把种类集合作为聚居地内容字段加载，不是运行时扫描结果。
- 查询范围以聚居地锚点为基准，由生成配置明确，不能把 Layout 中声明的建筑占地隐式当作资源范围。具体范围形状与参数随生成切片确定。
- 一种资源在范围内被采尽后，从派生种类中消失；体素或其 Resource Source 定义变化后，查询结果须反映当前世界。该结果只表示种类，不表示储量或产量；储量由实际 Source Voxel 的 CurrentDurability 与 Yield 派生。
- 周边资源种类、当前生产能力与当前货物库存是三份独立事实：农业聚居地可以没有 Grain Source 却大量生产 Grain，种类查询不从生产或库存反推，见 [13](13-production-runtime-and-facilities.md)。

### 聚居地

- 聚居地本身不是 Composite。首版模型记录 SettlementId、Archetype、三维布局锚点、朝向、实际建筑实例引用及可选 Station，保留既有的静态常住人口数据及其正数约束；消费、人口变化与 Faction 的玩法设计和实现延后，首版不保留阵营占位字段。聚居地的生产、库存、Power Pool 与 Labor Pool 接口由 [12](12-inventory-and-storage.md)、[13](13-production-runtime-and-facilities.md) 定义，能力来自建筑 Composite 内的真实设备 Voxel，聚居地不拥有无来源的抽象产能。
- **SettlementArchetype** 与术语表的聚居地类型是同一概念，不维护两套分类；首版描述生成所需的资源偏好与候选 Layout，不产生经济模拟行为。
- **SettlementLayoutDefinition** 负责空间布局：Building Composite、World Voxel、Decoration、Site Constraints、optional Station/Rail Socket。建筑为 Composite，道路与装饰为世界体素（转录 Q93）。

### 位置与布局实例

- 聚居地位置采用 Layout 锚点的世界三维整数体素坐标，布局朝向单独保存。高度由生成器结合地形与 Layout 约束确定。
- 二维地图需要位置时从三维锚点投影，不继续独立维护旧 `MapPosition(X, Y)`；具体代码与内容迁移在生成切片执行。
- Layout 只是生成模板，放置后形成实际建筑实例；聚居地记录这些实例，建筑数量按当前实例的建筑类型派生汇总，站点不计入普通建筑数量。
- 制造、拆除或破坏改变实际建筑集合后，统计反映新状态；修改 Layout 模板不自动重建已有聚居地。
- 静态建筑断裂后仍只记录原来的一个建筑，整体失效，不按分离部分增加计数；所有核心毁坏后移除原引用，重建时记录新身份。碎块归属及修复规则见 [03 的建筑契约](03-composite-and-behavior.md#本阶段静态建筑契约)。

### 聚居地与铁路

- 首版每个聚居地有零个或一个站点，允许没有站点或尚未接入铁路的聚居地；测试场景可显式选择需要生成铁路连接的站点，不要求贸易系统参与。
- 站点通过一个或多个 RailSocket 描述接轨位置和方向。Layout 可放置站点及其接口；RailSocket 是站点接轨能力的描述，不是聚居地身份的必要条件（转录 Q178 修正 Q102）。
- RailSocket 不等于物理轨道的 Track Port，也不自动创建铁路连接或压缩图节点。实际连通性由物理轨段的明确连接与当前有效区间决定，不能从轨道格邻接关系猜测；Station 作为重要位置参与派生的 RailControlPoint，见 [06](06-railway.md)。
- 铁路生成先规划连续几何，再登记钢轨、轨枕实体占格并验证车辆扫掠净空。空间不足时调整线路或拒绝方案，不生成单格急弯或默认 1:1 坡；遵循 [06 的首批标准](06-railway.md#首批铁路几何与机械参数)，未完成正式验证的线路组合不默认开放。五档合规车辆共用正常生成且完整的线路。
- 允许多个接轨接口不代表首版实现多站台运营或复杂调度。
- 本阶段一个站点对应一个实际建筑，沿用 [03 的建筑失效规则](03-composite-and-behavior.md#本阶段静态建筑契约)：断裂使整个站点失效，停止接受新的停靠。接轨接口绑定实际部件，部件消失时对应接口失效；站点身份、建筑可用状态、接轨接口和轨道连通性分别检查。站点受损不自动删除物理轨道，完整且满足其他运行条件的线路仍可通行。
- 接口声明在生成时落实到实际部件绑定；更新 Layout/Blueprint 不重写已放置站点的绑定。接口部件被修复后重新校验接轨状态，不凭位置相近创建轨道连接。站点失效或引用撤销不清除列车实际占用与必要通行保护，运行层继续遵守 [06](06-railway.md#本阶段网络运行契约)。

本阶段不含资源生产的生成契约，还须消费 [06 的网络运行契约](06-railway.md#本阶段网络运行契约)：面向声明支持的编组长度、方向和负载，提供实际可通行的站点路径、整列等待空间与会让条件。仅压缩图连通不能证明多列车能持续运行；具体拓扑、配置与失败条件由[地图与铁路生成契约](https://github.com/odradekk/train/issues/95)确定。此要求不强制每个聚居地设站或接轨，也不引入多站台和复杂调度。

### Layout 放置

- 手工 Layout 首版允许 0°、90°、180°、270°；不默认允许 Mirror、Arbitrary Rotation、Scale（转录 Q94）。
- Layout 拥有 Site Constraints：footprint、最大高度差、biome 或 tag 要求、forbidden terrain。
- 生成器允许有限、确定性的 Site Preparation：清理装饰、小范围填土、小范围挖平；超过约束则拒绝 Candidate。

### 静态建筑占格与净空

- 静态 Building Composite 保留独立身份与局部体素网格，同时在世界网格登记实际体素占用位置。占用登记只引用建筑中的体素，不复制为 World-owned Voxel，也不改变其 Composite 所有权。
- 同一世界格不能再放置另一个地形或轨道体素。检查实际体素占用，不把建筑包围盒中的所有空格都视为占用。
- 静态建筑参与统一的世界占用与碰撞查询。RailConstructionPlan 既验证轨道格占用，也验证车身 Swept Clearance；占用与 Collision 仍按 [01](01-voxel-world.md) 区分。
- 修改、拆除或破坏建筑时，占用与碰撞查询同步反映新状态，不留下已删除体素的占位。
- 建筑整体使用整数锚点和四向水平旋转，不缩放，不套车辆五档尺寸。新建、改装和完整修复均验证实际占格与既有铁路净空；冲突时原子拒绝，没有列车正在经过也不能破坏完整线路的通行条件。建筑空洞按真实空格处理；体素采用 None 或局部碰撞盒不免除整格占用及整格铁路净空检查。
- 建筑碎块原位转为世界体素，或修复时将符合条件的原位残块收回，均按 [03](03-composite-and-behavior.md#本阶段静态建筑契约)原子变更唯一所有者及其占用登记。修复目标描述期望完整设计，不替代当前实际布局，也不预占已缺失格子。

## 首版范围

本阶段实现上述无资源生成契约：Seed、GeneratorVersion、生效配置与内容指纹、真实三维地形、三维聚居地放置与朝向、生成用途的 Archetype、Layout、实际建筑及其派生统计、可选站点及 RailSocket、静态占用与净空查询、实际物理铁路及派生运行图，以及标准网络和联合运行验收。上文资源生成规则保留为后续设计，不纳入本阶段；首批生成器不自动生成桥梁或隧道。

## 明确延后

资源分布及资源偏好筛选、消费、人口变化、市场等经济行为，Faction 的设计与实现，多站台运营与复杂调度；桥梁和隧道自动生成、AI 铁路施工；Mirror、额外的环路密度调节（不影响本阶段必达跨站环路）。生产、开采与库存的设计见 [10](10-resources-and-extraction.md)–[14](14-construction-refit-and-deconstruction.md)，其实现同样不在本阶段。

## 开放问题
