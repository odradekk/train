## 边界

世界编辑器是面向本游戏、贯穿开发周期的唯一长期人工创作与调试环境，以普通游戏存档中的世界为工作对象，支持创建、加载、编辑、生成、运行和调试。面向用户的菜单和新文档使用“世界编辑器”；Playground 保留为既有代码和历史资料名称，按实际迁移需要处理，不为改名一次性重写代码。

创作范围包括世界实例、可复用 Blueprint/Layout、体素定义的数值、标签、行为参数与现有表现资产绑定，分期交付。直轨列车等人工调试案例归入示例存档，不按案例增设产品场景。近期仍聚焦体素、建筑、地图生成与铁路；资源、生产、经济后续接入。模型与贴图由外部工具制作，新行为逻辑通过代码实现，不建设与本游戏无关的引擎编辑器或任意代码插件平台。

编辑器与正式游戏共享世界、存档、模拟、修改、渲染和碰撞能力；正式游戏通过模式的权限、成本、建造时间、进度和界面约束形成玩法，不由沙盒类比增加故事模式。新建、打开、生成、另存等流程见[存档工作流](09-persistence.md#世界编辑器存档工作流)；生成算法与合法性沿用[地图生成契约](https://github.com/odradekk/train/issues/95)。历史原型中的地图、车辆和参数仍只是示例。

## 共用核心与模式边界

### 自由操作与世界正确性

编辑器允许免费、即时创建和修改对象，并可绕过后续玩法的进度和操作权限；身份唯一、引用完整、事务原子性、确定性，以及相应操作的结构、铁路几何和占用规则仍须满足。正式伤害可以形成断轨、残骸和失效建筑，这些是可保存、可运行的受损状态；受损状态不因不满足新建条件而被当作坏档。直接写坏内部数据和内部故障注入属于隔离测试，不能作为正常世界继续模拟。

编辑器、正式游戏、控制台和自动测试共享最终领域校验与提交逻辑，允许不同的上层流程。例如编辑器即时放置建筑，正式游戏以后先检查材料并执行建造任务，完成时仍经过同一建造校验与世界事务；不要求各模式按钮或外层命令完全相同。相机、面板、预览和 Godot 图形节点不成为世界事实来源。

### 草稿、世界与模拟

- 未完成的放置预览、线路及 Blueprint/Layout 修改属于编辑草稿，可以暂时不满足完整建造条件；校验通过后，通过明确操作原子提交。草稿不进入模拟，不被普通世界存档当成已建成对象。世界临时草稿不持久化，离开时明确处理，见[存档工作流](09-persistence.md#离开保护临时草稿与执行期间状态)；蓝图、Layout 及体素定义的独立创作文档可以保存草稿，发布与目标归属见[内容创作流程](02-definitions-and-content.md#世界编辑器内容创作流程)。
- 草稿与已接受、等待目标步执行的命令不同；后者仍按[保存边界与待执行输入](09-persistence.md#保存边界与待执行输入)持久化，不能因未执行而被当作面板草稿丢弃。
- 运行、暂停和步进作用于当前世界；模拟造成的变化直接保留，暂停不自动还原，保存包含运行结果。试验后回退须明确重新加载之前的存档；隔离复现或测试使用独立会话，不改变当前编辑世界。不承诺任意时间回退；后续交互决策补充的[有限编辑撤销](#有限撤销与重做)不回退模拟时间。
- 暂停时修改经过完整事务和必要结构结算，完成后仍停在当前模拟步；运行时进入共用输入顺序，在明确的完整模拟边界执行。预览不是执行许可，提交执行时仍检查当前条件。例如预览施工后列车驶入相应范围，若施工条件不再成立则明确拒绝，不偷偷停车、挪车或换目标。
- 确实只支持暂停执行的操作明确提示，由用户暂停后再提交；不把所有编辑一律限制为暂停，也不隐式暂停。已接受命令的拒绝、出队及内部故障处理继续遵守[输入契约](04-deterministic-simulation.md#命令失效与内部故障)。

### 三层创作的职责

| 修改对象 | 对已存在世界的影响 |
| --- | --- |
| 世界实例 | 显式修改实际地形、建筑、铁路、车辆或运行计划；不会自动改写来源 Blueprint/Layout。建筑完好时成功改装是否更新实例修复目标，仍按[建筑契约](03-composite-and-behavior.md#本阶段静态建筑契约)执行。 |
| Blueprint/Layout | 修改可复用模板，影响后续创建；不自动重建既有实例，不替换实例修复目标。保存草稿、独立副本及发布见[内容创作流程](02-definitions-and-content.md#世界编辑器内容创作流程)。 |
| 体素定义 | 数值、标签和行为参数发布沿用当前内容适配规则；先验证候选，成功后整体适配相关实例，失败保留旧内容与世界。实际布局与身份继续保留，不将模板变化混作定义数值适配。 |

具体创作界面、内容归属与发布流程见 [02 的内容创作流程](02-definitions-and-content.md#世界编辑器内容创作流程)。内置及已安装 Mod 在编辑器中只读，自定义蓝图、Layout 和体素定义支持存档内与用户内容库两种范围；草稿、发布与普通世界保存分别处理，外部引用继续采用当前定义。

### 后续功能的接入要求

每个交付切片都在同一个世界编辑器中提供足够的创建或配置方式、正式操作、状态及失败原因查看，并补齐新增状态所需的保存恢复和自动验证。常用创作操作提供图形入口，精确批量与低频调试可用控制台；中间切片可明确暂用命令及后续图形交付安排，不要求每个内部字段都有面板，也不为新系统再建长期调试场景。

独立自动验证复用正式能力，可以无界面或跨进程执行，不要求经过 GUI。测试按[测试标准](../implement-sop.md#testing-standard)选择覆盖真实风险的最小充分集合；统一测试执行设施优先于后续功能扩张落地，不把编辑器接入要求变成重复测试矩阵。

### 与既有契约的关系

本轮替代旧文档“通用编辑器整体延后”的范围安排，保留本游戏之外的编辑器、插件框架和外部资产制作工具的边界。以下契约继续有效，不因提供自由编辑而放宽：

- [单一权威世界 ADR](../adr/0004-keep-the-world-model-as-the-single-source-of-truth-and-treat-godot-as-a-derived-adapter.md)：Godot 是领域世界的派生适配层，显示与输入不成为第二套世界事实。
- [确定性 ADR](../adr/0003-use-scalar-doubles-and-stateless-random-for-determinism.md)及[模拟与输入契约](04-deterministic-simulation.md)：保留数值、随机、稳定身份、输入顺序和完整事务边界的约定，不扩大跨平台确定性承诺。
- [当前定义与版本 ADR](../adr/0005-resolve-current-definitions-and-separate-content-versions.md)：保留内容身份、版本区分、当前定义解析和候选原子发布；[普通读档与严格复现](09-persistence.md#本阶段保存与复现契约)仍分开。

本节共用核心边界决策未修改上述 ADR，也不固定新的类名、存档格式或通用框架。后续内容创作决策仅扩展 ADR-0001／ADR-0005 的用户内容类型与存储安排，保留身份、当前定义适配和版本原则。各专门决策继续细化运行诊断、性能和旧场景迁移，最后统一重整实施票。

## 世界创作工具与交互

> 交互决策：[确定世界创作工具与铁路编辑的统一交互](https://github.com/odradekk/train/issues/140)的 Q1–Q19 已确认，三轮原型流程均通过用户评议，Q20 已确认完整规格定稿。本节是目标契约，不表示当前固定按钮、命令或正式引擎已具备全部能力。

### 工作区、选择与输入

工作区按职责组织为工具与内容库、世界视图、对象检查器；工具包含地形／体素、建筑、铁路、车辆与运行计划。内容库读取当前有效定义及模板，不以固定矿石、空壳、最新车辆或固定直轨按钮充当通用能力。当前存档、未保存状态及模拟控制保持可见，操作结果与控制台可展开；面板方位、尺寸和视觉样式不在此冻结。

通常点选完整建筑、车辆或轨段，需要修改内部时显式进入该对象的局部编辑；世界体素用独立工具。界面显示当前层级、所属对象、目标身份和坐标系，允许返回整体。编组及运行计划从明确选中的列车进入；点选仍不自动聚焦或跟随。

支持视图框选和列表多选，列出数量、类型和身份，只提供共同支持的操作。同类批量操作整体校验、整体提交或拒绝；混合建筑、铁路和车辆不套用同一个自由拖动，也不在首批支持任意跨类型联合改造。已有草稿绑定明确目标集合，选择变化不重写目标，对象消失不换成其他对象。

左键按当前工具选择、放置或绘制；右键拖动只观察，WASD/QE 仅在世界视图获得输入时移动。文本框、面板和控制台消费自身输入，不同时触发世界修改或相机移动；失焦、松键及控制台打开后的拖动结束规则继续有效。聚焦和跟随须显式触发。有草稿时切换工具、层级或目标，先明确提交或放弃，不静默丢弃；快捷键细节不在此冻结。

### 工作平面与提交反馈

提供可见且可调整的工作平面：默认水平面可指定高度，支持竖直平面或拾取对象表面，显示轴向、网格、吸附点和坐标。世界坐标与对象局部坐标明确区分，空白世界无地形也能定位。体素遵守整数格和定义允许的正交朝向；连续铁路使用自身几何控制与合法接续吸附，不折成体素阶梯。

鼠标位置、方向或范围与检查器精确参数共用同一份预览。建筑放置、整体移动旋转、铁路施工和批量改装在明确确认后才提交；体素笔刷以一次笔划为操作单位，结束后整体校验提交，大范围或多步骤编辑先预览再确认。预览不写入世界，提交时仍按当前世界重新校验；失败指出具体冲突并保留可调整的草稿，不部分写入，不把连续拖动和每次键入直接提交。

### 各类创作工具

| 工具 | 本阶段目标行为 |
| --- | --- |
| 地形／世界体素 | 单格、笔刷及长方体区域的添加、移除、替换；从有效内容选择定义与允许朝向，预览准确范围、数量和冲突。不能用普通地形工具隐式拆散建筑、车辆或铁路所属体素，须进入相应对象工具或显式伤害操作。保留精确坐标及跨高度编辑；平滑、侵蚀、任意形状选区等高级工具后续扩展。 |
| 建筑 | 模板放置，整体移动、旋转、复制、删除，以及内部部件改装。合法移动旋转保留身份和状态；复制当前实例状态并分配新身份，不自动修复损伤。删除移除指定对象，伤害形成正式受损状态，两者分开。站点及其他引用影响须明确显示并整体验证，不隐式移动相连轨道、列车或删除外部引用；改装、损伤与完整修复继续遵守[建筑契约](03-composite-and-behavior.md#本阶段静态建筑契约)。 |
| 新建铁路 | 指定起终点、方向和高度约束，中间控制点表达走向；可从空白位置起线或吸附合法接续端点。精确参数与线路预览同步，显示线路、实际占格、净空和失败原因。正式几何及施工规则决定能否提交，不能提交任意非法样条。水平道岔使用专用工具，明确三端及连接；无合规结果时保留草稿。 |
| 既有铁路 | 改线、拆除、伤害、修复四类操作明确区分。改线预览替换范围、接续端点和影响，整体验证后原子提交；拆除显示轨段与连接。列车、通行保护或必要定位引用使操作不安全时拒绝，不挪车或清除保护。断轨测试走正式伤害，保留必要身份和定位依据，再正式修复，不以删除引用伪造故障。 |
| 车辆与编组 | 选择模板、明确既有车辆或完整编组，在轨道指定位置和朝向，预览整列姿态、接触点、车钩与净空。既有车辆重定位须实际停稳，并通过路径、占用、引用校验；暂停不等于停稳。编组内单车不能独立拖走，须先显式解编或操作整列。制造、连接／解编、起停和换端分别提供入口，不靠靠近自动猜测连接；离轨设计和部件试装由独立蓝图创作流程承担。 |
| 站点与运行计划 | 从实际站点建筑查看接轨接口及整列停车空间，连接通过正式施工建立，不因靠近轨道自动连通。选中编组编辑单次／循环站序、停留时长和换端许可。草稿可随时修改，提交替换既有计划前须显式停止计划并使整列停稳；新计划不自动启动，显式启动从首个目标站开始。缺失站点拒绝提交，临时断路、占用或停车空间不足明确诊断，不靠删车、改道或清除保护伪造可运行。 |

铁路几何、换端、通行保护及故障恢复继续遵守[铁路契约](06-railway.md)，工具不放宽规则；修改计划也不自动解除故障停车。以上按功能切片交付，中间版本明确尚未提供的能力，不要求在首个入口切片一次实现全表。

### 有限撤销与重做

草稿内支持撤销／重做；已提交编辑则只在当前会话暂停期间保留有限历史，不提供跨模拟时间、跨存档的完整回退。

- 撤销／重做作为新的正式编辑事务执行，不还原整个会话快照，不倒退模拟步、命令序号或实体分配游标。仍存在的对象保留身份；重建已删除对象使用新身份，并在支持范围内原子恢复必要引用。旧待执行命令不自动改指向新对象。无法安全恢复结构、占用或引用时整次拒绝，不能部分恢复。
- 面板、控制台及其他正式入口共用一条按原子操作记录的历史，按最近操作逐项撤销／重做；撤销后成功提交新编辑清除重做分支。不能绕过历史追踪偷偷修改世界。失败的修改或反向操作不清除既有历史。
- 常用创作能力随对应工具交付撤销：体素／区域编辑、建筑整体操作、对象局部改装，以及能够完整反向校验的铁路施工／改线／拆除和停稳车辆重定位。不能把本应支持的创作操作全部标成例外来宣称完成。
- 伤害／修复、编组连接／解编和运行控制首批可明确标为不可撤销；其他尚不支持撤销的世界修改也须执行前提示，成功后结束旧历史。提交的反向操作仍受正式校验及确定性记录要求约束，不仅改变画面。
- 实际进入运行或步进、成功切换世界或成功发布内容时，明确提示并结束该段历史；失败的操作不清除。单独保存、另存和导出保留历史；切换保护中的临时暂挂不等于一次世界恢复或模拟步进。
- 历史有容量上限，到限明确淘汰最旧项，不进入普通存档；数值后续测量，不预先冻结。重新打开存档不会恢复旧撤销栈。

### 原型与验收边界

[交互流程原型](../../archive/prototypes/world-editor-interaction.prototype.html)为无依赖单文件 HTML，仅保存页面内存状态。三轮的局部编辑、冲突后修正、笔划整体拒绝、删除后的新身份、保存／步进历史边界，以及施工方向修正、必要保护拒绝改线／拆除、停稳后替换计划均已获用户确认。独立流程卡不是正式产品场景，预设条件不构成几何、净空、调度或运动验证。

三个脚本块通过语法检查；讨论时无可连接浏览器，未取得代理实际点击或画面验证。三维工作平面、相机编辑手势、多选、车辆姿态求解和草稿内撤销未在原型中建模，不能从流程确认推导这些能力已验收。原型按用户授权原样归档于 `archive/prototypes/`，不纳入正式游戏代码；归档不增加视觉或正式引擎通过结论。

正式交付须用真实内容与所选对象完成相应操作，验证合法提交、必要拒绝、恢复及受影响的撤销／重做边界；画面、输入和正式领域状态的关系分别提供证据。跨进程恢复沿用[存档工作流](09-persistence.md#世界编辑器存档工作流)，测试仍按[最小充分覆盖标准](../implement-sop.md#testing-standard)选择。Blueprint/Layout 和定义创作发布见[内容创作流程](02-definitions-and-content.md#世界编辑器内容创作流程)；完整诊断、故障复现、旧场景退役及实施票重组仍由对应决策承接。

## 不变量

- Playground、控制台和自动验证使用正式领域入口，不各自维护一套世界或绕过验证。
- 相机、选择、面板与模拟控制相互独立；暂停自动推进不清除列车运动状态或故障。
- 旧入口退役以覆盖迁移和验收证据为前提；配置、步骤与历史证据不因删除旧驱动而一并丢弃。

## 规则

### 操作职责

| 入口 | 职责 |
| --- | --- |
| 存档工作区 | 主菜单的单一编辑器入口首先进入此处；新建、打开、从示例创建副本和本地导入均使用统一存档流程，不按固定配置建立独立产品入口。 |
| 世界视图 | 3D 自由观察、聚焦选中对象、跟随指定车辆；不要求世界先有车辆。 |
| 对象列表与检查面板 | 选择并读取对象状态，提供常用控制、修改、伤害、修复、保存与加载入口；选中对象不隐式改变镜头，可直接发起聚焦或跟随。 |
| 控制台 | 精确参数及批量操作，与面板调用同一正式逻辑，结果可追查；新增或修改正式命令时同步维护 [console 手册](../console/README.md)。 |
| 模拟控制 | 新建或打开当前世界后默认暂停自动推进；支持运行、暂停、单步和指定步数。普通面板、查询、镜头不隐式暂停；离开保护和世界切换期间明确暂挂，取消或失败后恢复原运行状态，见存档工作流。 |

恢复存档保留原速度、运行计划及故障状态；暂停自动推进不等于对所有列车执行停车。普通交通等待与故障显式恢复遵守 [06 的网络运行契约](06-railway.md#本阶段网络运行契约)。修改、伤害、修复可在暂停时执行，也可在运行时提交到明确模拟步，所有入口都经过正式验证和事务。

相机和窗口的对应边界见 [08 的 Playground 专节](08-desktop-window-and-camera.md#playground-调试观察与模拟控制)。自由相机是开发工具能力，不自动改变正式游戏的相机设计。

对象仍存在时保留选择和跟随，编组拆分不自动换到活动车头。目标彻底销毁时清除失效选择/跟随引用，明确提示目标失效；镜头保持当前位置并转为自由视角，不自动跳到其他列车。该规则针对 Playground；正式游戏目标销毁后的选择策略仍按其相机契约另定。

### 运行诊断工作流

[确定运行调试、诊断观察与故障复现工作流](https://github.com/odradekk/train/issues/142)已确认十八项决定，并经完整规格确认定稿。既有普通存档、有界录制、隔离复现及故障契约继续有效；以下是目标工作流，不表示功能已经实现。

#### 统一诊断与关联定位

编辑器提供统一诊断工作区，从检查器进入对象状态、命令记录、铁路运行关系及复现资料。错误条目可定位相关对象、轨段或位置；目标已失效时保留原身份和事件信息，不自动替换成其他对象。选择条目不移动镜头，聚焦／跟随仍显式触发。诊断只读取正式状态，修复、停车等修改继续走正式操作，不另建专用调试场景，也不冻结面板布局。

辅助图层按用途独立开关，分别显示体素实体占格、碰撞、车辆实际占用、线路净空、通行预留／道岔锁，以及 Chunk、视觉驻留和渲染原点，提供图例与对应模拟位置。默认围绕所选对象或指定区域；只显示局部或尚无数据时明确标出，不能把未显示当作没有冲突。观察开关不改变权威状态，也不自动暂停模拟。

#### 有限条件暂停

除运行、暂停和精确步进外，首批增加有限的运行到条件：指定模拟步，或指定命令被拒绝、指定对象发生故障等已支持事件。用户显式启用后，于完整提交边界暂停并说明命中原因；可取消，并设置最大推进步数，未命中时如实结束。这些操作实际推进当前世界并保留结果，不自动回退；首批不提供任意脚本断点或完整时间倒带。

条件绑定启用时明确指定的命令或对象稳定身份，匹配启用后发生的正式事件；选择变化不换目标。指定命令已结束、目标已失效或指定步已过去时，提示不能再等待，不自动重试或寻找替代目标。运行期间目标失效、达到步数上限、用户取消或命中条件都在完整边界停止，显示各自原因。设置仅属于本次调试会话，不进入普通世界存档，切换世界时清除。

#### 命令记录与故障反馈

记录明确区分提交前拒绝、待执行、执行成功、执行时拒绝和内部故障，显示操作来源、目标、参数、接受／计划／实际执行位置及结果原因。支持按对象、类型和结果筛选并定位关联条目；解析或入队前拒绝不伪造已接受命令的编号，执行时拒绝按原顺序出队、后续继续。界面标明显示范围及截断情况，有限日志不冒充完整录制，已接受不冒充已成功执行。

反馈区分三类结果：普通拒绝解释条件且不默认暂停；断轨、建筑失效等世界内可恢复故障显示正式修复和显式恢复所需条件，不偷偷修复或清除保护；内部异常／不变量破坏则突出显示会话冻结、最后完整边界及证据入口，保留查询和诊断导出，不能用“继续”按钮强行清除。内部故障后须加载已知有效状态或重建会话才能继续工作。条件暂停仅供观察，不改变上述领域语义。

#### 录制状态与检查点

默认有界录制提供常驻摘要及可展开面板，显示正在录制／不完整／尚无可用起点、实际可复现范围、容量占用和最近错误，并可从事件或命令定位对应记录。用户可在完整边界添加说明标记；标记不改世界，也不永久保留历史。旧记录将被裁剪或已不在完整窗口内时明确提示，只有实际保留的起点、输入与依赖齐全才显示可完整复现；容量与采样间隔仍由 Benchmark 决策实测冻结。

权威检查点支持人工打点及正式验证序列自动打点，均在完整事务边界捕获；显示模拟位置、输入位置、来源、内容和构建信息，可导出规范状态与摘要。比较先说明环境、来源和输入的可比性，再定位最早的可比较检查点、对象、字段及预期／实际值。内容适配与环境不一致单列，不冒充确定性缺陷；不同人工操作后的状态差异可用于排查，但不能据此宣称同输入复现失败。不默认每帧抓取完整状态。

导出默认包含当前完整录制窗口，也可将选中事件或完整边界作为终点，自动带入此前可用恢复起点及到终点所需的全部输入、内容与依赖，并预览实际范围；不能从任意日志行起拼成完整复现。开始导出后固定本次资料，当前世界可继续运行，后续变化不混入包。记录不全时说明缺口，只能作为不完整诊断资料导出。失败或取消保留已有目标文件，覆盖已有包须明确确认。

#### 故障片段留存

说明标记与保留故障片段分开：内部模拟故障发生时，或用户显式保留时，固定当时可用的起点、输入与依赖，形成待导出资料，并如实标注完整性，不能补造已经丢失的记录。留存数量与空间有上限，不能默默挤掉尚未处理的资料；无法继续留存时明确提示，保留已有片段，由用户处理容量。

切换世界或正常退出前，对尚未导出的保留片段明确选择导出、放弃或取消，与世界及草稿的离开保护合并提示。导出失败或取消不能当作已处理并继续丢弃资料；普通世界保存也不等于导出了片段。普通滚动记录不因此在每次离开时弹窗，首批不承诺崩溃后自动恢复这些资料。

#### 隔离重放入口

故障复现包在同一编辑器的独立隔离重放模式中打开。先经过当前世界、草稿及待导出故障片段的离开保护，包完整性、版本和依赖校验通过后才切换，失败保留原工作。不完整诊断资料不能作为完整重放包通过校验。重放使用包内规定内容，不覆盖已安装 Mod 或用户内容库；界面持续显示复现包身份、记录位置及重放状态。

重放默认暂停，允许自由观察、暂停和步进，但不接受新的世界修改或内容发布，避免改变原输入。显式运行后，在记录末尾、首次不一致或记录中的内部故障处停止；比较实际操作结果与已记录检查点。无法理解输入、缺失依赖或首次差异时保留位置和诊断，不跳过后继续宣称成功，暂停／步进不改变记录输入顺序。

重现包内故障时报告“故障已复现”，不报告产品验证通过；顺利播放结束也须说明是否有检查点对照，以及哪些画面问题仍待人工观察。播放、对照与人工结论分别呈现。

修改案例须显式创建未保存的普通编辑副本：在完整有效边界提取实际世界与待执行命令，按本机当前内容、来源支持及基底校验重新验证；成功后进入默认暂停的编辑会话，原包保持不变，新操作开始独立记录。不自动安装包内旧外部内容，也不将其作为普通存档的兼容兜底。不兼容则拒绝并保留重放会话；合法损伤保留，内部故障冻结状态不能借复制强行解锁。副本结果不再作为原包严格复现的证据。

#### 录制输入与回归案例

录制以正式操作、明确目标及实际结果为主。世界修改、运行输入、撤销／重做和内容发布尝试按正式边界记录；发布保留重放所需候选内容及依赖，不能只记文件路径。相机、选择、图层及渲染原点信息与领域输入分开，用于相关显示问题，不参与世界仲裁。未提交创作草稿、表单输入和文件读写失败可按问题附诊断资料，首批不承诺自动重放所有 GUI 手势或磁盘故障，也不把附属资料作为领域重放已经验证的证据。

人工探索可从完整起点及正式操作序列整理为案例草稿，由开发者明确规则、预期结果和必要检查点，不能直接把录制到的结果当作测试预期。缺陷案例优先保留原始故障资料，回归测试另行断言修复后的正确行为。案例通过统一测试入口，在所需领域、无头或真实 Godot 层执行并采用统一报告；不把每次鼠标操作或整段探索机械转成永久测试。

#### 自动化与工具边界

自动化和 Godot MCP 是正式能力的使用者，不另建世界修改路径。日常验证沿用统一测试入口；MCP 用于项目／引擎检查、启动、日志获取及必要交互观察，具体操作经过任务所需的正式命令或调试接口，不能直接改节点位置或内存来冒充领域操作。截图、日志及启动成功分别只证明实际观察范围。

工具不足时按 [Godot MCP 验证 SOP](../implement-sop.md#godot-mcp-validation)使用可等效的脚本，未覆盖项保持未验证。MCP 缺陷或必要功能请求按同一 SOP 提交到自维护的 [odradekk/godot-mcp](https://github.com/odradekk/godot-mcp/issues)，不在本设计中维护平行工具流程。

#### 性能概况与详细采样

轻量运行概况显示模拟是否跟上、帧／模拟耗时、内存与对象数量等已可测指标；详细追踪、较大范围图层和完整状态抓取由用户按需开启。记录采样范围、开关与自身开销，缺失指标显示未采集，不能用零值冒充结果。编辑器即时统计用于定位问题，不自动成为 Benchmark 通过证据；默认录制的成本仍计入正式性能验收。具体负载、采样频率、阈值及目标硬件由后续性能决策确定。

#### 代表案例与验收边界

至少贯通一次人工操作形成可复现案例、导出后在新进程隔离重放及检查点对照；另按风险覆盖受影响的内容更新、命令拒绝、内部故障、录制不完整、损坏包／缺失依赖及导出失败。共享机制集中验证，不为各入口复制整套矩阵；交互关联与辅助图层补充必要人工检查，报告分别记录领域对照、真实 Godot、人工观感和性能证据。

复用已有观察、保存保护与检查点能力；既有通过证据仅在仍适用时复用，新增流程不能仅凭旧脚本成功或截图存在验收。上述为目标工作流的验收要求，不代表当前实现已完成；旧场景退役仍经过独立迁移门槛。

### 诊断与采样

| 类别 | 首批必须可观察的信息 |
| --- | --- |
| 对象状态 | 身份、所属关系、耐久、运行资格及失败原因。 |
| 铁路运行 | 明确连接、车辆接触点、通行路径、车辆实际占用、预留、道岔锁及等待原因；沿用 06 对各状态的区分。 |
| 空间辅助图层 | 碰撞形状、净空、Chunk 边界、视觉驻留和渲染原点，可分别开关；由正式状态及对应派生数据提供，不以辅助画面反写领域状态。 |
| 性能采样与导出 | 模拟及渲染耗时、修改/保存/加载耗时、内存、对象数量；记录配置、版本、环境和采样条件，具体计量口径与门槛由性能决策收敛。 |

诊断用于解释所选对象及关联冲突，不把轨道实体占格、车辆实际占用和未来路径预留混为一个“占用”字段。采集成功、断言成功与人工观感确认分别记录，不用示例数值或未测量项目冒充真实性能结果。

### 配置与验证步骤

- 固定测试配置描述初始世界、车辆和参数；验证步骤描述按模拟步执行的操作与结果检查。二者分开管理，避免把用例再次写成互不通用的场景模式。
- 人工编辑器以普通存档为工作对象；固定配置可用于独立自动验证及制作、更新示例，制作脚本不在每次打开示例时执行。示例自身仍须通过正式存档恢复。各入口复用正式操作；需要真实显示、碰撞或进程恢复的检查仍运行对应 Godot/进程边界，不能仅由领域测试代替。
- 旧四切片有效用例的人工用途迁入示例存档，自动用途保留所需配置与验证步骤，不继续作为四个产品入口；逐项去向在迁移决策中核对。未来增加系统时按实际需求补充对象检查、创作与操作，不重造长期调试场景。

### 保存、切换与复现

- 新建、打开、返回工作区／主菜单及正常退出共用离开保护；重新加载与重新生成明确区分，重新加载用“另存当前修改”避免覆盖恢复目标。普通 JSON 存档导出与下述故障复现 ZIP 分开。候选替换、临时草稿、暂挂及失败保留规则以[存档工作流](09-persistence.md#世界编辑器存档工作流)为准。
- 一键导出故障复现资料：起始快照、此后按模拟步记录的修改操作、必要配置与内容版本、故障状态和日志，可附截图。另一会话能够恢复并重放；不是任意时间倒退或完整历史回放系统。
- 复现所需的状态、定义/内容依赖与输入顺序必须足以解释原结果，不能只记画面操作或用新版本偷偷重解释旧输入。已确认普通读档与严格复现分开：后者在隔离会话使用复现包内的数据内容及必要表现资产，核验构建、语义内容、模拟配置及兼容环境，不覆盖已安装 Mod。包内含起始状态、后续输入及版本/环境清单；暂停修改也记录步内顺序。依赖缺失时明确拒绝，游戏程序与运行环境不自动打包。具体规则见 [存档与复现契约](09-persistence.md#本阶段保存与复现契约)。Playground 默认有界录制，显示可复现范围；可用新起点建立后才裁剪；内容发布仍处于保留窗口内时，保留其前后内容及拒绝结果，正常裁剪后由剩余起点和输入完整承接。导出带版本和完整性清单的 ZIP，录制不完整与导出失败必须明确提示；容量、起点间隔及开销由性能实测冻结。
- 本阶段允许停止兼容旧切片开发存档，不支持时明确拒绝且保留当前会话，不静默转换。历史版本、验证报告与复现说明保留；旧用例以新配置重建，不要求永久维护旧生成器和旧场景驱动。

### 旧切片退役与案例迁移

[确定旧切片退役与示例存档、回归用例迁移](https://github.com/odradekk/train/issues/144)已确认九项决定，并经完整规格确认定稿。本轮只确定规则，不删除生产场景或用户存档。

迁移以保留有效行为契约为准，不逐个复制四套新场景。逐项登记旧入口、夹具、脚本、断言、人工步骤及调用文档，分别归入普通示例存档、独立自动测试、历史证据或可删除的专用驱动。多个旧用例可共用一个示例，同一契约可继续由已有测试覆盖；取消重复或已失效用例须说明依据，不能随入口退役丢掉仍有效的验证。

随项目分发少量具有人工探索价值的普通示例存档，例如直轨列车、车辆改装／断裂及体素编辑；示例数量和组合按用途决定，不固定为四个。每个示例说明用途、适用版本、依赖及简短操作步骤，打开时创建默认暂停的可编辑副本，不自动执行演示脚本。边界值、损坏存档和内部故障夹具保留在自动测试数据中，不进入正常示例列表。

退役按实际迁移能力与证据验收，取消旧退役票对程序生成交付的硬性前置。唯一存档工作区、普通示例恢复、所需正式编辑／运行操作和统一测试入口可用，旧有效契约在新体系逐项验证通过后，即可删除四个旧入口及专用驱动。程序生成、尚未用到的高级创作、完整复现及目标硬件性能各自继续验收；某项迁移实际依赖的能力必须先交付，不能留下失效用例就宣布退役完成。实施票的依赖与范围在后续分期重组时统一修改。

首批迁移示例优先从正式空白世界制作，通过正式操作建立所需地形、轨道与车辆，保存空白来源及实际世界差异。以后打开只走普通恢复，不重跑制作步骤；未来生成案例可采用正式生成来源。自动测试可保留独立具名配置，但示例和通用恢复不再依赖 Slice1–4 身份或旧场景驱动，也不为每个旧场景新增永久专用生成器。制作方式改变后须验证实际示例文件，制作脚本成功不代替恢复成功。

退役时明确停止支持依赖旧切片／旧固定配置来源的开发存档，不承诺批量转换。公布受影响来源与版本，加载时明确报告不支持，并保留当前会话和原文件；项目示例按新来源重新制作，需要保留的个别开发案例另列针对性迁移。历史提交及已记录环境保留为旧案例的复现依据，不为旧档长期保留当前产品入口，也不静默换基底、重编身份或清理用户存档。仍受支持的普通来源不因删除旧菜单而失效。

迁移清单记录原行为与历史依据、新示例／测试入口、合法及失败情形和结果位置。已有相关测试仍适用时复用，仅补缺口；显示／碰撞、真实输入、跨进程恢复等原有边界仍在新路径验证，人工观感按相关交互补验，不要求所有用例在每层重写或重跑全部旧脚本。示例使用随项目提供的实际文件，在新进程打开并完成代表操作；删除旧驱动后再验证受影响入口。

按逐组迁移、证据齐备后集中删除交付。体素／边界、车辆、铁路用例可分别迁入新体系，每组完成即登记证据；过渡期间旧入口仅供尚未迁完的回归使用，不再新增功能。全部有效用途有去向后，以独立删除交付移除四个旧菜单、旧场景及剩余专用驱动，并验证删除后的新入口。临时共存不变为长期双入口，实施票数量与依赖在后续分期决策统一安排。

仍有价值的旧性能操作负载与采样条件须先通过统一入口在新会话上完成等效测量，再删除旧驱动。实现变化导致旧数据不可直接比较时，记录差异并建立新基线，不能用更小负载冒充提速；旧报告和原始资料保留。此处只证明旧测量用途已有可执行去向，不等待目标硬件、完整编辑器负载或长期性能验收，也不等于新 Benchmark 全部完成。

最终清理覆盖菜单与场景路由、切片专用环境参数／快捷键／控制台入口、脚本调用、资源引用及当前操作文档。仍有效的通用领域代码和测试保留，不为消灭 Slice 字样机械改写全部代码；历史报告、已关闭 Issue、归档原型及用于明确拒绝旧档的版本标识可保留并注明历史用途。退役报告列出删除项、保留原因、替代入口和尚未完成的阶段关口，不删除用户存档、不重写历史验收结论。

### 可验证的退役条件

1. 唯一存档工作区、普通示例恢复、迁移所需正式编辑／运行操作和统一测试入口已就绪；人工调试及独立自动运行不再依赖旧菜单或切片专用驱动。不再以程序生成交付作为统一前置，按上文实际迁移依赖验收。
2. 对旧用例建立逐项映射：原契约、替代配置、操作步骤、自动断言、人工观察及证据位置。合法输出和必要失败反例均有去向，不能以“新场景能启动”宣称覆盖等价。
3. 对应领域验证、真实 Godot 显示/碰撞检查、跨进程恢复和人工观感检查迁移通过。脚本退出成功或截图存在只证明采集成功，不自动证明画面正确。
4. 有效旧性能用例已由统一入口在新会话承接，保留配置、环境、采样方式及历史结果；不可直接比较时明确说明并建立新基线，不以更小负载冒充提速。不等待完整 Benchmark 或目标实机通过，其独立关口见[性能工作流](roadmap.md#世界编辑器-benchmark-工作流)。
5. 旧测试存档的拒绝边界、当前会话保持、历史版本/报告/复现说明均有明确记录；新保存恢复流程独立通过。
6. 各组迁移证据齐备后，以独立交付集中删除旧菜单入口、旧场景、切片专用驱动及无用耦合；同步处理全部可执行调用者，删除后受影响的新入口再次验证通过。仍有用途的通用代码、配置、自动检查和历史证据保留；退役报告说明各项去向及仍待完成的阶段关口。

以上是后续实施的退役门槛，本决策阶段不删除生产场景、驱动或旧档。

### 原型与验证边界

[已归档流程原型](../../archive/prototypes/playground-workflow.prototype.html)是独立单文件 HTML，只验证对象选择、镜头切换、模拟控制、故障恢复及保存切换的流程。它不连接正式引擎；地图、运动、故障与导出内容为示例，不作为几何、运行防护、存档格式或性能证据。[原始提交](https://github.com/odradekk/train/blob/9876889ba12acc8fe7559879c40b8a613316ca20/docs/design/playground-workflow.prototype.html)仍保留当时资料。

- 用户确认“选择与镜头”“断轨与显式恢复”“切换保护”的操作流程符合预期；视觉样式和示例地图不作为最终设计。
- 原型覆盖流程讨论，不包含完整诊断图层、目标销毁及铁路/体素实现。Q8、Q9 的诊断和目标失效规则须由正式实施补验，不能把流程认可写成这些能力已验证。
- 原型原先归档于独立分支 `prototype/playground-workflow-96`，其历史现已合入主分支，文件统一存放于 `archive/prototypes/`，不进入正式产品代码。原型 JavaScript 通过语法检查；原讨论时代理环境无可用浏览器连接，未做浏览器点击或截图检查。用户评议与代理验证范围分别记录，本次归档不新增视觉通过结论。

## 首版范围

上一轮首版包含同一长期人工入口及三种会话来源、对象观察与操作、自由/聚焦/跟随相机、明确模拟控制、配置与验证步骤分离、复现资料导出、保存切换保护、诊断和采样，以及覆盖等价后的四切片退役。本轮将其扩展为上述世界编辑器方向，具体功能仍按端到端小切片交付；新的首批范围与顺序由[分期及实施票重组](https://github.com/odradekk/train/issues/145)确定，不将所有创作工具一次列为前置。

## 明确延后

正式游戏受玩法约束的玩家 UI、资源与生产调试模块、与本游戏无关的通用引擎编辑器和插件框架、任意时间倒退及完整历史回放、旧切片开发存档的永久兼容。世界编辑器自己的建造和车辆设计工具已纳入本轮规划，不能再以“正式玩家 UI 延后”为由一并排除。桌面停靠和多显示器能力不作为本阶段完成门槛。
