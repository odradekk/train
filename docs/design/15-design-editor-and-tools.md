# 15 设计编辑器、创作模式与调试模式

> **所属层**：工具；设计编辑器由体素引擎层构建。

> 决策出处：由[编辑器的去向](https://github.com/odradekk/train/issues/211)于 2026-10-05 确认。它取代了以全局体素世界存档为工作对象的世界编辑器，以及它的存档工作区、世界创作工具、存档内发布和跨范围复制规则。工作平面、预览与提交反馈沿用[确定世界创作工具与铁路编辑的统一交互](https://github.com/odradekk/train/issues/140)；从实例提取、草稿与发布前校验沿用[确定蓝图、布局与内容定义的创作和发布流程](https://github.com/odradekk/train/issues/141)；诊断、录制与重放的界面沿用[确定运行调试、诊断观察与故障复现工作流](https://github.com/odradekk/train/issues/142)。实例有自己的设计、蓝图只是模板、改装草稿与本局蓝图库，由[实例与蓝图：实例保存自己的设计，模板的存放与改装目标](https://github.com/odradekk/train/issues/260)于 2026-10-09 确认，见 ADR-0012。

## 边界

本文定义三样工具：面向玩家的设计编辑器，以及只在开发构建中提供的创作模式和调试模式。设计与设计合法性见 [03](03-vehicles-buildings-and-designs.md)；内容身份、版本与数据包见 [02](02-definitions-and-content.md)；核心命令、录制与复现见 [04](04-deterministic-simulation.md)；体素格网规则与拾取见 [01](01-voxel-engine-and-scenes.md)；相机见 [08](08-window-and-ui.md)。

2026-10-10 经[编辑器的草稿、校验、发布与改装接口](https://github.com/odradekk/train/issues/285)确认编辑暂停、草稿保存边界、缺失内容、立即应用和创作包发布规则。模块交接见[编辑协议](../contracts/editing.md)；具体接口与产品实现尚待后续任务。

## 不变量

- 设计编辑器和创作模式只编辑草稿，不修改核心状态；核心状态只能通过命令改变。
- 调试模式的每项修改都是一条调试命令，走核心的命令入口，同样校验、同样录制，没有撤销。
- 普通场景和调试模式中的选择、检查和图层等观察操作不改变核心状态，也不隐式暂停模拟；进入设计编辑器按下文暂停世界。
- 预览和草稿不进入有效内容。保存蓝图、提交改装时完整校验，失败时不部分写入。
- 草稿的撤销与重做只在本次编辑中有效，与核心无关。

## 规则

### 三样工具

| 工具 | 使用者 | 提供的构建 | 用途 |
| --- | --- | --- | --- |
| 设计编辑器 | 玩家 | 所有构建 | 设计车辆、建筑和大型设备的蓝图 |
| 创作模式 | 开发者、Mod 作者 | 开发构建 | 制作场景模型、聚居地模板，填写各类定义表单，写入数据包 |
| 调试模式 | 开发者 | 开发构建 | 调试命令、诊断、录制与重放 |

开发构建指在 Godot 编辑器中运行，或用 debug 导出模板导出的游戏；用 release 模板导出的是玩家构建，见 [ADR-0009](../adr/0009-split-the-code-into-godot-free-core-and-scene-libraries-and-rewrite-the-core.md)。开发工具的代码也在玩家构建中，只是不显示。

玩家构建中只有“报告问题”可以导出复现包，见 [08](08-window-and-ui.md#常驻控件)。

### 设计编辑器

#### 入口与场景

- 入口有三个：蓝图库（内容包、本局蓝图库、用户内容库）；车辆或建筑面板中的“改装”，以实例当前的设计建立改装草稿；新建。
- 设计编辑器占用当前场景，同一时间只有一个场景。进入时在完整边界暂停世界；编辑期间不推进模拟，其他面板和控制台的世界修改入口不可用，只读查询仍可用。退出后恢复进入前的暂停或倍速设置，不追赶编辑期间经过的真实时间，也不解除核心故障冻结。相机环绕设计物，见 [08](08-window-and-ui.md#相机)。
- 编辑器本身不下核心命令。保存草稿不要求建造合法；保存有效蓝图和提交目标设计要求完整校验。玩家回到面板明确下建造、立即应用或改装命令；编辑期间不需要处理实例继续运行导致的冲突或自动合并。
- 编辑会话使用固定内容；热重载或发布有效内容前先结束编辑，按保存草稿、放弃、取消处理未保存修改，取消则不发布。发布失败保留已保存草稿。保存有效蓝图先固定目标并结束编辑，再发布到所选库，不在打开的会话里处理内容版本切换，见[编辑保存边界](../contracts/editing.md#编辑会话与保存边界)。

#### 新建草稿

- 先选择要设计车辆、建筑还是大型设备。车辆声明尺寸，选五档之一；建筑设定地块尺寸、建筑类型和设施兼容标签；大型设备没有包络。车辆和建筑的编辑区显示对应的包络，不自动升档。
- 体素栏列出可以放进设计的体素定义，不含场景体素，并显示 Value 和质量。

#### 编辑

- 单格、笔刷和长方体区域三种工具，都可以添加、移除和替换。
- **工作平面**：水平面可以指定高度；竖直平面垂直于 X 或 Z 轴，整数位置就是该轴的目标格层；也可以拾取已有体素的表面。工作平面显示轴向、网格、吸附点和坐标。拾取沿射线逐格前进，添加目标是命中格沿面法线方向的相邻格，见 [01](01-voxel-engine-and-scenes.md#拾取)。
- 鼠标位置、方向或范围与检查器中的精确参数共用同一份预览。朝向只能取定义允许的正交朝向。
- 笔刷和长方体区域的预览显示覆盖范围、受影响格数、跳过格数和冲突格，笔划或区域作为一次修改写入草稿。当前上限是边长 16、覆盖格 4096，受影响格超过 512 时要求确认，常量位于 `VoxelRegionLimits`，可以按实测调整。
- **选区**：框选一组格后，可以整体移动、按 90° 旋转、复制。
- **剖切**：可以隐藏某一高度以上的格，便于编辑内部。
- **大型设备**（[复合体嵌套：大型设备装到车辆和建筑上](https://github.com/odradekk/train/issues/249)）：体素栏旁边列出三处蓝图库中的大型设备蓝图，放进宿主时，组装体复制它的设计，功能复合体只记录对它的引用（[功能复合体的来源、缺失内容的状态、结构耐久下限与嵌套排序](https://github.com/odradekk/train/issues/269)）。选中已装的设备，可以整体移动、按 90° 旋转、删除或换成另一份蓝图；对组装体，可以“进入设备”直接编辑这份复制品，也可以把它保存为新的蓝图；功能复合体是封闭的，不能进入编辑，只能整件操作，涂装时整件只能涂一个颜色。玩家的蓝图不能带功能性行为。编辑器显示转动扫过的范围，有冲突时指出冲突的格。
- **形状**：放置体素时，从该体素定义允许的形状（`shapes`）里选一种，不选就用列表的第一项；已放的格子可以改选，也可以批量改。形状只影响表现，不改变货物种类和 BOM（[Demo 内容与资产清单：覆盖场景与制作验收](https://github.com/odradekk/train/issues/283)，2026-10-10）。
- **涂装**：给体素选一个主色，单格、笔刷、长方体区域和选区都可以批量涂；选色器带推荐色卡。只有可涂装的材质类别会变色，涂装只影响表现，见[美术 03](../art/03-color-and-paint.md#玩家涂装)（[默认色彩与玩家涂装](https://github.com/odradekk/train/issues/250)）。
- 撤销与重做不限步数，只在本次编辑中有效。
- 缺失定义的部分保留原引用并锁定，不能通过整组选区操作间接移动、替换或删除；其他部分仍可编辑。功能复合体仍是不可进入的整件引用，缺失时占格未知，不能据此宣布完整冲突检查成功，见 [03](03-vehicles-buildings-and-designs.md#缺失的内容)。

#### 信息面板

- 尺寸、质量、部件清单、结构耐久上限；
- 设计属性，例如动力、空载和满载时的最高速度与加速度、载量、武器、产能，由内容层按 [03](03-vehicles-buildings-and-designs.md#设计属性) 计算；
- BOM 和总 Value；
- 不合法原因，例如超出包络、不连通、转动范围有冲突，能定位到具体的格；以及提示，例如“不能自己行驶”，见 [03 的设计合法性](03-vehicles-buildings-and-designs.md#设计合法性)。
- 缺失内容同时在游戏界面和控制台明确显示定义标识、所属包和被阻止的操作；可获得的包名用于辅助说明，未知名称不编造。校验尚未完成或只能计算部分信息时明确标注，旧结果不冒充当前草稿已经合法。

#### 草稿与保存

- 草稿可以不合法，也可包含暂时缺失的定义。活动编辑由体素层持有；明确点“保存草稿”后，内容层接收一份不可变快照作为已保存草稿。改装草稿与实例绑定，每个实例最多一份，和本局蓝图库的草稿一起放在当前存档的内嵌内容中；保存草稿更新本局记录，仍需保存游戏才能落盘。用户内容库与创作模式的草稿由宿主写入 `user://authoring-drafts/`，按来源和目标区分，不属于游戏存档，也不进入有效内容扫描。
- 手动存档和自动存档只捕获已明确保存的本局草稿，不自动接收编辑器里尚未保存的修改。关闭有未保存修改的编辑器时提示保存、放弃或取消；保存失败不关闭，取消继续编辑。选择放弃只丢弃本次未保存修改，不删除上次保存的草稿。离开整局还须处理本局记录尚未写入游戏存档的进度，见 [09](09-persistence.md#文件身份与写入)。
- 改装草稿以实例当前的设计为起点，不复制实例身份、耐久、损伤、速度或运行计划，也不修改原实例。草稿通过 [03 的建造合法性](03-vehicles-buildings-and-designs.md#设计合法性)检查后，可以提交改装，成为目标设计。
- 草稿或实例的设计随时可以“保存为蓝图”，存进本局蓝图库或用户内容库。保存要求通过建造合法性检查，不合法的只能留作草稿；保存失败时草稿保持不变。蓝图不分版本，保存时覆盖。
- 内置和 Mod 的蓝图只读，可以“复制为新蓝图”；新蓝图有新的身份。在本局蓝图库和用户内容库之间复制，也得到有新身份的独立蓝图。
- 库中的蓝图可以随时修改或删除，不检查引用：实例有自己的设计，不引用蓝图，见 [09](09-persistence.md#存档中的内容)。
- 从实例打开时，只改名称、说明、形状或涂装统一走面板上的“立即应用”。目标先通过完整合法性校验，内容层再确认构成没有变化；核心通过一条命令更新设计引用，不创建改装任务、不消耗货物，不改变损伤、部件耐久和其他运行状态。包含构成变化时，整份目标走正式改装，不提前应用其中的外观或文字修改。
- 保存有效蓝图、立即应用和正式改装采用同一目标设计合法性门槛。原实例因缺失内容或内容更新而不再合法时也不例外；未通过时只允许保存草稿，游戏界面和控制台说明原因。

### 创作模式

- 只在开发构建中提供。启动时选定一个内容包作为输出：开发源码目录中的 `core`，或某个 Mod 包；导出构建里的内置内容只读，不能写回 PCK。
- **场景模型**：使用设计编辑器的同一套网格工具，体素栏改为场景体素，可以标出平整区域，见 [01](01-voxel-engine-and-scenes.md#场景模型)。
- **聚居地模板**：选择聚居地类型和权重；在场景模型上放置地块，设定尺寸（含站点）和朝向；指定预建建筑、起始建筑和开局库存。建筑与地块尺寸不符是错误，不能发布。见 [16](16-settlements.md#聚居地模板)。
- **表单**：体素定义（按层分组的字段、Behavior 参数、资产绑定）、蓝图上的行为（功能复合体、生物、转动等）、生物聚落类型、聚居地类型。字段按适用类型显示，错误定位到具体字段或引用。能力只能由实际的 Behavior 推导，不能手工声明。生物由蓝图定义，用网格工具制作。
- **整包发布**：把选定包内的定义、蓝图和资产修改一起写入，并热重载到当前游戏，见 [02](02-definitions-and-content.md#mod-与热加载)。即使只改一份定义，也校验整个候选包、依赖和运行中引用。普通设计编辑器的保存草稿、保存蓝图及实例命令不属于整包发布。
- 发布时若源包已被外部工具修改，拒绝覆盖并保留草稿，提示重新载入、处理修改后再校验发布；不静默合并或覆盖。准备失败保留原有效内容；文件发布失败不切换当前内容，若文件需要恢复则明确报告并保留恢复材料。
- 生成配置等其他内容继续手写 JSON。新的行为逻辑仍由代码实现，模型和贴图由外部资产工具制作。

涉及持久写入与当前会话更新的发布，遵循[跨层协议](../contracts/transactions.md#持久发布的不可取消阶段)和[整包发布协议](../contracts/editing.md#创作模式整包发布)：先准备完整候选包、校验和状态适配，再进入不可取消的最终文件发布，成功后完成已准备的内存切换。启动加载前恢复中断的发布：未完成时恢复完整旧包，已完成且校验通过时使用完整新包；无法确认完整版本时停用该包并明确报错，保留恢复材料。暂存包不当作已发布内容，不加载新旧混合文件。文件布局与真实平台验证由[宿主接口](https://github.com/odradekk/train/issues/290)落实，不假定任意多文件替换具有原子性。

### 调试模式

只在开发构建中提供，叠加在普通游戏窗口上。

#### 调试命令

- 通过控制台或宏观地图上的右键菜单发出，例如：修改节点的占据者和资源；修改线路的铁轨数和断点；创建或删除列车、车辆；瞬时改装；设置资金、关系、士气；生成生物群。
- 全部走核心的命令入口，同样校验、同样录制，见 [04](04-deterministic-simulation.md#命令)。没有撤销，纠正时下一条新命令，或读回存档。
- 控制台承担精确参数和批量操作。新增或修改命令时，同步维护 [console 手册](../console/README.md)。

#### 检查器与命令记录

- 检查器只读显示任意核心对象的状态。选择不移动镜头。
- 命令记录可以按对象、类型和结果筛选，区分拒绝、执行和故障，显示来源、目标、参数、模拟位置和原因，并能定位关联的对象。目标已失效时保留原身份，不换成其他对象。界面标明显示范围和截断情况，有限的日志不冒充完整录制。

#### 运行控制

- 暂停、单步、推进指定步数。
- **运行到条件**：条件可以是到达某一步、某条命令被拒绝、某个对象出现故障、某类领域事件（例如开战）发生。可以设最大步数，也可以取消。命中、取消、目标失效或达到上限时，在完整边界停止并说明原因。条件只属于本次调试会话，不进存档。

#### 故障反馈

- **普通拒绝**：解释原因，默认不暂停。
- **世界内可恢复的问题**：例如断轨、建筑被毁，显示正式修复所需的条件，不偷偷修复。
- **内部故障**：突出显示会话已冻结、最后一个完整边界和证据入口。不能强行继续，须读档或重新开始，见 [04](04-deterministic-simulation.md#执行结果)。

#### 录制、检查点与隔离重放

- 显示录制状态（正在录制、不完整、尚无可用起点）、可复现的范围和容量占用，可以添加说明标记。
- **检查点**：人工或按验证序列自动打点，在完整边界捕获。比较时先说明来源、内容和输入是否可比，再定位最早出现差异的对象和字段；内容适配和环境不同单独列出，不当作确定性缺陷。
- **导出复现包**：默认导出当前完整的录制窗口，也可以选一个事件作为终点。记录不全时说明缺口。
- **隔离重放**：打开复现包经过当前对局的离开保护，候选通过后替换当前会话；Godot 同时只驱动一个会话，不常驻原局供一键返回。重放只执行包内命令及内容，禁止玩家／调试修改和安装目录热重载；可以观察、推进到指定位置、对比检查点，也可打开场景。某个边界可导出为普通存档，可编辑副本须再走普通读档，不能直接把原重放解锁。见 [04](04-deterministic-simulation.md#录制与复现)及[跨层协议](../contracts/transactions.md#新游戏普通读档与严格复现)。
- 人工探索可以整理成回归案例草稿，由开发者写明预期结果；不把录制到的结果直接当作测试预期。

#### 场景调试图层

可以显示区块边界、线路分段、浮动原点、拾取射线和中心线，也可以重新生成当前场景，见 [01](01-voxel-engine-and-scenes.md)。

#### 性能概况

显示模拟是否跟得上、帧耗时、模拟耗时、内存和对象数量。缺失的指标显示为未采集，不用零代替。这些即时统计用于定位问题，不自动成为 Benchmark 的通过证据。

#### 自动化

自动化测试和 Godot MCP 只通过正式命令和调试接口操作，不直接修改节点或内存来冒充领域操作。截图、日志和启动成功只证明各自实际观察到的范围。

## Demo 范围
