# 15 设计编辑器、创作模式与调试模式

> **所属层**：工具；设计编辑器由体素引擎层构建。

> 决策出处：由[编辑器的去向](https://github.com/odradekk/train/issues/211)于 2026-10-05 确认。它取代了以全局体素世界存档为工作对象的世界编辑器，以及它的存档工作区、世界创作工具、存档内发布和跨范围复制规则。工作平面、预览与提交反馈沿用[确定世界创作工具与铁路编辑的统一交互](https://github.com/odradekk/train/issues/140)；从实例提取、草稿与发布前校验沿用[确定蓝图、布局与内容定义的创作和发布流程](https://github.com/odradekk/train/issues/141)；诊断、录制与重放的界面沿用[确定运行调试、诊断观察与故障复现工作流](https://github.com/odradekk/train/issues/142)。

## 边界

本文定义三样工具：面向玩家的设计编辑器，以及只在开发构建中提供的创作模式和调试模式。蓝图版本与设计合法性见 [03](03-vehicles-buildings-and-designs.md)；内容身份、版本与数据包见 [02](02-definitions-and-content.md)；核心命令、录制与复现见 [04](04-deterministic-simulation.md)；体素格网规则与拾取见 [01](01-voxel-engine-and-scenes.md)；相机见 [08](08-window-and-ui.md)。

## 不变量

- 设计编辑器和创作模式只编辑草稿，不修改核心状态；核心状态只能通过命令改变。
- 调试模式的每项修改都是一条调试命令，走核心的命令入口，同样校验、同样录制，没有撤销。
- 选择、检查和图层等观察操作不改变核心状态，也不隐式暂停模拟。
- 预览和草稿不进入有效内容。发布时完整校验，失败时不部分写入。
- 草稿的撤销与重做只在本次编辑中有效，与核心无关。

## 规则

### 三样工具

| 工具 | 使用者 | 提供的构建 | 用途 |
| --- | --- | --- | --- |
| 设计编辑器 | 玩家 | 所有构建 | 设计车辆和建筑的蓝图 |
| 创作模式 | 开发者、Mod 作者 | 开发构建 | 制作场景模型、布局，填写各类定义表单，写入数据包 |
| 调试模式 | 开发者 | 开发构建 | 调试命令、诊断、录制与重放 |

开发构建指在 Godot 编辑器中运行，或用 debug 导出模板导出的游戏；用 release 模板导出的是玩家构建，见 [ADR-0009](../adr/0009-split-the-code-into-godot-free-core-and-scene-libraries-and-rewrite-the-core.md)。开发工具的代码也在玩家构建中，只是不显示。

玩家构建中只有“报告问题”可以导出复现包，见 [08](08-window-and-ui.md#常驻控件)。

### 设计编辑器

#### 入口与场景

- 入口有三个：蓝图库；车辆或建筑面板中的“改装”，以实例当前的蓝图版本作为草稿打开；新建。
- 设计编辑器占用当前场景，同一时间只有一个场景；模拟照常运行。相机环绕设计物，见 [08](08-window-and-ui.md#相机)。
- 编辑器本身不下核心命令。发布后，玩家回到面板下建造或改装命令。

#### 新建草稿

- 先选择要设计车辆还是建筑，再声明尺寸：车辆选五档之一，建筑选地块尺寸和建筑类型。编辑区显示对应的包络，不自动升档。
- 零件栏列出可以放进设计的体素定义，不含 `scene_only`，并显示 Value 和质量。

#### 编辑

- 单格、笔刷和长方体区域三种工具，都可以添加、移除和替换。
- **工作平面**：水平面可以指定高度；竖直平面垂直于 X 或 Z 轴，整数位置就是该轴的目标格层；也可以拾取已有体素的表面。工作平面显示轴向、网格、吸附点和坐标。拾取沿射线逐格前进，添加目标是命中格沿面法线方向的相邻格，见 [01](01-voxel-engine-and-scenes.md#拾取)。
- 鼠标位置、方向或范围与检查器中的精确参数共用同一份预览。朝向只能取定义允许的正交朝向。
- 笔刷和长方体区域的预览显示覆盖范围、受影响格数、跳过格数和冲突格，笔划或区域作为一次修改写入草稿。当前上限是边长 16、覆盖格 4096，受影响格超过 512 时要求确认，常量位于 `VoxelRegionLimits`，可以按实测调整。
- **选区**：框选一组格后，可以整体移动、按 90° 旋转、复制。
- **剖切**：可以隐藏某一高度以上的格，便于编辑内部。
- **涂装**：给体素选一个主色，单格、笔刷、长方体区域和选区都可以批量涂；选色器带推荐色卡。只有可涂装的材质类别会变色，涂装只影响表现，见[美术 03](../art/03-color-and-paint.md#玩家涂装)（[默认色彩与玩家涂装](https://github.com/odradekk/train/issues/250)）。
- 撤销与重做不限步数，只在本次编辑中有效。

#### 信息面板

- 尺寸、质量、部件清单、结构耐久上限；
- 设计属性，例如动力、空载和满载时的最高速度与加速度、载量、武器、产能，由内容层按 [03](03-vehicles-buildings-and-designs.md#设计属性) 计算；
- BOM 和总 Value；
- 不合法原因，例如超出包络、不连通、缺少必需部件，能定位到具体的格。

#### 草稿与发布

- 草稿可以不合法，保存在 `user://authoring-drafts/`，并记录它基于哪个蓝图版本。关闭有未保存修改的草稿时，提示保存、放弃或取消。
- 发布要求通过 [03 的建造合法性](03-vehicles-buildings-and-designs.md#设计合法性)校验，生成一个不可变的蓝图版本，放进用户库。发布失败时草稿保持不变。
- 从实例打开时，复制实例引用的蓝图版本作为草稿，不复制实例身份、耐久、损伤、速度或运行计划，也不修改原实例。
- 内置和 Mod 的蓝图只读，可以“复制为新蓝图”；新蓝图有新的身份。
- 用户库中的版本可以随时删除，不检查引用。用到它的存档和当前对局都有内嵌副本，已有实例照常运行，见 [09](09-persistence.md#存档中的内容)。

### 创作模式

- 只在开发构建中提供。启动时选定一个数据包作为输出：开发时是 `core`，也可以是某个 Mod 包。
- **场景模型**：使用设计编辑器的同一套网格工具，零件栏改为 `scene_only` 体素，可以标出平整区域，见 [01](01-voxel-engine-and-scenes.md#场景模型)。
- **布局**：在一个场景模型上放置地块，设定尺寸、朝向和是否是站点，并为地块指定初始建筑的蓝图。地块尺寸与蓝图不符时提示，见 [16](16-settlements.md#布局)。
- **表单**：体素定义（按层分组的字段、Behavior 参数、资产绑定）、生物种类、生物聚落类型、聚居地类型。字段按适用类型显示，错误定位到具体字段或引用。能力只能由实际的 Behavior 推导，不能手工声明。生物种类的外观引用一个场景模型。
- **发布**：整个数据包校验通过后写入，并热重载到正在运行的游戏，见 [02](02-definitions-and-content.md#mod-与热加载)。失败时保留草稿和原有内容。
- 生成配置等其他内容继续手写 JSON。新的行为逻辑仍由代码实现，模型和贴图由外部资产工具制作。

### 调试模式

只在开发构建中提供，叠加在普通游戏窗口上。

#### 调试命令

- 通过控制台或宏观地图上的右键菜单发出，例如：修改节点的占据者和资源；修改线路的铁轨数和断点；创建或删除列车、车辆；瞬时改装；设置资金、关系、士气；生成生物群。
- 全部走核心的命令入口，同样校验、同样录制，见 [04](04-deterministic-simulation.md#命令)。没有撤销，纠正时下一条新命令，或读回存档。
- 控制台承担精确参数和批量操作。新增或修改命令时，同步维护 [console 手册](../console/README.md)。

#### 检查器与命令记录

- 检查器只读显示任意核心对象的状态。选择不移动镜头。
- 命令记录可以按对象、类型和结果筛选，区分拒绝、执行和故障，显示来源、目标、参数、模拟位置和原因，并能定位关联的对象。目标已失效时保留原身份，不换成其他对象。界面标明显示范围和截断情况，有限的日志不冒充完整录制。

#### 运行控制

- 暂停、单步、推进指定步数。
- **运行到条件**：条件可以是到达某一步、某条命令被拒绝、某个对象出现故障、某类领域事件（例如开战）发生。可以设最大步数，也可以取消。命中、取消、目标失效或达到上限时，在完整边界停止并说明原因。条件只属于本次调试会话，不进存档。

#### 故障反馈

- **普通拒绝**：解释原因，默认不暂停。
- **世界内可恢复的问题**：例如断轨、建筑被毁，显示正式修复所需的条件，不偷偷修复。
- **内部故障**：突出显示会话已冻结、最后一个完整边界和证据入口。不能强行继续，须读档或重新开始，见 [04](04-deterministic-simulation.md#执行结果)。

#### 录制、检查点与隔离重放

- 显示录制状态（正在录制、不完整、尚无可用起点）、可复现的范围和容量占用，可以添加说明标记。
- **检查点**：人工或按验证序列自动打点，在完整边界捕获。比较时先说明来源、内容和输入是否可比，再定位最早出现差异的对象和字段；内容适配和环境不同单独列出，不当作确定性缺陷。
- **导出复现包**：默认导出当前完整的录制窗口，也可以选一个事件作为终点。记录不全时说明缺口。
- **隔离重放**：打开复现包后，在独立会话中只运行核心，可以选择打开场景；可以推进到指定位置、对比检查点。重放使用包内的内容，不覆盖已安装的内容，见 [04](04-deterministic-simulation.md#录制与复现)。可以把某个边界的状态存成一份普通存档，作为可编辑的副本。
- 人工探索可以整理成回归案例草稿，由开发者写明预期结果；不把录制到的结果直接当作测试预期。

#### 场景调试图层

可以显示区块边界、线路分段、浮动原点、拾取射线和中心线，也可以重新生成当前场景，见 [01](01-voxel-engine-and-scenes.md)。

#### 性能概况

显示模拟是否跟得上、帧耗时、模拟耗时、内存和对象数量。缺失的指标显示为未采集，不用零代替。这些即时统计用于定位问题，不自动成为 Benchmark 的通过证据。

#### 自动化

自动化测试和 Godot MCP 只通过正式命令和调试接口操作，不直接修改节点或内存来冒充领域操作。截图、日志和启动成功只证明各自实际观察到的范围。

## Demo 范围

设计编辑器的全部功能。创作模式和调试模式只在开发构建中提供，随开发需要分批实现。

## Demo 之后

面向玩家的创作模式；设计的镜像；任意形状的选区；完整的时间倒带；任意脚本断点；两个体素六面相邻、但模型在视觉上没有接触时给出提示，只提示，不阻止发布（[非立方体形状与构造语言](https://github.com/odradekk/train/issues/245)）。

## 开放问题

- 快捷键、面板布局和视觉样式，随界面原型确定，见 [08](08-window-and-ui.md#开放问题)。
- 区域编辑上限、录制容量等数值按实测调整。
