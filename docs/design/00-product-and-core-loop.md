# 00 产品形态与核心循环

> 决策出处：转录 Q2、Q8、Q109；`CONTEXT.md` 与 `docs/specs/mvp.md` 描述的 MVP 已验证循环；2026-09-05 围绕 [#29](https://github.com/odradekk/train/issues/29) 的产品方向确认。当前首版以专门测试场景验收体素基础，正式游戏场景与贸易玩法后续接入。

## 边界

本文回答三个问题：这是什么游戏，玩家在做什么，为什么是体素世界与桌面常驻窗口。经济规则、贸易方案编辑、列车调度、车辆设计 UI 的具体设计不在本文，留待后续扩充。窗口行为细节见 [08](08-desktop-window-and-camera.md)。

## 不变量

- 玩家不是一个直接控制的角色。
- 所有管理窗口只是同一个 World Model 的不同 View，不拥有独立世界状态；关闭辅助窗口不影响 Simulation。

## 规则

### 产品形态（已定）

游戏是一款以火车自动运行和贸易模拟为核心的桌面放置游戏。主要游戏视角是一个长期存在于桌面的 3D 条形窗口：

```text
┌──────────────────────────────────────┐
│                                      │
│          用户正在使用的其他软件        │
│                                      │
├──────────────────────────────────────┤
│         游戏 3D 火车观察窗口           │
└──────────────────────────────────────┘
```

首版默认：Windows-first；无边框；Bottom Dock；占满目标显示器宽度；高度可调整；默认主显示器，玩家可选择其他显示器；可以切换为 Floating 模式；Floating 模式允许任意移动和合理范围内调整尺寸，可选 Always-on-top；3D 窗口为游戏主窗口。

其他管理功能使用独立窗口，包括未来的：自动贸易策略、火车管理、车辆升级、车辆设计器、经济管理、其他 Gameplay UI。首版关闭主 3D 窗口视为退出游戏。

### 核心循环与当前阶段

- 长期产品方向沿用 MVP 已验证的循环：配置贸易方案 → 观察自动运行 → 阅读运行报告 → 策略迭代。相关术语见 `CONTEXT.md`。
- 玩家在桌面上长期观看底部 3D 条中的火车自动贸易，通过独立窗口配置贸易方案、升级改装与设计车辆（转录 Q8）。
- 当前首版先建立稳定、高效、支持修改的体素世界，并验证列车运行与桌面常驻观察。贸易玩法已在 MVP 验证，后续版本再接入，不作为当前首版验收条件。
- 开发按小切片推进，每次通过专门测试场景验证所选能力。达到下文验收条件后进入正式游戏场景开发，不以“整个系统完成”作为门槛，也不提前实现所有未来玩法需要的通用能力。

### 为什么是体素世界

- 转录 Q2：统一的体素模型让可交互物、设备、资源、地形共用一套建模与开发方式，简化内容生产；UI 与特效除外。
- 转录 Q109：铺轨、破坏地形、桥梁隧道等日后必加，它们依赖可破坏、可组合的体素世界，"这也是使用体素的重要原因之一"。
- 选择体素系统的重要原因是更简单、高效地支持修改、破坏与自定义。当前首版必须实际验证世界与车辆的这些能力，而不只展示静态体素场景。
- 可开采的自然资源、可铺设与破坏的铁路与地形、可组合和改装的车辆，是这些能力支持的玩法方向；不因此要求首版实现完整的开采、施工或车辆设计流程。
- 武器、生物属于"一切皆体素"的愿景（[01](01-voxel-world.md)），不在首版。

## 首版范围

当前首版是通过专门测试场景验收的体素基础版本。测试场景可直接加载地形、轨道与车辆，提供体素增删、破坏和车辆修改操作，用于开发、重复验证与性能测量；不要求正式面向玩家的建造或设计 UI。

测试场景直接使用正式的世界模型、模拟、渲染与存档代码。进入正式游戏场景开发前，需要证明：

- 世界生成、渲染与多车厢列车在直线、弯道、坡道上的运行可用。
- 修改与破坏后，世界状态、显示和碰撞保持一致。
- 修改车辆后，其结构和运行行为符合规则。
- 存档恢复能够保留修改结果。
- 在明确的世界规模和修改频率下，运行与桌面常驻性能达到约定目标。

具体范围、测试规模、规则与量化目标由 [#30](https://github.com/odradekk/train/issues/30)、[#37](https://github.com/odradekk/train/issues/37) 与后续切片 spec 落定。详见 [roadmap](roadmap.md)；首版每个必须项应服务于上述验收目标。

## 明确延后

正式游戏场景、经济、AI、自动贸易、列车调度、正式车辆设计与铁路施工 UI；Overlay、Top Dock、托盘与后台模式、离线进度（转录 Q18、Q154、Q85）。开发测试所需的修改操作入口属于首版。
