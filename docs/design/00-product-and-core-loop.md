## 边界

本文回答四个问题：这是什么游戏，玩家在做什么，体素起什么作用，Demo 包含什么。战斗与征服见 [17](17-combat.md)；市场、人口等玩法的具体规则不在本文。窗口与界面见 [08](08-window-and-ui.md)。

## 不变量

- 玩家扮演列车长，是管理者，不是一个直接控制的角色，也不操控单个单位。
- 世界自动运行。玩家通过计划、规则、建设和战前安排影响世界，不需要持续操作。
- 管理界面不拥有独立的世界状态。局部场景与核心模拟层的关系见[分层架构与局部场景的权威边界](https://github.com/odradekk/train/issues/198)。

## 规则

### 产品定位

游戏是一款自动经营（放置）游戏，经济、建设、战斗是三个并列的主循环。玩家扮演列车长，经营一家列车公司：设计并组建车队，取得、经营和建设聚居地，与世界生物和敌对的聚居地作战，通过控制市场和资源扩大经营。

“放置”指世界自动运行：玩家制定运行计划、交易规则、建设和战斗安排，观看自动运行的结果，按需调整；玩家可以开着游戏做别的事。游戏不采用离线收益、数值指数增长和周期性重置这些传统放置机制。

游戏使用普通游戏窗口，不做桌面停靠。主窗口、宏观地图、场景之间的切换、管理界面和相机见 [08](08-window-and-ui.md)。

### 核心循环

三个主循环并列，每个循环都是“制定计划 → 观看自动运行 → 按结果调整”：

- **经济**：制定运行计划和交易规则，列车自动运输，聚居地自动生产和交易；玩家阅读运行报告和经营报告，再调整方案。MVP 已验证的“配置贸易方案 → 观察自动运行 → 阅读运行报告 → 策略迭代”是它的基础，相关术语见 `CONTEXT.md`。
- **建设**：在自己的聚居地建造和改装建筑（生产、仓储、防御、站点），扩建铁轨、修建新线路，设计并制造列车；结果是产能、运力和防御提高。
- **战斗**：给列车安装武器，在编组中加入武装车辆作为护卫，安排路线，设定交战规则。遭遇敌人时由核心模拟层自动结算，玩家可以打开战斗场景观看，并下少量高层指令。战后修复损伤；胜利带来聚居地、资源或更安全的线路。

三个循环互相支撑：经济为建设和战斗提供资金和货物；建设提高经济产出和战斗能力；战斗保护线路、取得新的聚居地，从而扩大经济。玩家的长期成长体现为车队规模、拥有的聚居地，以及对市场和资源的控制。

### 开局与聚居地

- 开局时玩家是一家列车公司，有资金和少量列车，没有聚居地。
- 玩家通过征服，或在无人节点上建立新聚居地，取得聚居地。只有自己拥有的聚居地可以建造建筑、管理生产。
- 聚居地对玩家的关系分为玩家拥有、非敌对和敌对。所有非敌对聚居地都向玩家提供有偿服务：委托制造、维修和改装列车，以及租用仓库。在取得第一个聚居地之前，建设循环靠设计列车、委托服务和修建铁路进行。Demo 中关系只在生成世界、玩家宣战和征服时变化，见 [17](17-combat.md#聚居地关系与征服)。
- Demo 中玩家的对手是不属于玩家的聚居地和世界生物。这些聚居地各自独立，不组成势力；Demo 中没有与玩家竞争的 AI 势力。世界生物在世界中游荡，或从生物聚落出发，袭击线路和聚居地；清剿生物聚落可以获得奖励，或者打通一片区域，见 [17](17-combat.md#世界生物)。

### 战斗

- 玩家以战前安排为主，包括列车设计、编组（护卫就是编组中的武装车辆）、路线和交战规则。战斗中可以下少量高层指令，例如撤退、集中攻击某个目标，但不操控单个单位。
- Demo 的战斗单位只有三类：装有武器的列车（武器是在设计编辑器中安装的零件）、聚居地的防御建筑、世界生物。没有步兵、下车作战的乘员或飞行单位。
- 战斗发生在世界图的线路或节点上，即线路、聚居地和生物聚落。
- 战斗由核心模拟层按模拟步结算，战斗场景只作表现，不写回结果，见 [ADR-0008](../adr/0008-simulate-the-world-in-a-voxel-free-core-and-build-voxel-scenes-as-presentation.md)。战斗、世界生物与征服的规则见 [17](17-combat.md)。

### 体素的作用

核心模拟层负责整个世界，不涉及体素。体素引擎只用于玩家关注的局部场景：列车与建筑的设计和改装、聚居地管理与建设、战斗、列车运行。选择体素作为表现层的理由：

- 美术成本低：不需要高精度建模，配合合适的 shader 也能做出精美的画面。
- 玩家设计列车和建筑的门槛低：在编辑器里摆放体素零件即可。
- 战斗中的破坏效果容易表现。

原先“铺轨、地形破坏、桥梁隧道依赖可破坏、可组合的体素世界”（转录 Q109）这条理由依赖全局体素世界，已经删除。

本阶段是 Demo 之前的下一个开发里程碑：**首个切片：宏观贸易**。它回答一个玩法问题：宏观地图上的自动贸易好不好玩；同时证明核心模拟层 → 体素引擎层 → 渲染层三层能端到端跑通。

代码重构由地图[代码重构：为首个切片“宏观贸易”建立实施工单](https://github.com/odradekk/train/issues/218)负责，目的地是交付这个切片所需的实施工单全部建立。它决定代码结构与旧代码去留、测试与验证体系和切片内容，并建立实施工单；[集中退役旧切片入口与驱动](https://github.com/odradekk/train/issues/118)和[按用途整理 scripts 目录并统一测试脚本写法](https://github.com/odradekk/train/issues/164)也由它处置。

### 临时规则

以下规则只用于本切片，对应的切片完成后删除：

- **市场**：聚居地的货物沿用 `archive/mvp/` 已验证的市场模型：每个聚居地按类型对各货物设定供给量和需求量，按市场刻结算价格。市场与人口规则确定后替换。
- **列车来源**：开局按生成配置给几列预置列车。玩家可以在任一聚居地按 BOM 总 Value 立即购买预置蓝图的车辆，再自行编组。建造切片完成后，这条规则删除。

### 后续切片（暂定）

1. 节点场景与聚居地经营：地块、建造、站台；
2. 设计编辑器与列车制造、改装；
3. 生产与开采；
4. 扩建线路与断轨修复；
5. 战斗、世界生物与征服；
6. 市场与人口规则。

这是路线图，不是实施承诺。每完成一个切片，按得到的证据调整后面的顺序。

### 本阶段验收

- **试玩**：由用户试玩约 30 分钟：新开一局，组建列车，设定计划和交易规则，靠贸易赚钱；保存、退出、读档后继续。
- **确定性**：[04 的证据矩阵](04-deterministic-simulation.md#确定性验收)中与本切片相关的行：同输入重复运行与保存恢复、暂停时的命令与拒绝、列车在图上运行、地图生成、与观察无关、损坏或不兼容的输入、录制与复现包。
- **测试地图**：两者都由脚本制作，见 [09 的示例存档](09-persistence.md#示例存档)。
  - 一份小示例存档，约 8 个节点、3 列车，用于自动测试；
  - 一份固定种子生成的标准地图，约 50 个节点，用于长测和性能测量。
- **长测**：无界面地以最高倍速运行标准地图若干小时的游戏时间，没有故障，检查点可以复现。
- **线路场景**：人工检查跟随、弯道、坡度、8× 下的分段构建，以及浮动原点移动时有没有跳动。

领域自动测试、Godot 集成检查与人工观感共同验收；具体配置、操作序列和通过条件由实施工单规定。

### 本阶段性能目标

- **目标配置**：Ryzen 5 3600、桌面 GTX 1650 GDDR5 4 GB、16 GB 双通道内存、SSD、Windows 11 x64。开发机只用于开发和辅助测量，其结果不能替代目标配置验收，也不据此宣称产品最低配置。
- **体验目标**：1920×1080、Compatibility 渲染器、默认录制开启时，宏观地图和线路场景以 60 FPS 为目标；标准地图上，核心模拟层在 8× 下能跟上。
- **测量**：
  - 无界面的核心吞吐量：标准地图上每秒能算多少模拟步；
  - 宏观地图和线路场景的帧耗时记录：p50、p95、p99、最大值和卡顿；
  - 上文的长测。
- **正式测量**：使用目标配置实机、独立 Release 构建、真实 1080p 窗口和默认开启的录制。无界面的结果只用于吞吐量和定位开销，不能代替完整运行。没有目标实机的结果时，性能保持“待验证”。
- **数值确定**：录制容量与起点间隔、场景各项预算（区块边长、分段长度、预取距离等）、自动存档的默认间隔，先在开发机上测量，提交用户确认后再定；实施者不得自行放宽指标后宣布达标。
- **未达标处理**：先定位瓶颈并修正实现，不自动降低帧率目标或模拟精度。

## Demo 范围

Demo 是最终游戏完整可玩的最小集合，包含：

- **经济**：贸易与运行计划；聚居地的生产、库存、市场与人口模拟；资源与生产的最小链条（开采 → 生产 → 库存 → 作为贸易供给），见 [10](10-resources-and-extraction.md)–[13](13-production-runtime-and-facilities.md)。资源是节点上的储量，开采是普通生产流程，见 [10](10-resources-and-extraction.md)。
- **建设**：在自己的聚居地建造和改装建筑；扩建铁轨、修复断轨、修建新线路。
- **设计**：面向玩家的通用设计编辑器，用来设计列车和建筑，同时提供预置蓝图。
- **战斗**：武装列车、聚居地防御、世界生物和生物聚落。
- **聚居地取得**：征服，以及在无人节点上建立新聚居地。
- **世界与运行**：宏观世界的生成；多列车、多节编组在世界图上运行。
- **局部场景**：聚居地、战斗、列车运行和设计编辑器。
- **时间**：1× 以上的倍速运行，见 [04](04-deterministic-simulation.md)。

## Demo 之后

AI 势力与外交；离线进度；自动贸易策略；复杂运营调度；步兵、下车作战的乘员等非列车的战斗单位。

Overlay、Top Dock、托盘与后台模式（转录 Q18、Q154、Q85）已随桌面停靠一起从产品规划中删除，不再列为以后的功能。原先排在 Demo 之后的自由式车辆设计器、面向玩家的铁路施工和武器已经进入 Demo。
