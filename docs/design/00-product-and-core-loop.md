# 00 产品形态与核心循环

> 决策出处：转录 Q2、Q8、Q109；`CONTEXT.md` 与历史 [MVP 规格](https://github.com/odradekk/train/blob/eb6a502329a1830a51c5da62e2c24545f34c9a46/docs/specs/mvp.md) 描述的 MVP 已验证循环；2026-09-05 围绕 [#29](https://github.com/odradekk/train/issues/29) 的产品方向确认；Demo 范围及其与本阶段的区分由用户于 2026-10-01 确认。本阶段以世界编辑器、普通示例存档和独立自动测试验收体素基础，正式游戏场景与贸易玩法在 Demo 中接入。

## 边界

本文回答三个问题：这是什么游戏，玩家在做什么，为什么是体素世界与桌面常驻窗口。经济规则、贸易方案编辑、列车调度、车辆设计 UI 的具体设计不在本文，留待后续扩充。窗口行为细节见 [08](08-desktop-window-and-camera.md)。

## 不变量

- 玩家不是一个直接控制的角色。
- 所有管理窗口只是同一个 World Model 的不同 View，不拥有独立世界状态；关闭辅助窗口不影响 Simulation。

## 规则

### 产品形态（已定）

游戏是一款以火车自动运行和贸易模拟为核心的桌面放置游戏。主要游戏视角是一个长期存在于桌面的 3D 条形窗口：

```text
┌──────────────────────────────────────┐
│                                      │
│          用户正在使用的其他软件        │
│                                      │
├──────────────────────────────────────┤
│         游戏 3D 火车观察窗口           │
└──────────────────────────────────────┘
```

Demo 默认：Windows-first；无边框；Bottom Dock；占满目标显示器宽度；高度可调整；默认主显示器，玩家可选择其他显示器；可以切换为 Floating 模式；Floating 模式允许任意移动和合理范围内调整尺寸，可选 Always-on-top；3D 窗口为游戏主窗口。

其他管理功能使用独立窗口，包括未来的：自动贸易策略、火车管理、车辆升级、车辆设计器、经济管理、其他 Gameplay UI。Demo 中关闭主 3D 窗口视为退出游戏。

### 核心循环与当前阶段

- 长期产品方向沿用 MVP 已验证的循环：配置贸易方案 → 观察自动运行 → 阅读运行报告 → 策略迭代。相关术语见 `CONTEXT.md`。
- 玩家在桌面上长期观看底部 3D 条中的火车自动贸易，通过独立窗口配置贸易方案、升级改装与设计车辆（转录 Q8）。
- Demo 是最终游戏完整可玩的最小集合，范围见下文 [Demo 范围](#demo-范围)。本阶段是 Demo 之前的开发里程碑，先建立稳定、高效、支持修改的体素世界，并验证列车运行与观察；桌面常驻窗口和贸易玩法在 Demo 中接入，不作为本阶段验收条件。贸易循环已在 MVP 验证。
- 开发按小切片推进，每次通过世界编辑器、普通示例存档和独立自动测试验证所选能力。达到下文验收条件后进入正式游戏场景开发，不以“整个系统完成”作为门槛，也不提前实现所有未来玩法需要的通用能力。

### 为什么是体素世界

- 转录 Q2：统一的体素模型让可交互物、设备、资源、地形共用一套建模与开发方式，简化内容生产；UI 与特效除外。
- 转录 Q109：铺轨、破坏地形、桥梁隧道等日后必加，它们依赖可破坏、可组合的体素世界，"这也是使用体素的重要原因之一"。
- 选择体素系统的重要原因是更简单、高效地支持修改、破坏与自定义。本阶段必须实际验证世界与车辆的这些能力，而不只展示静态体素场景。
- 可开采的自然资源、可铺设与破坏的铁路与地形、可组合和改装的车辆，是这些能力支持的玩法方向；不因此要求本阶段实现完整的开采、施工或车辆设计流程。
- 武器、生物属于"一切皆体素"的愿景（[01](01-voxel-world.md)），不在 Demo 中。

## 本阶段范围

本阶段是 Demo 之前的开发里程碑，交付通过世界编辑器和独立自动测试验收的体素基础；具体分期与排期见各实施 Issue。人工调试统一进入世界编辑器，按[存档工作流](09-persistence.md#世界编辑器存档工作流)新建、生成、打开和保存普通存档，直接创建和修改地形、轨道、建筑与车辆，用于开发、重复验证与性能测量；不要求正式面向玩家的建造或设计 UI。

编辑器可以免费、即时创建和修改对象，并可绕过后续玩法的进度和操作权限；身份唯一、引用完整、事务原子性、确定性，以及相应操作的结构、铁路几何和占用规则仍须满足。正式伤害形成的断轨、残骸和失效建筑是可保存、可运行的受损状态，不因不满足新建条件而被当作坏档。

编辑器、正式游戏、控制台和自动测试共用最终的领域校验与提交逻辑，上层流程可以不同。例如编辑器即时放置建筑，正式游戏以后先检查材料并执行建造任务，完成时仍经过同一建造校验与世界事务。相机、面板、预览和 Godot 图形节点不是世界事实的来源。

世界编辑器和自动测试直接使用正式的世界模型、模拟、渲染与存档代码。进入正式游戏场景开发前，需要证明：

- 按 [05 的生成契约](05-world-generation-and-settlements.md)生成实际地形、聚居地与至少四站网络，支持 10 节泰坦能力及三列联合运行；五档和跨档混编通过 [06 的几何与网络契约](06-railway.md)，包含弯坡、道岔、冲突防护及持续通行。
- 修改与破坏后，世界状态、显示和碰撞保持一致。
- 修改车辆后，其结构和运行行为符合规则。
- 静态建筑断裂后保持单一身份并整体失效，修复完整还原实例最后确认的设计；身份终止及残块按 [03](03-composite-and-behavior.md#本阶段静态建筑契约)验收。
- 全图全精度模拟、跨进程确定性、普通存档恢复及严格复现通过 [04](04-deterministic-simulation.md#确定性验收) 与 [09](09-persistence.md#本阶段保存与复现契约)的证据矩阵；默认有界录制和故障复现包可用。
- 世界编辑器的新建、生成与存档恢复入口统一，三路表现、跨区观察及诊断可用，旧四切片按覆盖等价条件退役。
- 世界编辑器可以创作、校验并发布车辆／建筑蓝图、体素定义与聚居地 Layout，发布结果能在世界中实际使用，流程见 [02](02-definitions-and-content.md#世界编辑器内容创作流程)；已提交的编辑支持有限撤销与重做，范围见 [04](04-deterministic-simulation.md#编辑撤销与重做)。
- 在冻结的世界规模、负载和修改频率下，普通 1080p 窗口中的运行与长期稳定满足下文的[本阶段性能目标](#本阶段性能目标)。目标实机暂无时保持待验证；桌面停靠和多显示器不作为本阶段完成条件。

修改与破坏测试操作、Blueprint 形态、阵营延期及窗口策略已由 [#30](https://github.com/odradekk/train/issues/30) 确认，详见 [03](03-composite-and-behavior.md) 与 [08](08-desktop-window-and-camera.md)；其中 Blueprint 形态已由[蓝图、布局与内容定义的创作和发布决策](https://github.com/odradekk/train/issues/141)更新为在世界编辑器中创作和发布，见 [02](02-definitions-and-content.md#世界编辑器内容创作流程)。

领域自动测试、Godot 集成检查与人工观感共同验收；具体配置、操作序列和通过条件由各实施 Issue 规定。大世界、高频修改与多列车的性能要求以下文的本阶段性能目标为准，不能把小场景通过视为规模保证。

### 本阶段性能目标

测量方案与数值冻结流程由[性能验收决策](https://github.com/odradekk/train/issues/98#issuecomment-5856117703)确认，[性能 Benchmark 决策](https://github.com/odradekk/train/issues/143)将其扩展到世界编辑器。具体帧耗时分位数、卡顿容忍、可支持负载和内存稳定容差在代表负载实测后提交用户确认；实施者不得自行放宽指标后宣布达标。

- **目标配置**：Ryzen 5 3600、桌面 GTX 1650 GDDR5 4 GB、16 GB 双通道内存、SSD、Windows 11 x64。开发机只用于开发和辅助测量，其结果不能替代目标配置验收，也不据此宣称产品最低配置。
- **体验目标**：1920×1080、Compatibility 渲染器、默认复现录制开启时，正常交互（包括世界编辑器中的观察与编辑）以 60 FPS 为目标，同时模拟持续跟上 1× 时间。
- **Benchmark**：分为操作基准、真实窗口体验和长期稳定三部分，可分别选择执行并各自给出结论。编辑器负载由少量代表流程覆盖，不穷举工具组合。性能回归只与负载、环境和计量方式一致的基线比较；这些条件改变时建立新基线，并说明结果不能直接比较。
- **正式测量**：使用目标配置实机、独立 Release 构建、真实 1080p 窗口和默认开启的录制。headless 吞吐、关闭录制或部分表现的对照只用于定位开销，不能代替完整运行通过。没有目标实机测试证据前，性能保持“待验证”。
- **未达标处理**：先定位瓶颈并修正实现。可以缩减超出功能基线的压力负载或多余地图内容，但保留四站网络、三列联合运行、10 节泰坦能力、完整模拟与默认录制；不自动降低帧率目标、铁路标准或模拟精度。满足几何和功能的最小标准地图仍无法达标时，明确失败并重新提出配置或范围取舍。

## Demo 范围

Demo 包含：

- 桌面底部条形 3D 主窗口：Bottom Dock、Floating 与显示器选择，见 [08](08-desktop-window-and-camera.md)。
- 与世界编辑器分开的正式游戏场景。
- 贸易核心循环：配置贸易方案 → 观察自动运行 → 阅读运行报告 → 策略迭代。
- 世界生成：地形、聚居地、四站铁路网络，以及桥梁与隧道，见 [05](05-world-generation-and-settlements.md) 与 [06](06-railway.md#桥梁和隧道)。
- 聚居地市场模拟与人口模拟。
- 1× 之外的倍速运行，见 [04](04-deterministic-simulation.md)。
- 铁路网络运行：多列车、道岔与多节编组，见 [06](06-railway.md)。
- 资源与生产的最小链条：开采 → 生产 → 库存 → 作为贸易供给，见 [10](10-resources-and-extraction.md)–[13](13-production-runtime-and-facilities.md)。
- 玩家用预置蓝图建造和改装车辆，见 [03](03-composite-and-behavior.md) 与 [14](14-construction-refit-and-deconstruction.md)。

## Demo 之后

完整的自由式玩家车辆设计器；面向玩家的铁路施工界面（Demo 使用生成的线路）；自动贸易策略；AI；复杂运营调度；阵营；武器；离线进度；Overlay、Top Dock、托盘与后台模式（转录 Q18、Q154、Q85）。世界编辑器中的修改操作、蓝图创作和线路施工是本阶段的开发工具能力，不属于上述延后项。
