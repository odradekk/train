## 边界

本文回答四个问题：这是什么游戏，玩家在做什么，体素起什么作用，Demo 包含什么。战斗与征服见 [17](17-combat.md)；市场、人口等玩法的具体规则不在本文。窗口与界面见 [08](08-window-and-ui.md)。

## 不变量

- 玩家扮演列车长，是管理者，不是一个直接控制的角色，也不操控单个单位。
- 世界自动运行。玩家通过计划、规则、建设和战前安排影响世界，不需要持续操作。
- 管理界面不拥有独立的世界状态。局部场景与核心模拟层的关系见[分层架构与局部场景的权威边界](https://github.com/odradekk/train/issues/198)。

## 规则

### 产品定位

游戏是一款自动经营（放置）游戏，经济、建设、战斗是三个并列的主循环。玩家扮演列车长，经营一家列车公司：设计并组建车队，取得、经营和建设聚居地，与世界生物和敌对的聚居地作战，通过控制市场和资源扩大经营。

“放置”指世界自动运行：玩家制定运行计划、交易规则、建设和战斗安排，观看自动运行的结果，按需调整；玩家可以开着游戏做别的事。游戏不采用离线收益、数值指数增长和周期性重置这些传统放置机制。

游戏使用普通游戏窗口，不做桌面停靠。主窗口、宏观地图、场景之间的切换、管理界面和相机见 [08](08-window-and-ui.md)。

### 核心循环

三个主循环并列，每个循环都是“制定计划 → 观看自动运行 → 按结果调整”：

- **经济**：制定运行计划和交易规则，列车自动运输，聚居地自动生产和交易；玩家阅读运行报告和经营报告，再调整方案。MVP 已验证的“配置贸易方案 → 观察自动运行 → 阅读运行报告 → 策略迭代”是它的基础，相关术语见 `CONTEXT.md`。
- **建设**：在自己的聚居地建造和改装建筑（生产、仓储、防御、站点），扩建铁轨、修建新线路，设计并制造列车；结果是产能、运力和防御提高。
- **战斗**：给列车安装武器，在编组中加入武装车辆作为护卫，安排路线，设定交战规则。遭遇敌人时由核心模拟层自动结算，玩家可以打开战斗场景观看，并下少量高层指令。战后修复损伤；胜利带来聚居地、资源或更安全的线路。

三个循环互相支撑：经济为建设和战斗提供资金和货物；建设提高经济产出和战斗能力；战斗保护线路、取得新的聚居地，从而扩大经济。玩家的长期成长体现为车队规模、拥有的聚居地，以及对市场和资源的控制。

### 目标与一局结束

- Demo 是开放沙盒，玩家自行设定目标，没有强制目标顺序、通关条件或强制结局，也不通过任务解锁功能。
- Demo 不做任务、成就或里程碑系统。通过经营报告、库存、产能、车队和聚居地状态帮助玩家判断进展；操作提示与失败原因仍须清楚。下文的验收路径是开发验收要求，不是游戏内任务。
- 车辆、货物和建筑的损失真实保留。即使失去全部列车、资金不足或没有可恢复经营的聚居地，也不强制结束对局；玩家仍可查看状态、读档或重新开始。
- 不提供自动救济、贷款或免费替换列车，不保证所有经济困境都能恢复。合法的经营失败与内部故障分开，后者按 [04](04-deterministic-simulation.md) 冻结和报告。
- 玩家自行决定何时离开、读档或重新开始；未保存进度的离开保护见 [09](09-persistence.md#文件身份与写入)。没有离线进度。

### 开局与聚居地

- 开局时玩家是一家列车公司，有资金和少量列车，没有聚居地。
- 新局默认暂停，显示宏观地图，让玩家先查看世界、设置计划，再自行开始运行。
- 玩家通过征服，或在无人节点上建立新聚居地，取得聚居地。只有自己拥有的聚居地可以建造建筑、管理生产。
- 聚居地对玩家的关系分为玩家拥有、非敌对和敌对。所有非敌对聚居地都向玩家提供有偿服务：委托制造、维修和改装列车，以及租用仓库。在取得第一个聚居地之前，建设循环靠设计列车、委托服务和修建铁路进行。Demo 中关系只在生成世界、玩家宣战和征服时变化，见 [17](17-combat.md#聚居地关系与征服)。
- Demo 中玩家的对手是不属于玩家的聚居地和世界生物。这些聚居地各自独立，不组成势力；Demo 中没有与玩家竞争的 AI 势力。世界生物在世界中游荡，或从生物聚落出发，袭击线路和聚居地；清剿生物聚落可以获得奖励，或者打通一片区域，见 [17](17-combat.md#世界生物)。

#### 默认开局的可玩性约束

- 起始车队具备运输能力；起点通过已建成、无断点的铁路可达其他非敌对聚居地，存在无需先打仗就能启动的贸易机会。
- 初始资金、货物供应和服务条件足以支持起步，不要求先设计新车或拥有自己的工厂。
- 世界中存在建立聚居地、发展生产、征服和清剿的机会；这不保证玩家每种决策都成功，也不提供永久安全区。
- 这些是默认生成配置必须校验的约束，不满足时按 [05 的重试与预算](05-world-graph-and-generation.md#世界生成流程)重试或明确失败，不能把无法起步的世界作为成功结果交给玩家。
- 起始资金、列车数量和蓝图由[Demo 内容与资产清单：覆盖场景与制作验收](https://github.com/odradekk/train/issues/283)按上述约束配平，不直接继承旧切片的两列车配置。人口与消费规则见 [18](18-population-and-labor.md)，真实库存、备货、价格与有限现车见 [19](19-markets-and-trading.md)；不能用临时市场规则或隐形 NPC 物流证明默认开局可玩。

### 战斗

- 玩家以战前安排为主，包括列车设计、编组（护卫就是编组中的武装车辆）、路线和交战规则。战斗中可以下少量高层指令，例如撤退、集中攻击某个目标，但不操控单个单位。
- Demo 的战斗单位只有三类：装有武器的列车（武器是在设计编辑器中安装的部件或大型设备）、聚居地的防御建筑、世界生物。没有步兵、下车作战的乘员或飞行单位。
- 战斗发生在世界图的线路或节点上，即线路、聚居地和生物聚落。
- 战斗由核心模拟层按模拟步结算，战斗场景只作表现，不写回结果，见 [ADR-0008](../adr/0008-simulate-the-world-in-a-voxel-free-core-and-build-voxel-scenes-as-presentation.md)。战斗、世界生物与征服的规则见 [17](17-combat.md)。

### 体素的作用

核心模拟层负责整个世界，不涉及体素。体素引擎只用于玩家关注的局部场景：列车与建筑的设计和改装、聚居地管理与建设、战斗、列车运行。选择体素作为表现层的理由：

- 美术成本低：不需要高精度建模，配合合适的 shader 也能做出精美的画面。
- 玩家设计列车和建筑的门槛低：在编辑器里摆放体素即可。
- 战斗中的破坏效果容易表现。

原先“铺轨、地形破坏、桥梁隧道依赖可破坏、可组合的体素世界”（转录 Q109）这条理由依赖全局体素世界，已经删除。

### 本阶段验收

#### 三个循环的人工验收路径

由用户从正常新游戏开始，不用调试命令，完成以下路径；可以分多次试玩，不设“30 分钟必须走完”的限制：

1. 设置运行计划与交易规则，通过贸易取得资金和货物，并依据报告调整经营。
2. 设计并委托制造或改装车辆，将成果投入车队运行。
3. 建立自有聚居地，建设并运行生产链，把产物投入运输、销售或建设。
4. 配置武装并参与战斗，承担损失、维修并恢复经营。
5. 保存、退出、读档后继续经营。

用可复现的分支存档补测主路径未发生的征服、清剿、撤退、断轨修复等情况，以及合法经营失败后仍能查看状态、读档和重新开始且不会自动获救的行为。这是验收路径，不是玩家必须遵循的游玩顺序；分别运行互不相连的三个演示不能证明循环已经连通。

#### 测试世界与标准混合负载

- 小型功能测试世界用于定向自动测试，按待验证行为选择最小充分规模，不直接继承旧示例的数量。
- 标准世界采用固定种子，约 50 个节点、约 25 个聚居地，用于长测和性能测量。它代表已经发展起来的世界，不是默认新局的初始状态。
- 示例与分支存档按 [09 的示例存档](09-persistence.md#示例存档)由脚本制作并保留配方；正常新游戏仍使用生成器，不能用示例替代开局验收。

| 对象 | 标准混合负载目标 |
| --- | --- |
| 列车 | 20 列正在执行计划的列车，共 80 辆车辆，覆盖运行、交易和排队。 |
| 聚居地 | 25 个，其中 5 个归玩家所有。 |
| 建筑与生产 | 共 100 座建筑，其中 50 座运行生产或供能设施。 |
| 建造类任务 | 10 项同时进行的建造、改装、维修或拆解任务。 |
| 世界生物 | 共 100 只，覆盖驻守、游荡和袭击。 |
| 战斗 | 在不同地点同时进行 3 场，覆盖线路和节点。 |

上述数量是已确认的测试目标，不是已测得的承载能力，也不是玩家数量上限。具体货物、人口、配方、武器、设计和资产由[Demo 内容与资产清单：覆盖场景与制作验收](https://github.com/odradekk/train/issues/283)补齐。测试配方和结果必须记录实际活跃负载，不能靠空库存、停工或没有武器的“战斗”凑数量；对象被消灭、任务结束后，空闲时段不能继续算作繁忙负载的性能证据。

#### 大尺寸与拥挤场景专项

- Demo 内检查合法大尺寸设计，不再把规模检查整体推迟到 Demo 之后。标准混合负载之外，单独检查泰坦车辆、长编组、拥挤站点和繁忙战斗场景。
- 编辑器覆盖大尺寸设计、嵌套设备、区域编辑、撤销重做，以及发布后实际制造和使用。
- 内容票明确每份样例的占用格数、部件数、嵌套情况和同屏数量，不能只用空壳证明大尺寸已支持。专项性能保证覆盖哪些样例必须在测量前明确，不能看到结果后临时缩小范围；不承诺任意数量、任意复杂度都保持 60 FPS。

#### 正确性、长测与完成门槛

- **完整回归**：执行 [04 的确定性证据矩阵](04-deterministic-simulation.md#确定性验收)，覆盖完整 Demo 的领域规则、内容、存档和复现；按[实现 SOP](../implement-sop.md#testing-standard)验证真实边界。模块替身通过不等于真实模块联调通过。
- **核心长测**：标准混合负载累计推进至少 24 小时游戏时间；同输入做跨进程重复运行和保存恢复对照，在相同模拟位置检查权威检查点一致，同时检查资源、任务、运输和战斗的不变量，不只检查是否崩溃。
- **完整窗口长测**：至少 2 小时真实时间，包含场景与编辑器反复进出、保存读档、录制窗口轮换；检查内存是否持续增长、失效资源是否残留、操作是否逐渐变慢。
- **场景与交互**：在真实 Godot 游戏中人工检查跟随、弯道、坡度、8× 下的分段构建、浮动原点，以及进站、停靠、出站和穿过节点时的无缝切换；按美术文档检查节点、战斗与编辑器的表现和可读性。
- **完成门槛**：完整正确性回归、真实模块联调、性能和人工验收分别有适用证据；存档丢失、确定性错误、状态破坏、关键玩法无法继续等问题阻塞完成。缺环境、缺测量或未执行的检查保留“待验收”，不能用规划原型或运行时长替代通过证据。

长测时长是最低验证量，不是对任意长时间运行的保证。实施工单明确配置、操作序列和证据；若实测成本或风险要求调整，说明依据后提交用户确认，不得自行缩短或放宽验收。

### 本阶段性能目标

- **目标配置**：Ryzen 5 3600、桌面 GTX 1650 GDDR5 4 GB、16 GB 双通道内存、SSD、Windows 11 x64。开发机只用于开发和辅助测量，其结果不能替代目标配置验收，也不据此宣称产品最低配置。
- **体验目标**：1920×1080、Forward+ 渲染器（[ADR-0010](../adr/0010-render-with-forward-plus.md)）、默认画质、默认录制开启时，宏观地图、局部场景和设计编辑器以 60 FPS 为目标；标准混合负载下，核心模拟层在 8× 下能跟上。两项目标必须在完整游戏运行中同时验证，不能分别以暂停模拟的画面和无渲染的模拟拼成通过。
- **测量**：
  - 无界面测量核心吞吐量：标准混合负载上每秒能算多少完整模拟步，仅用于吞吐量和定位开销。
  - 在标准混合负载下分别测量宏观地图、列车跟随、聚居地、战斗和设计编辑器；覆盖正常操作和 8× 运行。性能测试可关闭“遇敌自动降速”，但须记录这一设置，不能混入功能默认值的验收。
  - 记录帧耗时 p50、p95、p99、最大卡顿、实际倍速、内存和显存。首次加载、场景切换、保存和设计发布单独报告，不能从报告中消失。
  - 执行上文的长测和大尺寸、拥挤场景专项。
- **正式测量**：使用目标配置实机、独立 Release 构建、真实 1080p 窗口和默认开启的录制，不得为了跑分关闭自动存档。无界面结果不能代替完整运行；只有贸易运行的测量不足以验收完整 Demo。没有目标实机的结果时，性能保持“待验收”。
- **数值确定**：帧耗时尾部阈值、加载等待上限、内存预算和场景构建预算，以及录制容量与起点间隔、场景各项预算（区块边长、分段长度、预取距离等）、自动存档默认间隔，先测量再提交用户确认。未确认时性能保持“待验收”，不能只凭平均 FPS 宣布完成，也不得自行放宽指标后宣布达标。
- **未达标处理**：先定位瓶颈并修正实现，不自动降低帧率目标或模拟精度。

## Demo 范围

Demo 是最终游戏完整可玩的最小集合，包含：

- **经济**：贸易与运行计划；聚居地的生产、库存、市场与人口模拟；资源与生产的最小链条（开采 → 生产 → 库存 → 作为贸易供给），见 [10](10-resources-and-extraction.md)–[13](13-production-runtime-and-facilities.md)。资源是节点上的储量，开采是普通生产流程，见 [10](10-resources-and-extraction.md)；人口按需求满足情况动态变化并提供劳动力，采用真实消费和供需软约束，见 [18](18-population-and-labor.md)。
- **建设**：在自己的聚居地建造和改装建筑；扩建铁轨、修复断轨、修建新线路。
- **设计**：面向玩家的通用设计编辑器，用来设计列车和建筑，同时提供预置蓝图。
- **战斗**：武装列车、聚居地防御、世界生物和生物聚落。
- **聚居地取得**：征服，以及在无人节点上建立新聚居地。
- **世界与运行**：宏观世界的生成；多列车、多节编组在世界图上运行。
- **局部场景**：聚居地、战斗、列车运行和设计编辑器。
- **时间**：1× 以上的倍速运行，见 [04](04-deterministic-simulation.md)。

## Demo 之后

AI 势力与外交；离线进度；自动贸易策略；复杂运营调度；步兵、下车作战的乘员等非列车的战斗单位。

Overlay、Top Dock、托盘与后台模式（转录 Q18、Q154、Q85）已随桌面停靠一起从产品规划中删除，不再列为以后的功能。原先排在 Demo 之后的自由式车辆设计器、面向玩家的铁路施工和武器已经进入 Demo。
