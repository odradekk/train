# 18 人口与劳动力

> **所属层**：核心模拟层；内容层提供人口规则参数，Godot 展示核心查询与事件，体素层不模拟居民。

> 决策出处：[人口与劳动力：Demo 的最小规则](https://github.com/odradekk/train/issues/280)，2026-10-10 的 Q1–Q21。Q4 确定供需软约束而非人口硬上限；Q15 最终确定基本需求与改善需求分别加权，取代讨论中曾建议的基本需求取最短板。本决定把聚合人口变化、居民消费和劳动力换算纳入 Demo，不保留生产文档中的旧分期。

## 边界

本文定义聚居地常住人口怎样消费、增长和减少，怎样提供劳动力，以及初始化、征服、保存恢复、内容缺失时的行为。只模拟聚居地总量，不模拟个人、年龄、职业、工资、疾病，也不追踪逐人的出生、死亡或城际迁移。

相关规则见[聚居地](16-settlements.md)、[货物目录](11-goods-and-production-network.md)、[库存](12-inventory-and-storage.md)、[生产与资源仲裁](13-production-runtime-and-facilities.md)、[确定性](04-deterministic-simulation.md)和[存档](09-persistence.md)。市场报价、收购、贸易留货和 NPC 如何采购见 [19](19-markets-and-trading.md)；外部供货依靠玩家运输，不存在无限货源、后台 NPC 贸易或免费补货。

本文是已确认的玩法规范，不是实现或测试通过记录。可编译接口及具体调用时序仍由[核心契约](https://github.com/odradekk/train/issues/287)、[内容契约](https://github.com/odradekk/train/issues/288)和[跨层事务](https://github.com/odradekk/train/issues/284)交付。

## 不变量

- 常住人口是核心权威状态，按整数人数记录，最低为 1。初始人口范围不是运行中的人口上限或保底人数。
- 不设人口硬上限，也不引入住房容量。实际生产、运输和可取得的货物与消费共同形成软约束；不保证人口必然平稳收敛。
- 玩家与 NPC 聚居地使用同一套人口规则。劳动力从人口派生，不由内容层、界面或场景各算一份。
- 居民只能消费真实取得的物资。库存扣除保持整数；消费剩余量与人口变化的小数余量都是影响未来模拟的状态。
- 同一份货物只取用一次；食品同时满足两个需求时，不重复扣货，不把已消费部分再次使用。
- 人口消费不凭空产生资金、货物或市场供给。需求满足率不是市场收购数量。
- 统计、消费、人口变化与劳动力分配遵循核心模拟时间、确定性资源仲裁和提交边界，不由墙钟、界面刷新或遍历顺序决定。

## 规则

### 一局共用的人口规则

一局世界全部聚居地共用一套人口规则内容数据；不按聚居地类型配置不同的生活需要或劳动比例。类型在人口方面仍只给出初始人数范围。地区差异先来自资源、设施、产能与运输。

人口规则提供以下数据，数值留待试玩调优，不能硬编码为界面常量：

| 数据 | 含义与单位 |
| --- | --- |
| 需求项、消费货物与换算 | 区分基本与改善需求；明确哪种货物满足哪项需求，以及每个货物单位能满足的量，不按任意标签隐式替代 |
| 人均需求率 | 每人每游戏秒所需的该项需求量；按人口与经过的游戏时间累计应需，而不是由当前库存反推需求 |
| 需求权重 | 各项正权重，在基本、改善两类内分别归一化；不是市场价格或消费优先级 |
| 劳动比例 | 常住人口换算为可用劳动力的比例；不代表需要保存的工人名单 |
| 消费间隔与人口统计期 | 固定模拟步数；人口更新比消费低频，统计期游戏秒数按核心步长换算 |
| 增长与流失参数 | 下文的基准增长率、改善增长加成、最大流失率，按每游戏秒的人口变化比例解释 |

引用、有限数值、单位和范围必须在内容进入核心前校验。文件组织、格式与完整校验清单由[内容契约](https://github.com/odradekk/train/issues/288)确定，不在现有聚居地类型的临时供需字段中塞入这些参数。

### 基本与改善需求

| 类别 | 需求与对应货物 |
| --- | --- |
| 基本 | 食物：主食 Staple Food；衣物：Clothing |
| 改善 | 改善饮食：加工食品 Prepared Food；日用品：Consumer Goods；消费电子：Consumer Electronics；医疗用品：Medical Supplies |

不做居民阶层。医疗用品是改善消费，不因此引入疾病、医院或医疗治疗机制。

- 基础食物先用主食，不足时加工食品按人口规则明示的比例补足；只有加工食品时也能满足基础食物需求。
- 实际消费的一份加工食品，可以同时满足对应的基础食物与改善饮食需求，库存只扣一次；每项满足程度独立封顶，不能重复记作同一项的两次消费。
- 主食已满足基础食物需求时，仍可以消费加工食品满足改善饮食；加工食品带来的额外基础食物满足量不超过该项需求。
- Grain、Produce、Animal Products 在 Demo 中不直接充当居民口粮，保留食品加工链。其他改善货物不能替代食物或衣物。

### 取得物资与消费剩余量

- Demo 中居民自动消费所在聚居地的统一库存。不另设居民钱包、私人库存或工资结算；消费本身不向玩家支付金钱。这是 Demo 的策略，不承诺后续完整经济模型仍采用同一方式。
- 不直接消费停靠列车、玩家租用库存或设施 OutputBuffer 中的货物；它们必须先按各自规则转入聚居地库存。人口系统也不能取回已经投入生产批次的原料。
- 货物按需整单位取出，之后可以逐步消费。尚未用完的部分作为消费剩余量保留，之后继续使用；它已退出库存，不能再销售、调拨或供生产使用，不是另一个可自由存取的居民仓库。
- 剩余量保留对应货物身份及其数量含义，不能混成无来源的通用“满足点”。换算为需求满足量时，只计算实际消耗的部分。
- 缺货导致的未满足需求用于本期反馈，不产生以后必须补吃的消费欠账。未来需求照常发生，历史短缺不能靠一次超额消费抹去。

例如某货物每消费周期需要 0.1 单位：取出 1 单位，消费 0.1，余下 0.9 留待以后；不是每期向上取整扣 1，也不是每期向下取整不扣。这里只说明计量语义，0.1 不是已选定的消费参数。

### 同步竞争的顺序

同一步竞争同一份可用库存时，依次满足：

1. 基本生活消费，包括为基础食物补缺的加工食品。
2. 生产、开采、供能等设施请求；设施之间沿用[生产优先级与确定性排序](13-production-runtime-and-facilities.md#shared-resource-resolver)。
3. 改善生活消费；先前为基本需求消费加工食品所产生的改善满足量不得丢失或再次扣货。

这是资源仲裁规则，不是靠系统调用先后来实现的优先级。它不越过已提交事务，不撤销已经卖出的货物，也不自动预留未来几天的口粮；贸易留货遵循 [19 的补货目标](19-markets-and-trading.md#补货目标与出售保留量)，不阻止消费使用库存。消费使用的库存边界与 [04 的 Tick Barrier](04-deterministic-simulation.md#resolver)、[12 的库存规则](12-inventory-and-storage.md)一致。

### 消费周期与需求满足率

消费按较短的固定模拟步间隔进行，人口按较长的统计期更新。统计期累计各项应需量与实际满足量，不只看结算瞬间仓库是否有货，也不在每次短缺时直接扣人口。

每项需求的满足率为实际满足量除以应需量，封顶为 1。设第 \(i\) 项满足率为 \(s_i\)、正权重为 \(w_i\)，则：

\[
B=\frac{\sum_{i\in\text{基本}}w_i s_i}{\sum_{i\in\text{基本}}w_i},
\qquad
I=\frac{\sum_{i\in\text{改善}}w_i s_i}{\sum_{i\in\text{改善}}w_i}
\]

- \(B\) 与 \(I\) 都在 0–1 内，分别代表基本与改善满足率。两类不混合加权，改善不能弥补基本短缺。
- 各项先封顶，之后再加权。因此额外食物不能抵消衣物缺失；基本需求不是取最短板，也不是无权平均。
- 尚无消费统计的初始状态不伪装成满需求，未完成统计期不提前增减人数。
- 暂停不累计时间；倍速只改变真实时间内推进的模拟步数，不改变同一模拟位置的结果。

例如食物满足 100%、衣物满足 0%，权重假设为 70∶30，则基本满足率是 70%，不是 0% 或 50%。这组权重仅用于解释加权方式，不是 Demo 配置。

### 人口变化与软约束

设本次结算前人口为 \(P\)，统计期长度为 \(\Delta t\) 游戏秒，人口变化率为 \(r\)：

\[
r=\begin{cases}
-d(1-B), & B<1 \\
g+aI, & B=1
\end{cases}
\qquad
\Delta P=P\,r\,\Delta t
\]

\(g\) 是基本需求全部满足时的基准增长率，\(a\) 是改善需求带来的最大增长加成，\(d\) 是基本需求完全未满足时的流失率。三者来自人口规则，不预先冻结数值。

- 基本需求不足时，缺口越大流失越快；改善需求即使全满也不能抵消流失。
- 基本需求完全满足时，没有改善消费也能缓慢增长，改善越充分增长越快；不能无限叠加加成。
- 接近满供但仍有缺口时，仍按小幅流失处理，不另加“差不多满足就算全满”的区间。
- 本次变化与已有小数余量合并，达到完整人数才改变人口，未满部分继续保留。不能每期把小变化清零，也不能把不足一人的流失直接向负无穷取整为一人。
- 人口不能低于 1；丢弃会使人口低于下限的负变化和余量，处在下限时不积累负人口债务。供给恢复后正常累计增长，不补偿此前损失，也不凭空消除实际短缺记录。
- 不设住房容量、类型人口上限或隐含的目标人口。初始范围只用于初始化，供应改善后可以继续增长。供给附近可能出现人口起伏，须用实际生产与运输负载试玩调整速率及反馈周期，不以新增硬上限掩盖问题。

最低 1 人不表示经济必然恢复，不免费补钱、补货或恢复到初始人数；仍遵循[开放沙盒的真实损失](00-product-and-core-loop.md#目标与一局结束)。

### 劳动力与玩家操作

人口规则有效时，可用劳动力等于常住人口乘以劳动比例，是连续容量，不逐个分配居民。生产、开采和施工共用该容量；分配及部分执行规则见 [13](13-production-runtime-and-facilities.md#labor)。劳动力不是货物，不因正常工作消耗，停止占用后释放。

短缺通过人口变化影响劳动力，不再额外施加缺食品或衣物的工作效率惩罚。Demo 的士气只影响 NPC 投降，不直接改变人口或劳动比例，见 [17](17-combat.md#聚居地关系与征服)。

Demo 不新增配给、消费开关、招募、人口搬迁或单独工人调配命令。玩家通过生产、运输、交易与现有生产优先级间接管理；基本与改善消费都没有独立开关。

### 创建、征服与恢复

- 世界生成在类型的初始人口范围内取值；玩家建城取下限，沿用[聚居地创建规则](16-settlements.md#建立聚居地)，不改变已有初始人口来源。
- 消费与人口统计从聚居地成立时开始计时；累计满第一个人口统计期后才首次增减人口。不虚构成立前的需求满足，也不赠送消费剩余量。人口从成立时就提供劳动力，不等首次人口结算。
- 玩家新建聚居地仍为空库存，另带生活物资并在建城后转入，或及时安排运输。没有免费口粮和新城专属免消费期；建城界面提前显示初始人口及预计生活物资需求。第一统计期只是统一反馈周期。
- 征服继承人口、消费剩余量、统计进度和人口变化余量；不能借易主清除短缺或重新获得统计缓冲期。
- 读档在相同规则下原样接续，不清余量、不重置进度、不提前结算，与不中断运行在相同模拟位置一致。

### 内容缺失与更新

- 新游戏必须有有效人口规则。
- 热重载删除正在使用的人口规则或必需引用时，按[候选内容校验](02-definitions-and-content.md#候选内容与运行中引用校验)拒绝整次发布，保留原内容与世界状态。
- 读档时整套人口规则缺失，玩家按既有缺内容流程确认继续后：保留人口、统计进度及全部余量；人口系统不消费、不增减人数，也不提供劳动力。明确报告“人口规则缺失”，不能伪装成正常运行或普通食物短缺。
- 规则失效期间不推进人口消费与统计进度。内容恢复后接续原状态，不补算失效期间的消费或增长，也不暗用旧外部定义兜底。其他核心系统仍按各自规则运行，不把功能缺失当成内部故障冻结整个世界。
- 合法参数更新不得改写已完成的消费和人口结算，不得丢弃统计与余量。改变结算周期时如何适配未完成统计期，交给[跨层事务票](https://github.com/odradekk/train/issues/284)确定；当前没有把这项适配视为已经解决或实现。

### 权威状态、查询与事件

以下是接口设计必须覆盖的信息，不规定内部类、容器或逐字段复制方式：

| 信息 | 责任 |
| --- | --- |
| 本局人口规则的引用与有效性 | 内容提供有效投影，核心判断其运行影响；缺失不能默认为旧参数或正常供给 |
| 常住人口、人口变化余量 | 核心保存并结算；其他层不直接设置人数或另算增长 |
| 消费剩余量、统计进度、累计应需与实际满足 | 核心保存；暂停、读档、征服不清零 |
| 可用、已分配与空闲劳动力 | 核心从人口规则及真实分配结果给出，不能用界面缓存作为事实 |
| 各需求项、消费率、满足率、人口趋势和原因 | 核心只读查询；区分未完成统计与结算结果，不能把需求率等同于固定的市场收购单 |
| 人口结算摘要 | 每个人口统计期一条，包含前后人数、实际增减、两类满足率与增长、短缺流失或下限等原因 |
| 面向玩家的状态变化 | 短缺开始、恢复、降至最低人口等，由核心提供事实，Godot 按通知设置展示；常规结算进入经营报告，不每期弹通知 |

市场使用真实库存和人口需求信息设计收购、报价与留货，不恢复旧的凭空供需。生产读取实际可用与分配劳动力，不依赖 Godot 或内容加载器。体素层不模拟居民、不按人口生成对应数量的行人。

模块归属沿用[四模块契约规范](../contracts/README.md)：核心拥有模拟输入、状态与对外查询事件的类型，内容负责解析和投影，Godot 只负责展示和宿主工作。具体签名、不可变读视图及模拟位置由[核心契约票](https://github.com/odradekk/train/issues/287)落实；持久化归属见 [09](09-persistence.md#聚居地与建筑状态恢复)。

### 后续验证要区分的结果

实施时通过公开会话与查询验证这些行为，不把本文当作测试已通过：

- 食物和衣物采用不相等权重，分别制造短缺；基本加权结果不能退回最短板或简单平均，改善全满也不能抵消基本短缺。
- 基本满供、略低于满供和严重不足产生不同方向或幅度；人口可以超过初始上限，但不能低于 1，处于下限时不积负债。
- 只有加工食品时能满足食物，两类需求的共同满足不重复扣货；整数取用后的余量支持多次小额消费。
- 同步争抢库存遵守基本消费、设施、改善消费的顺序；不能从列车、租用库存或 OutputBuffer 偷取。
- 在非零消费余量、非零正负人口余量和统计期中途保存恢复；对照不中断运行，也检查征服不重置、缺规则后恢复不补算。
- NPC 和玩家聚居地使用相同规则；不同倍速、界面或场景状态不改变相同模拟位置的结果。
- 用真实生产与间歇运输检查短缺反馈、人口起伏和恢复过程；不能只用无限库存证明软约束合理。

## Demo 范围

聚合动态人口；六类生活货物的基本与改善消费、明示食品替代；两类加权满足率；供需软约束与最低 1 人；劳动力换算；周期统计与小数余量；创建、征服、存档及缺内容接续；查询、经营摘要与状态通知。

## Demo 之后

个人与年龄结构、职业、工资、疾病与医疗系统、人口阶层、逐人出生死亡或城际迁移；住房系统、聚居地荒废与重新殖民；人口招募、搬迁、配给与独立消费开关。居民钱包等完整经济机制不在 Demo 中实施，本票不承诺未来一定采用哪种替代方案。
