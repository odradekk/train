## ART-Q180–ART-Q190 · 定位、用途与核心视觉语言

| 编号 | 最终决定 | 解释与边界 |
| --- | --- | --- |
| ART-Q180 | 电传动 + 多样发电、充电与补能方式。 | 不直接冻结能源模型、科技树和具体设备数量。 |
| ART-Q181 | 造型按用途区分：民用偏 A/B、军用偏 B/C，而非按尺寸自动升级。 | 用户修正；巨型民用车辆与小型军用车辆都成立。 |

| ART-Q184 | 武器以现实工程延伸为主，允许少量近未来尖端技术。 | 95%/5% 是主次示意，不是正式内容配额。 |
| ART-Q185 | 允许炮塔式、嵌入／炮廓式、垂直模块式安装语言。 | 不据此冻结射界、火控或某一种武器的实现。 |
| ART-Q186 | 泰坦强调长、宽、重，不依靠无限向上堆高。 | 具体尺寸遵守当前 GDD；原型尺寸不成为规格。 |
| ART-Q187 | 全泰坦或混合档位编组是玩家自由；后期能源系统形成自然软约束。 | 用户修正；不设美术层面的固定泰坦占比、车长或节数上限。能源平衡仍需验证。 |
| ART-Q188 | 功能通过真实设备轮廓识别；内置型号带基础设备，玩家和 AI 可再改装。 | 统一形状块与功能件组合；不只用换色／标签伪装功能。 |
| ART-Q189 | 默认车体配色克制并体现基础材料；玩家可以自行涂装与选色。 | 不把默认色板变成玩家的硬限制。 |
| ART-Q190 | 采用适中的常态磨损，表现长期服役、仍受维护的工业设备。 | 此前 40% 是描述性示意，非统一磨损参数。 |

## ART-Q191–ART-Q200 · 构件库与组合原则

| 编号 | 最终决定 | 解释与边界 |
| --- | --- | --- |
| ART-Q191 | 建立供官方与玩家共用的通用造型块库。 | 以构件复用为核心，不只制作整车整楼模型。 |
| ART-Q192 | 1/8 Voxel 是推荐美术子网格，不是绝对限制。 | 不新增 Gameplay 子格；圆周和细小倒角可采用必要的非格点顶点。 |
| ART-Q193 | 圆形采用低面数几何，不强制完全阶梯化或完全光滑。 | 8/12/16 边作为制作起点，具体资产需看尺度验证。 |
| ART-Q194 | 斜面、楔形、角楔和切角是重要基础构件。 | 不要求地形全面变为平滑斜面。 |
| ART-Q195 | 通用造型 Voxel 是结构件，并贡献耐久。 | 用户修正；当前 GDD 汇总为结构耐久，不沿用早期助手对“绝无共享 HP”的解释。 |
| ART-Q196 | 采用 C：模块边界可读，但不强调统一格线。 | 靠结构语义表达，远看整体、近看构件。 |
| ART-Q197 | 所有组成车辆／建筑的构件在游戏中均可获得，没有开发者专属组成块。 | 不保留早期建议中的不可获取核心块例外；场景专用地形另按 scene_only 管理。 |
| ART-Q198 | 建筑采用与车辆、机械相同的造型语言。 | 共享基础构件与材质，不等于所有建筑具有相同用途或轮廓。 |
| ART-Q199 | 大型设备强调标准化安装结构。 | 安装座、支架、接口要可读；不自动引入新的物理接口系统。 |
| ART-Q200 | 复杂造型优先由简单、清楚的大形组合产生。 | 结合 Q237；不要求把每个螺丝拆成 Voxel，也不靠单个超复杂整体模型。 |

## ART-Q201–ART-Q210 · 形状变体、接缝与生产方式

| 编号 | 最终决定 | 解释与边界 |
| --- | --- | --- |
| ART-Q201 | Shape 是可复用的视觉资产。 | 不成为独立的 Gameplay 身份或数值体系。 |
| ART-Q202 | 采用 1、1/2、1/4、1/8 Cell 四档标准厚度。 | 不要求所有形状 × 四种厚度全部建成定义。 |
| ART-Q203 | 先限制为标准形状和标准斜面。 | 不开放任意用户几何或无限坡度组合。 |
| ART-Q204 | 采用固定比例的形状变体。 | 不通过自由缩放绕过占格、包络与构件选择。 |
| ART-Q205 | 优先标准接头、直段与转角变体。 | 不在运行时随意拉伸几何来填缝。 |
| ART-Q206 | 按构件语义处理接缝。 | 连续结构可弱化格界；检修板、装甲和连接处可强调。 |
| ART-Q207 | 视觉接触问题只提供设计警告。 | 仅指 Mesh 未接触等外观问题；真实不连通、重叠或越界仍按设计规则拒绝发布／制造。 |
| ART-Q208 | 逐块涂装，并支持批量操作。 | 批量操作范围由正式工具接入；不依赖逐格核心实例。 |
| ART-Q209 | 采用程序化基础几何 + Blender 复杂设备的混合生产方式。 | 程序化与手工资产使用相同尺度、边界和材质标准。 |
| ART-Q210 | 根据实际场景需求逐步完善构件库。 | 不提前穷举全部资产和工具能力。 |

| ART-Q221 | 采用少量共享表现材质类别，允许必要的特殊材质。 | 不是提前建立 Gameplay MaterialDefinition。 |

| ART-Q229 | 玩家涂装可突破默认色板，提供推荐预设。 | 官方色板约束内置设计方向，不限制玩家选色。 |
| ART-Q230 | 三个样机采用一致的观察距离、光照、涂装和动态检查。 | 条窗现只作为低屏幕覆盖率压力测试，不恢复已删除的桌面停靠产品规划。 |

### 沿用的重要美术前提

近未来工业；Industrial / Monumental / Utilitarian / Modular / Cold / Restrained / Heavy / Engineered。
用途决定车辆造型语言，而非尺寸自动决定军用或民用属性。默认官方配色克制；玩家可以选择自己的颜色。
几何体素化、模块化、适当低面数；PBR 材料表现向更加写实调整。保留自然环境的颜色，不把冷峻等同于全世界灰黑。

一个体素占一个 Cell，半块仍占整格；普通模型严格内接 Cell；安装方向只使用 24 种正交旋转。造型块也是可损伤的结构件，不被当成无语义贴花。

Shape 是可复用的表现资产，不承担 VoxelDefinition 的身份、质量、耐久、碰撞或行为规则。
不创建复合体递归嵌套；大型装配模板是多个真实 Voxel 的布局便利工具，不暗中引入新的运行时所有者。

### 自动 UV / Triplanar 的默认约定

对通用结构与普通工业表面，优先自动映射，维持统一的名义纹理密度。对移动复合体，默认使用模型局部坐标而不是全局世界坐标，避免刚性移动引起纹理游移。自动 UV 应考虑几何尺度，不把同一张贴图任意拉伸到不同尺寸面上。

信息表面需要可读的朝向、内容布局或字形密度时，允许局部明确 UV / 信息贴花。Triplanar 不是对所有表面的强制规则；复杂曲面、定向纹理和独立机械运动的映射仍须用实际资产检查。

### 首轮验收对象

- 民用重载机车：检验工业运输造型、门窗、散热和维护结构。

- 军用重装车辆：检验重型装甲、设备安装、武器轮廓与构件复用。

- 工业维护建筑：检验同一构件库是否能跨车辆与建筑使用。

在近观、正常观察、侧向和实际条窗尺寸下，对中性日光、阴天和夜间人工光照分别检查。动态稳定性必须以实际运动观察为准，静帧不能独自证明无闪烁。

### 当前 Testbed 的地位

提供独立实验数据模型、几何资源和视觉渲染缓存。它不是正式 Train World Model、生产版 VoxelDefinition 或 Godot 场景。
此实验不确定最终游戏质量、耐久数值、能源平衡、轨距、构造合法性、战斗或断裂算法。通过实验支持的决定再迁入项目设计和实现。
