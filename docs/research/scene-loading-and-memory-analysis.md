# 场景打开时间与内存分析（#479）

## 结论

节点首开首先等待整个节点生成，再上传全部网格。B 的真实界面路径中，点击到可见中位为 23.848 秒，`node.build` 占 21.022 秒，其中逐面网格 15.448 秒、格索引 1.757 秒。一个 `Task.Run` 串行处理 900 个地形块，后台化没有缩短这条依赖链。同节点重开约 2.899 秒，主要仍是转换与上传。

当前“小型存档”的节点铺满 960×960 格地形，包含 5,533,086 个格、11,500,184 个顶点、3,988 个网格，尚未包含 #326 的城市建筑。独立 B 就绪快照有 1,960.656 MiB 托管对象，格及引用数组占 836.928 MiB，顶点及引用数组占 877.486 MiB。原入口节点工作集约 2.85 GiB、私有字节约 4.12 GiB、显存约 1 GiB。三项计量范围不同，不能相加。

私有字节扣除 GC 已提交空间后的约 2 GiB，包含地图基线约 1,090 MiB、节点新增约 924 MiB；直接分类进一步确认大量非 GC 私有提交区域，但尚不能将其分给 Godot、Vulkan 或驱动。关闭降低渲染缓冲区，缓存与 GC 空间仍可保留；完整切换序列的私有字节记录最高约 5.76 GiB，单次首开值不是全程上限。

减少每格/每面表示成本，以及限制首次构建和驻留的视野范围，是可同时改善时间与内存的两条路线。下文只提供实测、条件估算与待选择方案，没有实施优化或确认新预算。开发机、暂停世界和受控几何结果不能替代[目标配置](../design/00-product-and-core-loop.md#本阶段性能目标)的混合负载验收；城市是参数估算。

路径名只在此定义：`map-node`/`map-edge` 是从地图打开节点/线路；B 的 `map-follow` 在此前线路已打开后执行，铁路缓存已暖；C 的 `map-follow-first` 是新进程读档回地图后第一个场景，补足真正首次点击跟随。`*-reopen` 是关闭后打开同目标；`edge-to-node`/`node-to-edge` 是直接切换；`load-*` 从重新读档完成后的场景点击计时；`reload-*` 从读档按钮计时，包含读档、两操作间隔和随后同名 `load-*` 的信号。`initial-load` 是本进程初次界面读档。

每轮隔离 `APPDATA`/`LOCALAPPDATA`，Godot 用户着色器缓存新建；进程内重开已暖。每次记录 OS 文件缓存“未清除、已读过源文件/导出”、驱动着色器缓存“共享且暖度未知”，不是完全冷启动。编译次数分别记录 `PipelineCompilationsSurface/Draw/Mesh/Specialization`，次数不代表耗时；`Mesh=0` 也不代表没有编译。原生编译未单独定时，现有证据不支持它主导节点二十多秒等待；若后续尾部编译明显，需专机分冷/热缓存测量，不能清同机共享缓存后当作所有轮次相同。

同机一直有 9081、9084、9085 编辑器及其他任务进程。B 在 17:45–18:10 UTC 预约窗口测量，机器仍非完全空闲。总 CPU 含游戏；“其他进程”由已列进程累计 CPU 差除以实测采样间隔和 16 核，原组只列 Godot/`dotnet`/`train`，C 重测改列全部可读取 CPU 计数的进程。访问不到或采样间新建/退出的进程、内核负载可能漏计。间隔约 2–3 秒；短任务的 p95 只来自少数系统样本，不能当高精度区间统计。CPU、可用物理内存和分页原始记录均保留。

### 点击→可见与可见→就绪的分解

从原始阶段起止剪裁两个信号区间，排序端点，以并集分配每个时间片一次：网格→索引→地形块其余→节点构建其余→线路地形其余→布局→转换上传→显示准备其余→提交→帧生成/轮询→入口→未归属。嵌套子阶段从父阶段扣除，后台依赖优先于重叠主线程轮询。这是可复核的关键等待区间分解；线路缺任务依赖 ID，不能当作完整因果图。GC 已在阶段墙钟中，不再加一遍。

由快照对象尺寸与源码结构得到的主要项估算为 `M ≈ 104N + 262,168C + 344F` B：96 B 格对象及 8 B 占格列表引用；每个 32³ 区块引用数组及头；每面四个 72 B 顶点和各 8 B 引用，加六个 4 B 索引。另加对象拾取身份、查找表、容器余量、内容、临时峰值与 Godot 资源。区块数必须按每个独立格组分配，不可把全城拼接后理论填满的区块数当实测。

薄地形占格随面积线性增长，表面近似随面积；实心体格成本随体积增长、外表面随体积的 2/3 次方；空壳与碎片建筑的 F/N 高得多，极端离散格 F/N 可到 6。沿长度、面积、体积放大 100 倍不是同一种“百倍”。保持与当前节点相同几何组成而同时复制 N/C/F，按当前全部托管对象基线线性复制 10/30/100 倍约 19/58/192 GiB（包含固定项），网格缓冲区约 6/19/62 GiB，仅为线性外推，不是成功承载。GC 压力、内存带宽与分页可让时间劣化，但四点不足以证明算法必然超线性。
