# Demo 内容与资产清单

本文列出完整 Demo 要制作的正式内容、测试用内容和美术资产，以及每一项的数量、规格和由谁制作。清单由[Demo 内容与资产清单：覆盖场景与制作验收](https://github.com/odradekk/train/issues/283)于 2026-10-10 与用户逐项确认。

本文只列内容，不重复规则：货物和生产链见 [11](../design/11-goods-and-production-network.md)，流程与设施见 [13](../design/13-production-runtime-and-facilities.md)，聚居地见 [16](../design/16-settlements.md)，战斗与生物见 [17](../design/17-combat.md)，市场见 [19](../design/19-markets-and-trading.md)，Demo 范围和验收见 [00](../design/00-product-and-core-loop.md#本阶段范围)。字段写法见本目录的各格式说明。

清单是制作计划，不表示内容已经存在。配方数量、工作量、价格等数值不在本文冻结，按[数值的初值与配平](#数值的初值与配平)给出并试玩后确认；首个切片的三种货物、两种小型车辆和两列车配置不再沿用。

## 占位资产的使用范围

| 阶段 | 是否允许占位 |
| --- | --- |
| 模块独立测试、契约测试、联调、正确性回归、核心长测 | 允许纯色占位图（[tools/make_placeholder_pngs.py](tools/make_placeholder_pngs.py)）；这些检查不看画面 |
| 早期阶段的人工功能试玩 | 允许占位美术，只确认流程与交互；阶段票须提前注明范围，不能据此通过美术、正式性能或完整窗口长测 |
| 正式性能测量、完整窗口长测 | 必须用正式资产：贴图、模型面数和特效数量都影响帧耗时，用占位资产测得的结果不算数 |
| 美术检查、完整 Demo 人工验收 | 玩家能看到的全部内容必须是正式资产 |

早期功能试玩的例外由[阶段性交付流程](https://github.com/odradekk/train/issues/293) Q6 确认；它只收窄原来所有人工验收都要求正式资产的限制。正式资产没有完成时，依赖它的检查保持“待验收”。

正式美术按[工单重组](https://github.com/odradekk/train/issues/294) Q3 于 2026-10-11 确认的顺序交付：第一阶段验证基础场景和小型列车样稿，第三阶段验证三台样机、模型与涂装，第五阶段验证战斗视觉样稿；第六阶段分批补齐全部正式资产并验收。各阶段功能试玩仍可使用其余占位资产，样稿通过不等于全目录美术或正式性能通过。

## 货物

| 货物 | 作用 | 配方骨架 | 回收产出 | 设施兼容标签 |
| --- | --- | --- | --- | --- |
| 转向架 | 表现行为 `wheelset`：渲染器在这里生成轮对 | 结构金属 + 机械部件 | 结构金属 + 机械部件 | `assembly` |

## 默认开局

- **起始车队**：2 列小型列车。列车 A 是 1 台机车加 3 辆货车；列车 B 是 1 台机车、2 辆货车加 1 辆武装车。
- **起始资金**：数值由配平脚本确定。判断条件是两列车各满载采购一次后，还够委托建造 1 辆小型货车。
- **起点**：一个有站点的非敌对聚居地；经已建成的铁路至少能到达 2 个非敌对聚居地和 1 个空节点；相邻节点没有生物聚落。
- 这些条件由默认生成配置检查，不满足时按 [05](../design/05-world-graph-and-generation.md#世界生成流程)重试或明确失败。

## NPC 的初始库存与现车

初始库存不按模板逐项手写，由生成配置按规则计算：

- 输入原料和生活物资补到各自的[补货目标](../design/19-markets-and-trading.md)；
- 产出物预存若干小时的潜在产量，小时数是生成配置的参数；
- 模板的 `inventory` 只用于少量特殊货物。

现车：有车辆车间的 NPC 聚居地生成 1–2 辆满耐久的预置车辆，档位不超过车间的上限。收购名额按档位计（[19](../design/19-markets-and-trading.md#现车交易与估值)），每个档位 3 个。

这些新增的生成输入的格式由[内容层公开契约](https://github.com/odradekk/train/issues/288)确定。

## 数值的初值与配平

配方数量、`work_required`、功率、劳动力、施工规则、人口规则、市场规则、生成配置和起始资金，都由内容层工作线给出第一版。文档中的算例不作默认值。

仓库中放一个配平脚本，检查：

- 各条生产链的产量和消耗能否接上；
- 价值与成本是否大致一致；
- 默认开局能否起步：用给定的起始资金和车队，按一套固定的脚本贸易策略推进若干游戏小时，现金流必须为正。

核心测试只检查规则和不变量，不检查具体数值。数值试玩后调整，冻结前由用户确认。

## 制作途径与分工

编辑器完成之前，蓝图、场景模型和聚居地模板由脚本按参数生成，先供各模块联调和测量；编辑器可用后，在创作模式中修整正式外观，美术验收以修整后的版本为准。

| 工作 | 负责方 |
| --- | --- |
| 内容格式、加载与校验；正式内容数据（定义、流程、规则、生成配置）；蓝图与模板的生成脚本；配平脚本 | 内容层工作线 |
| 分支存档和标准世界的脚本配方（通过核心命令）；开局可起步检查 | 核心工作线 |
| 地形、桥梁、隧道口在场景中的构建；专项样例的场景构建测量 | 体素引擎工作线 |
| 资产导入；美术检查流程（三种距离、三种检查光照）；性能测量工具 | Godot 工作线 |
| 贴图、图标、模型、特效等美术资产的制作 | 单独的制作任务，不属于代码模块；制作方式由开发者决定 |
| 正式性能测量、完整窗口长测、人工验收 | 按阶段要求安排的联调验收任务；完整 Demo 的全量验收仍须覆盖全部要求 |
