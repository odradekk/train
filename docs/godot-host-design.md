# Godot 宿主内部接入方案

本页记录当前宿主实现方向，不是下层公开契约或已完成实现。模块端口与消费义务见[Godot 契约](contracts/godot.md)。产品行为仍由设计文档规定。

## 协调线程与帧驱动

协调线程采用 Godot 主线程，沿用当前 App 的串行接入方式。核心写入口、内容候选激活、体素会话入口、活动组切换及 UI 状态更新都在这里完成。禁止在模块调用中重入宿主操作；通知回调只更新表现，不在分发过程中递归提交命令。

主线程按完整边界处理一帧：

1. 接入后台完成结果，逐个核对操作身份、运行会话和基准；取消或失配结果只清理。准备完成不等于允许提交，技术锁和最终裁决仍遵循跨层协议。
2. 按收到的顺序处理用户应用操作；命令立即在当前完整边界裁决，完成相应的内容激活或聚居地副本配对后，再分发结果携带的新事件。技术锁期间明确返回忙，不把修改隐式排队到解锁后执行。
3. 按真实帧间隔、当前倍速和不足一步的余量算本帧额度。每次调用 `Advance(1)`，处理结果和通知策略后才决定下一步。事件要求暂停或降速时，不继续使用旧倍速的剩余额度；故障立即停止驱动。预算只在完整步之间判断，不能中断半步。
4. 每个成功的命令／步边界，把固定核心读视图、配对内容和本次新事件交给活动体素会话 `Observe`。地图及所有面板在本次 UI 刷新中共用最后一份读视图，不能各自读取不同步；不为画地图复制核心计算。
5. 未最小化时取得场景帧，准备资源并完整接入；相机和拾取使用实际显示帧。最小化仍处理输入、后台完成、模拟、通知和自动保存调度，只停止渲染及相应显示提交。恢复后从当前状态继续，不补演错过的短时效果。

60 Hz、倍速、掉帧不追赶以及实际速度显示以[时钟规则](design/04-deterministic-simulation.md#时钟与倍速)为准。使用单调时间测工作预算与实际速度；保存日期使用真实日期。测试可向宿主注入帧间隔和计时来源，核心与内容不新增时钟、调度或回调接口。每帧预算及平滑统计窗口由 Profiling 决定；现有 App 的 5 ms 是旧实现暂定值，不是本契约承诺。

暂停的来源分别保留：玩家／通知、失焦、编辑、技术操作锁及核心冻结。玩家继续可解除玩家和通知暂停，不能绕过其他阻止原因；重新聚焦只解除失焦暂停。通知暂停优先于同一步的降速，降速不解除暂停。编辑结束与技术操作结束按各自协议恢复设置，不能清除期间仍有效的其他暂停原因；新局／普通读档仍以暂停开始。暂停时固定世界表现的插值，UI 和相机照常响应。

后台只处理不可变输入：内容准备、核心候选准备、编码和文件写入可由宿主调度；活动会话不交给后台修改。体素自己管理构建与取消，宿主不接管区块队列。主线程不通过 `.Wait()`／`.Result` 等待后台工作。


## Godot API 调度

初始接入方案把 Godot 文件及解码 API 操作串行放在主线程：后台内容加载经宿主端口发送这类调用并等待结果，主线程继续泵送这些请求，不同步等待加载任务。纯本地文件 I/O、哈希和纯 .NET 准备可留在后台。取消后仍保证已经开始的端口调用结束，结果失去发布资格并释放临时 Godot 对象，不强行终止线程。若以后证明某种 API 在所用 Godot 版本的单工作线程上安全，可在宿主内部调整；不改变同步端口和不重入承诺。

这项安排不承诺每次解码都在一帧预算内。大资产解码、首次导入、候选缓存和取消延迟必须测量；不能靠假设所有 Godot API 都线程安全来宣称无卡顿。官方[线程安全说明](https://docs.godotengine.org/en/4.7/tutorials/performance/thread_safe_apis.html)也区分场景树、资源与 GPU 操作；本票尚未提供逐 API 的真实线程验证。


## 市场界面

市场显示核心返回的报价、可交易量、限制及现车损伤，标注报价不锁定。手动提交数量及整单最大付款／最低收款，自动规则提交逐件限价与显式顺序；不在 Godot 重算边际价格、需求、容量或部分成交。执行拒绝后保留用户输入、刷新当前报价并显示原因，不在新价格上悄悄重试；自有留货风险明确展示。自动执行的未完成原因和净现金流报告读取核心记录，不能拿通知历史重建经营账目。业务规则见[市场与交易](design/19-markets-and-trading.md)。


## 保存路径与容器

路径及格式沿用[存档设计](design/09-persistence.md#文件身份与写入)：`user://saves/<UUID>/save.json`，单 JSON、头部先写，当前格式从版本 6 开始；自动存档为每局 3 个独立轮换位置。头部摘要从同一捕获边界取得。核心及内容各自 `Encode`／`Decode`，宿主只组合容器、头部和公开引用，不把字符串重新解释为业务字段；外层字段编码在实现时落实并与存档版本一起管理，不影响模块载荷归属。


外部草稿写入 `user://authoring-drafts/`，用户蓝图按 `RequiredWrites` 写入 `user://content-library/`；内置内容根映射到 `res://builtin/core`。这些路径由宿主管理，不成为下层模块的文件系统假设。

### 当前存档接入

新契约宿主的 `HostCoordinator` 固定活动组的核心和内容捕获，持有运行绑定、存档 UUID、名称及已保存修订基准；名称是当前唯一的宿主持久元数据。`App/Saves/SaveService` 负责后台写盘、读档和导入的候选流程、列表、离开保护、自动保存计时与轮换。`SaveContainer` 用格式 6 单 JSON 组合先写的 `Header` 和两个不透明字符串载荷；头部的位置是两个数字，包列表是包 ID 与版本，均使用容器自己的类型，模块契约形状不直接进入外层格式。容器和文件代码只依赖 BCL，可由命令行工具直接链接。资金和世界来源当前没有可用的公开查询，因此头部不写这两项，也不读取模块内部载荷补齐。

列表只读取头部。手动位置是 `save.json`，自动位置是同目录的 `autosave-0.json` 至 `autosave-2.json`；自动保存和导出都不改变手动目标或已保存修订。导入先校验独立恢复候选，确认固定缺失清单后丢弃候选，只换外层 UUID，保留两份模块载荷；不激活导入世界。读取自动位置则保留该局 UUID，并把手动保存状态标为未保存。

`SaveService.SetAutoSaveInterval` 接收真实时间间隔，`null` 关闭自动保存。本票不提供设置页或设置持久化；五分钟是待测量及用户确认的暂定默认值。间隔到期时最多合并一个所属运行绑定的请求，空闲后才捕获最新边界，离开绑定后作废。

App 只有在新契约宿主存在时才显示存档入口。当前默认启动仍走旧入口；真实工厂接入和完整 Godot 隔离归 #424，真实四模块往返和阶段试玩归 #298。装配在构造宿主时提供当前运行的 `CoreSessionOptions`，返回菜单后仍可读档，不从存档头部推测运行环境。

### 当前录制与报告问题接入

新契约宿主在所有构建中挂接 `App/Recording/RecordingService`。`HostCoordinator` 按活动组保留内容视图的产生顺序，包括同一核心输入身份的多个持久修订、实例模板副本，以及已受理但拒绝或故障的发布目标。核心反馈 `ReleasedInputs` 后，宿主释放其中非当前活动视图的历史引用；已返回的内容捕获自行持有其历史，不依赖宿主继续保留。后台编码和写盘只使用固定捕获，不读取安装目录补历史。

初始起点和周期起点各写一个自包含窗口 ZIP，普通位置固定为 `user://recordings/snapshot.zip`；只有起点与全部依赖写入、读回比较并发布成功后，协调线程才确认该起点可裁剪。写入失败确认 `Failed`，保留旧文件与核心缺口。已有未确认的写入时不捕获新起点，活动会话的每个起点只确认一次。换局时立即释放旧核心；已捕获的普通写入和已排队的故障窗口继续完成文件，迟到结果不确认旧核心，也不能接入新局。

起点间隔暂取 18,000 个已完成模拟步（1× 下 5 分钟）。保留数量使用创建会话时明确传入的 `CoreSessionOptions.RetainedRecordingStarts`，测量候选为 3；数值仍待用户阶段试玩确认。命令不会触发写盘，进程崩溃后不承诺恢复上次起点写入之后的内存命令。

内部故障自动把故障边界的当前窗口写入独立的 `fault-<运行绑定>-<唯一标识>.zip`，普通起点替换和换局不删除这些文件。正常退出等待已开始的写入及故障队列完成；强制移除 App 时取消未完成工作、保留已发布文件，不阻塞引擎线程，也不把丢失的写盘结果当作成功。

“报告问题”从当前内存窗口捕获，冻结后仍可使用。面板显示完整状态、模拟范围、缺口和证据目录，使用原生保存对话框选择 ZIP；覆盖目标需要确认。没有容量占用显示或网络上传。#320 设置菜单合入前，入口按存档按钮方式配置在 MainMenu，仅在新宿主存在时显示；同步主线时移入设置菜单。

ZIP 外层格式为 1，包含 `manifest.json`、完整回执的 `commands.jsonl`、不透明的内容复现载荷 `content.payload`，以及各故障片段的命令 JSONL。清单保存全部起点公开信息及核心编码载荷、截止位置、检查点、缺口、引用和实际会话运行环境。读回解码后比较全部写入值；模块载荷继续由各模块编码，不在宿主解析业务状态。单文件候选、校验、发布和清理与存档共用 `FileSaveStore.Write`。

宿主协调测试用明确情景的核心和内容替身，文件测试使用真实 I/O，报告面板使用真实 Godot 验证；这些证据不替代 #424 的完整 Godot 隔离或 #298 的真实模块联调。本票不改变导出装配，以 Debug、Release、ExportDebug、ExportRelease 编译检查构建配置覆盖。

### 当前开发检查工具

Debug App 在新契约宿主存在时挂接 `DeveloperTools` 和独立 `DeveloperInspector` 窗口，通过 [`dev`](console/dev.md) 打开。它在普通会话中按完整边界执行单步、指定步数和条件运行，使用暂定 5 ms 帧预算。条件只观察启用后的新事件或回执；对象条件保存稳定身份，失效时停止。最大步数、条件、通知暂停和冻结同时发生时保留全部原因，冻结优先显示。取消及换局清除运行条件，不继续推进。

对象检查只读公开固定视图；命令检查显示录制范围、缺口、规范负载及完整回执。检查点和说明标记只存于本进程，换局保留。检查点比较按模拟位置、世界种子、运行环境、核心输入身份依次判断；前置元数据不兼容时不调用核心比较，兼容时才显示核心返回的一致或首个字段差异。`sim checkpoint` 接入同一内存列表。

复现包通过唯一的 `RecordingPackage.Read` 严格读取 ZIP、UTF-8、清单和 JSONL；宿主不解析核心或内容不透明载荷。重放优先选择清单中的第一个故障片段；否则选择能连续无缺口到达截止位置的最早录制起点。后台准备使用包中内容历史，接入时核对操作身份、运行绑定和内容基准，失败或取消保留原组。重放只按录制推进，拒绝新命令和内容重载；导出当前完整边界得到新 UUID 的普通存档，只有再次普通读档才恢复普通会话的修改入口。

场景页通过 Scenes 的调试线与命中契约观察区块、线路段、原点、拾取射线和中心线，重新生成只重建场景。此入口不证明 Scenes 已生成全部调试线。性能页显示 Godot 进程帧耗时、静态内存、对象数、请求及实际模拟速度与调试线数；模拟耗时、录制容量尚未采集。开发检查工具不宣告生产默认工厂接线、完整 Godot 隔离或阶段验收完成，#424 与 #298 的后续范围保持有效。
