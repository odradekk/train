# Separate module contracts and limit implementation access to composition

2026-10-09 经[四模块的依赖、公开类型归属与契约变更规则](https://github.com/odradekk/train/issues/279)的 Q1–Q13 确认：核心、内容、体素各有独立契约程序集，实现之间只依赖公开契约；Godot 在明确的装配入口创建真实实现。这样才能在其他模块未实现时独立构建与测试，而不只是约定调用方不读内部代码。

项目布局、依赖允许范围、类型归属和跨层职责统一写在[契约索引](../contracts/README.md)，数据所有权、错误、文档权威范围和基线变更见[公共约定](../contracts/conventions.md)。这些是目标规范，生产代码尚未迁移。

## Considered Options

- **实现项目之间继续引用，仅依赖其 public 方法**：消费方构建仍依赖对方实现项目，不能验证删除其他实现后的隔离性；现有 public 类型也会被误当成稳定契约。
- **一个通用 Common 或统一契约程序集**：会把无关类型聚到一起，使核心在编译时看见布局与表现数据，并模糊类型的唯一所有者。
- **四模块各有一个对称的契约程序集**：Godot 是装配与适配宿主，下层所需接口由下层自己定义，无须为对称再建一个 Godot 契约项目。

选择三个模块自有契约项目，接受额外项目和依赖检查的维护成本。实现默认隐藏，只公开少量返回契约接口的创建工厂；Godot 仅 `App/Composition/` 使用真实工厂，其他代码接收接口。暂不引入依赖注入容器或反射装配框架。

## Consequences

- 保留 ADR-0008 的核心权威和场景只作表现，以及 ADR-0011 的按读取方投影。类型声明的所有者不等于计算者：设计属性供核心接收，设计计算和布局遍历仍由内容实现。
- 取代 ADR-0009、ADR-0011 的实现项目相互引用及日志、控制台归核心的安排。诊断日志输出与控制台文本分发改归 Godot 宿主，核心仍拥有命令记录、稳定故障和确定性重放。
- 确定 ADR-0011 留待接口设计的完整存档组装责任：宿主组合核心状态与内容载荷，并组织复现包及会话切换；不读取模块内部结构或复制业务规则。跨层事务协议由下述修订补齐。
- 不承诺保留现有全部 public 入口。契约需要公开可用的值与替身构造方式，不能通过反射、友元访问或引用对方源码测试跨模块调用。
- 契约变更由用户确认，整组基线绑定明确提交；存档、内容和命令格式继续独立管理版本。文档、声明和测试冲突时不能建立新基线。
- 本决定不代表独立构建、自动依赖检查或四模块接口已完成；契约原型和后续实施分别提供验证证据，旧实施票仍等待地图完成后的重组。

## 跨层协调修订

2026-10-10，[存档、内容发布与会话切换的跨层事务](https://github.com/odradekk/train/issues/284)确定[跨层协议](../contracts/transactions.md)：宿主协调候选和活动绑定，核心及内容通过自己的公开操作承担捕获、引用声明、适配与记录，不把内部数据遍历交给宿主。运行会话身份与存档 UUID 分离，旧异步结果不能重新绑定新局。

采用准备完整候选、统一切换、事后通知及资源退役，放弃逐模块发布与补偿回滚。Demo 接受读档和热重载期间短暂停止驱动的代价，以保持发布边界明确；普通保存只在捕获时锁定，场景构建不阻塞核心。具体签名和独立验证仍由模块接口及原型交付，不因此建立契约基线或宣称产品实现完成。
