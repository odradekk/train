# Give each composite instance its own design and keep blueprints as templates

2026-10-09 经[实例与蓝图：实例保存自己的设计，模板的存放与改装目标](https://github.com/odradekk/train/issues/260)确认，属于地图[内容定义标准：体素、复合体与聚居地模板的格式和样例](https://github.com/odradekk/train/issues/256)。

每个复合体实例有自己的**设计**：
- 设计是实例当前的构成，包括体素布局、其中的复合体、涂装、蓝图类别和尺寸。
- 设计不可变，以设计哈希识别。设计哈希是对设计全部内容的规范化编码计算的 SHA-256。

**蓝图**只是创建复合体的模板：
- 建造、购买或世界生成时，从蓝图复制一份设计给实例，之后实例和蓝图不再有关系。
- 改装把实例换成另一份设计；修理把实例恢复到它自己的设计。
- 蓝图不分版本，修改时直接覆盖。已建成的对象不受影响。

蓝图存放在三处：
- **内容包**：内置包和 Mod，只读，身份是 `命名空间:local id`。
- **本局蓝图库**：存在当前存档里。
- **用户内容库**：全局，所有存档共用。

玩家蓝图的身份用 UUID。在库与库之间复制，得到一份独立的新蓝图。

保存为蓝图要求通过建造合法性检查，所以每份蓝图都能直接建造。

**编辑一个实例**时，以它当前的设计为起点建立改装草稿：
- 改装草稿存在存档里，与这个实例绑定，可以不合法。
- 草稿通过检查后可以提交改装，成为目标设计。完工时实例换成目标设计。
- 草稿或实例的设计随时可以保存为蓝图。

**只改涂装**时立即生效，不需要改装任务，也不消耗货物：
- 核心模拟层用一条命令把实例换成一份只有涂装不同的设计。
- 内容层负责检查两份设计只有涂装不同。

我们放弃了：
- **实例引用固定的蓝图版本**（ADR-0005 的核心存档修订、设计文档 03）。这种做法需要保留每份蓝图的全部版本，并把被引用的版本嵌入存档。每次编辑都要先产生一个新的蓝图版本，玩家并不想要这么多版本。
- **实例跟随蓝图的最新内容**。修改蓝图会让已建成的对象凭空改变，绕过了改装的成本和工期。

## Consequences

- **对 ADR-0005 的影响**：本决定取代 ADR-0005 中实例引用蓝图版本的部分，以及用户内容库保留全部版本、存档内嵌蓝图版本的部分。ADR-0005 的其余原则不变：外部定义按当前安装的内容解析，语义、资产和目录三种版本分开。设计中的体素定义仍解析为当前定义，设计属性随之重算。
- **存档**：
  - 存档的内嵌内容包括：实例、进行中任务的目标设计、委托和改装草稿用到的全部设计，相同内容只存一份；本局蓝图库；已有聚居地使用的聚居地模板。
  - 内容包和用户内容库中的蓝图不嵌入存档，所以随时可以删除。
- **命令**：
  - 建造、改装、改涂装命令都引用一份设计。录制和复现包带上被引用的设计。
  - 保存或删除蓝图不是命令，因为它不改变任何实例。
- **破损顺序**：场景中结构破损的顺序改由实例身份和设计派生。
- **范围**：单格的对象（货物、场景体素）没有设计。复合体嵌套时设计怎样包含其中的复合体，由[复合体嵌套](https://github.com/odradekk/train/issues/249)决定。
