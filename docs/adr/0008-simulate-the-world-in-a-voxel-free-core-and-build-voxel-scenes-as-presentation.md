# Simulate the world in a voxel-free core and build voxel scenes as presentation

2026-10-05 经[分层架构与局部场景的权威边界](https://github.com/odradekk/train/issues/198)确认，属于地图[体素引擎改作局部场景：设计文档与 open issue 全面修订](https://github.com/odradekk/train/issues/193)。

全部游戏状态归核心模拟层。核心模拟层在抽象世界图上，以同一精度模拟整个世界，包括节点、线路与铁轨、聚居地、列车、经济、战斗、世界生物、时钟和命令。它不涉及体素，也不依赖 Godot。体素引擎只在玩家进入某个地点时构建局部场景（线路场景或节点场景），或构建设计编辑器。场景只表现核心状态，不保存状态，也不影响任何结果。

我们放弃了两种做法：

- 以完整体素世界为模拟核心（全图常驻、全精度实时模拟，转录 Q5）。经营、建设和战斗玩法都不依赖完整的体素世界，而模拟和渲染整个体素世界的成本过高。
- 玩家打开战斗场景后由场景决定结果。玩家不操控单位，让"观看"改变结果只会带来确定性、存档和结算校准上的代价，没有收益。

## Consequences

- **依赖方向与接口**：依赖方向是渲染层 → 体素引擎层 → 核心模拟层，下层不知道上层的存在。每层只通过窄接口对外，并隐藏内部实现：
  - 核心模拟层对外提供命令入口、按地点或对象的只读查询，以及供表现使用的领域事件。它隐藏自己的数据结构，以及调度、战斗等算法。
  - 体素引擎层对外提供：为某个地点构建、更新、销毁场景；拾取，即把点击位置映射回核心对象的身份；交给渲染层的场景数据。它隐藏体素存储、生成算法和网格构建。
  - 渲染层（Godot）负责渲染、相机、输入和界面，不向下层提供接口。宏观地图和管理界面通过核心模拟层的只读查询读取数据，不经过体素引擎层。具体接口在代码重构时设计；项目划分、依赖方向和核心层的线程见 [ADR-0009](0009-split-the-code-into-godot-free-core-and-scene-libraries-and-rewrite-the-core.md)。
- **命令与战斗**：玩家在任何界面或场景中的操作，都作为命令提交给核心模拟层。战斗由核心模拟层结算；玩家在战斗中下的少量指令也是普通命令。场景里的体素破坏只表现核心状态中已经存在的损伤，所以核心战斗模型必须给出细到部件的单位状态和战斗事件。
- **场景的生成与更新**：
  - 场景只由三样输入生成：该地点的核心状态快照、内容定义，以及由 WorldSeed 和地点身份派生的无状态随机键。因此同一地点每次生成的结果相同。
  - 场景随核心状态更新。列车位置在相邻两个模拟步之间插值，最多延迟一步，不外推；这沿用了 ADR-0007 的显示插值规则。
  - 弹坑、碎片只存在于场景中；持久损伤以核心状态为准。
  - 同一时间只显示一个场景。跟随列车时，最多在后台预建一个下一场景，使切换无缝；这一修订由[实施工单的拆分、顺序与写法](https://github.com/odradekk/train/issues/217)于 2026-10-06 确认，原文为“同一时间只构建一个场景”。
- **与观察无关**：模拟结果与帧率、相机、窗口状态无关，也与场景是否打开、打开的是哪一个无关。核心模拟层不按距离、视野或观察情况降低精度。战斗进行时世界不暂停。
- **确定性、复现与存档**：ADR-0003 的确定性契约只覆盖核心模拟层。场景可以使用 Godot 物理等不确定的表现手段。录制和故障复现包只包含核心模拟层的输入。存档只保存核心状态，场景打开时也可以存档。
- **内容**：体素定义、蓝图等内容是核心模拟层和体素引擎层共用的只读数据。核心模拟层只读取由设计派生出的属性。2026-10-09 起改为：内容层把每份定义按读取方拆开，分别交给各层，核心模拟层只得到 `simulation` 一节和设计属性，见 [ADR-0011](0011-move-the-content-layer-into-its-own-project-and-split-definitions-by-reader.md)。
- **对其他 ADR 的影响**：
  - 本决定取代 [ADR-0004](0004-keep-the-world-model-as-the-single-source-of-truth-and-treat-godot-as-a-derived-adapter.md) 中关于游戏状态范围的描述（体素、Composite、铁路网络都是游戏状态）。ADR-0004 中"领域不依赖 Godot，Godot 是派生适配层"的结论仍然有效。
  - [ADR-0006](0006-preserve-physical-rail-geometry-and-local-breaks.md) 和 [ADR-0007](0007-drive-connected-assemblies-from-physical-rail-positions.md) 以物理轨道作为铁路的事实来源，将由[列车在图上的运行与调度](https://github.com/odradekk/train/issues/203)取代。
