# Nest composites by copying designs and treat storable composites as goods

2026-10-09 经[复合体嵌套：大型设备装到车辆和建筑上](https://github.com/odradekk/train/issues/249)确认，属于地图[内容定义标准：体素、复合体与聚居地模板的格式和样例](https://github.com/odradekk/train/issues/256)。

**嵌套**：复合体可以包含复合体。宿主的设计为每个被嵌套的复合体记录三样东西：
- 放置位置：宿主网格中的整数格；
- 朝向：24 种正交方向之一；
- 它自己的一份设计，从蓝图复制而来。

蓝图之间没有引用，修改设备蓝图不影响任何宿主。复制品不可能包含自己，所以不会出现循环。内容加载时最多允许 4 层嵌套，这个上限是可以调整的内容常量。

允许的组合：
- 车辆、建筑、大型设备里可以装大型设备；
- 场景模型里可以装场景模型；
- 生物暂时不能装任何东西。

被嵌套的复合体：
- 不能和宿主的体素或其他被嵌套的复合体重叠；
- 计入宿主的尺寸包络；
- 至少有一面贴着宿主的体素。

设备蓝图可以声明一个转动：
- 声明的内容：绕自身的哪根轴、转轴经过哪一格、角度范围。
- 内容层算出转动时扫过的格。安装时这些格必须是空的，并且在宿主的包络之内。
- 转动只属于表现。

**核心模拟层**里，被嵌套的复合体不是单独的对象：
- 它的部件就是宿主的部件，结构体素并入宿主的结构耐久；
- 质量、能力、BOM 和工作量都计入宿主的设计属性；
- 部件编号连续排列：先排宿主自己的体素，按坐标排序；再按放置位置的顺序排各个被嵌套的复合体，每个复合体内部也按同样的规则排。

**货物**：货物是能入库、运输和交易的东西，有两种：
- 带 `simulation` 一节的体素定义；
- 能入库的复合体。

哪些复合体能入库，由蓝图类别决定：大型设备能；车辆、建筑、场景模型、生物不能。车辆和建筑能整体买卖，但不入库，不是货物。

复合体货物的规则：
- 在库存里按设计计数。入库时去掉涂装，并且总是完好的：整体拆下时先修好，修理计入这次任务。
- 基本货币价值等于其中全部体素的 Value 之和。
- 宿主的 BOM 列出整件设备，不展开成其中的体素。
- 设备来源有三种：在建造设施里按蓝图建造，完工后入库；从宿主上拆下；从市场买。
- 装上、拆下、更换设备都算宿主的改装。

我们放弃了：
- **宿主蓝图引用设备蓝图的身份**：会让蓝图之间互相依赖，需要处理循环和更新传播，而实例已经各自拥有设计。
- **设备在核心里作为独立对象，有自己的身份和耐久**：核心要多维护一层所属关系和损伤分配。玩法上需要的整体转动、整体替换都只在设计和场景里发生。
- **只有体素是货物**（ADR-0001 的“每种货物都是一个体素定义”）：武器和大型设备按常识应该能入库和交易。
- **宿主的 BOM 展开成设备里的体素**：违反“建造只消费做好的货物，不自动展开配方”。

## Consequences

- **对 ADR-0001 的影响**：本决定修订 ADR-0001 中“每种货物都是一个体素定义”一条。货物种类可以是体素定义，也可以是去掉涂装的复合体设计。体素定义的命名空间身份规则不变。
- **库存**：库存仍只按种类和数量计数，种类是体素定义标识或设计哈希；库存里没有受损或带状态的件。
- **场景**：被嵌套的复合体在场景里是宿主的子对象，有自己的根变换，转动只改这个根变换。拾取命中设备里的某一格时，体素引擎层先换算成宿主的部件编号，再交给核心。
- **修订**：2026-10-09，[ADR-0014](0014-use-code-provided-behavior-types-and-sealed-functional-composites.md) 引入功能复合体：上文“它的部件就是宿主的部件”只适用于组装体，功能复合体整件是宿主的一个部件。
- **之后再定的部分**：市场怎样收卖设备、价格怎样计算，以及车辆和建筑整体买卖的规则，由贸易和聚居地的设计确定。
