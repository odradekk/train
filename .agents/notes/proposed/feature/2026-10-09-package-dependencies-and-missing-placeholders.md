# Declare package dependencies and keep missing content as placeholders

Status: proposed

## Problem

需要确定内容定义怎样分文件、内容包之间怎样声明依赖、缺依赖时怎样处理，以及读档时内容缺失怎样处理。

## Proposal

2026-10-09 经[内容包与依赖：内容定义的文件组成、依赖声明、缺依赖处理与热插拔](https://github.com/odradekk/train/issues/262)确认，属于地图[内容定义标准：体素、复合体与聚居地模板的格式和样例](https://github.com/odradekk/train/issues/256)。

**文件组成**：一个文件只写一份内容定义，文件名是 `<local id>.<种类>.json`。它的资产放在同名文件夹里。文件按种类分目录：`voxels/`、`blueprints/`、`settlement-types/`、`settlement-templates/`、`markets/`。加入或移除一份定义，就是加入或删除一个文件和它的文件夹。几份同类定义共用的资产放在该种类目录的 `shared/` 文件夹里，所以 `shared` 不能用作 local id。

**内容包**是发布、启用和依赖的单位，有命名空间和版本：
- 内置的 `core` 也是一个包，版本就是游戏版本；
- 内容定义是引用和热重载的单位，属于且只属于一个包。

**依赖**：
- 依赖写在 manifest 里，以包为单位，每条依赖写包的 UUID 和最低版本。`core` 默认依赖。
- 定义本身不声明依赖。内容层按引用的命名空间检查：引用了其他包的定义，那个包必须写在依赖里。
- 加载按依赖排序；处在依赖循环里的包都不加载。
- 缺依赖、依赖版本太低，或者包内任何定义有错，整个包都不加载，依赖它的包也跟着不加载。
- 仍然不允许覆盖或修改其他包的定义。

**库里的蓝图**：本局蓝图库和用户内容库的蓝图记下保存时用到的包，包括 UUID、名称和版本，只用于显示。缺了依赖的蓝图显示为不可用，列出缺了哪些包；不删除，也不能建造。

**读档时缺内容**：读档前列出缺失的包和定义，由玩家选择取消或继续。继续时：
- 缺失的东西用占位代替，并保留原来的标识；
- 设计里缺失的体素变成占位体素：算结构，没有质量、价值和能力；
- 库存里缺失的货物保留为缺失货物，不能使用，也不能交易；
- 其他缺失的定义同样保留标识，功能失效；
- 存档时写回原来的标识，装回包以后再读档，就恢复原样。

**热重载**（Debug 构建）：
- 加入的定义立即可用。
- 更新按当前定义规则生效。
- 移除一份定义时，运行中的世界必须已经不再引用它，否则这次重载被拒绝，并列出还有哪些地方在引用。
- 占位只在读档时使用。

玩家构建在主菜单里启用或停用 Mod，下次读档时生效。

### 对其他决策的影响

- **对 `2026-08-27-limit-mods-to-data-packages` 的影响**：加入包级依赖和最低版本，按依赖顺序加载。其余原则不变：Mod 只是数据，不能覆盖其他包，无效的包整包隔离。
- **对 `2026-09-05-resolve-current-definitions-separate-versions` 的影响**：“读档缺失必需定义就失败”改为由玩家选择，并用占位保留原始标识。热重载缺失仍然整轮拒绝。

### 修订

- **修订**：2026-10-09，[功能复合体的来源、缺失内容的状态、结构耐久下限与嵌套排序](https://github.com/odradekk/train/issues/269)规定占位保留存档里的实例状态原样，不删除也不改写按部件编号记录的部件。缺失的体素和功能复合体没有能力、质量、价值，也不贡献结构，不受伤害。这取代上文“缺失的体素变成占位体素：算结构”。内容更新使上限变小时，不改写存档里的耐久，计算时取存档值和上限中较小的一个。定义缺失的格子不能改装或修理。装回包以后，一切恢复原样。
- **修订**：2026-10-09，按标识引用的功能复合体缺失时，和体素一样变成占位。

### 跨层确认与已有占位的修订

2026-10-10，[存档、内容发布与会话切换的跨层事务](https://github.com/odradekk/train/issues/284)明确：占位的授权仍来自普通读档，但后续热重载允许原样保留或部分恢复已有占位，不要求一次补齐全部缺失。这细化了上文“占位只在读档时使用”和“热重载缺失整轮拒绝”：热重载不能新增原有效运行引用的缺失，也不能借已有占位创建非法运行状态；候选包自身仍须自洽。

读档确认绑定具体候选和缺失清单，候选固定所用定义与资产字节；重新扫描不能继承对新缺失的许可。拒绝保留旧业务状态和内容世代，不抹去已进入核心的拒绝记录；核心故障仍冻结，独立读档候选失败不冻结旧局。协调时序与失败分类只在[跨层协议](../../../../docs/contracts/transactions.md)维护。

## Alternatives considered

**按单个定义隔离错误**：包内的错是作者的错，整包失效更容易发现，规则也更简单。

**读档缺内容直接失败**（`2026-09-05-resolve-current-definitions-separate-versions`）：玩家卸载一个 Mod 后，存档就完全打不开。

**静默删除缺失的内容**：数据永久丢失，装回 Mod 也找不回来。

**存档或蓝图内嵌外部定义的旧副本**：会和“外部定义按当前安装的内容解析”冲突。

## Acceptance criteria

每份内容定义是一个 `<local id>.<种类>.json` 文件；manifest 用 UUID 和最低版本声明依赖，缺依赖或含错误定义的包及依赖它的包整包不加载。读档缺内容时玩家可以选择继续，缺失部分用保留原标识的占位代替，存档写回原标识。

## Risks

- **之后再定的部分**：定义改名用的迁移表放到 Demo 之后，在那之前改名按缺失处理。
- **格式**：一个文件多份定义的旧格式（`.voxels.json` 等）由实施工单改成每个文件一份定义。
