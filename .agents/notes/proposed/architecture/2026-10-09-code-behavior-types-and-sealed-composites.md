# Use code-provided behavior types and sealed functional composites

Status: proposed

## Problem

需要确定行为由谁定义、参数怎样按层拆分、内容能否自带脚本，以及多格的大型设备怎样提供能力。

## Proposal

2026-10-09 经[行为模型：行为类型、参数、按层拆分与脚本](https://github.com/odradekk/train/issues/261)确认，属于地图[内容定义标准：体素、复合体与聚居地模板的格式和样例](https://github.com/odradekk/train/issues/256)。

**行为是数据**，声明一个对象提供什么能力、参数是多少，本身不运行：
- 核心模拟层的各个系统，例如铁路、贸易、战斗、生产，读取汇总后的能力来运行；
- 场景按表现参数播放动作。

一辆车能做什么，就是它所有部件的能力汇总。

**行为类型由游戏代码提供**：
- 内容只声明用哪种类型、填哪些参数，类型标识是不带命名空间的字符串，例如 `propulsion`。
- 每种类型自己规定：是否功能性、核心参数和表现参数各有哪些、能力在一份设计里怎样汇总（数值相加、只看有无，或像武器那样逐个列出）。
- 核心参数写在 `simulation` 一节，表现参数写在 `appearance` 一节，按类型对应；一种行为可以只有一边。
- 类型按功能命名，所有武器共用 `weapon`，生物的攻击也用它；新增类型之前，先看现有类型加参数能不能表达。
- 一个定义里每种类型最多一个。
- 内容定义不能自带脚本。

**行为可以挂在体素定义和蓝图上**：
- 带功能性行为的体素定义是单格的部件。
- **功能复合体**是蓝图本身带功能性行为的复合体，例如大型柴油机、多格火炮。它整体提供能力，里面只装没有功能性行为的体素，不再嵌套复合体。
  - 只有内容包里的蓝图可以是功能复合体。玩家设计的蓝图不能带功能性行为。
  - 功能复合体是封闭的：玩家可以整件装上、拆下、替换和涂装，但不能编辑它的体素或行为。
  - 在核心里，一件功能复合体是宿主里的一个部件，有一个部件编号。它的耐久上限等于其中全部体素耐久上限之和，被毁时整件失效。
  - 它和其他大型设备一样，按蓝图在建造设施里建造，BOM 是其中的体素。
- **组装体**是车辆、建筑和炮塔这类复合体，能力只来自其中的部件，部件可以是功能体素，也可以是功能复合体。
- 蓝图上还可以带两类行为：
  - 没有部件的类别（生物）用行为给出自己的数值；
  - 只有表现的行为，例如大型设备的转动。

### 对其他决策的影响

`2026-10-09-nest-composites-by-copying-designs` 中“被嵌套的复合体的部件就是宿主的部件”只适用于组装体。功能复合体作为一个整体的部件，在部件编号中占一个号。

### 规则与推论

- **Demo 的行为类型**：
  - 功能性：`propulsion`、`control`、`storage`、`production`、`extraction`、`construction`、`power`、`weapon`、`platform`；
  - 生物：`creature`；
  - 只有表现：`rotation`、`wheelset`、`light`。

  各类型的参数由格式说明确定。
- **未知类型**：内容里写了未知类型，整个包无效。
- **不变的部分**：标签只做被动分类，建筑蓝图上的设施兼容标签仍是标签。

### 修订

- **修订**：2026-10-09，[体素定义的格式说明、Schema 与样例](https://github.com/odradekk/train/issues/264)把 `cargo` 并入 `storage`，列车和聚居地的库存容量都由它提供，Demo 的行为类型因此是 12 种。参数见 [docs/content/voxel.md](../../../../docs/content/voxel.md)。
- **修订**：2026-10-09，[聚居地模板：初始状态、格式说明、Schema 与样例](https://github.com/odradekk/train/issues/266)新增 `platform`：站点里的站台部件提供站台，每个完好的部件一个。Demo 的行为类型因此是 13 种。
- **修订**：2026-10-09，[内容定义标准的整体一致性检查](https://github.com/odradekk/train/issues/267)明确 `wheelset` 挂在转向架体素上，表示渲染器在这里生成轮对。轮对可以跨格，轮径和轴距随轨距在车辆内容切片确定。它不是让这个体素自己转动。
- **修订**：2026-10-09，[功能复合体的来源、缺失内容的状态、结构耐久下限与嵌套排序](https://github.com/odradekk/train/issues/269)规定宿主设计按身份引用功能复合体，不复制它的设计。被复制的设计不能带功能行为，所以加载器能保证功能复合体是密封的，玩家文件无法伪造。缺失的功能复合体按占位处理（见 `2026-10-09-package-dependencies-and-missing-placeholders`）。
- **修订**：2026-10-09，[功能复合体的来源、缺失内容的状态、结构耐久下限与嵌套排序](https://github.com/odradekk/train/issues/269)规定结构耐久上限等于结构体素的耐久上限，加上每个部件自身耐久上限的一部分（代码常量，初始为 1/2，向上取整）。命中按体素数量选择目标；命中部件时先伤部件，超出部分（包括命中已损毁部件的伤害）算在结构上。只有伤害能损毁实例。

## Alternatives considered

**功能设备严格是单格体素**（设计文档 03 原规则）。多格的大型引擎只能是外壳，动力要靠里面塞的单格引擎体素，既不直观，也和“超过一格的都是复合体”不一致。

**玩家设计的蓝图也能带功能性行为。** 玩家可以凭空写出一台“整车大引擎”。

**内容定义自带脚本，或运行中加载、卸载代码。** 研究见[研究：同类游戏的零件定义、行为与依赖](https://github.com/odradekk/train/issues/258)：对这个项目当前的规模和确定性要求（`2026-09-05-scalar-doubles-and-stateless-random`），纯数据加代码内置的行为类型更合适。同类游戏里也有带运行时脚本的（例如 Factorio 的 control.lua），.NET 也能卸载程序集，但需要清理全部引用，现在不值得承担这些工程约束。

## Acceptance criteria

内容只能选用游戏代码提供的行为类型并填参数，写了未知类型的包整包无效，内容定义不能自带脚本。只有内容包里的蓝图能带功能性行为，一件功能复合体在核心里是宿主的一个部件。

## Risks

**代码 Mod**：允许代码 Mod 注册新的行为类型放在 Demo 之后，只在启动时加载，届时修订 `2026-08-27-limit-mods-to-data-packages`，类型标识加上命名空间。
