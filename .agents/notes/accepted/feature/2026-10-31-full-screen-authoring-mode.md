# 创作面板改为全屏的创作模式

Status: accepted

## Problem

创作面板是游戏画面里 520 px 宽的一条滚动列，用来编辑内容包里的定义，处处要手工输入：

- 所有字段都是单行文本框：枚举要手输英文名，引用其他定义要手输 ID，列表用逗号分隔；格式错误要到保存时才出现在最底部。
- 聚居地模板的地块只能输入坐标；预览里点地块，只是让表单里那一行获得焦点，既不高亮也不能拖动。预览要手动点「更新预览」，改任何字段都会清空它。
- 写入结果、进度和所有错误都挤在最底部的同一个标签里，表单一长就看不到。

## Proposal

创作面板改为全屏的创作模式：

- 从主菜单或游戏菜单进入，只在开发构建出现。和设计编辑器一样，打开时暂停世界。
- 顶栏：退出、源包选择（要编辑的内容包：仓库里的 core 开发源码、本地模组目录，或新建本地模组）、重新载入、问题数、未保存和待写入的数量、保存草稿、写入包并重载。
- 左边是定义树：按种类分组，可以搜索；有问题、未保存、已存草稿的定义各有标记。还没有表单的种类（工序、各类规则、生成配置等）标为只读，并说明要直接改源文件。

### 表单

中间是表单，按「基本、模拟、行为、朝向与碰撞、表现」等分节：

- 枚举用中文下拉框。
- 引用字段只能从同类定义里选，而且只列本包、依赖包和 core 里的定义。
- 数字带单位，可以留空的写「使用默认值」；资产路径旁有「选择文件…」。
- 字段一改就校验，错误写在这个字段下方。
- 新建定义时，本地 ID 实时检查格式和是否重复，并显示完整 ID。
- 蓝图类定义（车辆、建筑、设备、生物）从表单进入设计编辑器编辑体素网格。

### 预览与模板地块

右边是预览，改动后自动更新，没有「更新预览」按钮。聚居地模板的地块在俯视布局图上拖动，按 R 旋转；选中的地块和表单里的那一行相互高亮；重叠的地块标红，并写明和哪一块重叠。布局图旁保留「在 3D 场景里查看」。

### 写入

先保存草稿，再写入包并重载：

- 确认框列出要写入的定义，并提醒写入期间不要用别的工具改这个包。
- 写入时分步显示进度：校验草稿、载入并校验候选包、复核源文件没被外部修改、写入文件、重新载入内容。
- 成功时列出写入的文件。失败时写明一个文件也没写、游戏里的内容保持原样、草稿还在；每条诊断都带「定位」，点了跳到对应的定义。

### 需要随实现修改的文档

设计编辑器与工具设计文档里「在场景模型上放置地块」改为本笔记的俯视布局图。

## Alternatives considered

**创作面板保留为游戏里的侧栏（现状）。** 可以一边看游戏一边改，但表单很长、预览需要空间；而且现在打开表单时游戏本来就进入编辑暂停，一边看游戏的好处并不存在。

**在 3D 场景模型上直接摆放地块。** 这是设计文档原来的设想，最直观，但要做 3D 里的拖动、旋转和吸附，工作量大；俯视布局图已经能表达地块的位置、大小和朝向。

## Acceptance criteria

- 创作模式里没有需要手输英文枚举名或定义 ID 的字段；字段错误在字段下方立即显示。
- 引用选择框里只出现本包、依赖包和 core 里的定义。
- 模板地块能在布局图上拖动和旋转，重叠时标红；改动后预览自动更新。
- 写入失败时，每条诊断都能定位到对应的定义。

## Risks

- 引用选择框要按包的依赖关系过滤，需要内容层提供列出可引用定义的查询。
- 俯视布局图只表达地块的平面位置和朝向，高度和地形贴合还要在 3D 场景里核对。
- 全屏以后不能一边看着游戏一边改定义；如果以后要边改边看效果，需要另想办法。
