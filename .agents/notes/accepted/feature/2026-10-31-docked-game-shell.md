# 游戏界面改为停靠式外壳

Status: accepted

## Problem

现在的游戏界面让玩家花很多点击，还常找不到东西。2026-10-31 对全部界面的盘点发现：

- 顶栏平铺十多个按钮。所有面板的位置写死、不能拖动，节点、线路、车队列表和通知记录默认叠在同一个位置。顶栏按钮只能打开面板、不能关闭，Esc 不关面板，在局部场景里却直接返回宏观地图。
- 在宏观地图上单击对象会直接切进局部场景，想看详情反而要打开列表再点一行。点聚居地或战斗标记都不会打开对应的面板，停在同一节点的列车互相遮挡。
- 一件事分散在多个面板里：买车、编组、写运行计划、发车要点约 27 次，跨 4 个面板。
- 反馈缺失或误导：成交后没有提示，还能连点重复成交；所有错误都叫「操作未完成」，要手动关；置灰的按钮不说原因。
- 界面直接显示内部编号、哈希、英文枚举名和代码里的记录文本，同一个概念有几种叫法。

## Proposal

采纳 2026-10-31 定稿的 UI 原型作为首版界面。原型是可以点击的 HTML 页面，和重设计前的界面盘点一起放在研究资料目录 `docs/research` 下，实现时以它和这几份笔记为准。本笔记决定游戏画面的外壳和全局交互规则，具体界面由另外五份笔记决定：

- 经营、列车、建设、战斗和经营报告：Decision note: 2026-10-31-object-centric-management-screens
- 设计编辑器、蓝图库和改装：Decision note: 2026-10-31-design-editor-direct-editing
- 主菜单、存档、设置和报告问题：Decision note: 2026-10-31-menus-saves-and-settings
- 开发工具底栏：Decision note: 2026-10-31-developer-dock
- 创作模式：Decision note: 2026-10-31-full-screen-authoring-mode

文中的现车、委托、运行计划等词都按项目术语表的意思使用。

### 画面分区

| 区域 | 内容 |
|---|---|
| 顶栏 | 左边是暂停、1×/2×/4×/8× 倍速、游戏时间和自动暂停的原因；在局部场景里，中间显示「宏观地图 › 地名」和返回按钮；右边是资金（变化时短暂显示增减）、通知和菜单 |
| 导航栏 | 屏幕左侧一列图标加文字：车队、线路、聚居地、报告、设计、战斗，带待处理数量 |
| 列表 | 点导航栏的车队、线路、聚居地或战斗，在旁边展开带搜索、筛选和分组的列表；再点一次收起 |
| 检查器 | 屏幕右侧，显示选中对象的全部信息和操作，主操作固定在底部 |
| 工作区 | 居中的大面板，用于编组、运行计划、委托与建造、经营报告、蓝图库这类多步编辑；同一时间只开一个；点四周的遮罩不会关闭它，以免误触丢掉编辑 |
| 提示条 | 底部居中，最多 3 条，6 秒后消失，严重级别的不自动消失；点一下选中相关对象 |

导航栏的「报告」打开经营报告工作区，「设计」打开蓝图库工作区。顶栏的通知按钮打开通知中心：按级别筛选，未读数标在按钮上，点一条通知选中相关对象。

设计编辑器和创作模式是全屏模式，打开时不显示上面这些区域，各有自己的顶栏、快捷键和 Esc 顺序，见各自的笔记。

### 地图与局部场景

- 在宏观地图上单击节点、线路、列车或战斗标记，只选中它并打开检查器，不进入局部场景。悬停时显示名称和状态。
- 双击对象，或点检查器里的「进入场景」（V），才进入它的局部场景（节点场景或线路场景）。
- 列表里点一行只选中对象，不移动地图视角；要移动视角，点检查器的「定位」（F）。
- 停在同一节点的多列列车围绕节点散开，每一列都能点到。
- 地图左下角是缩放、「全图」和「图层」。图层面板开关三个信息层（节点资源、站台占用、世界生物），并列出图例。
- 节点场景的节点小地图放在左下角，因为右侧给了检查器。宏观地图用偏暗的灰绿底色，让深色面板和彩色标记更醒目。

### 全局交互规则

- 每按一次 Esc 关掉最上面的一层，顺序是：对话框、弹出菜单、覆盖层（存档、设置等）、工作区、检查器、列表。这些都关掉以后，在局部场景里再按 Esc 回到宏观地图，在宏观地图上再按则打开菜单。
- 游戏画面的快捷键：空格暂停或继续；1–4 切换倍速；T 车队、L 线路、J 聚居地、R 报告、D 设计、B 战斗；F 定位；V 进入场景；WASD 平移地图；Ctrl+S 保存；` 开关开发工具底栏。这些键只在游戏画面里有效，全部可以在设置里改。
- 只花钱的操作不另弹确认，按钮上写明金额，例如买卖货物、修理、铁路施工、委托、建造、租用仓库。会改变关系、所有权或丢掉东西的操作先确认，问题里写明后果：宣战、占领、出售或拆解车辆、拆除建筑、解编、建立聚居地，以及丢掉未保存进度的读档、返回主菜单和退出。买现车也弹确认框，因为框里要提供「购买并编组」。
- 置灰的按钮旁边写明原因。
- 报价随输入实时更新，界面上没有「获取报价」按钮；提交按钮写明数量和金额，成功后在原处显示结果。
- 失败提示写在出错的地方，并说明怎么改，不再统一弹「操作未完成」。
- 界面上不出现内部编号、哈希、英文枚举名和代码文本（开发工具除外）。对象用名称；同一概念全程只用术语表里的一个词。
- 向玩家显示的时间只用游戏时间（第几天、时:分）和秒，不显示模拟步数（开发工具除外）。
- 新对局和读档后都处于暂停。打开存档、设置这类覆盖层时模拟暂停；设计编辑器和创作模式打开时也暂停世界。

### 与已有决定的关系

- Decision note: 2026-10-05-voxel-free-core-and-presentation-scenes：界面操作仍然作为命令提交，战斗进行时世界不暂停，进入设计编辑器时宿主暂停世界。本笔记照此执行。
- Decision note: 2026-10-10-separate-module-contracts：新界面需要的查询，例如实时报价，如果要改模块契约，按这份笔记由用户确认。
- Decision note: 2026-09-05-scalar-doubles-and-stateless-random：界面上的报价和费用都从核心模拟读取，界面不自己计算。
- Decision note: 2026-10-26-performance-measurement-system：单击不再打开场景，所以场景打开的计时起点改为「双击或点进入场景」；测量代码里引用旧面板的地方随实现迁移。
- Decision note: 2026-10-26-post-demo-performance-and-memory-gaps：读档到第一个可操作画面不超过 10 秒的要求，对新界面同样适用。

### 需要随实现修改的文档

窗口与界面设计文档里的下列规则改为本笔记的做法：点线路或列车进入场景、点建筑打开它的面板、可以同时打开多个面板、节点小地图在右上角。术语表增加导航栏、检查器、工作区、开发工具底栏四个词。

## Alternatives considered

**全屏管理页。** 地图只负责观看和选中，车队、聚居地、报告各有一个全屏页面，用标签切换。信息量大，但打开管理页就看不到地图。这是一款开着游戏看世界自动运行的经营游戏，玩家要边看地图边管理，所以没选。

**保留浮动面板，只修排布。** 面板可以拖动、自动排开，顶栏按钮可以开关，Esc 关闭最上层。改动最小，但面板一多仍会互相遮挡，玩家还要自己摆位置；买车到发车这类跨面板的任务也不会变短。

**单击直接进入局部场景（现状）。** 看一眼列车状态也要切进场景、等它加载，看完再返回；查看和进入混在同一个动作里。

**点列表时移动地图视角。** 设计文档规定管理界面不隐式改变视角；查列表时视角跳来跳去会打断观察，所以保留这条规则，另给显式的「定位」。

## Acceptance criteria

- 进入世界后屏幕上默认只有顶栏、导航栏和宏观地图；任何时候最多一个工作区，面板不会叠在同一位置。
- 在宏观地图上单击任一对象，右侧检查器显示它，不进入局部场景；双击或点「进入场景」才进入。
- Esc 按上面的顺序逐层关闭；在局部场景里关掉所有面板后再按 Esc，回到宏观地图。
- 从选中一个非敌对聚居地开始，买 3 辆现车、编组、写一条两站往返的运行计划并发车，不超过 16 次点击。
- 除开发工具外，界面文本里没有内部编号、哈希、英文枚举名和代码文本。
- 每个置灰的按钮旁都写着原因，每个花钱的按钮都写着金额；上面列出的会改变关系、所有权或丢掉东西的操作都先确认。
- 快捷键表里的每个键在游戏画面里都能用，也能在设置里改。

## Risks

- 这是对游戏内全部界面的重写，工作量大；全部替换完成前，新旧界面会并存一段时间。
- 原型是 HTML，没有在 Godot 里验证：字体渲染、界面缩放、1920×1080 以外的窗口尺寸，以及局部场景和检查器同屏时的帧时间，都要在真实窗口里检查。
- 单击地图不再进入局部场景，习惯旧操作的人要重新适应。
- 同一时间只开一个工作区，要对照两个工作区时只能来回切换。经营报告里直接提供「编辑计划」入口来减少切换。
