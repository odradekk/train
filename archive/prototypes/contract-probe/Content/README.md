# 内容消费与文件边界原型

这是可抛弃原型，不是内容加载器、存档系统或第二套游戏规则。在仓库根运行：

```powershell
pwsh -NoProfile -File archive/prototypes/contract-probe/Content/Run.ps1
```

只复制核心／内容契约、原有内容消费样例和本原型到独立临时目录。实际解析的第一方程序集必须来自该目录。证据位于 `TestResults/run-tests/contract-probe-292/content/<本次时间>/`，含输入 SHA256、构建和引用、逐项结果、子进程退出码及实际文件。

`Factory`、`Candidate`、`View`、`CoreSession` 只支持显式配置的固定情景；不解析或计算设计，不选择经济和模拟结果。固定单格设计、BOM、场景定位及模板来源配对。未配置操作抛异常并有自检。原有 `ConsumerExamples` 执行以下调用：

- 保存蓝图再建造；设计随命令交入，接受才激活目标，拒绝／故障仍保留命令所用候选视图。
- 实例立即应用、三种重载分支、未受理与正常拒绝的区别。
- 同一 `CoreInputId` 的两份设计视图完整传给录制捕获；这里只验证不去重和传递，没有执行内容编码或真实重放。
- 新局先准备模板副本再激活；建城接受后关联副本再从样例返回。故意错配作为调用前提错误传播，内部关联异常也不会从样例正常返回。真正宿主停用活动组仍待生产验证。
- 读档候选失败保留调用方的活动视图；候选释放和保留值寿命。

故意提前激活拒绝候选时，同一个旧状态断言明确失败；正确、破坏、恢复三阶段在同次程序执行中记录。它检查协调方的前后状态，不给合规替身增加错误行为。

真实 Windows 文件检查另列：同目录替换前／后子进程直接退出、占用目标拒绝且保留旧字节、递归来源字节比较发现同长度同时间戳修改／新增／删除／嵌套二进制、逐文件写入中第二文件失败后的实际混合磁盘结果，以及 `IContentFiles.Read` 返回字节的保留和超限拒绝。只支持一个配置文件的端口不会假装通用文件适配。来源捕获拒绝路径链接，但本轮没有链接夹具，不计该项通过。

这些文件检查不证明真正取消 API、替换过程中强杀、断电耐久、完整保存容器或生产重启加载；JSON 语法拒绝也不证明内容语义校验。它们没有把局部字符串状态当作生产活动内容。人口／市场／构成／缺失占位等业务规则、完整资产检查、生产 `PrepareLoad`／`CaptureReplay` 和真实宿主协调仍待模块实现。
