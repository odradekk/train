# 核心契约有限情景

原型 `ScenarioSession` 只依赖公开契约，现有 `ConsumerExamples` 执行读取同一边界、流程输出、设计同步提交、无引擎推进与保存失败消费路径。`SharedCases.Run(ICoreSession, ICoreFactory)` 保存同一组可观察断言，供将来的真实实现通过自己的公开准备入口建立相同情景后复用；值等价不要求复用同一个记录或数组实例。

固定情景：一辆小型车辆、一个节点、三个固定完整合法的结构设计与 BOM；三个设计命令依次接受、正常拒绝、内部故障，返回类型与稳定代码可区分。接受更新可观察设计和持久修订；拒绝保留业务状态；固定一次推进建立新的位置和修订；故障冻结前业务边界，同时记录故障并改变持久修订。世界种子及地貌保持固定。冻结保存返回失败，冻结命令不取得编号。动态设计不改变外部输入身份。保留旧视图和嵌套地貌特征数组在推进及释放后仍有效。

`ReadRecording()` 为接受、拒绝、故障三个 Completed 分别保留完整 `DesignInput` 的 fixture 载荷和回执，并声明初始设计、三个目标设计及外部定义的依赖。替身自检解析自己的 fixture 格式，检查全部公开设计字段和嵌套返还/BOM 集合；共享断言与普通消费代码均保持载荷不透明，只检查公开依赖清单、回执身份、结果和边界。`PrepareReplay` 仅接受这组固定输入及完整固定依赖，缺少依赖返回 `content_missing`。通过现有消费样例分别停在同一步接受/拒绝命令后的精确边界，再推进一个固定模拟步并停止于记录故障；保留旧重放视图和公开边界捕获仍可用。

这些是固定情景下的记录依赖交接和重放调用流程证据。fixture 使用 .NET JSON 序列化完整公开输入及不透明起点 token，没有实现生产核心的格式 2 命令/存档编解码或模拟重算。共享断言只接收 `ICoreSession`/`ICoreFactory`；替身未配置调用检查单独执行。其他命令、参数、顺序、查询及录制起点持久化入口明确抛出 `UNCONFIGURED`，不会默认成功。

`--mutable-snapshot` 使用独立的故意违规模式，把可变数组包装为 ImmutableArray 后改写旧地貌特征，由同一 `SharedCases` 的 nested collection 断言检出；它不参与合规替身通过结论。结构运行器依次执行正确、破坏、恢复版本并保存日志。

这不是第二套模拟或经济算法。所有结果来自明示的固定情景，不说明真实核心生成、命令裁决、存档编解码、人口续接、市场重判、记录持久化、确定性重算或多步首故障行为已通过。真实核心尚未按这些新契约实现，生产者验证仍待后续任务。
